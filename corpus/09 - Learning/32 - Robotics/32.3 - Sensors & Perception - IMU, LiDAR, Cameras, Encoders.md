# 32.3 — Sensors & Perception: IMU, LiDAR, Cameras, Encoders

> *"A robot's sensors are not its eyes — they are statistical pleas for help. Treat them probabilistically or be lied to."*

---

## 🎯 Learning Objectives

1. Use an **IMU** (3-axis gyro + 3-axis accel + optional magnetometer) and fuse it with a complementary or Mahony / Madgwick filter.
2. Process **LiDAR** scans: voxel grid downsample, RANSAC plane fit, **ICP** registration, free-space + occupancy.
3. Calibrate a **camera**: intrinsics (pinhole + distortion), extrinsics, rectification.
4. Use **RGB-D** (RealSense, OAK-D) and **stereo** to recover depth.
5. Read **encoders** (absolute, incremental quadrature) for joint position + velocity.
6. Fuse multi-modal data with **EKF / UKF / IEKF** and **factor graphs** (GTSAM / Ceres).

## 📚 1. IMU — Integrate With Care

A 6-axis IMU gives angular rate $\omega$ (gyro) and linear acceleration $a$ (accel). Naïve integration:
$$
\theta(t) = \int_0^t \omega(\tau)\,d\tau,\quad p(t) = \int_0^t \!\!\int_0^\tau a(s)\,ds\,d\tau
$$
**Drift** is brutal — bias of 0.01°/s yields > 30°/hr. The fix: fuse with gravity (accel) + magnetometer + visual / wheel odometry.

### Common filters
- **Complementary filter** (1 line of code, surprisingly good for tilt).
- **Madgwick / Mahony** filters — quaternion-based, drone-grade.
- **EKF** with quaternion state — production-grade.

## 📡 2. LiDAR — From Point Cloud to Surface

A 2D / 3D LiDAR returns ranges per beam. Pipeline:

1. **Filter** — distance gating, intensity gating, statistical outlier removal.
2. **Downsample** — voxel grid keeps ≤1 point per cell.
3. **Segment ground** — RANSAC plane fit (pcl::SACSegmentation).
4. **Cluster** — Euclidean cluster extraction or DBSCAN.
5. **Register** — ICP / NDT to align scans across time → odometry.

Common 3D LiDARs (2026): Velodyne (legacy), Ouster OS-0/1/2, Hesai PandarXT, Livox Mid-360 (cheap).

## 📷 3. Camera — Pinhole + Distortion

Pinhole projection:
$$
\begin{bmatrix} u \\ v \\ 1 \end{bmatrix} = K \begin{bmatrix} R \mid t \end{bmatrix} \begin{bmatrix} X \\ Y \\ Z \\ 1 \end{bmatrix}
$$
where $K = \mathrm{diag}(f_x, f_y, 1)$ with principal point $(c_x, c_y)$ and skew typically 0.

**Distortion** — radial $k_1, k_2, k_3$ + tangential $p_1, p_2$ (Brown-Conrady). Calibrate with a chessboard / ChArUco using OpenCV `cv2.calibrateCamera`.

### Stereo + RGB-D
- Stereo recovers depth via disparity: $Z = f B / d$.
- Active depth (RealSense, Kinect Azure, OAK-D) projects IR pattern + computes disparity in hardware.
- ToF (some Apple devices, iPad Pro LiDAR) measures photon round-trip per pixel.

### Camera-IMU calibration
**Kalibr** is the de-facto open-source tool for visual-inertial calibration.

## 🌀 4. Encoders

| Type | Output | Use |
|---|---|---|
| Incremental quadrature (A/B) | counts per revolution | Wheel & joint speed |
| Index (Z) channel | once-per-rev pulse | Home reference |
| Absolute (SSI, BiSS-C) | magnetic-encoded angle | Joint absolute position |
| Magnetic (AS5048, AS5600) | I²C/SPI, contactless | Cheap absolute angle |
| Optical strip / disk | encoded patterns | Linear stages |

Quadrature decoding: 4× resolution by counting both edges of A and B.

## 🔀 5. Sensor Fusion

| Approach | Pros | Cons |
|---|---|---|
| Complementary filter | Simple, fast | Tunable but ad-hoc |
| **EKF** | Workhorse, well-understood | Linearization error, Gaussian assumption |
| **UKF / IEKF** | Better for non-linear, manifold-aware | Heavier compute |
| **Particle filter** | Handles non-Gaussian | Curse of dimensionality |
| **Factor graphs** (GTSAM, Ceres) | Optimal smoothing, loop closure | Bigger conceptual jump |

ROS 2 ships **`robot_localization`** (EKF/UKF for odom + IMU + GPS) which solves 80% of mobile-robot fusion needs out of the box.

## 🛠️ 6. Worked Example (skeleton) — Wheel Odometry + IMU EKF

1. Wheel encoders → linear & angular velocity (ROS 2 `/odom`).
2. IMU → angular velocity & orientation (ROS 2 `/imu/data`).
3. `robot_localization` EKF fuses → drift-reduced `/odometry/filtered`.
4. Validate by driving in a 1 m × 1 m square; final pose should land < 5 cm from start.

## ⚠️ 8. Common Misconceptions

- **"IMUs alone tell you position."** Without aiding, integrated IMU drifts unboundedly. Always fuse.
- **"More LiDAR points = better."** Beyond a certain density you saturate processing without information gain. Voxel-downsample.
- **"Cameras are too noisy for state estimation."** Modern visual-inertial SLAM (ORB-SLAM3, OpenVINS) routinely beats LiDAR on cost.
- **"Calibration is one-and-done."** Re-calibrate after thermal cycles, mechanical shocks, or any time the rigid-body assumption is questioned.
