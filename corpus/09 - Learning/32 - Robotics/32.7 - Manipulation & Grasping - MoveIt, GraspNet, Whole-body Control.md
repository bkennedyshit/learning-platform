# 32.7 — Manipulation & Grasping: MoveIt 2, GraspNet, Whole-Body Control

> *"Mobile robotics is hard. Manipulation is harder. Whole-body manipulation is the unsolved-but-rapidly-being-solved frontier of 2026."*

## 🎯 Learning Objectives

1. Plan collision-free trajectories with **MoveIt 2** (PickNik) using sampling planners (RRT-Connect, BiTRRT) and optimization-based planners (CHOMP, STOMP).

3. Generate grasps with classical methods (force closure, GPD) and learned methods (GG-CNN, GraspNet-1Billion, Contact-GraspNet, AnyGrasp).

6. Recognize **whole-body control (WBC)** and its role in modern humanoids (Atlas, Optimus, Digit, NEO).
7. Survey **vision-language-action (VLA)** foundation models that are reshaping manipulation in 2026: RT-2 / OpenVLA / Helix / RDT-1B / pi-0.

## 📚 1. The Manipulation Pipeline

```
Perception → Object pose / point cloud
        ↓
Grasp generation → Candidate gripper poses (G_i, q_i)
        ↓
Motion planning → Joint trajectory q(t) from current → grasp pose
        ↓
Execution + monitoring → Track joint positions / forces; abort on failure
        ↓
Re-grasp / re-plan if needed
```

## 🛤️ 2. Motion Planning with MoveIt 2

MoveIt 2 ships planning pipelines around **OMPL** (sampling) and **CHOMP / STOMP** (optimization), with collision via FCL or HPP-FCL.

### Sampling planners (OMPL)
- RRT-Connect — fast, no quality guarantee.
- BiTRRT — bidirectional + trajectory optimization.
- BFMT, BIT*, AIT* — newer, better quality with modest compute.

### Optimization-based
- CHOMP — gradient-based; smooth.
- STOMP — stochastic; handles non-differentiable cost.

### Constrained planning
For tasks with end-effector constraints (e.g., keep cup upright while moving) MoveIt 2 supports **constrained sampling** via OMPL's projection-based methods.

## ✋ 3. Grasping

### Classical
- **Force closure** — analytic test for grasp stability given contact set.
- **GPD (Grasp Pose Detection)** — older sampling-based on point clouds.

### Learned
- **GG-CNN** — fast 2D grasp generator on RGB-D.
- **GraspNet-1Billion** — large-scale grasp dataset + family of models.
- **Contact-GraspNet** — point-cloud-conditioned 6-DOF grasp generator.
- **AnyGrasp** — strong general-purpose 6-DOF grasper.
- **GraspNetAPI / MetaGraspNet** — datasets + benchmarks.

### Decision flow
1. Get RGB-D from RealSense / OAK-D.
2. Segment object (SAM 2, Grounded-SAM, classic depth threshold).
3. Run grasp model → list of $(pose, confidence)$ poses.
4. Rank by reachability (IK solvable + collision-free) + score.
5. Execute via MoveIt 2.

## 💪 4. Whole-Body Control

When the robot is itself part of the manipulation envelope (humanoid reaches with arms while balancing), classical IK breaks down. Modern approach:

**Hierarchical QP (quadratic programming) WBC.** Per control cycle:
- Define tasks (keep CoM over support polygon, track end-effector pose, regularize joints).
- Stack as a hierarchy (priority order).
- Solve a QP each step (~1 kHz) with constraints (joint limits, friction cones, contact).

Toolboxes: **TSID** (Pinocchio-based), **OpenSoT**, **Drake's `InverseDynamicsController`**, **NVIDIA cuRobo** for GPU-accelerated TAMP/WBC.

## 🤖 5. The 2026 VLA Layer

Vision-Language-Action models trained on large multimodal datasets are starting to dominate research benchmarks (and increasingly production). Notable open / public 2026 systems:

- **OpenVLA** — open-weight VLA based on a vision-language backbone.
- **RT-2 / RT-X** (Google DeepMind, partial release) — VLM grounded in robot trajectories.
- **Helix** (Figure AI, mostly closed) — production VLA on Figure 03.
- **pi-0** (Physical Intelligence / pi.world) — broad-coverage manipulation.
- **RDT-1B** — diffusion transformer for manipulation.
- **NVIDIA GR00T** — humanoid foundation model effort.

In all cases the **interface** is roughly: image(s) + instruction → action chunk. They consume topic-level perception and produce trajectories that classical control closes the loop on.

## 🛠️ 6. Worked Example (skeleton) — Pick a Cup

1. RGB-D from RealSense.
2. Detect cup with Grounded-SAM ("the red cup").
3. Run AnyGrasp on the segmented point cloud → top-N grasps.
4. For each grasp: IK + collision check via MoveIt 2.
5. Plan trajectory from current → pre-grasp → grasp → post-grasp → place.
6. Execute via FollowJointTrajectory action.
7. Add force monitoring on the gripper for grip detection / failure.

## ⚠️ 8. Common Misconceptions

- **"Pick a planner once."** Different tasks suit different planners — sampling for free space, optimization for tight spaces, constrained for tasks with maintained orientation.
- **"Learned grasping replaces IK."** Grasps still need to be reachable + collision-free. The two layers compose.
- **"VLA models are end-to-end."** They emit short action chunks; classical controllers + safety layers close the actual loop.
- **"WBC is academic."** Every modern humanoid demo is WBC + MPC under the hood.
