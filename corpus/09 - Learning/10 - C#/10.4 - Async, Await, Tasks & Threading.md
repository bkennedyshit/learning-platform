# 10.4 — Async/Await, Tasks & Threading

> *"Async/await is not about threads. It's about not blocking the thread you're already on."* — Stephen Toub

Python's `asyncio` is single-threaded cooperative multitasking. C#'s `async/await` is similar in concept but fundamentally different in execution: it can actually use multiple threads, and the runtime manages the scheduling. In Unity, you face an additional constraint — the main thread owns all engine APIs. This chapter teaches you to write responsive, non-blocking code without freezing your game.

---

## 🎯 Learning Objectives

1. Understand the Task-based Asynchronous Pattern (TAP).
2. Write `async`/`await` code that doesn't block the main thread.
3. Distinguish CPU-bound (use threads) from I/O-bound (use async) work.
4. Handle cancellation with `CancellationToken`.
5. Understand Unity's threading constraints and alternatives (coroutines, UniTask).
6. Use `Task.WhenAll`, `Task.WhenAny` for concurrent operations.
7. Avoid common deadlocks and race conditions.

## 📚 1. Concepts

### Concept 3.4.1 — The Task-Based Asynchronous Pattern (TAP)

```csharp
// Synchronous (blocks the thread)
string data = File.ReadAllText("save.json");  // Thread waits for disk I/O

// Asynchronous (frees the thread during I/O)
string data = await File.ReadAllTextAsync("save.json");  // Thread does other work
```

A `Task` represents a future result. `await` suspends the current method until the task completes, but **does not block the thread** — the thread is free to do other work.

**Python comparison:**
| Python asyncio | C# TAP |
|----------------|--------|
| `async def foo():` | `async Task Foo()` |
| `await asyncio.sleep(1)` | `await Task.Delay(1000)` |
| `asyncio.gather(*tasks)` | `Task.WhenAll(tasks)` |
| `asyncio.run(main())` | `await Main()` or `Task.Run()` |
| Single-threaded event loop | Thread pool + SynchronizationContext |
| GIL prevents true parallelism | Real multi-threading |

### Concept 3.4.2 — async/await Mechanics

```csharp
public async Task<PlayerData> LoadPlayerAsync(string playerId, CancellationToken ct = default)
{
    // 1. Starts executing synchronously until first await
    var path = Path.Combine(SaveFolder, $"{playerId}.json");

    // 2. await suspends this method, returns Task to caller
    string json = await File.ReadAllTextAsync(path, ct);

    // 3. Resumes here when I/O completes (possibly on different thread!)
    var data = JsonSerializer.Deserialize<PlayerData>(json);

    // 4. Returns result wrapped in completed Task
    return data!;
}
```

The compiler transforms `async` methods into state machines. Each `await` is a suspension point.

### Concept 3.4.3 — CPU-Bound vs I/O-Bound

| Type | Example | Solution |
|------|---------|----------|
| **I/O-bound** | File read, HTTP request, DB query | `async/await` (no extra thread needed) |
| **CPU-bound** | Pathfinding, mesh generation, AI | `Task.Run()` (offload to thread pool) |
| **Unity main thread** | Transform, Physics, Rendering | Must execute on main thread |

```csharp
// I/O-bound: just await (no thread needed)
var response = await httpClient.GetStringAsync(url);

// CPU-bound: offload to thread pool
var path = await Task.Run(() => CalculateExpensivePath(start, end));

// Then back to main thread for Unity API calls
transform.position = path[0];  // Must be on main thread!
```

### Concept 3.4.4 — CancellationToken

```csharp
public async Task<Texture2D> LoadTextureAsync(string url, CancellationToken ct)
{
    ct.ThrowIfCancellationRequested();  // Check before starting

    using var client = new HttpClient();
    var bytes = await client.GetByteArrayAsync(url, ct);  // Cancellable

    ct.ThrowIfCancellationRequested();  // Check between steps

    var texture = new Texture2D(2, 2);
    texture.LoadImage(bytes);
    return texture;
}

// Usage with timeout
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(10));
try
{
    var tex = await LoadTextureAsync(url, cts.Token);
}
catch (OperationCanceledException)
{
    Debug.Log("Load cancelled or timed out");
}
```

### Concept 3.4.5 — Unity's Threading Constraint

Unity's API is **not thread-safe**. You cannot call `Transform.position`, `GameObject.SetActive()`, `Instantiate()`, etc. from any thread other than the main thread.

Options for async work in Unity:
1. **Coroutines** (legacy, Unity-native) — cooperative on main thread
2. **UniTask** (recommended) — allocation-free async/await for Unity
3. **Task.Run + dispatcher** — offload CPU work, dispatch results back
4. **Job System** (Chapter 10.6) — structured parallelism for data transforms

## 🔑 2. Mechanics

### 2.1 — Task Combinators

```csharp
// Run multiple async operations concurrently
public async Task LoadGameAsync()
{
    // All three load simultaneously
    var playerTask = LoadPlayerAsync();
    var worldTask = LoadWorldAsync();
    var inventoryTask = LoadInventoryAsync();

    // Wait for ALL to complete
    await Task.WhenAll(playerTask, worldTask, inventoryTask);

    // Access results
    var player = playerTask.Result;
    var world = worldTask.Result;
    var inventory = inventoryTask.Result;

    InitializeGame(player, world, inventory);
}

// First to complete wins (e.g., try multiple servers)
public async Task<ServerResponse> ConnectToFastestAsync(string[] servers)
{
    var tasks = servers.Select(s => TryConnectAsync(s));
    var winner = await Task.WhenAny(tasks);
    return await winner;  // Unwrap the winning task
}
```

### 2.2 — IAsyncEnumerable (Async Streams)

```csharp
// Python comparison: async for item in async_generator()
public async IAsyncEnumerable<ChunkData> LoadChunksAsync(
    Vector2Int center,
    int radius,
    [EnumeratorCancellation] CancellationToken ct = default)
{
    for (int x = -radius; x <= radius; x++)
    {
        for (int z = -radius; z <= radius; z++)
        {
            ct.ThrowIfCancellationRequested();
            var chunk = await LoadChunkFromDiskAsync(center + new Vector2Int(x, z));
            yield return chunk;  // Caller processes each chunk as it arrives
        }
    }
}

// Consumer
await foreach (var chunk in LoadChunksAsync(playerChunk, 3, ct))
{
    worldGrid.PlaceChunk(chunk);
    await Task.Yield();  // Give main thread a frame to render
}
```

### 2.4 — SynchronizationContext and ConfigureAwait

```csharp
// In UI/Unity apps, await resumes on the captured context (main thread)
await LoadDataAsync();
UpdateUI();  // ✓ Runs on main thread

// In library code, use ConfigureAwait(false) to avoid capturing context
public async Task<byte[]> DownloadAsync(string url)
{
    using var client = new HttpClient();
    // Don't need to resume on main thread — we're just processing data
    var bytes = await client.GetByteArrayAsync(url).ConfigureAwait(false);
    return ProcessBytes(bytes);  // Runs on thread pool thread
}
```

### 2.5 — UniTask (Unity-Optimized Async)

```csharp
// UniTask: zero-allocation async for Unity
// Install: https://github.com/Cysharp/UniTask

using Cysharp.Threading.Tasks;

public class SceneLoader : MonoBehaviour
{
    public async UniTaskVoid LoadSceneAsync(string sceneName)
    {
        // Show loading screen
        loadingUI.SetActive(true);

        // Async scene load (Unity-native, no Task allocation)
        await SceneManager.LoadSceneAsync(sceneName).ToUniTask(
            progress: Progress.Create<float>(p => loadingBar.value = p));

        // Wait one frame for scene to initialize
        await UniTask.Yield();

        // Fade in
        await canvasGroup.DOFade(1f, 0.5f).ToUniTask();

        loadingUI.SetActive(false);
    }
}

// UniTask with cancellation on destroy
public class EnemySpawner : MonoBehaviour
{
    private CancellationTokenSource _cts;

    void OnEnable()
    {
        _cts = new CancellationTokenSource();
        SpawnLoop(_cts.Token).Forget();  // Fire and forget
    }

    void OnDisable() => _cts?.Cancel();

    private async UniTaskVoid SpawnLoop(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            SpawnEnemy();
            await UniTask.Delay(TimeSpan.FromSeconds(2), cancellationToken: ct);
        }
    }
}
```

## ✍️ 3. Worked Examples

### Example 10.4.1 — Async Save System

```csharp
public class SaveSystem
{
    private readonly string _savePath;
    private readonly SemaphoreSlim _lock = new(1, 1);  // Prevent concurrent saves

    public SaveSystem(string savePath) => _savePath = savePath;

    public async Task SaveAsync(GameState state, CancellationToken ct = default)
    {
        await _lock.WaitAsync(ct);
        try
        {
            var json = JsonSerializer.Serialize(state, new JsonSerializerOptions
            {
                WriteIndented = true
            });

            // Write to temp file first (atomic save)
            var tempPath = _savePath + ".tmp";
            await File.WriteAllTextAsync(tempPath, json, ct);

            // Rename is atomic on most filesystems
            File.Move(tempPath, _savePath, overwrite: true);
        }
        finally
        {
            _lock.Release();
        }
    }

    public async Task<GameState?> LoadAsync(CancellationToken ct = default)
    {
        if (!File.Exists(_savePath)) return null;

        var json = await File.ReadAllTextAsync(_savePath, ct);
        return JsonSerializer.Deserialize<GameState>(json);
    }
}
```

### Example 10.4.2 — CPU-Bound Work Off Main Thread

```csharp
public class WorldGenerator : MonoBehaviour
{
    public async UniTask<ChunkData[,]> GenerateWorldAsync(int width, int height)
    {
        var chunks = new ChunkData[width, height];

        // Heavy computation on thread pool
        await UniTask.RunOnThreadPool(() =>
        {
            Parallel.For(0, width, x =>
            {
                for (int y = 0; y < height; y++)
                {
                    chunks[x, y] = GenerateChunk(x, y);  // Pure computation, no Unity API
                }
            });
        });

        // Back on main thread — safe to use Unity APIs
        for (int x = 0; x < width; x++)
        {
            for (int y = 0; y < height; y++)
            {
                InstantiateChunkVisuals(chunks[x, y]);
            }
            await UniTask.Yield();  // Spread instantiation across frames
        }

        return chunks;
    }
}
```

## ⚠️ 4. Gotchas

### Gotcha 3.4.1 — async void (Fire and Forget Danger)
```csharp
// ❌ async void — exceptions are unobservable, crash the app
async void LoadData() { await File.ReadAllTextAsync("..."); }

// ✓ async Task — caller can await and catch exceptions
async Task LoadDataAsync() { await File.ReadAllTextAsync("..."); }

// ✓ In Unity with UniTask: async UniTaskVoid (explicitly fire-and-forget)
async UniTaskVoid StartAnimation() { /* ... */ }
```

### Gotcha 3.4.2 — Deadlock with .Result / .Wait()
```csharp
// ❌ DEADLOCK in Unity/WPF (SynchronizationContext captures main thread)
void Start()
{
    var data = LoadDataAsync().Result;  // Blocks main thread waiting for task
    // But task needs main thread to resume! → DEADLOCK
}

// ✓ Use await all the way up (async all the way)
async void Start()  // Unity allows async void for lifecycle methods
{
    var data = await LoadDataAsync();
}
```

### Gotcha 3.4.3 — Forgetting to Dispose CancellationTokenSource
```csharp
// ❌ Leaks timer resources
var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
await DoWork(cts.Token);

// ✓ Always dispose
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
await DoWork(cts.Token);
```

### Gotcha 3.4.4 — Race Conditions with Shared State
```csharp
// ❌ Multiple tasks modifying shared list
var results = new List<int>();
await Task.WhenAll(
    Task.Run(() => { for (int i = 0; i < 1000; i++) results.Add(i); }),
    Task.Run(() => { for (int i = 0; i < 1000; i++) results.Add(i); })
);
// List<T> is NOT thread-safe! Corruption, exceptions, wrong counts.

// ✓ Use concurrent collections or locks
var results = new ConcurrentBag<int>();
// Or: lock, SemaphoreSlim, Channel<T>
```

### Example 8.1 — ConfigureAwait(false): When and Why

**Problem:** Your game server's async code is deadlocking, or your library code is unnecessarily marshaling back to the UI thread. Understanding `ConfigureAwait` is essential for writing correct async code.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### What ConfigureAwait Does

```csharp
// By default, await captures the current SynchronizationContext
// and resumes on that context after the await completes.

// In Unity (main thread context):
async Task LoadPlayerDataAsync()
{
    // Running on Unity main thread
    var data = await FetchFromServerAsync(); // Suspends here
    // RESUMES ON MAIN THREAD (because Unity has a SynchronizationContext)
    
    _playerName.text = data.Name; // ✅ Safe — we're on main thread
}

// With ConfigureAwait(false):
async Task LoadPlayerDataAsync()
{
    var data = await FetchFromServerAsync().ConfigureAwait(false);
    // RESUMES ON THREAD POOL THREAD (context not captured)
    
    _playerName.text = data.Name; // ❌ CRASH — not on main thread!
}
```

#### The Rules

```csharp
// RULE 1: Application-level code (Unity MonoBehaviours, UI handlers)
// → Do NOT use ConfigureAwait(false)
// → You NEED to resume on the main thread for Unity API calls
public class PlayerUI : MonoBehaviour
{
    async void OnLoginButtonClicked()
    {
        var result = await AuthService.LoginAsync(username, password);
        // Must be on main thread to update UI
        _statusText.text = result.Success ? "Welcome!" : "Failed";
    }
}

// RULE 2: Library/infrastructure code (no UI dependency)
// → DO use ConfigureAwait(false) everywhere
// → Prevents deadlocks, improves throughput
public class HttpGameClient
{
    private readonly HttpClient _http;

    public async Task<PlayerData> GetPlayerAsync(string id)
    {
        var response = await _http.GetAsync($"/players/{id}")
            .ConfigureAwait(false); // ✅ Library code — no UI dependency
        
        var json = await response.Content.ReadAsStringAsync()
            .ConfigureAwait(false); // ✅ Every await in the chain
        
        return JsonSerializer.Deserialize<PlayerData>(json)!;
    }
}

// RULE 3: Game server code (ASP.NET Core, console apps)
// → ConfigureAwait(false) is technically unnecessary (no SyncContext)
// → But it's good practice for portability
public class GameServerHandler
{
    public async Task<GameState> ProcessTurnAsync(TurnCommand cmd)
    {
        var state = await _repository.LoadAsync(cmd.GameId)
            .ConfigureAwait(false);
        state.ApplyTurn(cmd);
        await _repository.SaveAsync(state)
            .ConfigureAwait(false);
        return state;
    }
}
```

#### The Classic Deadlock Scenario

```csharp
// This DEADLOCKS in Unity (or WPF, WinForms):
public class BadExample : MonoBehaviour
{
    void Start()
    {
        // .Result blocks the main thread, waiting for the task
        var data = LoadDataAsync().Result; // ⚠️ DEADLOCK!
    }

    async Task<string> LoadDataAsync()
    {
        // This await wants to resume on main thread (captured context)
        // But main thread is BLOCKED by .Result above!
        var text = await File.ReadAllTextAsync("save.json");
        return text; // Never reaches here — deadlock
    }
}

// FIX 1: Use async all the way (best)
async void Start()
{
    var data = await LoadDataAsync(); // ✅ No blocking
}

// FIX 2: ConfigureAwait(false) in the library (if you can't change caller)
async Task<string> LoadDataAsync()
{
    var text = await File.ReadAllTextAsync("save.json")
        .ConfigureAwait(false); // Doesn't need main thread to resume
    return text; // ✅ Resumes on thread pool, no deadlock
}
```

### Example 8.2 — ValueTask vs Task: When to Optimize

**Problem:** Your game's entity system calls async methods millions of times per frame, but most calls complete synchronously (cache hits). `Task<T>` allocates on every call. `ValueTask<T>` avoids this.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### The Allocation Problem

```csharp
// Task<T> ALWAYS allocates a Task object on the heap (~100 bytes)
public async Task<EnemyData> GetEnemyAsync(int id)
{
    if (_cache.TryGetValue(id, out var cached))
        return cached; // Still allocates a Task to wrap the result!
    
    return await _database.LoadAsync(id);
}
// Called 10,000 times/frame × 60fps = 600,000 allocations/second
// = Massive GC pressure in Unity

// ValueTask<T> avoids allocation for synchronous completions
public ValueTask<EnemyData> GetEnemyAsync(int id)
{
    if (_cache.TryGetValue(id, out var cached))
        return new ValueTask<EnemyData>(cached); // NO allocation! Stack-only.
    
    return new ValueTask<EnemyData>(LoadFromDatabaseAsync(id));
}

private async Task<EnemyData> LoadFromDatabaseAsync(int id)
{
    return await _database.LoadAsync(id);
}
```

#### ValueTask Rules

```csharp
// RULE 1: Use ValueTask when the method OFTEN completes synchronously
// (cache hits, buffered reads, already-computed results)

// RULE 2: A ValueTask can only be awaited ONCE
var vt = GetEnemyAsync(42);
var result1 = await vt; // ✅ First await
var result2 = await vt; // ❌ UNDEFINED BEHAVIOR! Don't do this.

// RULE 3: Don't use .Result or .GetAwaiter().GetResult() on ValueTask
// (Unlike Task, ValueTask may be backed by a pooled object that gets reused)

// RULE 4: If you need to await multiple times, convert to Task first:
var vt = GetEnemyAsync(42);
var task = vt.AsTask(); // Convert to Task (allocates, but now safe)
var r1 = await task;
var r2 = await task; // ✅ Safe on Task

// RULE 5: Use Task<T> for public API surfaces unless perf-critical
// ValueTask has footguns; Task is safer for general use
```

#### IValueTaskSource: Custom Pooling (Advanced)

```csharp
// For extreme performance: pool the async state machine backing object
// Used by Kestrel (ASP.NET Core web server) for zero-alloc I/O

public class PooledSocketOperation : IValueTaskSource<int>
{
    private ManualResetValueTaskSourceCore<int> _core;
    private static readonly ObjectPool<PooledSocketOperation> _pool = 
        new(() => new PooledSocketOperation());

    public static ValueTask<int> ReadAsync(Socket socket, Memory<byte> buffer)
    {
        var op = _pool.Get();
        op.StartRead(socket, buffer);
        return new ValueTask<int>(op, op._core.Version);
    }

    // IValueTaskSource implementation...
    public int GetResult(short token)
    {
        var result = _core.GetResult(token);
        _core.Reset();
        _pool.Return(this); // Return to pool for reuse
        return result;
    }
    
    public ValueTaskSourceStatus GetStatus(short token) => _core.GetStatus(token);
    public void OnCompleted(Action<object?> continuation, object? state, 
        short token, ValueTaskSourceOnCompletedFlags flags)
        => _core.OnCompleted(continuation, state, token, flags);
}
```

### Example 8.3 — Cancellation Token Propagation

**Problem:** Your game needs to cancel async operations when: a scene unloads, a player disconnects, a timeout expires, or the user cancels matchmaking. Proper CancellationToken propagation is critical.

<details>
<summary>🔍 Full step-by-step solution</summary>

```csharp
// ═══════════════════════════════════════════════════════════════
// PATTERN: Linked cancellation tokens (multiple cancel reasons)
// ═══════════════════════════════════════════════════════════════
public class MatchmakingService : MonoBehaviour
{
    private CancellationTokenSource _sceneLifetime;
    
    private void OnEnable()
    {
        _sceneLifetime = new CancellationTokenSource();
    }
    
    private void OnDisable()
    {
        _sceneLifetime?.Cancel();
        _sceneLifetime?.Dispose();
    }

    public async Task<MatchResult> FindMatchAsync()
    {
        // Timeout after 30 seconds
        using var timeout = new CancellationTokenSource(TimeSpan.FromSeconds(30));
        
        // Cancel if EITHER scene unloads OR timeout expires
        using var linked = CancellationTokenSource.CreateLinkedTokenSource(
            _sceneLifetime.Token, timeout.Token);

        try
        {
            return await SearchForMatchAsync(linked.Token);
        }
        catch (OperationCanceledException) when (timeout.IsCancellationRequested)
        {
            Debug.Log("Matchmaking timed out");
            return MatchResult.Timeout;
        }
        catch (OperationCanceledException)
        {
            Debug.Log("Matchmaking cancelled (scene unloaded)");
            return MatchResult.Cancelled;
        }
    }

    private async Task<MatchResult> SearchForMatchAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            var response = await _httpClient.PostAsync("/matchmaking/search", null, ct);
            var result = await response.Content.ReadFromJsonAsync<MatchResponse>(ct);
            
            if (result?.Found == true)
                return new MatchResult(result.ServerIp, result.Port);
            
            // Poll every 2 seconds
            await Task.Delay(2000, ct); // Throws if cancelled during wait
        }
        
        ct.ThrowIfCancellationRequested();
        return MatchResult.Cancelled; // Unreachable but satisfies compiler
    }
}

// ═══════════════════════════════════════════════════════════════
// PATTERN: Graceful shutdown with cancellation
// ═══════════════════════════════════════════════════════════════
public class GameServer
{
    private readonly CancellationTokenSource _shutdownCts = new();

    public async Task RunAsync()
    {
        var listener = new TcpListener(IPAddress.Any, 7777);
        listener.Start();

        try
        {
            while (!_shutdownCts.IsCancellationRequested)
            {
                // AcceptAsync respects cancellation
                var client = await listener.AcceptTcpClientAsync(_shutdownCts.Token);
                _ = HandleClientAsync(client, _shutdownCts.Token);
            }
        }
        catch (OperationCanceledException)
        {
            Console.WriteLine("Server shutting down gracefully...");
        }
        finally
        {
            listener.Stop();
        }
    }

    public void Shutdown() => _shutdownCts.Cancel();
}

// ═══════════════════════════════════════════════════════════════
// PATTERN: Per-operation cancellation in Unity with destroyCancellationToken
// ═══════════════════════════════════════════════════════════════
public class AsyncLoader : MonoBehaviour
{

    {

    }
}
```

### Example 8.4 — UniTask in Unity: Zero-Allocation Async

**Problem:** Unity's `Task`-based async allocates garbage every frame. UniTask provides allocation-free async/await designed specifically for Unity's player loop.

<details>
<summary>🔍 Full step-by-step solution</summary>

```csharp
using Cysharp.Threading.Tasks;

// ═══════════════════════════════════════════════════════════════
// UniTask basics — replaces Task in Unity code
// ═══════════════════════════════════════════════════════════════
public class UniTaskExamples : MonoBehaviour
{
    // UniTask instead of Task — zero allocation
    async UniTask LoadSceneAsync(string sceneName, CancellationToken ct)
    {
        // Await Unity's AsyncOperation directly (no wrapper allocation)
        await SceneManager.LoadSceneAsync(sceneName).WithCancellation(ct);
    }

    // UniTask<T> instead of Task<T>
    async UniTask<Sprite> LoadSpriteAsync(string address, CancellationToken ct)
    {
        var handle = Addressables.LoadAssetAsync<Sprite>(address);
        return await handle.WithCancellation(ct);
    }

    // Await frames (replaces coroutine yield return null)
    async UniTaskVoid FadeInAsync(CanvasGroup group, CancellationToken ct)
    {
        group.alpha = 0f;
        while (group.alpha < 1f)
        {
            group.alpha += Time.deltaTime * 2f;
            await UniTask.Yield(ct); // Wait one frame, zero alloc
        }
    }

    // Await specific timing
    async UniTask DelayedSpawnAsync(CancellationToken ct)
```

## 📖 9. Appendix: Extended Derivations & Special Cases

### Appendix 9.1 — Async State Machine Code Generation

When you write `async Task<int> MyMethodAsync()`, the compiler transforms your method into a state machine struct. Understanding this helps debug async issues.

#### What the Compiler Generates

```csharp
// YOUR CODE:
public async Task<int> CalculateAsync(int x)
{
    var a = await GetValueAsync(x);
    var b = await GetValueAsync(a + 1);
    return a + b;
}

// COMPILER GENERATES (simplified):
[AsyncStateMachine(typeof(<CalculateAsync>d__0))]
public Task<int> CalculateAsync(int x)
{
    var stateMachine = new <CalculateAsync>d__0();
    stateMachine.<>t__builder = AsyncTaskMethodBuilder<int>.Create();
    stateMachine.x = x;
    stateMachine.<>1__state = -1; // Initial state
    stateMachine.<>t__builder.Start(ref stateMachine);
    return stateMachine.<>t__builder.Task;
}

private struct <CalculateAsync>d__0 : IAsyncStateMachine
{
    public int <>1__state;  // Which await are we at?
    public AsyncTaskMethodBuilder<int> <>t__builder;
    public int x;           // Parameter
    private int <a>5__1;    // Local variable 'a' (hoisted to field)
    private int <b>5__2;    // Local variable 'b' (hoisted to field)
    private TaskAwaiter<int> <>u__1; // Awaiter storage

    void IAsyncStateMachine.MoveNext()
    {
        int result;
        try
        {
            TaskAwaiter<int> awaiter;
            switch (<>1__state)
            {
                case -1: // Initial
                    awaiter = GetValueAsync(x).GetAwaiter();
                    if (!awaiter.IsCompleted)
                    {
                        <>1__state = 0;
                        <>u__1 = awaiter;
                        <>t__builder.AwaitUnsafeOnCompleted(ref awaiter, ref this);
                        return; // Suspend! Will be called back later.
                    }
                    goto case_0_completed;

                case 0: // Resumed after first await
                    awaiter = <>u__1;
                    <>u__1 = default;
                    <>1__state = -1;
                    case_0_completed:
                    <a>5__1 = awaiter.GetResult();

                    awaiter = GetValueAsync(<a>5__1 + 1).GetAwaiter();
                    if (!awaiter.IsCompleted)
                    {
                        <>1__state = 1;
                        <>u__1 = awaiter;
                        <>t__builder.AwaitUnsafeOnCompleted(ref awaiter, ref this);
                        return; // Suspend again!
                    }
                    goto case_1_completed;

                case 1: // Resumed after second await
                    awaiter = <>u__1;
                    <>u__1 = default;
                    <>1__state = -1;
                    case_1_completed:
                    <b>5__2 = awaiter.GetResult();

                    result = <a>5__1 + <b>5__2;
                    break;
            }
        }
        catch (Exception ex)
        {
            <>1__state = -2; // Finished (error)
            <>t__builder.SetException(ex);
            return;
        }
        <>1__state = -2; // Finished (success)
        <>t__builder.SetResult(result);
    }
}
```

#### Key Insights

1. **Each `await` = one state**: The state machine has N+1 states for N awaits
2. **Local variables become fields**: They must survive across suspensions
3. **The struct is boxed on first suspension**: If the task completes synchronously, no allocation!
4. **`async void` uses `AsyncVoidMethodBuilder`**: No Task returned, exceptions go to SynchronizationContext

### Appendix 9.2 — SynchronizationContext Pitfalls

#### What is SynchronizationContext?

```csharp
// SynchronizationContext is the mechanism that determines WHERE
// code resumes after an await.

// Unity's UnitySynchronizationContext:
//   - Captures: main thread
//   - Post(): queues work to main thread's update loop
//   - Result: await resumes on main thread

// ASP.NET Core:
//   - NO SynchronizationContext (by design)
//   - await resumes on any thread pool thread
//   - Result: better throughput, no deadlock risk

// WPF/WinForms DispatcherSynchronizationContext:
//   - Captures: UI thread
//   - Post(): queues to dispatcher
//   - Result: same deadlock risks as Unity
```

#### Common Pitfalls

```csharp
// PITFALL 1: Blocking on async in Unity
void Start()
{
    // DEADLOCK: Main thread blocked, await can't resume on main thread
    var result = LoadAsync().Result;
    
    // FIX: Use async void Start() or UniTask
}

// PITFALL 2: Thread pool work trying to access Unity API
async Task ProcessAsync()
{
    await Task.Run(() =>
    {
        // Running on thread pool thread
        transform.position = Vector3.zero; // ❌ CRASH: Unity API not thread-safe
    });
    
    // FIX: Do computation on thread pool, update Unity on main thread
    var newPos = await Task.Run(() => CalculateExpensivePosition());
    transform.position = newPos; // ✅ Back on main thread after await
}

// PITFALL 3: ConfigureAwait(false) then accessing Unity API
async Task LoadAndApplyAsync()
{
    var data = await FetchDataAsync().ConfigureAwait(false);
    // Now on thread pool thread!
    _text.text = data.Name; // ❌ CRASH
    
    // FIX: Switch back to main thread
    await UniTask.SwitchToMainThread();
    _text.text = data.Name; // ✅ Safe
}

// PITFALL 4: Fire-and-forget losing exceptions
async void Start()
{
    DoSomethingAsync(); // ⚠️ Exception silently lost!
    
    // FIX: Use UniTaskVoid with Forget(), or await it
    DoSomethingAsync().Forget(); // Logs exception to Unity console
}
```

### Appendix 9.3 — Thread Safety Patterns for Game Servers

```csharp
// Game servers process multiple clients concurrently.
// These patterns prevent race conditions:

// PATTERN 1: Immutable game state + atomic swap
public class GameRoom
{
    private volatile GameState _state; // Immutable snapshots
    
    public void ProcessCommand(PlayerCommand cmd)
    {
        GameState oldState, newState;
        do
        {
            oldState = _state;
            newState = oldState.ApplyCommand(cmd); // Pure function, new object
        } while (Interlocked.CompareExchange(ref _state, newState, oldState) != oldState);
    }
}

// PATTERN 2: Channel-based message passing (no shared state)
public class GameLoop
{
    private readonly Channel<GameCommand> _commandChannel = 
        Channel.CreateUnbounded<GameCommand>();

    // Multiple threads write commands
    public async ValueTask EnqueueCommandAsync(GameCommand cmd)
    {
        await _commandChannel.Writer.WriteAsync(cmd);
    }

    // Single thread processes them sequentially
    public async Task RunAsync(CancellationToken ct)
    {
        await foreach (var cmd in _commandChannel.Reader.ReadAllAsync(ct))
        {
            ProcessCommand(cmd); // No locks needed — single consumer
        }
    }
}

// PATTERN 3: Reader-writer lock for read-heavy workloads
public class LeaderboardService
{
    private readonly ReaderWriterLockSlim _lock = new();
    private List<LeaderboardEntry> _entries = new();

    public IReadOnlyList<LeaderboardEntry> GetTop10()
    {
        _lock.EnterReadLock();
        try { return _entries.Take(10).ToList(); }
        finally { _lock.ExitReadLock(); }
    }

    public void UpdateScore(string playerId, int score)
    {
        _lock.EnterWriteLock();
        try
        {
            // Modify and re-sort
            var entry = _entries.Find(e => e.PlayerId == playerId);
            if (entry != null) entry.Score = score;
            _entries.Sort((a, b) => b.Score.CompareTo(a.Score));
        }
        finally { _lock.ExitWriteLock(); }
    }
}
```
