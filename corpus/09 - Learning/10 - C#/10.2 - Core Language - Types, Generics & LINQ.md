# 10.2 — Core Language: Types, Generics & LINQ

> *"The type system is your first line of defense. Make illegal states unrepresentable."* — Mads Torgersen

Python lets you put anything anywhere and hopes for the best at runtime. C# catches entire categories of bugs at compile time — but only if you lean into the type system rather than fighting it. This chapter teaches you to think in types, constrain with generics, and query with LINQ the way you'd use list comprehensions in Python.

---

## 🎯 Learning Objectives

1. Distinguish value types (struct) from reference types (class) and understand their memory implications.
2. Use generics with constraints to write reusable, type-safe containers.
3. Write LINQ queries (method syntax and query syntax) as fluently as Python comprehensions.
4. Apply C# 11/12 pattern matching for expressive control flow.
5. Use nullable reference types to eliminate null-reference exceptions.
6. Understand records, tuples, and modern data-carrying types.

## 📚 1. Concepts

### Concept 3.2.1 — Value Types vs Reference Types

This is the **single most important distinction** in C# that doesn't exist in Python:

| Aspect | Value Type (`struct`) | Reference Type (`class`) |
|--------|----------------------|--------------------------|
| Storage | Stack (or inline in containing type) | Heap (GC-managed) |
| Assignment | Copies the data | Copies the pointer |
| Default | Zero-initialized | `null` |
| Equality | By value (all fields) | By reference (identity) |
| Examples | `int`, `float`, `bool`, `Vector3`, `DateTime` | `string`, `List<T>`, `GameObject`, your classes |
| GC pressure | None (no allocation) | Yes (GC must track and collect) |

```csharp
// Value type — copied on assignment
Vector3 a = new(1, 2, 3);
Vector3 b = a;          // b is an independent COPY
b.x = 99;              // a.x is still 1

// Reference type — shared reference
List<int> listA = new() { 1, 2, 3 };
List<int> listB = listA;  // listB points to SAME object
listB.Add(4);             // listA also sees the 4!
```

**Python comparison:** In Python, everything is a reference to a heap object. Even `int` is a heap-allocated object (CPython caches small ints, but semantically it's still a reference). C# gives you the choice.

### Concept 3.2.2 — The Type Hierarchy

```
System.Object (object)
├── System.ValueType
│   ├── Primitives: int, float, double, bool, char, byte, long
│   ├── Structs: Vector3, DateTime, Guid, your custom structs
│   └── Enums: DayOfWeek, your custom enums
└── Reference Types
    ├── string (immutable, special-cased)
    ├── Arrays: int[], string[], T[]
    ├── Classes: List<T>, Dictionary<K,V>, your classes
    ├── Delegates: Action, Func<T>, event handlers
    └── Interfaces: IEnumerable<T>, IDisposable
```

### Concept 3.2.3 — Nullable Reference Types (NRT)

C# 8+ with `<Nullable>enable</Nullable>` makes the compiler track nullability:

```csharp
string name = "Bill";     // Non-nullable — compiler guarantees not null
string? nickname = null;  // Nullable — must check before use

// Compiler warning: possible null dereference
int len = nickname.Length;  // ⚠️ CS8602

// Correct: null check
if (nickname is not null)
{
    int len = nickname.Length;  // ✓ Safe
}

// Or: null-conditional + null-coalescing
int len = nickname?.Length ?? 0;
```

**Python comparison:** Like `Optional[str]` in type hints, but enforced by the compiler, not just mypy.

### Concept 3.2.4 — Records (Immutable Data Types)

Records are C#'s answer to Python's `@dataclass(frozen=True)`:

```csharp
// Record class (reference type, immutable by convention)
public record Crop(string Name, int GrowthDays, float SellPrice);

// Record struct (value type, truly immutable)
public readonly record struct Tile(int X, int Y);

// Usage
var parsnip = new Crop("Parsnip", 4, 35f);
var upgraded = parsnip with { SellPrice = 50f };  // Non-destructive mutation

// Built-in: Equals, GetHashCode, ToString, deconstruction
var (name, days, price) = parsnip;
Console.WriteLine(parsnip);  // Crop { Name = Parsnip, GrowthDays = 4, SellPrice = 35 }
```

### Concept 3.2.5 — Tuples

Quick multi-return without defining a type:

```csharp
// Named tuple (like Python's NamedTuple)
(int X, int Y) GetPlayerTile() => (playerX / 16, playerY / 16);

var tile = GetPlayerTile();
Console.WriteLine($"Tile: {tile.X}, {tile.Y}");

// Deconstruction
var (x, y) = GetPlayerTile();

// Python comparison:
// def get_player_tile() -> tuple[int, int]: return (px // 16, py // 16)
```

### Concept 3.2.6 — Enums (Stronger Than Python's)

```csharp
public enum Season { Spring, Summer, Fall, Winter }

// Flags enum (bitwise combinable)
[Flags]
public enum CropNeeds
{
    None    = 0,
    Water   = 1 << 0,  // 1
    Sun     = 1 << 1,  // 2
    Fertile = 1 << 2,  // 4
    All     = Water | Sun | Fertile
}

// Usage
var needs = CropNeeds.Water | CropNeeds.Sun;
bool needsWater = needs.HasFlag(CropNeeds.Water);  // true
```

## 📐 2. Mental Models

### Model 3.2.1 — Python Duck Typing → C# Generics + Constraints

In Python, you write functions that work on "anything with a `.damage` attribute." In C#, you express that contract explicitly:

```csharp
// Python: def apply_damage(target): target.health -= target.damage
// C#: Express the contract as a constraint

public interface IDamageable
{
    float Health { get; set; }
    float MaxHealth { get; }
}

public static void ApplyDamage<T>(T target, float amount) where T : IDamageable
{
    target.Health = MathF.Max(0, target.Health - amount);
}
```

### Model 3.2.2 — List Comprehensions → LINQ

| Python | C# LINQ (Method Syntax) | C# LINQ (Query Syntax) |
|--------|-------------------------|------------------------|
| `[x*2 for x in items]` | `items.Select(x => x * 2)` | `from x in items select x * 2` |
| `[x for x in items if x > 5]` | `items.Where(x => x > 5)` | `from x in items where x > 5 select x` |
| `sum(x.price for x in items)` | `items.Sum(x => x.Price)` | — |
| `sorted(items, key=lambda x: x.name)` | `items.OrderBy(x => x.Name)` | `from x in items orderby x.Name select x` |
| `any(x.ready for x in items)` | `items.Any(x => x.Ready)` | — |
| `{k: v for k, v in pairs}` | `pairs.ToDictionary(p => p.Key, p => p.Value)` | — |

## 🔑 3. Mechanics — Generics

### 10.1 — Generic Classes and Methods

```csharp
// Generic class — like Python's Generic[T] but enforced
public class ObjectPool<T> where T : class, new()
{
    private readonly Stack<T> _pool = new();
    private readonly int _maxSize;

    public ObjectPool(int maxSize = 100) => _maxSize = maxSize;

    public T Get() => _pool.Count > 0 ? _pool.Pop() : new T();

    public void Return(T obj)
    {
        if (_pool.Count < _maxSize)
            _pool.Push(obj);
    }
}

// Generic method
public static T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) >= 0 ? a : b;
```

### 10.2 — Constraint Types

```csharp
where T : struct          // Value type only (no null, no GC)
where T : class           // Reference type only
where T : new()           // Has parameterless constructor
where T : BaseClass       // Inherits from BaseClass
where T : IInterface      // Implements interface
where T : notnull         // Non-nullable
where T : unmanaged       // Blittable (no references) — for native interop

// Multiple constraints
where T : class, ISerializable, new()

// Constraint on multiple type params
public class Map<TKey, TValue>
    where TKey : notnull, IEquatable<TKey>
    where TValue : struct
{ }
```

### 10.3 — Generic Variance (Covariance / Contravariance)

```csharp
// Covariant (out) — can return T, not accept T
public interface IReadOnlyList<out T> { T this[int index] { get; } }

// Contravariant (in) — can accept T, not return T
public interface IComparer<in T> { int Compare(T x, T y); }

// Practical: IEnumerable<Crop> can be assigned to IEnumerable<object>
IEnumerable<Crop> crops = GetCrops();
IEnumerable<object> objects = crops;  // ✓ Covariant
```

### 10.4 — Game-Relevant Generic Pattern: Component Lookup

```csharp
// Type-safe component retrieval (like Unity's GetComponent<T>)
public class Entity
{
    private readonly Dictionary<Type, object> _components = new();

    public void Add<T>(T component) where T : class
        => _components[typeof(T)] = component;

    public T? Get<T>() where T : class
        => _components.TryGetValue(typeof(T), out var c) ? (T)c : null;

    public bool Has<T>() where T : class
        => _components.ContainsKey(typeof(T));
}

// Usage
var player = new Entity();
player.Add(new HealthComponent(100));
player.Add(new InventoryComponent(24));

var health = player.Get<HealthComponent>();  // Type-safe, no casting
```

## 🔑 4. Mechanics — LINQ

### 4.1 — LINQ Fundamentals

LINQ (Language Integrated Query) is C#'s killer feature for data manipulation. It's lazy-evaluated (like Python generators) until you materialize with `.ToList()`, `.ToArray()`, or iterate.

```csharp
// Sample data
public record Item(string Name, int StackSize, float Value, ItemCategory Category);

var inventory = new List<Item>
{
    new("Parsnip", 64, 35f, ItemCategory.Crop),
    new("Iron Ore", 128, 10f, ItemCategory.Resource),
    new("Galaxy Sword", 1, 5000f, ItemCategory.Weapon),
    new("Pumpkin", 64, 320f, ItemCategory.Crop),
    new("Gold Bar", 64, 250f, ItemCategory.Resource),
};

// Filter + Transform (Python: [i.name for i in inv if i.value > 100])
var valuableNames = inventory
    .Where(i => i.Value > 100f)
    .Select(i => i.Name)
    .ToList();
// ["Galaxy Sword", "Pumpkin", "Gold Bar"]

// Grouping (Python: itertools.groupby after sort)
var byCategory = inventory
    .GroupBy(i => i.Category)
    .ToDictionary(g => g.Key, g => g.ToList());

// Aggregation
float totalValue = inventory.Sum(i => i.Value * i.StackSize);
var mostValuable = inventory.MaxBy(i => i.Value);
int distinctCategories = inventory.Select(i => i.Category).Distinct().Count();

// Chaining (fluent pipeline)
var report = inventory
    .Where(i => i.Category == ItemCategory.Crop)
    .OrderByDescending(i => i.Value)
    .Select(i => $"{i.Name}: {i.Value:C}")
    .ToList();
```

### 4.2 — LINQ Operators Cheat Sheet

```csharp
// Filtering
.Where(predicate)              // Filter elements
.OfType<T>()                   // Filter by type (safe cast)
.Distinct()                    // Remove duplicates
.Take(n) / .Skip(n)           // Pagination
.TakeWhile(pred)              // Take until predicate fails

// Projection
.Select(transform)             // Map each element
.SelectMany(transform)         // Flatten nested collections (flatmap)

// Ordering
.OrderBy(key) / .OrderByDescending(key)
.ThenBy(key)                   // Secondary sort

// Aggregation
.Count() / .Sum() / .Average() / .Min() / .Max()
.Aggregate(seed, func)         // Python's functools.reduce

// Element access
.First() / .FirstOrDefault()   // First match (throws / returns default)
.Single() / .SingleOrDefault() // Exactly one match
.ElementAt(index)

// Set operations
.Union(other) / .Intersect(other) / .Except(other)

// Joining
.Join(inner, outerKey, innerKey, resultSelector)
.GroupJoin(...)                 // Left join with grouping

// Quantifiers
.Any(predicate)                // Python: any()
.All(predicate)                // Python: all()
.Contains(item)                // Python: item in collection
```

### 4.3 — LINQ Performance Considerations for Games

```csharp
// ❌ BAD: LINQ in Update() — allocates every frame
void Update()
{
    // Each .Where() and .ToList() allocates a new list + closure
    var nearby = enemies.Where(e => Vector3.Distance(e.Pos, Pos) < 10f).ToList();
}

// ✓ GOOD: Pre-allocated list, manual loop in hot path
private readonly List<Enemy> _nearbyCache = new(32);

void Update()
{
    _nearbyCache.Clear();
    foreach (var e in enemies)
    {
        if (Vector3.SqrMagnitude(e.Pos - Pos) < 100f)  // Avoid sqrt!
            _nearbyCache.Add(e);
    }
}

// ✓ OK: LINQ in initialization, event handlers, editor code (not per-frame)
void Start()
{
    var cropDefs = Resources.LoadAll<CropDefinition>("Crops")
        .OrderBy(c => c.GrowthDays)
        .ToDictionary(c => c.Id);
}
```

## 🔑 5. Mechanics — Pattern Matching (C# 11/12)

### 5.1 — Pattern Types

```csharp
// Type pattern (Python: isinstance())
object item = GetItem();
if (item is Weapon w)
{
    Console.WriteLine($"Damage: {w.Damage}");
}

// Property pattern
if (item is { Value: > 1000, Category: ItemCategory.Weapon } weapon)
{
    EquipWeapon(weapon);
}

// Switch expression (Python: match/case but more powerful)
string description = crop switch
{
    { GrowthDays: <= 3 } => "Fast grower",
    { GrowthDays: <= 7, SellPrice: > 100 } => "Profitable mid-range",
    { GrowthDays: > 14 } => "Patience required",
    _ => "Standard crop"
};

// List patterns (C# 11)
int[] scores = { 90, 85, 92, 88 };
var result = scores switch
{
    [var first, .., var last] when first > last => "Declining",
    [var first, .., var last] when first < last => "Improving",
    [var single] => $"Only one: {single}",
    [] => "Empty",
    _ => "Stable"
};

// Relational + logical patterns
string tier = player.Level switch
{
    < 10 => "Beginner",
    >= 10 and < 25 => "Intermediate",
    >= 25 and < 50 => "Advanced",
    >= 50 => "Master"
};
```

### 5.2 — Pattern Matching in Game Logic

```csharp
// Tile interaction system using patterns
public string Interact(Tile tile, Tool currentTool) => (tile, currentTool) switch
{
    (SoilTile { IsWatered: false }, WateringCan can) when can.Water > 0
        => "Watering soil",
    (SoilTile { HasCrop: true, Crop.IsReady: true }, _)
        => "Harvesting crop",
    (SoilTile { HasCrop: false, IsTilled: true }, _) when HasSeedSelected()
        => "Planting seed",
    (RockTile, Pickaxe { Level: >= 2 })
        => "Breaking rock",
    (TreeTile { Health: > 0 }, Axe axe)
        => $"Chopping tree (damage: {axe.Damage})",
    _ => "Nothing to do here"
};
```

## ✍️ 6. Worked Examples

### Example 10.2.1 — Generic Inventory System

```csharp
public interface IStackable
{
    string Id { get; }
    int MaxStack { get; }
}

public record CropItem(string Id, string Name, int MaxStack, float SellPrice) : IStackable;
public record ToolItem(string Id, string Name, int Durability) : IStackable
{
    public int MaxStack => 1;  // Tools don't stack
}

public class Inventory<T> where T : IStackable
{
    private readonly record struct Slot(T Item, int Count);
    private readonly Slot?[] _slots;

    public int Capacity { get; }
    public int UsedSlots => _slots.Count(s => s.HasValue);

    public Inventory(int capacity)
    {
        Capacity = capacity;
        _slots = new Slot?[capacity];
    }

    public bool TryAdd(T item, int count = 1)
    {
        // Try to stack with existing
        for (int i = 0; i < _slots.Length; i++)
        {
            if (_slots[i] is { } slot && slot.Item.Id == item.Id
                && slot.Count + count <= item.MaxStack)
            {
                _slots[i] = slot with { Count = slot.Count + count };
                return true;
            }
        }

        // Find empty slot
        for (int i = 0; i < _slots.Length; i++)
        {
            if (_slots[i] is null)
            {
                _slots[i] = new Slot(item, count);
                return true;
            }
        }
        return false;  // Inventory full
    }

    // LINQ-powered queries
    public IEnumerable<(T Item, int Count)> GetAll() =>
        _slots.Where(s => s.HasValue).Select(s => (s!.Value.Item, s.Value.Count));

    public int TotalCount(string id) =>
        _slots.Where(s => s?.Item.Id == id).Sum(s => s!.Value.Count);

    public IEnumerable<T> FindByType<TSpecific>() where TSpecific : T =>
        GetAll().Select(x => x.Item).OfType<TSpecific>();

    public float TotalValue() where T : CropItem =>
        GetAll().Sum(x => ((CropItem)(object)x.Item).SellPrice * x.Count);
}
```

## ⚠️ 7. Gotchas

### Gotcha 3.2.1 — Struct Mutability Trap
```csharp
// ❌ Mutating a struct through a property returns a COPY
public struct Position { public float X, Y; }
public class Player { public Position Pos { get; set; } }

var player = new Player();
player.Pos.X = 5;  // ⚠️ This modifies a COPY, not the actual field!
// Fix: player.Pos = new Position { X = 5, Y = player.Pos.Y };
// Or: make Position a class, or use ref returns
```

### Gotcha 3.2.2 — LINQ Deferred Execution
```csharp
var query = items.Where(i => i.IsActive);  // Nothing executes yet!
items.Add(newItem);                         // Added AFTER query definition
var results = query.ToList();               // newItem IS included!

// If you need a snapshot, materialize immediately:
var snapshot = items.Where(i => i.IsActive).ToList();
```

### Gotcha 3.2.3 — Boxing Value Types
```csharp
int x = 42;
object boxed = x;    // ALLOCATES on heap (boxing)
int y = (int)boxed;  // Unboxing

// Avoid boxing in hot paths. Use generics instead of object:
// ❌ void Process(object value)
// ✓  void Process<T>(T value) where T : struct
```

### Gotcha 3.2.4 — String Comparison
```csharp
// ❌ Culture-sensitive by default (Turkish 'i' problem)
"INFO".ToLower() == "info"  // May fail in Turkish locale!

// ✓ Always specify comparison type
string.Equals(a, b, StringComparison.OrdinalIgnoreCase)
```

#### Basic Switch Expression (C# 8+)

```csharp
// Traditional switch statement (verbose)
string GetDamageDescription(int damage)
{
    switch (damage)
    {
        case 0: return "Miss";
        case int d when d < 10: return "Scratch";
        case int d when d < 50: return "Hit";
        case int d when d < 100: return "Critical";
        default: return "Devastating";
    }
}

// Switch EXPRESSION (C# 8+) — concise, returns a value
string GetDamageDescription(int damage) => damage switch
{
    0 => "Miss",
    < 10 => "Scratch",
    < 50 => "Hit",
    < 100 => "Critical",
    _ => "Devastating"  // _ is the discard pattern (default)
};
```

public record Enemy(string Type, int Health, bool IsElite, int Level);

    (< 0, 0) => "West",

#### Combining Patterns with `when` Guards and `and`/`or`/`not`

```csharp
public record GameEvent(string Type, string Source, int Value, DateTime Timestamp);

string HandleEvent(GameEvent evt) => evt switch
{
    { Type: "damage", Value: > 0 } and { Source: "player" }
        => "Player dealt damage",

        => $"Restored {v} HP",

        => "Blocked!",
    
    _ => "Unhandled event"
};
```

### Example 8.2 — LINQ Deferred vs Immediate Execution Deep Dive

**Problem:** Your game's entity query system uses LINQ, but you're getting stale results or unexpected multiple enumerations. Understanding deferred execution is critical.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### The Core Concept

```csharp
var enemies = new List<Enemy>
{
    new("Goblin", 30, false),
    new("Dragon", 500, true),
    new("Slime", 10, false)
};

// DEFERRED: This does NOT execute the query. It builds a pipeline.
var dangerousEnemies = enemies.Where(e => e.Health > 20);
// Type: IEnumerable<Enemy> — it's a "recipe", not a "result"

// The query executes HERE, when you enumerate:
foreach (var e in dangerousEnemies) // Executes Where() NOW
    Console.WriteLine(e.Name);

// PROOF: Modify the source AFTER creating the query
enemies.Add(new Enemy("Lich", 800, true));

// This INCLUDES the Lich! The query re-executes on each enumeration.
foreach (var e in dangerousEnemies)
    Console.WriteLine(e.Name); // Goblin, Dragon, Lich
```

#### Deferred vs Immediate Operators

```csharp
// ═══════════════════════════════════════════════════════════════
// DEFERRED (lazy) — Returns IEnumerable<T>, executes on enumeration
// ═══════════════════════════════════════════════════════════════
var deferred1 = enemies.Where(e => e.IsElite);        // Filter
var deferred2 = enemies.Select(e => e.Name);          // Map
var deferred3 = enemies.OrderBy(e => e.Health);       // Sort
var deferred4 = enemies.Skip(1).Take(2);              // Pagination
var deferred5 = enemies.SelectMany(e => e.Abilities); // Flatten
var deferred6 = enemies.Distinct();                   // Deduplicate
var deferred7 = enemies.Concat(moreEnemies);          // Combine
var deferred8 = enemies.Zip(positions);               // Pair up
var deferred9 = enemies.OfType<BossEnemy>();           // Type filter
var deferred10 = enemies.Cast<IEntity>();             // Type cast

// ═══════════════════════════════════════════════════════════════
// IMMEDIATE (eager) — Executes NOW, returns concrete result
// ═══════════════════════════════════════════════════════════════
List<Enemy> list = enemies.Where(e => e.IsElite).ToList();       // Materializes
Enemy[] array = enemies.Where(e => e.IsElite).ToArray();         // Materializes
int count = enemies.Count(e => e.IsElite);                       // Scalar
Enemy first = enemies.First(e => e.IsElite);                     // Scalar
Enemy? maybe = enemies.FirstOrDefault(e => e.Level > 99);        // Scalar or null
bool any = enemies.Any(e => e.IsElite);                          // Boolean
bool all = enemies.All(e => e.Health > 0);                       // Boolean
int sum = enemies.Sum(e => e.Health);                            // Aggregate
Dictionary<string, Enemy> dict = enemies.ToDictionary(e => e.Id); // Materializes
```

#### The Multiple Enumeration Problem

```csharp
// BAD: This query executes TWICE (once for Count, once for foreach)
var query = enemies.Where(e => e.Health > 0);
Console.WriteLine($"Found {query.Count()} alive enemies"); // Enumeration #1
foreach (var e in query) Process(e);                       // Enumeration #2

// If the source is a database or network call, this means TWO round-trips!
// If the source is modified between enumerations, results differ!

// GOOD: Materialize once, reuse the list
var aliveEnemies = enemies.Where(e => e.Health > 0).ToList(); // Single execution
Console.WriteLine($"Found {aliveEnemies.Count} alive enemies");
foreach (var e in aliveEnemies) Process(e);

// ReSharper/Rider warning: "Possible multiple enumeration of IEnumerable"
// This is why that warning exists!
```

#### Building Custom Deferred Operators with `yield return`

```csharp
// Custom LINQ-style operator: deferred, lazy, streaming
public static IEnumerable<T> WhereWithLogging<T>(
    this IEnumerable<T> source,
    Func<T, bool> predicate,
    Action<T, bool> logger)
{
    foreach (var item in source)
    {
        bool matches = predicate(item);
        logger(item, matches);
        if (matches)
            yield return item;  // Deferred! Only produces values on demand
    }
    // Execution reaches here only when enumeration completes
}

// Usage:
var results = enemies
    .WhereWithLogging(
        e => e.Health > 50,
        (e, matched) => Debug.Log($"{e.Name}: {(matched ? "PASS" : "FAIL")}"))
    .Take(3); // Only evaluates until 3 matches found — short-circuits!
```

#### Performance: Chaining vs Materializing

```csharp
// EFFICIENT: Single pass through data (streaming pipeline)
var result = enemies
    .Where(e => e.IsAlive)        // Filters as it goes
    .Select(e => e.Position)      // Transforms in same pass
    .OrderBy(p => p.X)            // Must buffer for sort
    .Take(10)                     // Stops after 10
    .ToList();                    // Single materialization

// INEFFICIENT: Multiple materializations (allocates intermediate lists)
var alive = enemies.Where(e => e.IsAlive).ToList();     // Allocation #1
var positions = alive.Select(e => e.Position).ToList(); // Allocation #2
var sorted = positions.OrderBy(p => p.X).ToList();      // Allocation #3
var top10 = sorted.Take(10).ToList();                   // Allocation #4
```

### Example 8.3 — Expression Trees for ORM Mapping

**Problem:** You want to understand how Entity Framework translates LINQ to SQL. The key is expression trees — code represented as data that can be analyzed and translated.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### Func vs Expression

```csharp
using System.Linq.Expressions;

// A Func is COMPILED CODE — opaque, can only be executed
Func<Enemy, bool> funcFilter = e => e.Health > 50;
// The runtime sees: "some delegate that takes Enemy, returns bool"
// It CANNOT inspect what's inside

// An Expression is CODE AS DATA — a tree structure that can be analyzed
Expression<Func<Enemy, bool>> exprFilter = e => e.Health > 50;
// The runtime sees:
//   BinaryExpression (GreaterThan)
//   ├── Left: MemberExpression (e.Health)
//   └── Right: ConstantExpression (50)
```

#### Inspecting Expression Trees

```csharp
Expression<Func<Enemy, bool>> expr = e => e.Health > 50 && e.IsElite;

// Walk the tree
void PrintExpression(Expression exp, int indent = 0)
{
    var prefix = new string(' ', indent * 2);
    switch (exp)
    {
        case BinaryExpression bin:
            Console.WriteLine($"{prefix}{bin.NodeType}");
            PrintExpression(bin.Left, indent + 1);
            PrintExpression(bin.Right, indent + 1);
            break;
        case MemberExpression mem:
            Console.WriteLine($"{prefix}Member: {mem.Member.Name}");
            break;
        case ConstantExpression con:
            Console.WriteLine($"{prefix}Constant: {con.Value}");
            break;
        case UnaryExpression un:
            Console.WriteLine($"{prefix}{un.NodeType}");
            PrintExpression(un.Operand, indent + 1);
            break;
        case LambdaExpression lam:
            Console.WriteLine($"{prefix}Lambda ({string.Join(", ", lam.Parameters)})");
            PrintExpression(lam.Body, indent + 1);
            break;
    }
}

PrintExpression(expr);
// Output:
// Lambda (e)
//   AndAlso
//     GreaterThan
//       Member: Health
//       Constant: 50
//     Member: IsElite
```

#### How EF Core Translates to SQL

```csharp
// When you write this:
var query = dbContext.Enemies
    .Where(e => e.Health > 50 && e.IsElite)
    .OrderBy(e => e.Level)
    .Select(e => new { e.Name, e.Level })
    .Take(10);

// EF Core's query pipeline:
// 1. Receives Expression<Func<Enemy, bool>> (not compiled Func!)
// 2. Walks the expression tree
// 3. Translates each node to SQL:
//    - BinaryExpression(GreaterThan) → "Health > 50"
//    - BinaryExpression(AndAlso) → "AND"
//    - MemberExpression(IsElite) → "IsElite = 1"
//    - MethodCall(OrderBy) → "ORDER BY Level"
//    - MethodCall(Take) → "TOP 10" or "LIMIT 10"

// Generated SQL:
// SELECT TOP(10) [e].[Name], [e].[Level]
// FROM [Enemies] AS [e]
// WHERE [e].[Health] > 50 AND [e].[IsElite] = 1
// ORDER BY [e].[Level]
```

#### Building Dynamic Queries with Expressions

```csharp
// Game scenario: Dynamic filter builder for inventory search
public static class QueryBuilder
{
    public static Expression<Func<T, bool>> And<T>(
        Expression<Func<T, bool>> left,
        Expression<Func<T, bool>> right)
    {
        var parameter = Expression.Parameter(typeof(T), "x");
        
        var leftBody = new ParameterReplacer(left.Parameters[0], parameter)
            .Visit(left.Body);
        var rightBody = new ParameterReplacer(right.Parameters[0], parameter)
            .Visit(right.Body);
        
        var combined = Expression.AndAlso(leftBody, rightBody);
        return Expression.Lambda<Func<T, bool>>(combined, parameter);
    }
}

// Usage: Build filters dynamically based on UI selections
Expression<Func<Item, bool>> filter = item => true; // Start with "match all"

if (searchByName)
    filter = QueryBuilder.And(filter, i => i.Name.Contains(searchText));
if (filterByRarity)
    filter = QueryBuilder.And(filter, i => i.Rarity >= minRarity);
if (filterByLevel)
    filter = QueryBuilder.And(filter, i => i.RequiredLevel <= playerLevel);

var results = dbContext.Items.Where(filter).ToListAsync();
// Generates ONE optimized SQL query with all conditions
```

## 📖 9. Appendix: Extended Derivations & Special Cases

### Appendix 9.1 — IQueryable vs IEnumerable Internals

#### The Interface Hierarchy

```csharp
// IEnumerable<T> — In-memory iteration
public interface IEnumerable<T>
{
    IEnumerator<T> GetEnumerator();
}

// IQueryable<T> — Remote query composition
public interface IQueryable<T> : IEnumerable<T>
{
    Type ElementType { get; }
    Expression Expression { get; }      // The query as a tree
    IQueryProvider Provider { get; }    // Translates & executes
}
```

#### How They Differ in Practice

```csharp
// IEnumerable: LINQ operators use Func<T, bool> (compiled delegates)
IEnumerable<Enemy> memoryEnemies = enemyList;
var filtered = memoryEnemies.Where(e => e.Health > 50);
// Calls: Enumerable.Where(IEnumerable<T>, Func<T, bool>)
// Execution: Iterates in-memory, applies predicate to each item

// IQueryable: LINQ operators use Expression<Func<T, bool>> (expression trees)
IQueryable<Enemy> dbEnemies = dbContext.Enemies;
var filtered = dbEnemies.Where(e => e.Health > 50);
// Calls: Queryable.Where(IQueryable<T>, Expression<Func<T, bool>>)
// Execution: Builds expression tree, translates to SQL on enumeration
```

#### The Dangerous Boundary

```csharp
// DANGEROUS: Accidentally switching from IQueryable to IEnumerable
var query = dbContext.Enemies  // IQueryable — SQL translation
    .Where(e => e.Level > 10) // Still IQueryable — becomes SQL WHERE
    .AsEnumerable()           // ⚠️ SWITCHES TO IN-MEMORY
    .Where(e => e.Health > 50); // Now IEnumerable — runs in C# memory!

// What actually happens:
// SQL: SELECT * FROM Enemies WHERE Level > 10  (downloads ALL matching rows)
// C#:  Then filters Health > 50 in memory (wasteful!)

// CORRECT: Keep everything as IQueryable
var query = dbContext.Enemies
    .Where(e => e.Level > 10 && e.Health > 50) // Single SQL query
    .ToListAsync(); // Only materializes final result
```

#### Custom IQueryable Provider (Simplified)

```csharp
// This is how EF Core, MongoDB driver, etc. work internally
public class GameQueryProvider : IQueryProvider
{
    public IQueryable CreateQuery(Expression expression)
    {
        // Build a new queryable with the updated expression tree
        return new GameQueryable<object>(this, expression);
    }

    public object Execute(Expression expression)
    {
        // THIS is where translation happens:
        // 1. Walk the expression tree
        // 2. Convert to target query language (SQL, MongoDB query, etc.)
        // 3. Execute against the data source
        // 4. Map results back to C# objects
        
        var sql = new SqlTranslator().Translate(expression);
        return Database.Execute(sql);
    }
}
```

### Appendix 9.2 — LINQ to SQL Translation Rules

Understanding how C# expressions map to SQL helps you write efficient queries:

| C# LINQ | SQL Generated | Notes |
|---------|---------------|-------|
| `.Where(e => e.X > 5)` | `WHERE X > 5` | Direct translation |
| `.Select(e => e.Name)` | `SELECT Name` | Column projection |
| `.OrderBy(e => e.X)` | `ORDER BY X ASC` | |
| `.OrderByDescending(e => e.X)` | `ORDER BY X DESC` | |
| `.Take(10)` | `TOP 10` / `LIMIT 10` | DB-dependent syntax |
| `.Skip(20).Take(10)` | `OFFSET 20 ROWS FETCH NEXT 10` | Pagination |
| `.Count()` | `SELECT COUNT(*)` | Aggregate |
| `.Any(e => e.X > 5)` | `SELECT CASE WHEN EXISTS(...)` | Existence check |
| `.Contains(value)` | `WHERE X IN (...)` | Set membership |
| `.GroupBy(e => e.Type)` | `GROUP BY Type` | Grouping |
| `.Include(e => e.Items)` | `LEFT JOIN Items ON...` | Eager loading |
| `.String.Contains("x")` | `WHERE Name LIKE '%x%'` | String search |
| `.StartsWith("x")` | `WHERE Name LIKE 'x%'` | Prefix search |

#### Expressions That CANNOT Be Translated

```csharp
// These force client-side evaluation (or throw):
.Where(e => MyCustomMethod(e.Name))     // Custom C# method — no SQL equivalent
.Where(e => regex.IsMatch(e.Name))      // Regex — not standard SQL
.Where(e => e.Tags.Any(t => ProcessTag(t))) // Complex nested logic
.Select(e => new { Formatted = $"{e.Name} (Lv.{e.Level})" }) // String interpolation

// EF Core 8+ will WARN you:
// "The LINQ expression could not be translated. Either rewrite the query
//  in a form that can be translated, or switch to client evaluation explicitly
//  by inserting a call to 'AsEnumerable()'."
```

### Appendix 9.3 — Value Types vs Reference Types: Complete Decision Tree

```
Should this be a struct (value type)?
│
├── Is it logically a single value? (like int, float, Vector3)
│   ├── YES → Consider struct
│   └── NO → Use class
│
├── Is it immutable? (all fields readonly after construction)
│   ├── YES → Strong candidate for struct or record struct
│   └── NO → Use class (mutable structs are bugs waiting to happen)
│
├── Is it small? (≤ 16 bytes ideally, ≤ 64 bytes max)
│   ├── YES → struct is efficient
│   └── NO → Use class (large structs are expensive to copy)
│
├── Is it short-lived? (created and discarded within a method)
│   ├── YES → struct avoids GC pressure
│   └── NO → class is fine (GC handles long-lived objects well)
│
├── Will it be stored in collections?
│   ├── YES, in arrays → struct gives cache-friendly layout
│   └── YES, in List<T> → struct is fine (stored inline)
│   └── YES, in interfaces → BOXING! Use class or generic constraints
│
└── Final answer:
    • Vector2, Vector3, Color, Rect → struct
    • Enemy, Player, GameManager → class
    • PlayerInput (per-frame) → struct
    • SaveData, Config → class (or record class)
```

### Appendix 9.4 — Generic Variance: Covariance and Contravariance

```csharp
// COVARIANCE (out) — "Produces T" — Can use derived type where base expected
interface IReadOnlyList<out T>  // out = covariant
{
    T this[int index] { get; }  // T only in OUTPUT positions
    int Count { get; }
}

IReadOnlyList<string> strings = new List<string> { "a", "b" };
IReadOnlyList<object> objects = strings;  // ✅ Legal! string : object

// CONTRAVARIANCE (in) — "Consumes T" — Can use base type where derived expected
interface IComparer<in T>  // in = contravariant
{
    int Compare(T x, T y);  // T only in INPUT positions
}

IComparer<object> objectComparer = Comparer<object>.Default;
IComparer<string> stringComparer = objectComparer;  // ✅ Legal! Reversed direction

// WHY THIS MATTERS FOR GAME DEV:
// Event systems, command handlers, and dependency injection all use variance

interface IEventHandler<in TEvent> where TEvent : IGameEvent
{
    void Handle(TEvent evt);
}

// A handler for base events can handle derived events
IEventHandler<IGameEvent> generalHandler = new LoggingHandler();
IEventHandler<DamageEvent> damageHandler = generalHandler; // ✅ Contravariance
```
