## 📚 1. Dialect Comparison

### 1.1 Feature Matrix

| Feature | PostgreSQL | MySQL 8.0+ | SQLite | DuckDB |
|---------|-----------|------------|--------|--------|
| Window functions | ✓ Full | ✓ Full | ✓ (3.25+) | ✓ Full |
| CTEs (recursive) | ✓ | ✓ | ✓ | ✓ |
| LATERAL JOIN | ✓ | ✓ | ✗ | ✓ |
| FULL OUTER JOIN | ✓ | ✗ (emulate) | ✓ | ✓ |
| JSONB native | ✓ | JSON type | json1 ext | ✓ |
| Arrays | ✓ | ✗ | ✗ | ✓ (LIST) |
| UPSERT syntax | `ON CONFLICT` | `ON DUPLICATE KEY` | `ON CONFLICT` | `ON CONFLICT` |
| Generated columns | ✓ | ✓ | ✓ (3.31+) | ✓ |
| Partitioning | ✓ Declarative | ✓ | ✗ | ✓ |
| GIN/GiST indexes | ✓ | ✗ | ✗ | ✗ |
| Columnar storage | ✗ (row-based) | ✗ | ✗ | ✓ (native) |
| Concurrent writes | ✓ MVCC | ✓ MVCC | ✗ (WAL mode helps) | Limited |
| Best for | OLTP + OLAP | Web apps | Embedded/testing | Analytics |

### 1.2 Syntax Differences

```sql
-- Auto-increment primary key:
-- PostgreSQL:
CREATE TABLE t (id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY);
-- MySQL:
CREATE TABLE t (id BIGINT AUTO_INCREMENT PRIMARY KEY);
-- SQLite:
CREATE TABLE t (id INTEGER PRIMARY KEY AUTOINCREMENT);
-- DuckDB:
CREATE TABLE t (id BIGINT PRIMARY KEY DEFAULT nextval('t_id_seq'));

-- UPSERT (insert or update on conflict):
-- PostgreSQL / SQLite / DuckDB:
INSERT INTO users (email, name) VALUES ('a@b.com', 'Alice')
ON CONFLICT (email) DO UPDATE SET name = EXCLUDED.name;
-- MySQL:
INSERT INTO users (email, name) VALUES ('a@b.com', 'Alice')
ON DUPLICATE KEY UPDATE name = VALUES(name);

-- String concatenation:
-- PostgreSQL: 'hello' || ' ' || 'world'
-- MySQL: CONCAT('hello', ' ', 'world')
-- SQLite: 'hello' || ' ' || 'world'

-- LIMIT with OFFSET:
-- PostgreSQL/MySQL/SQLite/DuckDB: LIMIT 10 OFFSET 20
-- (All support this syntax)

-- Boolean type:
-- PostgreSQL: BOOLEAN (true/false)
-- MySQL: TINYINT(1) or BOOLEAN (alias)
-- SQLite: INTEGER (0/1)
-- DuckDB: BOOLEAN
```

### 1.3 When to Choose Each

| Use Case | Best Choice | Why |
|----------|-------------|-----|
| Production web app | PostgreSQL | MVCC, extensions, reliability, JSON support |
| Simple web app / shared hosting | MySQL | Widespread hosting, good enough for most apps |
| Embedded / mobile / testing | SQLite | Zero config, single file, stdlib in Python |
| Analytics / data science | DuckDB | Columnar, vectorized, reads Parquet natively |
| ML data pipeline ingestion | DuckDB → PostgreSQL | DuckDB for transform, PG for serving |

## 📚 2. SQLAlchemy 2.x — The Python ORM Standard

### 2.1 Architecture Overview

SQLAlchemy has two layers:
- **Core:** SQL expression language (generates SQL, no object mapping)
- **ORM:** Object-Relational Mapping (maps Python classes to tables)

Both share the same engine and connection infrastructure.

### 2.2 Engine and Connection

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import Session

# Connection string format: dialect+driver://user:pass@host:port/dbname
engine = create_engine(
    "postgresql+psycopg://user:pass@localhost:5432/mydb",
    pool_size=10,           # connection pool size
    max_overflow=20,        # extra connections beyond pool_size
    pool_timeout=30,        # seconds to wait for a connection
    pool_recycle=3600,      # recycle connections after 1 hour
    echo=False,             # set True to log all SQL
)

# Using a session (ORM):
with Session(engine) as session:
    result = session.execute(text("SELECT 1"))
    session.commit()
```

### 2.3 Declarative Models (SQLAlchemy 2.x Style)

```python
from datetime import datetime
from decimal import Decimal
from sqlalchemy import ForeignKey, String, Numeric, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship

class Base(DeclarativeBase):
    pass

class Department(Base):
    __tablename__ = "departments"

    dept_id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))

    # Relationship (ORM-level, not a column)
    employees: Mapped[list["Employee"]] = relationship(back_populates="department")

class Employee(Base):
    __tablename__ = "employees"

    emp_id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(200))
    email: Mapped[str] = mapped_column(String(255), unique=True)
    salary: Mapped[Decimal] = mapped_column(Numeric(10, 2))
    dept_id: Mapped[int] = mapped_column(ForeignKey("departments.dept_id"))
    hired_at: Mapped[datetime] = mapped_column(server_default=func.now())

    department: Mapped["Department"] = relationship(back_populates="employees")
```

### 2.4 Querying with the 2.x Select API

```python
from sqlalchemy import select, func
from sqlalchemy.orm import Session

with Session(engine) as session:
    # Simple select
    stmt = select(Employee).where(Employee.salary > 80000)
    employees = session.scalars(stmt).all()

    # Join
    stmt = (
        select(Employee.name, Department.name)
        .join(Department)
        .where(Department.name == "Engineering")
        .order_by(Employee.salary.desc())
    )
    results = session.execute(stmt).all()

    # Aggregation
    stmt = (
        select(Department.name, func.count(), func.avg(Employee.salary))
        .join(Employee)
        .group_by(Department.name)
        .having(func.count() > 5)
    )
    dept_stats = session.execute(stmt).all()

    # Subquery
    avg_salary = select(func.avg(Employee.salary)).scalar_subquery()
    stmt = select(Employee).where(Employee.salary > avg_salary)
    above_avg = session.scalars(stmt).all()
```

### 2.5 Insert, Update, Delete

```python
with Session(engine) as session:
    # Insert
    new_emp = Employee(name="Alice", email="alice@co.com", salary=95000, dept_id=1)
    session.add(new_emp)

    # Bulk insert
    session.add_all([
        Employee(name="Bob", email="bob@co.com", salary=85000, dept_id=2),
        Employee(name="Carol", email="carol@co.com", salary=90000, dept_id=1),
    ])

    # Update
    stmt = (
        update(Employee)
        .where(Employee.dept_id == 3)
        .values(salary=Employee.salary * 1.1)
    )
    session.execute(stmt)

    # Delete
    stmt = delete(Employee).where(Employee.email == "bob@co.com")
    session.execute(stmt)

    session.commit()
```

### 2.6 Async SQLAlchemy

```python
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession
from sqlalchemy.orm import sessionmaker

async_engine = create_async_engine(
    "postgresql+asyncpg://user:pass@localhost/mydb",
    pool_size=20,
)
AsyncSessionLocal = sessionmaker(async_engine, class_=AsyncSession, expire_on_commit=False)

async def get_employees():
    async with AsyncSessionLocal() as session:
        stmt = select(Employee).where(Employee.salary > 80000)
        result = await session.execute(stmt)
        return result.scalars().all()
```

## 📚 3. SQLModel — SQLAlchemy + Pydantic for FastAPI

### 3.1 Why SQLModel?

SQLModel combines SQLAlchemy's ORM with Pydantic's validation. One model class serves as:
- Database table definition
- API request/response schema
- Validation layer

```python
from sqlmodel import SQLModel, Field, Session, create_engine, select
from datetime import datetime
from decimal import Decimal

class EmployeeBase(SQLModel):
    """Shared fields (used for create/update schemas)."""
    name: str = Field(max_length=200)
    email: str = Field(max_length=255, unique=True)
    salary: Decimal = Field(ge=0, decimal_places=2)
    dept_id: int

class Employee(EmployeeBase, table=True):
    """Database model (has table=True)."""
    emp_id: int | None = Field(default=None, primary_key=True)
    hired_at: datetime = Field(default_factory=datetime.utcnow)

class EmployeeCreate(EmployeeBase):
    """Request schema for creating an employee."""
    pass

class EmployeeRead(EmployeeBase):
    """Response schema (includes ID and timestamp)."""
    emp_id: int
    hired_at: datetime
```

### 3.2 FastAPI Integration

```python
from fastapi import FastAPI, Depends, HTTPException
from sqlmodel import Session, select

app = FastAPI()

def get_session():
    with Session(engine) as session:
        yield session

@app.post("/employees/", response_model=EmployeeRead)
def create_employee(emp: EmployeeCreate, session: Session = Depends(get_session)):
    db_emp = Employee.model_validate(emp)
    session.add(db_emp)
    session.commit()
    session.refresh(db_emp)
    return db_emp

@app.get("/employees/", response_model=list[EmployeeRead])
def list_employees(
    skip: int = 0,
    limit: int = 20,
    session: Session = Depends(get_session)
):
    stmt = select(Employee).offset(skip).limit(limit)
    return session.exec(stmt).all()

@app.get("/employees/{emp_id}", response_model=EmployeeRead)
def get_employee(emp_id: int, session: Session = Depends(get_session)):
    emp = session.get(Employee, emp_id)
    if not emp:
        raise HTTPException(status_code=404, detail="Employee not found")
    return emp
```

## 📚 4. DuckDB — Analytics in Your Python Process

### 4.1 Why DuckDB?

DuckDB is an **in-process analytical database** — like SQLite but optimized for OLAP:
- Columnar storage (vectorized execution)
- Reads Parquet, CSV, JSON directly (no ETL needed)
- Integrates with Pandas/Polars DataFrames
- Zero external dependencies
- Perfect for ML data preparation

### 4.2 Basic Usage

```python
import duckdb

# In-memory (default):
con = duckdb.connect()

# Query a Parquet file directly (no import step!):
result = con.sql("""
    SELECT
        product_category,
        COUNT(*) AS order_count,
        SUM(amount) AS total_revenue,
        AVG(amount) AS avg_order_value
    FROM 'data/orders_2025.parquet'
    WHERE order_date >= '2025-01-01'
    GROUP BY product_category
    ORDER BY total_revenue DESC
    LIMIT 10
""").fetchdf()  # returns a Pandas DataFrame

# Query multiple Parquet files with glob:
con.sql("""
    SELECT * FROM 'data/events_*.parquet'
    WHERE event_type = 'purchase'
""")

# Query a CSV:
con.sql("SELECT * FROM read_csv_auto('data/users.csv') WHERE age > 25")
```

### 4.3 DuckDB + Pandas Integration

```python
import pandas as pd
import duckdb

# Create a DataFrame
df = pd.DataFrame({
    "user_id": [1, 2, 3, 1, 2],
    "event": ["view", "view", "purchase", "purchase", "view"],
    "amount": [0, 0, 49.99, 29.99, 0],
})

# Query the DataFrame with SQL (zero-copy!):
result = duckdb.sql("""
    SELECT
        user_id,
        COUNT(*) AS events,
        SUM(amount) AS total_spend,
        COUNT(*) FILTER (WHERE event = 'purchase') AS purchases
    FROM df
    GROUP BY user_id
""").fetchdf()
```

### 4.4 DuckDB for ML Data Pipelines

```python
import duckdb

con = duckdb.connect()

# Feature engineering pipeline:
features = con.sql("""
    WITH user_events AS (
        SELECT * FROM 'data/events_*.parquet'
    ),
    user_features AS (
        SELECT
            user_id,
            COUNT(*) AS total_events,
            COUNT(*) FILTER (WHERE event_type = 'purchase') AS purchase_count,
            SUM(amount) AS lifetime_value,
            MAX(event_time) AS last_active,
            CURRENT_TIMESTAMP - MAX(event_time) AS days_since_active,
            AVG(amount) FILTER (WHERE event_type = 'purchase') AS avg_purchase
        FROM user_events
        GROUP BY user_id
    )
    SELECT
        uf.*,
        CASE WHEN days_since_active > INTERVAL '90 days' THEN 1 ELSE 0 END AS churned
    FROM user_features uf
    WHERE total_events >= 5
""").fetchdf()

# Export to Parquet for model training:
con.sql("COPY (SELECT * FROM features) TO 'data/training_features.parquet' (FORMAT PARQUET)")
```

### 4.5 DuckDB Persistent Database

```python
# Persistent storage (like SQLite):
con = duckdb.connect("analytics.duckdb")

# Create tables, they persist:
con.sql("""
    CREATE TABLE IF NOT EXISTS daily_metrics AS
    SELECT * FROM 'data/metrics_*.parquet'
""")

# Subsequent runs can query without re-importing:
con.sql("SELECT * FROM daily_metrics WHERE date > '2025-06-01'")
```

### 5.3 Migration File Example

```python
"""add employee table

Revision ID: a1b2c3d4e5f6
"""
from alembic import op
import sqlalchemy as sa

def upgrade():
    op.create_table(
        'employees',
        sa.Column('emp_id', sa.Integer(), primary_key=True),
        sa.Column('name', sa.String(200), nullable=False),
        sa.Column('email', sa.String(255), unique=True, nullable=False),
        sa.Column('salary', sa.Numeric(10, 2)),
        sa.Column('dept_id', sa.Integer(), sa.ForeignKey('departments.dept_id')),
        sa.Column('hired_at', sa.DateTime(), server_default=sa.func.now()),
    )
    op.create_index('idx_emp_email', 'employees', ['email'])

def downgrade():
    op.drop_index('idx_emp_email')
    op.drop_table('employees')
```

### 6.3 Repository Pattern

```python
from sqlalchemy import select
from sqlalchemy.orm import Session

class EmployeeRepository:
    def __init__(self, session: Session):
        self.session = session

    def get_by_id(self, emp_id: int) -> Employee | None:
        return self.session.get(Employee, emp_id)

    def get_by_email(self, email: str) -> Employee | None:
        stmt = select(Employee).where(Employee.email == email)
        return self.session.scalar(stmt)

    def list_by_department(self, dept_id: int, limit: int = 50) -> list[Employee]:
        stmt = (
            select(Employee)
            .where(Employee.dept_id == dept_id)
            .order_by(Employee.name)
            .limit(limit)
        )
        return list(self.session.scalars(stmt))

    def create(self, **kwargs) -> Employee:
        emp = Employee(**kwargs)
        self.session.add(emp)
        self.session.flush()  # get ID without committing
        return emp
```

## 📚 12. Deep Dive — DuckDB Analytics, PostgreSQL Extensions & Python ORM Patterns

### 12.1 DuckDB for Analytics — In-Process OLAP

DuckDB is an in-process analytical database (like SQLite for OLAP). It excels at:
- Columnar storage and vectorized execution
- Direct querying of Parquet, CSV, JSON files without loading
- Zero-copy integration with Pandas/Polars DataFrames
- Window functions and complex aggregations at blazing speed

**Direct file querying:**

```python
import duckdb

# Query Parquet files directly (no ETL needed):
result = duckdb.sql("""
    SELECT
        customer_id,
        DATE_TRUNC('month', order_date) AS month,
        SUM(amount) AS monthly_spend,
        COUNT(*) AS order_count
    FROM 'data/orders/*.parquet'
    WHERE order_date >= '2025-01-01'
    GROUP BY customer_id, month
    HAVING SUM(amount) > 1000
    ORDER BY monthly_spend DESC
""").fetchdf()

# Query CSV with auto-detection:
duckdb.sql("""
    SELECT * FROM read_csv_auto('data/sales.csv',
        header=true,
        dateformat='%Y-%m-%d'
    ) WHERE region = 'US'
""")

# Query JSON:
duckdb.sql("""
    SELECT
        json_extract_string(data, '$.user.name') AS user_name,
        json_extract(data, '$.events') AS events
    FROM read_json_auto('logs/*.jsonl')
""")
```

**Integration with Pandas/Polars:**

```python
import pandas as pd
import polars as pl
import duckdb

# Query a Pandas DataFrame directly:
df = pd.read_csv("large_dataset.csv")
result = duckdb.sql("""
    SELECT category, AVG(price) AS avg_price, COUNT(*) AS cnt
    FROM df
    GROUP BY category
    HAVING COUNT(*) > 100
""").fetchdf()

# Query a Polars DataFrame:
lf = pl.scan_parquet("data/*.parquet")
result = duckdb.sql("""
    SELECT * FROM lf WHERE amount > 500
""").pl()  # returns Polars DataFrame

# Export results to Parquet:
duckdb.sql("""
    COPY (
        SELECT * FROM 'raw_data/*.csv'
        WHERE date >= '2025-01-01'
    ) TO 'output/filtered.parquet' (FORMAT PARQUET, COMPRESSION ZSTD)
""")
```

**DuckDB-specific SQL features:**

```sql
-- QUALIFY (filter window function results):
SELECT customer_id, order_date, amount
FROM orders
QUALIFY ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date DESC) = 1;

-- PIVOT:
PIVOT orders ON status USING SUM(amount) GROUP BY customer_id;

-- UNPIVOT:
UNPIVOT monthly_sales ON jan, feb, mar, apr INTO NAME month VALUE revenue;

-- ASOF JOIN (temporal join — find nearest match):
SELECT o.*, r.rate
FROM orders o
ASOF JOIN exchange_rates r ON o.order_date >= r.effective_date AND o.currency = r.currency;

-- LIST aggregation (collect into array):
SELECT customer_id, LIST(product_name ORDER BY order_date) AS purchase_history
FROM orders
GROUP BY customer_id;

-- STRUCT types:
SELECT {'name': name, 'salary': salary, 'dept': dept_id} AS employee_struct
FROM employees;

-- Recursive filename globbing:
SELECT * FROM 'data/**/*.parquet';
```

### 12.2 PostgreSQL Extensions for Modern Workloads

**pgvector — Vector Similarity Search (AI/ML Embeddings):**

```sql
-- Install:
CREATE EXTENSION IF NOT EXISTS vector;

-- Create table with embedding column:
CREATE TABLE documents (
    doc_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    title TEXT NOT NULL,
    content TEXT NOT NULL,
    embedding vector(1536)  -- OpenAI ada-002 dimension
);

-- Insert embeddings (from Python):
-- cur.execute("INSERT INTO documents (title, content, embedding) VALUES (%s, %s, %s)",
--             (title, content, embedding_list))

-- Create HNSW index (fast approximate nearest neighbor):
CREATE INDEX idx_docs_embedding ON documents
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);

-- Similarity search (cosine distance):
SELECT doc_id, title, 1 - (embedding <=> query_embedding) AS similarity
FROM documents
ORDER BY embedding <=> query_embedding  -- <=> is cosine distance operator
LIMIT 10;

-- With metadata filtering:
SELECT doc_id, title, 1 - (embedding <=> $1) AS similarity
FROM documents
WHERE category = 'technical'
  AND created_at > '2025-01-01'
ORDER BY embedding <=> $1
LIMIT 10;

-- Hybrid search (combine FTS + vector):
WITH fts_results AS (
    SELECT doc_id, ts_rank(search_vector, query) AS fts_score
    FROM documents, plainto_tsquery('english', 'machine learning') AS query
    WHERE search_vector @@ query
),
vector_results AS (
    SELECT doc_id, 1 - (embedding <=> $1) AS vec_score
    FROM documents
    ORDER BY embedding <=> $1
    LIMIT 100
)
SELECT
    COALESCE(f.doc_id, v.doc_id) AS doc_id,
    COALESCE(f.fts_score, 0) * 0.3 + COALESCE(v.vec_score, 0) * 0.7 AS combined_score
FROM fts_results f
FULL OUTER JOIN vector_results v ON f.doc_id = v.doc_id
ORDER BY combined_score DESC
LIMIT 20;
```

**TimescaleDB — Time-Series Data:**

```sql
-- Install and create hypertable:
CREATE EXTENSION IF NOT EXISTS timescaledb;

CREATE TABLE sensor_data (
    time TIMESTAMPTZ NOT NULL,
    sensor_id INT NOT NULL,
    temperature DOUBLE PRECISION,
    humidity DOUBLE PRECISION,
    pressure DOUBLE PRECISION
);

-- Convert to hypertable (auto-partitions by time):
SELECT create_hypertable('sensor_data', 'time',
    chunk_time_interval => INTERVAL '1 day');

-- Continuous aggregates (auto-refreshing materialized views):
CREATE MATERIALIZED VIEW sensor_hourly
WITH (timescaledb.continuous) AS
SELECT
    time_bucket('1 hour', time) AS bucket,
    sensor_id,
    AVG(temperature) AS avg_temp,
    MIN(temperature) AS min_temp,
    MAX(temperature) AS max_temp,
    COUNT(*) AS readings
FROM sensor_data
GROUP BY bucket, sensor_id;

-- Auto-refresh policy:
SELECT add_continuous_aggregate_policy('sensor_hourly',
    start_offset => INTERVAL '3 hours',
    end_offset => INTERVAL '1 hour',
    schedule_interval => INTERVAL '1 hour');

-- Compression (huge storage savings for old data):
ALTER TABLE sensor_data SET (
    timescaledb.compress,
    timescaledb.compress_segmentby = 'sensor_id',
    timescaledb.compress_orderby = 'time DESC'
);

-- Compress chunks older than 7 days:
SELECT add_compression_policy('sensor_data', INTERVAL '7 days');

-- Retention policy (drop old data):
SELECT add_retention_policy('sensor_data', INTERVAL '90 days');

-- Time-series specific queries:
SELECT
    time_bucket('5 minutes', time) AS bucket,
    sensor_id,
    AVG(temperature) AS avg_temp,
    last(temperature, time) AS latest_temp,  -- TimescaleDB function
    first(temperature, time) AS earliest_temp
FROM sensor_data
WHERE time > NOW() - INTERVAL '1 hour'
GROUP BY bucket, sensor_id
ORDER BY bucket DESC;
```

### 12.3 SQLAlchemy 2.x Async Patterns

```python
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship
from sqlalchemy import select, func
from datetime import datetime

# Async engine setup:
engine = create_async_engine(
    "postgresql+asyncpg://user:pass@localhost/mydb",
    pool_size=20,
    max_overflow=10,
    echo=False,
)

async_session = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

# Model definitions (SQLAlchemy 2.x style):
class Base(DeclarativeBase):
    pass

class Employee(Base):
    __tablename__ = "employees"

    emp_id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(200))
    email: Mapped[str] = mapped_column(String(255), unique=True)
    salary: Mapped[float] = mapped_column(Numeric(10, 2))
    dept_id: Mapped[int] = mapped_column(ForeignKey("departments.dept_id"))
    hired_at: Mapped[datetime] = mapped_column(default=func.now())

    department: Mapped["Department"] = relationship(back_populates="employees")

class Department(Base):
    __tablename__ = "departments"

    dept_id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))

    employees: Mapped[list["Employee"]] = relationship(back_populates="department")

# Async CRUD operations:
async def get_employees_by_dept(dept_id: int) -> list[Employee]:
    async with async_session() as session:
        stmt = (
            select(Employee)
            .where(Employee.dept_id == dept_id)
            .order_by(Employee.salary.desc())
        )
        result = await session.execute(stmt)
        return list(result.scalars().all())

async def create_employee(name: str, email: str, salary: float, dept_id: int) -> Employee:
    async with async_session() as session:
        emp = Employee(name=name, email=email, salary=salary, dept_id=dept_id)
        session.add(emp)
        await session.commit()
        await session.refresh(emp)
        return emp

# Eager loading (avoid N+1):
async def get_departments_with_employees():
    async with async_session() as session:
        stmt = select(Department).options(selectinload(Department.employees))
        result = await session.execute(stmt)
        return list(result.scalars().unique().all())
```

### 12.4 SQLModel for FastAPI

```python
from sqlmodel import SQLModel, Field, Session, create_engine, select, Relationship
from fastapi import FastAPI, Depends, HTTPException, Query
from typing import Optional

# Models (SQLModel = SQLAlchemy + Pydantic):
class DepartmentBase(SQLModel):
    name: str = Field(max_length=100)

class Department(DepartmentBase, table=True):
    dept_id: Optional[int] = Field(default=None, primary_key=True)
    employees: list["Employee"] = Relationship(back_populates="department")

class EmployeeBase(SQLModel):
    name: str = Field(max_length=200)
    email: str = Field(max_length=255, unique=True)
    salary: float = Field(ge=0)
    dept_id: int = Field(foreign_key="department.dept_id")

class Employee(EmployeeBase, table=True):
    emp_id: Optional[int] = Field(default=None, primary_key=True)
    department: Optional[Department] = Relationship(back_populates="employees")

class EmployeeCreate(EmployeeBase):
    pass

class EmployeeRead(EmployeeBase):
    emp_id: int

class EmployeeReadWithDept(EmployeeRead):
    department: Optional[DepartmentBase] = None

# FastAPI app:
app = FastAPI()
engine = create_engine("postgresql://user:pass@localhost/mydb")

def get_session():
    with Session(engine) as session:
        yield session

@app.get("/employees", response_model=list[EmployeeRead])
def list_employees(
    dept_id: Optional[int] = None,
    min_salary: Optional[float] = None,
    offset: int = Query(default=0, ge=0),
    limit: int = Query(default=20, le=100),
    session: Session = Depends(get_session),
):
    stmt = select(Employee)
    if dept_id is not None:
        stmt = stmt.where(Employee.dept_id == dept_id)
    if min_salary is not None:
        stmt = stmt.where(Employee.salary >= min_salary)
    stmt = stmt.offset(offset).limit(limit)
    return session.exec(stmt).all()

@app.post("/employees", response_model=EmployeeRead, status_code=201)
def create_employee(emp: EmployeeCreate, session: Session = Depends(get_session)):
    db_emp = Employee.model_validate(emp)
    session.add(db_emp)
    session.commit()
    session.refresh(db_emp)
    return db_emp

@app.get("/employees/{emp_id}", response_model=EmployeeReadWithDept)
def get_employee(emp_id: int, session: Session = Depends(get_session)):
    emp = session.get(Employee, emp_id)
    if not emp:
        raise HTTPException(status_code=404, detail="Employee not found")
    return emp
```

## 📚 13. Appendix — Logical Replication, CDC & Modern Table Formats

### 13.1 PostgreSQL Logical Replication

Logical replication streams row-level changes (INSERT, UPDATE, DELETE) from a publisher to subscribers. Unlike physical replication (byte-level WAL shipping), logical replication:
- Can replicate a subset of tables
- Can replicate between different PostgreSQL versions
- Allows the subscriber to have additional indexes, tables, or different schemas
- Enables CDC (Change Data Capture) to external systems

```sql
-- Publisher setup:
-- postgresql.conf: wal_level = logical

-- Create publication (what to replicate):
CREATE PUBLICATION my_publication FOR TABLE orders, customers, products;

-- Or replicate all tables:
CREATE PUBLICATION all_tables FOR ALL TABLES;

-- Filter rows (PostgreSQL 15+):
CREATE PUBLICATION us_orders FOR TABLE orders WHERE (region = 'US');

-- Subscriber setup (on another PostgreSQL instance):
CREATE SUBSCRIPTION my_subscription
    CONNECTION 'host=publisher_host dbname=mydb user=repl_user password=secret'
    PUBLICATION my_publication;

-- Monitor replication lag:
SELECT
    slot_name,
    confirmed_flush_lsn,
    pg_current_wal_lsn() - confirmed_flush_lsn AS lag_bytes
FROM pg_replication_slots;
```

### 13.2 Change Data Capture (CDC) with Debezium

Debezium captures row-level changes from database transaction logs and streams them to Kafka.

```yaml

  database.hostname: localhost
  database.port: 5432
  database.user: debezium
  database.password: secret
  database.dbname: mydb
  database.server.name: myserver
  plugin.name: pgoutput
  slot.name: debezium_slot
  publication.name: debezium_publication
  table.include.list: public.orders,public.customers
  transforms: unwrap
  transforms.unwrap.type: io.debezium.transforms.ExtractNewRecordState
  key.converter: org.apache.kafka.connect.json.JsonConverter
  value.converter: org.apache.kafka.connect.json.JsonConverter
```

**Consuming CDC events in Python:**

```python
from kafka import KafkaConsumer
import json

consumer = KafkaConsumer(
    'myserver.public.orders',
    bootstrap_servers=['localhost:9092'],
    value_deserializer=lambda m: json.loads(m.decode('utf-8')),
    auto_offset_reset='earliest',
    group_id='my-consumer-group'
)

for message in consumer:
    event = message.value
    operation = event.get('op')  # 'c'=create, 'u'=update, 'd'=delete, 'r'=read(snapshot)

    if operation == 'c':
        print(f"New order: {event['after']}")
    elif operation == 'u':
        print(f"Updated order: {event['before']} → {event['after']}")
    elif operation == 'd':
        print(f"Deleted order: {event['before']}")
```

### 13.3 Apache Iceberg vs Delta Lake Table Formats

Modern "lakehouse" table formats add ACID transactions, schema evolution, and time travel to data lake storage (Parquet files on S3/GCS).

**Comparison:**

| Feature | Apache Iceberg | Delta Lake | Apache Hudi |
|---------|---------------|------------|-------------|
| Developed by | Netflix/Apple | Databricks | Uber |
| Storage format | Parquet (default) | Parquet | Parquet/Avro |
| Transaction log | Metadata files (JSON/Avro) | JSON log (_delta_log/) | Timeline metadata |
| Schema evolution | Full (add, drop, rename, reorder) | Add/rename columns | Add columns |
| Partition evolution | Yes (change partitioning without rewrite) | No (requires rewrite) | No |
| Time travel | Yes (snapshot-based) | Yes (version-based) | Yes (timeline-based) |
| Hidden partitioning | Yes (partition by transform) | No (explicit partition columns) | No |
| Engine support | Spark, Trino, DuckDB, Flink, Snowflake | Spark, Trino, DuckDB | Spark, Flink, Trino |
| Merge-on-read | Yes | Yes (with deletion vectors) | Yes (primary use case) |

**Querying Iceberg with DuckDB:**

```python
import duckdb

# Install and load Iceberg extension:
duckdb.sql("INSTALL iceberg; LOAD iceberg;")

# Query an Iceberg table:
duckdb.sql("""
    SELECT
        DATE_TRUNC('month', order_date) AS month,
        SUM(amount) AS revenue
    FROM iceberg_scan('s3://my-bucket/warehouse/orders')
    WHERE order_date >= '2025-01-01'
    GROUP BY month
    ORDER BY month
""")

# Time travel (query historical snapshot):
duckdb.sql("""
    SELECT * FROM iceberg_scan('s3://my-bucket/warehouse/orders',
        version='2')  -- specific snapshot version
""")
```

**Querying Delta Lake with DuckDB:**

```python
import duckdb

duckdb.sql("INSTALL delta; LOAD delta;")

# Query Delta table:
duckdb.sql("""
    SELECT * FROM delta_scan('s3://my-bucket/delta/orders')
    WHERE region = 'US'
""")
```

### 13.4 PostgreSQL as a Data Platform

Modern PostgreSQL can serve as a complete data platform:

```sql
-- Foreign Data Wrappers (query external systems from PostgreSQL):
CREATE EXTENSION IF NOT EXISTS postgres_fdw;
CREATE EXTENSION IF NOT EXISTS file_fdw;

-- Connect to another PostgreSQL:
CREATE SERVER remote_db FOREIGN DATA WRAPPER postgres_fdw
    OPTIONS (host 'remote-host', dbname 'analytics', port '5432');

CREATE USER MAPPING FOR current_user SERVER remote_db
    OPTIONS (user 'reader', password 'secret');

CREATE FOREIGN TABLE remote_orders (
    order_id BIGINT,
    customer_id INT,
    amount NUMERIC,
    order_date DATE
) SERVER remote_db OPTIONS (table_name 'orders');

-- Now query remote data as if it's local:
SELECT * FROM remote_orders WHERE order_date > '2025-01-01';

-- Join local and remote data:
SELECT c.name, SUM(ro.amount) AS total
FROM local_customers c
JOIN remote_orders ro ON c.customer_id = ro.customer_id
GROUP BY c.name;

-- Query CSV files directly:
CREATE SERVER csv_server FOREIGN DATA WRAPPER file_fdw;

CREATE FOREIGN TABLE csv_imports (
    col1 TEXT, col2 TEXT, col3 NUMERIC
) SERVER csv_server
OPTIONS (filename '/data/imports.csv', format 'csv', header 'true');
```

### 13.5 Choosing the Right Database for the Job

| Workload | Best Choice | Why |
|----------|-------------|-----|
| General OLTP | PostgreSQL | ACID, extensions, mature ecosystem |
| High-write OLTP | MySQL InnoDB, CockroachDB | Efficient undo-based MVCC, distributed |
| Analytics (OLAP) | DuckDB (embedded), ClickHouse (server) | Columnar, vectorized execution |
| Time-series | TimescaleDB, InfluxDB | Compression, continuous aggregates |
| Vector search | pgvector, Milvus, Pinecone | HNSW/IVF indexes for embeddings |
| Graph queries | Neo4j, Apache AGE (PostgreSQL) | Native graph traversal |
| Document store | MongoDB, PostgreSQL JSONB | Flexible schema, nested queries |
| Cache/session | Redis, DragonflyDB | In-memory, sub-ms latency |
| Data lake analytics | DuckDB + Iceberg/Delta | Lakehouse pattern, Parquet-native |
| Global distribution | CockroachDB, Spanner, YugabyteDB | Geo-distributed ACID |
