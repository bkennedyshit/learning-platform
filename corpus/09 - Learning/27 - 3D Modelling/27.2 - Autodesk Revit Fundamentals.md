# 27.2 — Autodesk Revit Fundamentals

> *Revit is not a 3D modeller that happens to do schedules. It is a relational database with a 3D viewport bolted on the front. Once you see this, every quirk makes sense.*

You already know Revit at the journeyman level from architecture school. This chapter re-grounds it in **the data-model perspective** so the advanced material in [[27.3 - Advanced Revit - Families, Adaptive Components & Dynamo|27.3]] lands cleanly.

## 📚 1. The Revit Data Model

```
Project
├─ Categories (Walls, Doors, Windows, Floors, Roofs, Stairs, …)
│   ├─ Family (system family OR loadable family)
│   │   ├─ Type (parameters that are SHARED across instances of this type)
│   │   └─ Instance (parameters unique to this placement: Mark, Comments, location)
│   └─ Schedules (database views of any category)
├─ Views (plans, sections, elevations, 3D, schedules, sheets)
└─ Sheets (titleblock + viewports of views)
```

**Key insight:** A schedule is not a printable report — it is **the surface of the database**. Editing a cell edits the underlying instance. Every chapter that follows leans on this fact.

### System families vs Loadable families
- **System families** live inside the project (Walls, Floors, Roofs, Pipes, Ducts). You cannot save them out — you transfer project standards.
- **Loadable families** are `.rfa` files (Doors, Windows, Furniture, Equipment). Externally authored; can be parameterized arbitrarily.
- **In-place families** are bespoke modelled-in-context geometry. Avoid for production.

## 📐 2. Setup Discipline

| Step | Why it matters |
|---|---|
| **Project base point** vs **Survey point** | Coordinate origin for design vs the world (lat/long). Set BEFORE modelling. |
| **Project units** | mm vs in. Cannot easily change post-hoc on existing dimensions. |
| **Levels & grids** | The 3D scaffold the rest of the model snaps to. |
| **View templates** | Lock visibility/graphics so views stay consistent. |
| **Browser organization** | Group views by sheet/discipline/phase. Saves 10× later. |
| **Worksets** (Worksharing) | Required for team-collaboration workflows. |

## 🆕 3. Revit 2026 Highlights

- **Accelerated Graphics Tech Preview** — modern GPU pipeline; smoother orbit/pan in dense models.
- **ReCap Pro Mesh plugin** — drop reality-capture meshes (drone scan, LiDAR) directly into Revit.
- **Site & topography** — expanded toolkit (long-overdue parity with Civil 3D).
- **Dynamo 3.5** (with Revit 2026.1) — refreshed visual programming environment, better Python (CPython 3) nodes.
- **Design → analysis bridge** — speeds up structural and energy analysis hand-off.

## 🔁 4. IFC 4.x Round-Trip Discipline

When you export to IFC, **map your Revit categories to IFC entities deliberately**:

| Revit category | IFC class |
|---|---|
| Walls | IfcWall / IfcWallStandardCase |
| Floors | IfcSlab |
| Roofs | IfcRoof |
| Doors | IfcDoor |
| Windows | IfcWindow |
| Generic Models | IfcBuildingElementProxy (avoid if possible) |

Verify with **buildingSMART validators** or **BIMcollab Zoom** before sending to a non-Revit consultant.

## 🛠️ 5. Worked Example — A Schedulable Door Family

> Skeleton — full step-by-step in [[27.3 - Advanced Revit - Families, Adaptive Components & Dynamo]].

**Goal:** Create a door family with shared parameters for fire rating, manufacturer, cost, and an instance parameter for keying group, so a Door Schedule can drive the door schedule sheet directly.

Steps (high-level):
1. New Door family from `Metric Door.rft` template.
2. Add **shared parameters** (fire rating, manufacturer, cost) — must use a **shared parameters file** so they survive cross-project + IFC export.
3. Configure **Type** vs **Instance** scope on each parameter.
4. Build geometry referencing planes constrained to family origin.
5. Test in a sandbox project; place several instances; make a Schedule.
6. Export to IFC and confirm parameters survive the round-trip.

## ⚠️ 7. Common Misconceptions

- **"In-place families are quick."** They poison the schedule and never reuse — avoid.
- **"Shared parameters are optional."** Shared parameters are how data survives exports; treat them as the canonical parameter system.
- **"Worksharing is for big teams."** Even solo, worksharing protects you from corruption on long projects.
- **"Linked Revit is the same as Worksharing."** Different mechanism — linking is for separate models, worksharing for collaborators on one model.
