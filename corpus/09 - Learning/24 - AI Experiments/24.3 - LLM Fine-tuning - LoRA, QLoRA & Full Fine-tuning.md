# 24.3 — LLM Fine-tuning: LoRA, QLoRA & Full Fine-tuning

> *"Don't train from scratch. Fine-tune. The pretrained model already knows language — you're just teaching it your task."*
> — **Andrej Karpathy**, *State of GPT* (2023)

This chapter covers the full spectrum of LLM fine-tuning: from parameter-efficient LoRA adapters that fit on a single 24GB GPU, through QLoRA's 4-bit quantized training, to full fine-tuning with FSDP. You'll fine-tune Llama-3-8B, align it with DPO, merge adapters, and export to GGUF for local inference.

## 📚 1. Concepts & Definitions

| Concept | Definition |
|---------|-----------|
| **SFT (Supervised Fine-Tuning)** | Training on (instruction, response) pairs with cross-entropy loss |
| **LoRA** | Low-Rank Adaptation — adds trainable rank-$r$ matrices to frozen weights |
| **QLoRA** | LoRA on a 4-bit quantized base model (NF4 quantization) |
| **DPO** | Direct Preference Optimization — aligns without a reward model |
| **RLHF** | RL from Human Feedback — PPO on a learned reward model |
| **Adapter Merging** | Combining LoRA weights back into base model for inference |
| **PEFT** | Parameter-Efficient Fine-Tuning (HuggingFace library) |

### Memory Requirements Comparison

```
Model: Llama-3-8B (8.03B parameters)

Full Fine-tuning (FP16):
  Weights:     8B × 2 = 16 GB
  Gradients:   8B × 2 = 16 GB
  Optimizer:   8B × 8 = 64 GB (AdamW: params + momentum + variance in FP32)
  Activations: ~10-20 GB (depends on batch/seq_len)
  TOTAL:       ~106-116 GB → needs 5× A100-80GB or FSDP

LoRA (FP16 base, FP16 adapters):
  Frozen base: 8B × 2 = 16 GB
  LoRA params: ~20M × 2 = 40 MB (rank=32, all linear layers)
  Gradients:   20M × 2 = 40 MB
  Optimizer:   20M × 8 = 160 MB
  Activations: ~4-8 GB
  TOTAL:       ~22-26 GB → fits on 1× RTX 4090!

QLoRA (4-bit base, FP16 adapters):
  Frozen base: 8B × 0.5 = 4 GB (NF4 quantization)
  LoRA params: ~20M × 2 = 40 MB
  Optimizer:   20M × 8 = 160 MB
  Activations: ~4-8 GB (computed in FP16 via double quantization)
  TOTAL:       ~10-14 GB → fits with room to spare!
```

## 🔬 2. Theory Briefing

> For transformer architecture details, see [[23.5 - Transformer Architectures & LLMs]]. For RLHF theory, see [[23.7 - Reinforcement Learning & RLHF]].

### LoRA: Low-Rank Adaptation

For a pretrained weight matrix $W_0 \in \mathbb{R}^{d \times k}$, LoRA adds:

$$
W = W_0 + \frac{\alpha}{r} BA
$$

where $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$, rank $r \ll \min(d, k)$.

- $A$ initialized from $\mathcal{N}(0, \sigma^2)$, $B$ initialized to zero → $\Delta W = 0$ at start
- $\alpha/r$ is the scaling factor (higher $\alpha$ = stronger adaptation)
- Only $A$ and $B$ are trained; $W_0$ stays frozen

### QLoRA: 4-bit Quantized LoRA

Three innovations from Dettmers et al. (2023):
1. **NF4 (NormalFloat4):** Quantization data type optimal for normally-distributed weights
2. **Double Quantization:** Quantize the quantization constants themselves (saves ~0.4 GB for 65B)
3. **Paged Optimizers:** Use CPU RAM for optimizer states that don't fit in VRAM

### DPO: Direct Preference Optimization

Instead of training a separate reward model + PPO (RLHF), DPO directly optimizes the policy:

$$
\mathcal{L}_{DPO}(\pi_\theta; \pi_{ref}) = -\mathbb{E}_{(x, y_w, y_l)}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right)\right]
$$

where $y_w$ is the preferred response, $y_l$ is the rejected response, and $\beta$ controls deviation from the reference policy.

### Experiment 4.1 — QLoRA Fine-tuning on Custom Instructions

```python
import torch
from datasets import load_dataset
from transformers import (
    AutoModelForCausalLM, AutoTokenizer,
    BitsAndBytesConfig, TrainingArguments,
)
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import SFTTrainer

# === 1. Quantization Config ===
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)

# === 2. Load Model ===
model_name = "meta-llama/Meta-Llama-3-8B"
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=bnb_config,
    device_map="auto",
    attn_implementation="flash_attention_2",
)
model = prepare_model_for_kbit_training(model)

tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token
tokenizer.padding_side = "right"

# === 3. LoRA Config ===
lora_config = LoraConfig(
    r=32,                          # Rank (16-64 typical)
    lora_alpha=64,                 # Alpha (usually 2×rank)
    target_modules=[               # Which layers to adapt
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# Expected: trainable params: ~20M (0.25% of 8B)

# === 4. Dataset ===
# Using a subset of OpenAssistant for demo
dataset = load_dataset("timdettmers/openassistant-guanaco", split="train[:5000]")

# Format as ChatML
def format_chat(example):
    return {"text": f"<|im_start|>user\n{example['input']}<|im_end|>\n<|im_start|>assistant\n{example['output']}<|im_end|>"}

dataset = dataset.map(format_chat)

# === 5. Training ===
training_args = TrainingArguments(
    output_dir="./llama3-qlora-output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,  # Effective batch = 16
    learning_rate=2e-4,
    lr_scheduler_type="cosine",
    warmup_ratio=0.05,
    fp16=False,
    bf16=True,
    logging_steps=10,
    save_strategy="steps",
    save_steps=200,
    optim="paged_adamw_8bit",
    max_grad_norm=0.3,
    seed=42,
    report_to="wandb",
)

trainer = SFTTrainer(
    model=model,
    train_dataset=dataset,
    tokenizer=tokenizer,
    args=training_args,
    dataset_text_field="text",
    max_seq_length=2048,
    packing=True,  # Pack multiple short examples into one sequence
)

trainer.train()
trainer.save_model("./llama3-qlora-output/final")
```

### Experiment 4.2 — DPO Alignment

```python
import torch
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig
from trl import DPOConfig, DPOTrainer

# Load SFT model (from Experiment 4.1 or a pre-trained chat model)
model_name = "meta-llama/Meta-Llama-3-8B-Instruct"

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
)

model = AutoModelForCausalLM.from_pretrained(
    model_name, quantization_config=bnb_config, device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token

# Reference model (frozen copy for KL penalty)
ref_model = AutoModelForCausalLM.from_pretrained(
    model_name, quantization_config=bnb_config, device_map="auto"
)

# DPO dataset format: {"prompt": str, "chosen": str, "rejected": str}
dataset = load_dataset("argilla/ultrafeedback-binarized-preferences", split="train[:2000]")

# LoRA for DPO
peft_config = LoraConfig(
    r=16, lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.05, bias="none", task_type="CAUSAL_LM",
)

# DPO Training
dpo_config = DPOConfig(
    output_dir="./llama3-dpo-output",
    num_train_epochs=1,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,
    learning_rate=5e-5,
    beta=0.1,  # KL penalty strength
    bf16=True,
    logging_steps=10,
    optim="paged_adamw_8bit",
    max_length=1024,
    max_prompt_length=512,
)

trainer = DPOTrainer(
    model=model,
    ref_model=ref_model,
    args=dpo_config,
    train_dataset=dataset,
    tokenizer=tokenizer,
    peft_config=peft_config,
)

trainer.train()
trainer.save_model("./llama3-dpo-output/final")
```

## ⚠️ 6. Gotchas & Debugging

| Issue | Cause | Fix |
|-------|-------|-----|
| Loss = NaN | LR too high or dtype mismatch | Reduce LR to 1e-5, ensure bf16 compute |
| Loss doesn't decrease | LR too low or wrong target modules | Increase LR, add all linear layers |
| Catastrophic forgetting | Too many epochs on small data | 1-3 epochs max, use regularization |
| Repetitive outputs | Overfitting on training patterns | Reduce epochs, increase data diversity |
| Merge fails with size mismatch | Quantized base vs FP16 merge | Load base in FP16 for merge (on CPU) |
| GGUF conversion errors | Wrong llama.cpp version | Use latest main branch |

### LoRA Hyperparameter Guide

```
Rank (r):
  4-8:   Light adaptation (style, tone)
  16-32: Standard instruction tuning
  64-128: Heavy domain adaptation (code, medical)

Alpha (α):
  Rule of thumb: α = 2×r
  Higher α = stronger LoRA effect
  
Target modules:
  Minimum: q_proj, v_proj (attention only)
  Standard: q_proj, k_proj, v_proj, o_proj (all attention)
  Maximum: + gate_proj, up_proj, down_proj (attention + MLP)
  
Dropout:
  0.0: For large datasets (>10K examples)
  0.05-0.1: For small datasets (<5K examples)
```

## 🔬 7. Variations & Extensions

1. **NEFTune:** Add noise to embeddings during training for better generalization. Just set `neftune_noise_alpha=5` in `SFTTrainer`.

2. **ORPO (Odds Ratio Preference Optimization):** Combines SFT + alignment in a single training stage. No reference model needed.

3. **Continued Pretraining:** Before instruction tuning, continue pretraining on domain-specific text (medical papers, legal docs, code).

4. **Multi-Adapter Serving:** Load multiple LoRA adapters and switch between them at inference time with `peft`'s adapter management.

5. **Reward Model Training:** Train your own reward model on preference data, then use it for RLHF with PPO via `trl.PPOTrainer`.

## 🧠 9. Extended Experiments & Variations

### Experiment 9.1 — DPO vs ORPO vs SimPO Alignment Comparison

Train the same base model with three different preference optimization algorithms and compare on alignment benchmarks. This reveals which method works best for different data regimes.

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import DPOTrainer, DPOConfig, ORPOTrainer, ORPOConfig
from datasets import load_dataset
import json
import time

def prepare_base_model(model_name="meta-llama/Meta-Llama-3.1-8B-Instruct"):
    """Load quantized base model with LoRA for alignment training."""
    from transformers import BitsAndBytesConfig
    
    bnb_config = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_compute_dtype=torch.bfloat16,
        bnb_4bit_use_double_quant=True,
    )
    
    model = AutoModelForCausalLM.from_pretrained(
        model_name, quantization_config=bnb_config, device_map="auto",
        attn_implementation="flash_attention_2",
    )
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    tokenizer.pad_token = tokenizer.eos_token
    
    model = prepare_model_for_kbit_training(model)
    
    lora_config = LoraConfig(
        r=32, lora_alpha=64, lora_dropout=0.05,
        target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                       "gate_proj", "up_proj", "down_proj"],
        bias="none", task_type="CAUSAL_LM",
    )
    model = get_peft_model(model, lora_config)
    
    return model, tokenizer

def prepare_preference_dataset(dataset_name="argilla/ultrafeedback-binarized-preferences"):
    """Load and format preference dataset for DPO/ORPO."""
    dataset = load_dataset(dataset_name, split="train[:5000]")
    
    def format_example(example):
        return {
            "prompt": example["instruction"],
            "chosen": example["chosen_response"],
            "rejected": example["rejected_response"],
        }
    
    return dataset.map(format_example, remove_columns=dataset.column_names)

# === DPO Training ===
def train_dpo(model, tokenizer, dataset, output_dir="./dpo_output"):
    """Train with Direct Preference Optimization."""
    training_args = DPOConfig(
        output_dir=output_dir,
        num_train_epochs=1,
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        learning_rate=5e-5,
        beta=0.1,  # KL penalty coefficient
        loss_type="sigmoid",  # standard DPO loss
        bf16=True,
        logging_steps=10,
        save_steps=200,
        max_length=1024,
        max_prompt_length=512,
        gradient_checkpointing=True,
    )
    
    trainer = DPOTrainer(
        model=model,
        args=training_args,
        train_dataset=dataset,
        tokenizer=tokenizer,
    )
    
    start = time.perf_counter()
    trainer.train()
    elapsed = time.perf_counter() - start
    
    metrics = trainer.state.log_history
    return {"time_min": elapsed / 60, "final_loss": metrics[-1].get("loss", None)}

# === ORPO Training ===
def train_orpo(model, tokenizer, dataset, output_dir="./orpo_output"):
    """Train with Odds Ratio Preference Optimization (no reference model needed)."""
    training_args = ORPOConfig(
        output_dir=output_dir,
        num_train_epochs=1,
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        learning_rate=5e-5,
        beta=0.1,  # odds ratio weight
        bf16=True,
        logging_steps=10,
        save_steps=200,
        max_length=1024,
        max_prompt_length=512,
        gradient_checkpointing=True,
    )
    
    trainer = ORPOTrainer(
        model=model,
        args=training_args,
        train_dataset=dataset,
        tokenizer=tokenizer,
    )
    
    start = time.perf_counter()
    trainer.train()
    elapsed = time.perf_counter() - start
    
    return {"time_min": elapsed / 60}

# === SimPO Training ===
def train_simpo(model, tokenizer, dataset, output_dir="./simpo_output"):
    """Train with Simple Preference Optimization (length-normalized, no reference)."""
    # SimPO uses DPOTrainer with specific settings
    training_args = DPOConfig(
        output_dir=output_dir,
        num_train_epochs=1,
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        learning_rate=5e-5,
        beta=2.0,  # SimPO uses higher beta
        loss_type="simpo",  # SimPO loss variant
        simpo_gamma=1.0,  # reward margin
        bf16=True,
        logging_steps=10,
        max_length=1024,
        max_prompt_length=512,
        gradient_checkpointing=True,
    )
    
    trainer = DPOTrainer(
        model=model,
        args=training_args,
        train_dataset=dataset,
        tokenizer=tokenizer,
    )
    
    start = time.perf_counter()
    trainer.train()
    elapsed = time.perf_counter() - start
    
    return {"time_min": elapsed / 60}

# Run comparison
dataset = prepare_preference_dataset()
print(f"Dataset size: {len(dataset)} preference pairs")

# Train each method (reload model each time for fair comparison)
for method, train_fn in [("DPO", train_dpo), ("ORPO", train_orpo), ("SimPO", train_simpo)]:
    print(f"\n{'='*60}\nTraining {method}...")
    model, tokenizer = prepare_base_model()
    result = train_fn(model, tokenizer, dataset)
    print(f"{method} completed in {result['time_min']:.1f} minutes")
    del model; torch.cuda.empty_cache()
```

**Expected output:**

| Method | Training Time | VRAM | Reference Model | Best For |
|--------|-------------|------|-----------------|----------|
| DPO | 45 min | 20 GB | Required (frozen copy) | Standard alignment |
| ORPO | 35 min | 16 GB | Not needed | Memory-constrained |
| SimPO | 40 min | 16 GB | Not needed | Length-balanced responses |

**Key differences:**
- **DPO** requires keeping a frozen reference model in memory (extra ~4 GB for 4-bit).
- **ORPO** combines SFT + preference in one loss — trains faster, no reference model.
- **SimPO** normalizes by response length, preventing the model from gaming rewards with verbose outputs.

**Gotchas:**
- DPO's `beta` is critical: too low (0.01) = ignores preferences; too high (1.0) = collapses to reference model.
- ORPO can be unstable with very small datasets (<1000 pairs) — use DPO for small data.
- SimPO's `gamma` (reward margin) should be tuned: 0.5-2.0 range, higher = stricter preference enforcement.

### Experiment 9.3 — RLHF Reward Model Training

Train a reward model on preference data, then use it to score outputs. This is the foundation for full PPO-based RLHF (though DPO is simpler for most use cases).

```python
import torch
from transformers import (
    AutoModelForSequenceClassification, AutoTokenizer,
    TrainingArguments, Trainer
)
from datasets import load_dataset
from peft import LoraConfig, get_peft_model, TaskType
import numpy as np

def train_reward_model(
    model_name="meta-llama/Meta-Llama-3.1-8B-Instruct",
    dataset_name="argilla/ultrafeedback-binarized-preferences",
    output_dir="./reward_model",
):
    """Train a reward model on preference pairs."""
    # Load model as sequence classifier (adds a scalar head)
    model = AutoModelForSequenceClassification.from_pretrained(
        model_name,
        num_labels=1,  # scalar reward
        torch_dtype=torch.bfloat16,
        device_map="auto",
        load_in_4bit=True,
    )
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    tokenizer.pad_token = tokenizer.eos_token
    model.config.pad_token_id = tokenizer.pad_token_id
    
    # Add LoRA
    lora_config = LoraConfig(
        r=16, lora_alpha=32, lora_dropout=0.05,
        target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
        bias="none", task_type=TaskType.SEQ_CLS,
    )
    model = get_peft_model(model, lora_config)
    
    # Load preference dataset
    dataset = load_dataset(dataset_name, split="train[:10000]")
    
    def preprocess(examples):
        """Format preference pairs for reward model training."""
        chosen_texts = []
        rejected_texts = []
        
        for instruction, chosen, rejected in zip(
            examples["instruction"], examples["chosen_response"], examples["rejected_response"]
        ):
            chosen_texts.append(f"User: {instruction}\nAssistant: {chosen}")
            rejected_texts.append(f"User: {instruction}\nAssistant: {rejected}")
        
        chosen_enc = tokenizer(chosen_texts, truncation=True, max_length=512, padding="max_length")
        rejected_enc = tokenizer(rejected_texts, truncation=True, max_length=512, padding="max_length")
        
        return {
            "input_ids_chosen": chosen_enc["input_ids"],
            "attention_mask_chosen": chosen_enc["attention_mask"],
            "input_ids_rejected": rejected_enc["input_ids"],
            "attention_mask_rejected": rejected_enc["attention_mask"],
        }
    
    dataset = dataset.map(preprocess, batched=True, batch_size=100,
                         remove_columns=dataset.column_names)
    
    # Custom trainer for pairwise ranking loss
    class RewardTrainer(Trainer):
        def compute_loss(self, model, inputs, return_outputs=False, **kwargs):
            # Forward pass for chosen
            chosen_outputs = model(
                input_ids=torch.tensor(inputs["input_ids_chosen"]).to(model.device),
                attention_mask=torch.tensor(inputs["attention_mask_chosen"]).to(model.device),
            )
            chosen_rewards = chosen_outputs.logits.squeeze(-1)
            
            # Forward pass for rejected
            rejected_outputs = model(
                input_ids=torch.tensor(inputs["input_ids_rejected"]).to(model.device),
                attention_mask=torch.tensor(inputs["attention_mask_rejected"]).to(model.device),
            )
            rejected_rewards = rejected_outputs.logits.squeeze(-1)
            
            # Bradley-Terry pairwise loss
            loss = -torch.nn.functional.logsigmoid(chosen_rewards - rejected_rewards).mean()
            
            if return_outputs:
                return loss, {"chosen_rewards": chosen_rewards, "rejected_rewards": rejected_rewards}
            return loss
    
    training_args = TrainingArguments(
        output_dir=output_dir,
        num_train_epochs=1,
        per_device_train_batch_size=4,
        gradient_accumulation_steps=4,
        learning_rate=1e-4,
        bf16=True,
        logging_steps=20,
        save_steps=500,
        gradient_checkpointing=True,
    )
    
    trainer = RewardTrainer(
        model=model,
        args=training_args,
        train_dataset=dataset,
    )
    
    trainer.train()
    trainer.save_model(output_dir)
    
    return model, tokenizer

def score_responses(reward_model, tokenizer, prompt, responses):
    """Score multiple responses with the reward model."""
    scores = []
    for response in responses:
        text = f"User: {prompt}\nAssistant: {response}"
        inputs = tokenizer(text, return_tensors="pt", truncation=True, max_length=512).to(reward_model.device)
        
        with torch.no_grad():
            score = reward_model(**inputs).logits.squeeze().item()
        scores.append(score)
    
    # Rank responses
    ranked = sorted(zip(responses, scores), key=lambda x: x[1], reverse=True)
    return ranked

# Train and evaluate
reward_model, tokenizer = train_reward_model()

# Test scoring
prompt = "Explain quantum computing in simple terms"
responses = [
    "Quantum computing uses qubits that can be 0 and 1 simultaneously, enabling parallel computation.",
    "idk google it lol",
    "Quantum computing leverages quantum mechanical phenomena like superposition and entanglement to process information in ways classical computers cannot, potentially solving certain problems exponentially faster.",
]

ranked = score_responses(reward_model, tokenizer, prompt, responses)
for response, score in ranked:
    print(f"[{score:.3f}] {response[:80]}...")
```

**Expected output:**
- Training time: ~60 min on RTX 4090 (10K pairs, 1 epoch)
- Accuracy on held-out pairs: 70-75% (choosing the human-preferred response)
- Clear score separation between high-quality and low-quality responses

## 📘 10. Appendix: Production Considerations & Theory Bridges

### 10.1 Rank vs Alpha Tuning — The Effective Learning Rate

> **Cross-reference:** [[23.5 - Transformer Architectures & LLMs]] §24.3 for multi-head attention weight dimensions.

The LoRA update to a pretrained weight matrix $W_0 \in \mathbb{R}^{d \times k}$ is:

$$
W = W_0 + \frac{\alpha}{r} \cdot BA
$$

where $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$, $r$ is rank, and $\alpha$ is the scaling factor.

**Why $\alpha/r$ matters:** The initialization is $A \sim \mathcal{N}(0, \sigma^2)$, $B = 0$. During training, the effective magnitude of the LoRA update scales as:

$$
\|\Delta W\| \propto \frac{\alpha}{r} \cdot \|B\| \cdot \|A\| \propto \frac{\alpha}{r} \cdot \sqrt{r} \cdot \sqrt{r} = \alpha
$$

So the *magnitude* of the update is controlled by $\alpha$ alone, while $r$ controls the *expressiveness* (rank of the update). This means:

| Configuration | Effect |
|--------------|--------|
| $r=16, \alpha=32$ | Standard expressiveness, standard magnitude |
| $r=64, \alpha=32$ | High expressiveness, same magnitude |
| $r=16, \alpha=64$ | Standard expressiveness, 2× magnitude |
| $r=64, \alpha=128$ | High expressiveness, 2× magnitude |

**Practical tuning strategy:**
1. Start with $r=32, \alpha=64$ (ratio = 2) for instruction tuning.
2. If underfitting (loss plateaus high): increase $r$ to 64 or increase $\alpha$.
3. If overfitting (eval loss diverges): decrease $\alpha$ or add dropout.
4. For domain adaptation (code, medical): use $r=64-128$ with more data.

**Target module selection impact:**

| Modules | Trainable Params (8B model) | Use Case |
|---------|---------------------------|----------|
| q_proj, v_proj only | ~10M | Light style adaptation |
| All attention (q,k,v,o) | ~20M | Standard instruction tuning |
| Attention + MLP (all linear) | ~50M | Heavy domain adaptation |
| All + embeddings | ~80M | Language adaptation |

### 10.2 Catastrophic Forgetting Countermeasures

When fine-tuning on a narrow domain, the model "forgets" general capabilities. This section covers detection and mitigation.

**Detection — benchmark before and after:**

```python
from lm_eval import evaluator

def measure_forgetting(base_model_path, finetuned_model_path):
    """Compare general benchmarks before/after fine-tuning."""
    tasks = ["mmlu", "hellaswag", "arc_challenge", "winogrande"]
    
    base_results = evaluator.simple_evaluate(
        model="hf", model_args=f"pretrained={base_model_path}",
        tasks=tasks, batch_size=8,
    )
    
    ft_results = evaluator.simple_evaluate(
        model="hf", model_args=f"pretrained={finetuned_model_path}",
        tasks=tasks, batch_size=8,
    )
    
    print(f"{'Task':<20} {'Base':<10} {'Fine-tuned':<12} {'Delta':<8}")
    print("-" * 50)
    for task in tasks:
        base_acc = base_results["results"][task]["acc,none"]
        ft_acc = ft_results["results"][task]["acc,none"]
        delta = ft_acc - base_acc
        flag = "⚠️" if delta < -0.02 else "✓"
        print(f"{task:<20} {base_acc:.3f}     {ft_acc:.3f}       {delta:+.3f} {flag}")
```

**Mitigation strategies:**

1. **Replay buffer:** Mix 10-20% general instruction data with domain-specific data during training.

```python
from datasets import concatenate_datasets

def create_mixed_dataset(domain_dataset, general_dataset, domain_ratio=0.8):
    """Mix domain-specific and general data to prevent forgetting."""
    n_domain = len(domain_dataset)
    n_general = int(n_domain * (1 - domain_ratio) / domain_ratio)
    
    general_subset = general_dataset.shuffle(seed=42).select(range(min(n_general, len(general_dataset))))
    mixed = concatenate_datasets([domain_dataset, general_subset]).shuffle(seed=42)
    return mixed
```

2. **Elastic Weight Consolidation (EWC):** Add a penalty for changing important weights:

$$
\mathcal{L}_{EWC} = \mathcal{L}_{task} + \frac{\lambda}{2} \sum_i F_i (\theta_i - \theta_i^*)^2
$$

where $F_i$ is the Fisher information (importance) of parameter $i$.

3. **Low rank + low learning rate:** LoRA with $r \leq 16$ and $\text{lr} \leq 1\text{e-5}$ naturally limits forgetting because the update subspace is small.

4. **Progressive training:** Start with general instruction data, then gradually increase domain-specific data ratio over training.

**Empirical forgetting rates (Llama-3-8B, 5K domain examples):**

| Method | MMLU Drop | HellaSwag Drop | Domain Accuracy |
|--------|-----------|----------------|-----------------|
| Full fine-tune | -5.2% | -3.8% | 92% |
| LoRA r=64 | -2.1% | -1.5% | 89% |
| LoRA r=32 | -0.8% | -0.5% | 87% |
| LoRA r=32 + replay | -0.2% | -0.1% | 86% |
| QLoRA r=32 + replay | -0.3% | -0.2% | 85% |

### 10.3 DPO Loss Derivation — From RLHF to Closed-Form

> **Cross-reference:** [[23.7 - Reinforcement Learning & RLHF]] for PPO and reward modeling theory.

**The RLHF objective:** Maximize expected reward while staying close to the reference policy:

$$
\max_{\pi_\theta} \mathbb{E}_{x \sim D, y \sim \pi_\theta(\cdot|x)} [r(x, y)] - \beta \cdot D_{KL}[\pi_\theta(\cdot|x) \| \pi_{ref}(\cdot|x)]
$$

**Key insight (Rafailov et al., 2023):** The optimal policy has a closed-form solution:

$$
\pi^*(y|x) = \frac{1}{Z(x)} \pi_{ref}(y|x) \exp\left(\frac{r(x,y)}{\beta}\right)
$$

Rearranging to express reward in terms of policy:

$$
r(x, y) = \beta \log \frac{\pi^*(y|x)}{\pi_{ref}(y|x)} + \beta \log Z(x)
$$

**The DPO loss:** Substituting into the Bradley-Terry preference model $p(y_w \succ y_l | x) = \sigma(r(x, y_w) - r(x, y_l))$:

$$
\mathcal{L}_{DPO} = -\mathbb{E}_{(x, y_w, y_l)} \left[ \log \sigma\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right) \right]
$$

The $Z(x)$ terms cancel because they don't depend on $y$. This eliminates the need for:
- A separate reward model
- RL training (PPO)
- Reward model inference during training

**Gradient intuition:** The DPO gradient increases the likelihood of chosen responses and decreases rejected responses, weighted by how "surprising" the preference is to the current model. If the model already strongly prefers the chosen response, the gradient is small (it's already aligned).
