## 📚 1. WebAssembly (WASM)

### 1.1 — Why Rust + WASM

| Feature | JavaScript | Rust → WASM |
|---------|-----------|-------------|
| Execution speed | JIT (variable) | Near-native (predictable) |
| Memory safety | GC pauses | No GC, deterministic |
| Binary size | N/A (interpreted) | ~50-200KB typical |
| Use case | UI, DOM manipulation | Compute-heavy: image processing, crypto, physics |

### 1.3 — Writing WASM-Exported Functions

```rust
use wasm_bindgen::prelude::*;

// Export to JavaScript
#[wasm_bindgen]
pub fn fibonacci(n: u32) -> u64 {
    match n {
        0 => 0,
        1 => 1,
        _ => {
            let mut a: u64 = 0;
            let mut b: u64 = 1;
            for _ in 2..=n {
                let temp = a + b;
                a = b;
                b = temp;
            }
            b
        }
    }
}

// Structs exported to JS
#[wasm_bindgen]
pub struct Universe {
    width: u32,
    height: u32,
    cells: Vec<u8>,
}

#[wasm_bindgen]
impl Universe {
    pub fn new(width: u32, height: u32) -> Self {
        let cells = vec![0; (width * height) as usize];
        Universe { width, height, cells }
    }

    pub fn tick(&mut self) {
        // Game of Life step...
        let mut next = self.cells.clone();
        for row in 0..self.height {
            for col in 0..self.width {
                let idx = (row * self.width + col) as usize;
                let live_neighbors = self.live_neighbor_count(row, col);
                next[idx] = match (self.cells[idx], live_neighbors) {
                    (1, 2) | (1, 3) => 1,
                    (1, _) => 0,
                    (0, 3) => 1,
                    (otherwise, _) => otherwise,
                };
            }
        }
        self.cells = next;
    }

    pub fn cells_ptr(&self) -> *const u8 {
        self.cells.as_ptr()  // Direct memory access from JS!
    }

    fn live_neighbor_count(&self, row: u32, col: u32) -> u8 {
        let mut count = 0;
        for dr in [self.height - 1, 0, 1] {
            for dc in [self.width - 1, 0, 1] {
                if dr == 0 && dc == 0 { continue; }
                let r = (row + dr) % self.height;
                let c = (col + dc) % self.width;
                count += self.cells[(r * self.width + c) as usize];
            }
        }
        count
    }
}

// Call JavaScript from Rust
#[wasm_bindgen]
extern "C" {
    #[wasm_bindgen(js_namespace = console)]
    fn log(s: &str);
}

#[wasm_bindgen]
pub fn greet(name: &str) {
    log(&format!("Hello, {name}! From Rust WASM."));
}
```

### 2.3 — Rust ↔ Python with PyO3

```rust
use pyo3::prelude::*;

/// A fast Rust function callable from Python
#[pyfunction]
fn sum_of_squares(numbers: Vec<f64>) -> f64 {
    numbers.iter().map(|x| x * x).sum()
}

/// A Rust class exposed to Python
#[pyclass]
struct TokenCounter {
    counts: std::collections::HashMap<String, usize>,
}

#[pymethods]
impl TokenCounter {
    #[new]
    fn new() -> Self {
        TokenCounter { counts: std::collections::HashMap::new() }
    }

    fn add(&mut self, text: &str) {
        for word in text.split_whitespace() {
            *self.counts.entry(word.to_lowercase()).or_insert(0) += 1;
        }
    }

    fn top_n(&self, n: usize) -> Vec<(String, usize)> {
        let mut pairs: Vec<_> = self.counts.iter()
            .map(|(k, &v)| (k.clone(), v))
            .collect();
        pairs.sort_by(|a, b| b.1.cmp(&a.1));
        pairs.truncate(n);
        pairs
    }
}

/// Python module
#[pymodule]
fn rust_nlp(m: &Bound<'_, PyModule>) -> PyResult<()> {
    m.add_function(wrap_pyfunction!(sum_of_squares, m)?)?;
    m.add_class::<TokenCounter>()?;
    Ok(())
}
```

## 📚 3. Embedded Rust (no_std)

### 3.1 — What is no_std?

`no_std` means no standard library — no heap allocation, no OS, no filesystem. Just the `core` library (math, iterators, Option, Result) and optionally `alloc` (Vec, String, Box with a custom allocator).

```rust
#![no_std]
#![no_main]

use cortex_m_rt::entry;
use panic_halt as _;  // Panic handler (required in no_std)

#[entry]
fn main() -> ! {
    // Embedded code runs forever (-> !)
    let peripherals = stm32f4::Peripherals::take().unwrap();

    // Configure GPIO
    let gpioa = &peripherals.GPIOA;
    gpioa.moder.modify(|_, w| w.moder5().output());

    loop {
        // Blink LED
        gpioa.odr.modify(|_, w| w.odr5().set_bit());
        cortex_m::asm::delay(8_000_000);
        gpioa.odr.modify(|_, w| w.odr5().clear_bit());
        cortex_m::asm::delay(8_000_000);
    }
}
```

### 3.2 — embedded-hal (Hardware Abstraction Layer)

```rust
use embedded_hal::digital::OutputPin;
use embedded_hal::delay::DelayNs;

// Generic over any hardware that implements the HAL traits
fn blink<P: OutputPin, D: DelayNs>(pin: &mut P, delay: &mut D, times: u32) {
    for _ in 0..times {
        pin.set_high().ok();
        delay.delay_ms(500);
        pin.set_low().ok();
        delay.delay_ms(500);
    }
}

// Works on STM32, nRF52, ESP32, RP2040 — any chip with an embedded-hal impl!
```

### 4.2 — Bevy ECS Fundamentals

```rust
use bevy::prelude::*;

// COMPONENTS: Plain data structs
#[derive(Component)]
struct Position { x: f32, y: f32 }

#[derive(Component)]
struct Velocity { dx: f32, dy: f32 }

#[derive(Component)]
struct Health(f32);

#[derive(Component)]
struct Player;

#[derive(Component)]
struct Enemy;

// SYSTEMS: Functions that operate on components
fn movement_system(mut query: Query<(&mut Position, &Velocity)>, time: Res<Time>) {
    for (mut pos, vel) in &mut query {
        pos.x += vel.dx * time.delta_secs();
        pos.y += vel.dy * time.delta_secs();
    }
}

fn damage_system(
    mut enemies: Query<(&Position, &mut Health), With<Enemy>>,
    players: Query<&Position, With<Player>>,
) {
    for player_pos in &players {
        for (enemy_pos, mut health) in &mut enemies {
            let dx = player_pos.x - enemy_pos.x;
            let dy = player_pos.y - enemy_pos.y;
            let distance = (dx * dx + dy * dy).sqrt();
            if distance < 50.0 {
                health.0 -= 10.0;
            }
        }
    }
}

// RESOURCES: Global state
#[derive(Resource)]
struct Score(u32);

fn score_system(mut score: ResMut<Score>, query: Query<&Health, With<Enemy>>) {
    for health in &query {
        if health.0 <= 0.0 {
            score.0 += 100;
        }
    }
}

// STARTUP SYSTEM: Runs once
fn setup(mut commands: Commands) {
    // Spawn player entity
    commands.spawn((
        Player,
        Position { x: 0.0, y: 0.0 },
        Velocity { dx: 0.0, dy: 0.0 },
        Health(100.0),
    ));

    // Spawn enemies
    for i in 0..10 {
        commands.spawn((
            Enemy,
            Position { x: (i as f32) * 100.0, y: 300.0 },
            Velocity { dx: -1.0, dy: 0.0 },
            Health(50.0),
        ));
    }
}

// APP: Wire everything together
fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .insert_resource(Score(0))
        .add_systems(Startup, setup)
        .add_systems(Update, (
            movement_system,
            damage_system,
            score_system,
        ))
        .run();
}
```

```rust
#[derive(States, Debug, Clone, PartialEq, Eq, Hash, Default)]
enum GameState {
    #[default]
    Menu,
    Playing,
    Paused,
    GameOver,
}

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .init_state::<GameState>()
        .add_systems(OnEnter(GameState::Playing), setup_game)
        .add_systems(OnExit(GameState::Playing), cleanup_game)
        .add_systems(Update, game_logic.run_if(in_state(GameState::Playing)))
        .add_systems(Update, pause_toggle)
        .run();
}

fn pause_toggle(
    keyboard: Res<ButtonInput<KeyCode>>,
    state: Res<State<GameState>>,
    mut next_state: ResMut<NextState<GameState>>,
) {
    if keyboard.just_pressed(KeyCode::Escape) {
        match state.get() {
            GameState::Playing => next_state.set(GameState::Paused),
            GameState::Paused => next_state.set(GameState::Playing),
            _ => {}
        }
    }
}
```

### 4.5 — Bevy Events

```rust
#[derive(Event)]
struct CollisionEvent {
    entity_a: Entity,
    entity_b: Entity,
    impact_force: f32,
}

fn collision_detection(
    query: Query<(Entity, &Position, &Collider)>,
    mut events: EventWriter<CollisionEvent>,
) {
    let entities: Vec<_> = query.iter().collect();
    for i in 0..entities.len() {
        for j in (i + 1)..entities.len() {
            let (e1, p1, c1) = entities[i];
            let (e2, p2, c2) = entities[j];
            let dist = ((p1.x - p2.x).powi(2) + (p1.y - p2.y).powi(2)).sqrt();
            if dist < c1.radius + c2.radius {
                events.send(CollisionEvent {
                    entity_a: e1,
                    entity_b: e2,
                    impact_force: (c1.radius + c2.radius - dist),
                });
            }
        }
    }
}

fn handle_collisions(mut events: EventReader<CollisionEvent>) {
    for event in events.read() {
        println!("Collision! Force: {}", event.impact_force);
    }
}
```

## ⚠️ 6. Gotchas

### Gotcha 14.8.1 — WASM Limitations

- No direct filesystem access (use Web APIs via `web-sys`)
- No threads by default (SharedArrayBuffer + atomics required)
- No networking (use `fetch` via `web-sys` or `gloo-net`)
- Binary size matters — use `wasm-opt` and `opt-level = "s"`

### Gotcha 14.8.2 — FFI is Always Unsafe

```rust
// ALL FFI calls are unsafe — you're trusting external code
extern "C" {
    fn external_function(ptr: *mut u8, len: usize) -> i32;
}

// Wrap in a safe API:
pub fn safe_wrapper(data: &mut [u8]) -> Result<i32, &'static str> {
    let result = unsafe { external_function(data.as_mut_ptr(), data.len()) };
    if result < 0 {
        Err("External function failed")
    } else {
        Ok(result)
    }
}
```

### Gotcha 14.8.3 — Bevy's Rapid Evolution

Bevy is pre-1.0 and has breaking changes between minor versions. Pin your version:

```toml
[dependencies]
bevy = "0.15"  # Pin to specific version
```

Check migration guides: https://bevyengine.org/learn/migration-guides/

### Example 8.1 — WASM with wasm-bindgen: Interactive Canvas Application

**Problem:** Build a complete WASM module that renders a particle system on an HTML5 Canvas, demonstrating JS↔Rust interop, shared memory access, and performance-critical rendering loops.

<details>
<summary>🔍 Full step-by-step solution</summary>

```rust
// === src/lib.rs ===
use wasm_bindgen::prelude::*;
use web_sys::{CanvasRenderingContext2d, HtmlCanvasElement};

#[wasm_bindgen]
pub struct ParticleSystem {
    particles: Vec<Particle>,
    width: f64,
    height: f64,
    gravity: f64,
}

struct Particle {
    x: f64,
    y: f64,
    vx: f64,
    vy: f64,
    life: f64,
    max_life: f64,
    size: f64,
    color_r: u8,
    color_g: u8,
    color_b: u8,
}

#[wasm_bindgen]
impl ParticleSystem {
    #[wasm_bindgen(constructor)]
    pub fn new(width: f64, height: f64) -> Self {
        // Set panic hook for better error messages in browser console
        console_error_panic_hook::set_once();
        
        ParticleSystem {
            particles: Vec::with_capacity(10_000),
            width,
            height,
            gravity: 0.1,
        }
    }
    
    /// Spawn particles at a position (called from JS on mouse move)
    pub fn emit(&mut self, x: f64, y: f64, count: u32) {
        for _ in 0..count {
            let angle = js_sys::Math::random() * std::f64::consts::TAU;
            let speed = js_sys::Math::random() * 3.0 + 1.0;
            let life = js_sys::Math::random() * 60.0 + 30.0;
            
            self.particles.push(Particle {
                x,
                y,
                vx: angle.cos() * speed,
                vy: angle.sin() * speed - 2.0,
                life,
                max_life: life,
                size: js_sys::Math::random() * 4.0 + 1.0,
                color_r: (js_sys::Math::random() * 155.0 + 100.0) as u8,
                color_g: (js_sys::Math::random() * 100.0 + 50.0) as u8,
                color_b: (js_sys::Math::random() * 50.0) as u8,
            });
        }
    }
    
    /// Update physics (called every frame from JS requestAnimationFrame)
    pub fn update(&mut self) {
        for particle in &mut self.particles {
            particle.vy += self.gravity;
            particle.x += particle.vx;
            particle.y += particle.vy;
            particle.life -= 1.0;
            
            // Bounce off walls
            if particle.x < 0.0 || particle.x > self.width {
                particle.vx *= -0.8;
            }
            if particle.y > self.height {
                particle.vy *= -0.6;
                particle.y = self.height;
            }
        }
        
        // Remove dead particles
        self.particles.retain(|p| p.life > 0.0);
    }
    
    /// Render to canvas (direct DOM manipulation from Rust)
    pub fn render(&self, ctx: &CanvasRenderingContext2d) {
        ctx.clear_rect(0.0, 0.0, self.width, self.height);
        
        for particle in &self.particles {
            let alpha = (particle.life / particle.max_life).max(0.0);
            let color = format!(
                "rgba({}, {}, {}, {:.2})",
                particle.color_r, particle.color_g, particle.color_b, alpha
            );
            ctx.set_fill_style_str(&color);
            ctx.begin_path();
            ctx.arc(
                particle.x, particle.y,
                particle.size * alpha,
                0.0, std::f64::consts::TAU,
            ).unwrap();
            ctx.fill();
        }
    }
    
    /// Get particle count (for FPS display in JS)
    pub fn particle_count(&self) -> u32 {
        self.particles.len() as u32
    }
    
    /// Direct memory access for high-performance rendering
    /// Returns a pointer to particle positions for JS to read directly
    pub fn positions_ptr(&self) -> *const f64 {
        // Pack positions into a flat array for zero-copy JS access
        // In production, use a separate Vec<f64> for this
        self.particles.as_ptr() as *const f64
    }
}
```

### Example 8.2 — FFI ABI Considerations: Safe C Interop Layer

**Problem:** Wrap a C library (e.g., SQLite) with a safe Rust API. Handle memory ownership across the FFI boundary, string conversions, error codes, and callback functions.

<details>
<summary>🔍 Full step-by-step solution</summary>

```rust
use std::ffi::{CStr, CString};
use std::os::raw::{c_char, c_int, c_void};
use std::ptr;

// ============================================================
// RAW FFI BINDINGS (unsafe, low-level)
// ============================================================

// Opaque type (we never look inside — C owns the layout)
#[repr(C)]
pub struct SqliteDb {
    _private: [u8; 0],  // Zero-sized, opaque
}

#[repr(C)]
pub struct SqliteStmt {
    _private: [u8; 0],
}

// C function declarations
extern "C" {
    fn sqlite3_open(filename: *const c_char, db: *mut *mut SqliteDb) -> c_int;
    fn sqlite3_close(db: *mut SqliteDb) -> c_int;
    fn sqlite3_exec(
        db: *mut SqliteDb,
        sql: *const c_char,
        callback: Option<unsafe extern "C" fn(*mut c_void, c_int, *mut *mut c_char, *mut *mut c_char) -> c_int>,
        arg: *mut c_void,
        errmsg: *mut *mut c_char,
    ) -> c_int;
    fn sqlite3_errmsg(db: *mut SqliteDb) -> *const c_char;
    fn sqlite3_free(ptr: *mut c_void);
}

const SQLITE_OK: c_int = 0;

// ============================================================
// SAFE RUST WRAPPER
// ============================================================

#[derive(Debug, thiserror::Error)]
pub enum SqliteError {
    #[error("SQLite error ({code}): {message}")]
    Database { code: i32, message: String },
    
    #[error("Invalid UTF-8 in string: {0}")]
    InvalidString(#[from] std::ffi::NulError),
    
    #[error("Null pointer returned from SQLite")]
    NullPointer,
}

/// Safe wrapper around a SQLite database connection.
/// Automatically closes the connection on drop.
pub struct Database {
    db: *mut SqliteDb,
}

// SAFETY: SQLite with serialized threading mode is thread-safe
unsafe impl Send for Database {}

impl Database {
    /// Open a database file. Creates it if it doesn't exist.
    pub fn open(path: &str) -> Result<Self, SqliteError> {
        let c_path = CString::new(path)?;
        let mut db: *mut SqliteDb = ptr::null_mut();
        
        let rc = unsafe { sqlite3_open(c_path.as_ptr(), &mut db) };
        
        if rc != SQLITE_OK {
            let msg = if db.is_null() {
                "Failed to allocate database handle".to_string()
            } else {
                let err = unsafe { CStr::from_ptr(sqlite3_errmsg(db)) };
                let msg = err.to_string_lossy().into_owned();
                unsafe { sqlite3_close(db); }
                msg
            };
            return Err(SqliteError::Database { code: rc as i32, message: msg });
        }
        
        if db.is_null() {
            return Err(SqliteError::NullPointer);
        }
        
        Ok(Database { db })
    }
    
    /// Execute a SQL statement (no results).
    pub fn execute(&self, sql: &str) -> Result<(), SqliteError> {
        let c_sql = CString::new(sql)?;
        let mut errmsg: *mut c_char = ptr::null_mut();
        
        let rc = unsafe {
            sqlite3_exec(self.db, c_sql.as_ptr(), None, ptr::null_mut(), &mut errmsg)
        };
        
        if rc != SQLITE_OK {
            let message = if errmsg.is_null() {
                "Unknown error".to_string()
            } else {
                let msg = unsafe { CStr::from_ptr(errmsg) }
                    .to_string_lossy()
                    .into_owned();
                unsafe { sqlite3_free(errmsg as *mut c_void); }
                msg
            };
            return Err(SqliteError::Database { code: rc as i32, message });
        }
        
        Ok(())
    }
    
    /// Execute a query with a callback for each row.
    pub fn query<F>(&self, sql: &str, mut callback: F) -> Result<(), SqliteError>
    where
        F: FnMut(&[(&str, &str)]) -> bool,
    {
        let c_sql = CString::new(sql)?;
        let mut errmsg: *mut c_char = ptr::null_mut();
        
        // Box the closure and pass as void pointer to C
        let callback_ptr: *mut c_void = &mut callback as *mut F as *mut c_void;
        
        // The C callback that bridges to our Rust closure
        unsafe extern "C" fn c_callback<F: FnMut(&[(&str, &str)]) -> bool>(
            arg: *mut c_void,
            argc: c_int,
            argv: *mut *mut c_char,
            col_names: *mut *mut c_char,
        ) -> c_int {
            let closure = &mut *(arg as *mut F);
            
            let mut row = Vec::with_capacity(argc as usize);
            for i in 0..argc as isize {
                let col = CStr::from_ptr(*col_names.offset(i)).to_str().unwrap_or("");
                let val = if (*argv.offset(i)).is_null() {
                    "NULL"
                } else {
                    CStr::from_ptr(*argv.offset(i)).to_str().unwrap_or("")
                };
                row.push((col, val));
            }
            
            if closure(&row) { 0 } else { 1 }  // 0 = continue, 1 = abort
        }
        
        let rc = unsafe {
            sqlite3_exec(
                self.db,
                c_sql.as_ptr(),
                Some(c_callback::<F>),
                callback_ptr,
                &mut errmsg,
            )
        };
        
        if rc != SQLITE_OK && rc != 4 /* SQLITE_ABORT */ {
            let message = if errmsg.is_null() {
                "Unknown error".to_string()
            } else {
                let msg = unsafe { CStr::from_ptr(errmsg) }.to_string_lossy().into_owned();
                unsafe { sqlite3_free(errmsg as *mut c_void); }
                msg
            };
            return Err(SqliteError::Database { code: rc as i32, message });
        }
        
        Ok(())
    }
}

/// RAII: Close database on drop
impl Drop for Database {
    fn drop(&mut self) {
        if !self.db.is_null() {
            unsafe { sqlite3_close(self.db); }
        }
    }
}

// === Usage ===
fn demo() -> Result<(), SqliteError> {
    let db = Database::open(":memory:")?;
    
    db.execute("CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT)")?;
    db.execute("INSERT INTO users (name) VALUES ('Alice'), ('Bob')")?;
    
    db.query("SELECT * FROM users", |row| {
        println!("Row: {:?}", row);
        true  // continue
    })?;
    
    Ok(())
}
```

```rust
// version = "0.1.0"

// [dependencies]
// cortex-m = "0.7"

#![no_main]

use rtic::app;
use stm32f4xx_hal::{
    gpio::{Output, PushPull, Input, PullUp, Edge, PA5, PC13},
    i2c::I2c,
    pac,
    prelude::*,
    timer::MonoTimerUs,
};

// Temperature sensor (TMP102) I2C address
const TMP102_ADDR: u8 = 0x48;

#[app(device = pac, peripherals = true, dispatchers = [SPI1])]
mod app {
    use super::*;
    
    #[shared]
    struct Shared {
        temperature: f32,
        alarm_active: bool,
    }
    
    #[local]
    struct Local {
        led: PA5<Output<PushPull>>,
        button: PC13<Input<PullUp>>,
        i2c: I2c<pac::I2C1>,
    }
    
    #[init]
    fn init(ctx: init::Context) -> (Shared, Local) {
        // Configure clocks
        let rcc = ctx.device.RCC.constrain();
        let clocks = rcc.cfgr.sysclk(84.MHz()).freeze();
        
        // Configure GPIO
        let gpioa = ctx.device.GPIOA.split();
        let gpiob = ctx.device.GPIOB.split();
        let gpioc = ctx.device.GPIOC.split();
        
        // LED on PA5
        let led = gpioa.pa5.into_push_pull_output();
        
        // Button on PC13 with interrupt
        let mut button = gpioc.pc13.into_pull_up_input();
        let mut syscfg = ctx.device.SYSCFG.constrain();
        button.make_interrupt_source(&mut syscfg);
        button.enable_interrupt(&mut ctx.device.EXTI);
        button.trigger_on_edge(&mut ctx.device.EXTI, Edge::Falling);
        
        // I2C for temperature sensor
        let scl = gpiob.pb6.into_alternate_open_drain();
        let sda = gpiob.pb7.into_alternate_open_drain();
        let i2c = I2c::new(ctx.device.I2C1, (scl, sda), 100.kHz(), &clocks);
        
        // Start periodic temperature reading
        read_temperature::spawn().ok();
        
        defmt::info!("System initialized");
        
        (
            Shared { temperature: 0.0, alarm_active: false },
            Local { led, button, i2c },
        )
    }
    
    /// Periodic task: read temperature every 500ms
    #[task(local = [i2c], shared = [temperature, alarm_active], priority = 1)]
    async fn read_temperature(mut ctx: read_temperature::Context) {
        loop {
            // Read 2 bytes from TMP102
            let mut buf = [0u8; 2];
            if ctx.local.i2c.write_read(TMP102_ADDR, &[0x00], &mut buf).is_ok() {
                // Convert raw bytes to temperature (TMP102 format)
                let raw = ((buf[0] as i16) << 4) | ((buf[1] as i16) >> 4);
                let temp = raw as f32 * 0.0625;
                
                ctx.shared.temperature.lock(|t| *t = temp);
                
                // Check alarm threshold
                let alarm = temp > 30.0;
                ctx.shared.alarm_active.lock(|a| *a = alarm);
                
                if alarm {
                    defmt::warn!("Temperature alarm: {:.1}°C", temp);
                    blink_fast::spawn().ok();
                }
                
                defmt::info!("Temperature: {:.1}°C", temp);
            }
            
            // Wait 500ms before next reading
            Mono::delay(500.millis()).await;
        }
    }
    
    /// Fast blink when alarm is active
    #[task(local = [led], shared = [alarm_active], priority = 2)]
    async fn blink_fast(mut ctx: blink_fast::Context) {
        while ctx.shared.alarm_active.lock(|a| *a) {
            ctx.local.led.toggle();
            Mono::delay(100.millis()).await;
        }
        ctx.local.led.set_low();  // LED off when alarm clears
    }
    
    /// Button interrupt: toggle alarm acknowledgment
    #[task(binds = EXTI15_10, local = [button], shared = [alarm_active])]
    fn button_pressed(mut ctx: button_pressed::Context) {
        ctx.local.button.clear_interrupt_pending_bit();
        
        // Acknowledge alarm
        ctx.shared.alarm_active.lock(|a| *a = false);
        defmt::info!("Alarm acknowledged");
    }
}
```

### 9.1 panic = abort vs unwind: Binary Size and Performance Tradeoffs

When a Rust program panics, there are two possible behaviors controlled by the `panic` setting in `Cargo.toml`:

**panic = "unwind" (default):**

The stack is unwound frame by frame, running destructors (`Drop` impls) for each local variable. This is similar to C++ exception unwinding.

- **Pros**: Destructors run (RAII cleanup), `catch_unwind()` works, threads can recover
- **Cons**: Larger binary (~10-20% more code for unwind tables), slight runtime overhead
- **Use for**: Libraries, applications where graceful recovery matters

**panic = "abort":**

The process immediately terminates. No destructors run, no stack unwinding.

- **Pros**: Smaller binary (no unwind tables), faster panics, simpler codegen
- **Cons**: No cleanup on panic, `catch_unwind()` is a no-op, threads can't recover
- **Use for**: Embedded systems, WASM, size-optimized binaries, when panics = bugs

```toml
# Cargo.toml
[profile.release]
panic = "abort"     # Smaller binary, no unwind overhead
# panic = "unwind"  # Default: destructors run on panic
```

**Size impact (real-world example):**

```
                    unwind      abort       savings
Simple CLI:         1.2 MB      0.9 MB      25%
Web server:         8.5 MB      7.1 MB      16%
WASM module:        180 KB      120 KB      33%
Embedded firmware:  48 KB       32 KB       33%
```

**When destructors matter:**

```rust
struct TempFile { path: String }

impl Drop for TempFile {
    fn drop(&mut self) {
        std::fs::remove_file(&self.path).ok();
        // With panic=abort, this NEVER runs on panic
        // Temp files leak!
    }
}

// With panic=unwind: temp file is cleaned up even on panic
// With panic=abort: temp file leaks if the program panics
```

**The `catch_unwind` escape hatch:**

```rust
use std::panic;

// Only works with panic=unwind
let result = panic::catch_unwind(|| {
    // Code that might panic
    risky_operation();
});

match result {
    Ok(value) => println!("Success: {value:?}"),
    Err(_) => println!("Caught a panic!"),
}

// Use cases for catch_unwind:
// - FFI boundaries (don't let panics cross into C code)
// - Thread pools (one task panicking shouldn't kill the pool)
// - Plugin systems (isolate plugin panics)
```

### 9.2 std vs core vs alloc: The Three Standard Libraries

Rust actually has three "standard libraries" that form a hierarchy:

```
┌─────────────────────────────────────────────┐
│  std (full standard library)                 │
│  - Requires OS (threads, filesystem, network)│
│  - Includes everything from core and alloc   │
│  - Default for normal Rust programs          │
├─────────────────────────────────────────────┤
│  alloc (heap allocation)                     │
│  - Requires a memory allocator               │
│  - Vec, String, Box, Rc, Arc, BTreeMap       │
│  - No OS required (just malloc/free)         │
├─────────────────────────────────────────────┤
│  core (no dependencies)                      │
│  - No OS, no allocator, no nothing           │
│  - Primitives, Option, Result, Iterator      │
│  - Slices, arrays, math, formatting traits   │
│  - Used for embedded/kernel/bootloader code  │
└─────────────────────────────────────────────┘
```

**Using each level:**

```rust
// === Full std (normal programs) ===
use std::collections::HashMap;
use std::fs::File;
use std::net::TcpStream;
use std::thread;

// === no_std + alloc (OS-free but has heap) ===
#![no_std]
extern crate alloc;

use alloc::vec::Vec;
use alloc::string::String;
use alloc::boxed::Box;
use core::fmt;

// Must provide a global allocator:
#[global_allocator]
static ALLOCATOR: MyAllocator = MyAllocator;

// === no_std, no alloc (bare metal) ===
#![no_std]
#![no_main]

use core::panic::PanicInfo;

#[panic_handler]
fn panic(_info: &PanicInfo) -> ! {
    loop {}  // Hang on panic (embedded)
}

// Only core types available:
// - Primitives (u8, i32, f64, bool, char)
// - Option<T>, Result<T, E>
// - Slices (&[T], &str)
// - Arrays ([T; N])
// - Iterator trait and combinators
// - fmt::Write (for no-alloc formatting)
// - Atomic types
// - PhantomData, Pin
```

**What you lose without std:**

| Feature | std | alloc | core |
|---------|-----|-------|------|
| Vec, String, Box | ✅ | ✅ | ❌ |
| HashMap, BTreeMap | ✅ | ✅ (BTree only) | ❌ |
| File I/O | ✅ | ❌ | ❌ |
| Networking | ✅ | ❌ | ❌ |
| Threads | ✅ | ❌ | ❌ |
| println! | ✅ | ❌ | ❌ |
| Random numbers | ✅ | ❌ | ❌ |
| Time/Duration | ✅ | ❌ | ❌ |
| Option, Result | ✅ | ✅ | ✅ |
| Iterator | ✅ | ✅ | ✅ |
| Formatting traits | ✅ | ✅ | ✅ |
| Atomic types | ✅ | ✅ | ✅ |

### 9.3 Tauri vs Egui for Desktop Applications

Both Tauri and Egui let you build desktop applications in Rust, but with fundamentally different architectures:

**Tauri (web-based UI, Rust backend):**

```
Architecture:
┌──────────────────────────────────┐
│  Frontend (HTML/CSS/JS/React)    │  ← Web technologies for UI
├──────────────────────────────────┤
│  WebView (system browser engine) │  ← OS-provided (not Electron's Chromium)
├──────────────────────────────────┤
│  Rust Backend (tauri core)       │  ← Business logic, file I/O, system access
└──────────────────────────────────┘

Pros:
- Familiar web UI (React, Vue, Svelte, etc.)
- Small binary (~3-10MB vs Electron's 100MB+)
- Uses system WebView (no bundled Chromium)
- Full system access from Rust backend
- Cross-platform (Windows, macOS, Linux, mobile)

Cons:
- Two languages (JS frontend + Rust backend)
- WebView rendering differences across platforms
- IPC overhead between frontend and backend
- Web UI limitations (no native widgets)
```

**Egui (immediate-mode GUI, pure Rust):**

```
Architecture:
┌──────────────────────────────────┐
│  Egui (immediate-mode UI)        │  ← Pure Rust, redraws every frame
├──────────────────────────────────┤
│  eframe/winit (window management)│  ← Cross-platform windowing
├──────────────────────────────────┤
│  wgpu/glow (GPU rendering)       │  ← Hardware-accelerated rendering
└──────────────────────────────────┘

Pros:
- 100% Rust (single language, single binary)
- Immediate mode: simple mental model (no state sync)
- Very fast iteration (hot reload with egui)
- Works on WASM (runs in browser too)
- Great for tools, debug UIs, data visualization

Cons:
- Not native-looking (custom rendered widgets)
- Redraws entire UI every frame (GPU usage when idle)
- Less mature ecosystem than web UI
- Limited text editing, accessibility
- No CSS — layout is code-based
```

**Decision guide:**

| Criterion | Choose Tauri | Choose Egui |
|-----------|-------------|-------------|
| UI complexity | Rich, styled UI | Simple tools/dashboards |
| Team skills | Web developers available | Rust-only team |
| Native look | Important | Not important |
| Binary size | ~5MB acceptable | Want smallest possible |
| Platform | Need mobile too | Desktop + WASM |
| Performance | UI is simple, backend is complex | UI needs 60fps (visualizations) |
| Accessibility | Required | Not critical |

### 9.4 Bevy ECS Architecture: Why Data-Oriented Design Wins

Bevy's Entity Component System is built on **data-oriented design** principles that maximize cache performance and enable automatic parallelism.

**Traditional OOP (Unity-style):**

```
GameObject
├── Transform
├── MeshRenderer
├── RigidBody
└── PlayerController (script)

// Problem: Each GameObject is a heap allocation.
// Iterating over "all things with Transform + RigidBody" requires
// chasing pointers across the heap → cache misses everywhere.
```

**Bevy's ECS (data-oriented):**

```
Archetype Table: [Transform, Velocity, Health]
┌─────────────┬─────────────┬─────────────┐
│ Transform 0 │ Velocity 0  │ Health 0    │  Entity 0
│ Transform 1 │ Velocity 1  │ Health 1    │  Entity 1
│ Transform 2 │ Velocity 2  │ Health 2    │  Entity 2
│ ...         │ ...         │ ...         │
└─────────────┴─────────────┴─────────────┘

// Components of the same type are stored CONTIGUOUSLY in memory.
// Iterating over all Transforms is a linear memory scan → cache-friendly.
// The CPU prefetcher loves this pattern.
```

**Archetype-based storage:**

Bevy groups entities by their **archetype** — the set of components they have. All entities with the same component set are stored together in a table.

```rust
// These two entities have the SAME archetype: (Transform, Velocity, Health)
commands.spawn((Transform::default(), Velocity(1.0), Health(100.0)));
commands.spawn((Transform::default(), Velocity(2.0), Health(50.0)));

// This entity has a DIFFERENT archetype: (Transform, Velocity)
commands.spawn((Transform::default(), Velocity(3.0)));

// Bevy stores them in separate tables:
// Table 1: [Transform, Velocity, Health] — 2 entities
// Table 2: [Transform, Velocity] — 1 entity
```

**Automatic system parallelism:**

Bevy analyzes system signatures at startup and determines which systems can run in parallel:

```rust
// These systems access DIFFERENT components → run in PARALLEL automatically
fn movement(query: Query<(&mut Transform, &Velocity)>) { /* ... */ }
fn damage(query: Query<&mut Health, With<Enemy>>) { /* ... */ }

// These systems CONFLICT (both access &mut Transform) → run SEQUENTIALLY
fn movement(query: Query<&mut Transform, With<Player>>) { /* ... */ }
fn gravity(query: Query<&mut Transform, With<RigidBody>>) { /* ... */ }
// (Unless the queries are disjoint via With/Without filters)
```

**Performance comparison (10,000 entities):**

```
Traditional OOP (virtual dispatch, scattered memory):
  Update loop: ~2.5ms per frame

Bevy ECS (data-oriented, contiguous memory):
  Update loop: ~0.3ms per frame

Speedup: ~8x (primarily from cache efficiency)
```

The ECS pattern is why Bevy can handle hundreds of thousands of entities at 60fps — it's not just good API design, it's fundamentally better memory access patterns.
