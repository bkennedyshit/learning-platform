# 11.4 — Error Handling: Result, Option & the ? Operator

> *"Rust doesn't have exceptions. It has values."* — Aaron Turon

Python uses `try/except` — errors are invisible in function signatures and can propagate silently. Rust makes errors **explicit in the type system**. If a function can fail, its return type says so. If you don't handle the error, your code won't compile.

This isn't bureaucracy — it's a guarantee that every failure path is accounted for.

---

## 🎯 Learning Objectives

By the end of this chapter you will be able to:

1. Use `Result<T, E>` and `Option<T>` for fallible operations.
2. Propagate errors ergonomically with the `?` operator.
3. Define custom error types with `thiserror`.
4. Use `anyhow` for application-level error handling.
5. Know when to `panic!` vs return `Result`.
6. Chain error transformations with `map`, `and_then`, `unwrap_or_else`.

## 📚 1. Concepts

### Concept 14.4.1 — Result<T, E>

```rust
enum Result<T, E> {
    Ok(T),   // Success — contains the value
    Err(E),  // Failure — contains the error
}
```

Every function that can fail returns `Result`:

```rust
use std::fs;
use std::io;

fn read_config(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)  // Returns Result<String, io::Error>
}

fn main() {
    match read_config("config.toml") {
        Ok(contents) => println!("Config: {contents}"),
        Err(e) => eprintln!("Failed to read config: {e}"),
    }
}
```

### Concept 14.4.2 — Option<T> (Absence, Not Failure)

```rust
enum Option<T> {
    Some(T),  // Value present
    None,     // Value absent
}
```

Use `Option` when absence is **normal**, not an error:

```rust
fn find_user(users: &[User], name: &str) -> Option<&User> {
    users.iter().find(|u| u.name == name)
}

// Option vs Result:
// Option: "might not exist" (HashMap::get, Vec::first, str::find)
// Result: "might fail" (file I/O, network, parsing)
```

### Concept 14.4.3 — The ? Operator (Early Return on Error)

`?` is syntactic sugar for "if this is Err, return the error immediately":

```rust
// Without ?:
fn read_username_verbose(path: &str) -> Result<String, io::Error> {
    let contents = match fs::read_to_string(path) {
        Ok(c) => c,
        Err(e) => return Err(e),
    };
    Ok(contents.trim().to_string())
}

// With ?:
fn read_username(path: &str) -> Result<String, io::Error> {
    let contents = fs::read_to_string(path)?;  // Returns Err early if fails
    Ok(contents.trim().to_string())
}

// Chain multiple fallible operations:
fn setup_database(config_path: &str) -> Result<Database, AppError> {
    let config_str = fs::read_to_string(config_path)?;
    let config: DbConfig = toml::from_str(&config_str)?;
    let connection = Database::connect(&config.url)?;
    connection.run_migrations()?;
    Ok(connection)
}
```

### Concept 14.4.4 — panic! vs Result

| Use `panic!` when... | Use `Result` when... |
|---------------------|---------------------|
| Bug in your code (invariant violated) | Expected failure (file not found, network timeout) |
| Unrecoverable state | Caller can handle or retry |
| Tests and prototypes | Library code (let caller decide) |
| `unwrap()` on values you've already validated | Any I/O, parsing, or user input |

```rust
// panic! — programmer error, should never happen in correct code
fn get_element(slice: &[i32], index: usize) -> i32 {
    assert!(index < slice.len(), "index out of bounds: bug in caller");
    slice[index]
}

// Result — expected failure, caller handles it
fn parse_port(s: &str) -> Result<u16, std::num::ParseIntError> {
    s.parse::<u16>()
}
```

## 📐 2. Mental Models

### Model 14.4.1 — Errors as Railway Tracks

Think of `Result` as a **railway switch**:
- The "happy path" (Ok track) flows forward
- The "error path" (Err track) diverts to error handling
- `?` is a switch that diverts to the error track on failure
- `map`, `and_then` operate only on the Ok track

```rust
fn process_order(order_id: &str) -> Result<Receipt, OrderError> {
    let order = fetch_order(order_id)?;        // Switch to Err track if fails
    let validated = validate_order(order)?;     // Switch to Err track if fails
    let charged = charge_payment(validated)?;   // Switch to Err track if fails
    let receipt = generate_receipt(charged)?;   // Switch to Err track if fails
    Ok(receipt)                                 // Stay on Ok track
}
// If ANY step fails, the function returns immediately with that error.
// No nested try/except blocks. No forgotten error paths.
```

### Model 14.4.2 — Option as a Null-Safe Pipeline

```rust
// Python: user.get("address", {}).get("city", "Unknown")
// Rust: method chaining with Option

fn get_city(user: &User) -> &str {
    user.address
        .as_ref()                      // Option<&Address>
        .map(|a| a.city.as_str())      // Option<&str>
        .unwrap_or("Unknown")          // &str (with default)
}
```

## 🔑 3. Mechanics

### 3.1 — Combinators on Result and Option

```rust
// map: transform the Ok/Some value
let length: Result<usize, _> = fs::read_to_string("file.txt").map(|s| s.len());

// and_then (flatmap): chain fallible operations
let port: Result<u16, _> = std::env::var("PORT")
    .map_err(|_| "PORT not set")
    .and_then(|s| s.parse::<u16>().map_err(|_| "PORT not a number"));

// unwrap_or: provide default on error
let port: u16 = std::env::var("PORT")
    .ok()                          // Result -> Option (discards error)
    .and_then(|s| s.parse().ok())  // Option<u16>
    .unwrap_or(8080);              // u16 with default

// unwrap_or_else: lazy default (only computed on error)
let config = load_config().unwrap_or_else(|e| {
    eprintln!("Config error: {e}, using defaults");
    Config::default()
});

// ok_or / ok_or_else: Option -> Result
fn find_user(id: u64) -> Option<User> { None }
let user: Result<User, AppError> = find_user(42)
    .ok_or(AppError::NotFound("user 42".into()));
```

### 3.2 — Custom Error Types with `thiserror`

```rust
use thiserror::Error;

#[derive(Error, Debug)]
enum AppError {
    #[error("Database error: {0}")]
    Database(#[from] sqlx::Error),

    #[error("Configuration error: {0}")]
    Config(#[from] toml::de::Error),

    #[error("IO error: {0}")]
    Io(#[from] std::io::Error),

    #[error("Validation failed: {field} - {message}")]
    Validation { field: String, message: String },

    #[error("Not found: {0}")]
    NotFound(String),
}

// #[from] auto-generates From<sqlx::Error> for AppError
// This means ? automatically converts sqlx::Error -> AppError

fn load_user(id: u64) -> Result<User, AppError> {
    let config = fs::read_to_string("db.toml")?;  // io::Error -> AppError::Io
    let db_config: DbConfig = toml::from_str(&config)?;  // toml::Error -> AppError::Config
    let user = db.query_user(id)?;  // sqlx::Error -> AppError::Database
    Ok(user)
}
```

### 3.3 — Application-Level Errors with `anyhow`

For binaries (not libraries), `anyhow` provides ergonomic error handling without defining custom types:

```rust
use anyhow::{Context, Result, bail, ensure};

fn main() -> Result<()> {
    let config_path = std::env::args().nth(1)
        .context("Usage: app <config-path>")?;

    let config = fs::read_to_string(&config_path)
        .with_context(|| format!("Failed to read config from {config_path}"))?;

    let port: u16 = config.parse()
        .context("Config must be a valid port number")?;

    ensure!(port > 1024, "Port must be > 1024, got {port}");

    if port == 6666 {
        bail!("Refusing to use port 6666");  // Early return with error
    }

    start_server(port)?;
    Ok(())
}
```

**Rule of thumb:**
- **Libraries**: Use `thiserror` (callers need to match on specific error variants)
- **Applications**: Use `anyhow` (just need to display errors to users)

### 3.4 — The ? Operator with Type Conversion

`?` calls `From::from()` on the error, enabling automatic conversion:

```rust
use std::num::ParseIntError;
use std::io;

#[derive(Debug)]
enum MyError {
    Io(io::Error),
    Parse(ParseIntError),
}

impl From<io::Error> for MyError {
    fn from(e: io::Error) -> Self { MyError::Io(e) }
}

impl From<ParseIntError> for MyError {
    fn from(e: ParseIntError) -> Self { MyError::Parse(e) }
}

fn read_number(path: &str) -> Result<i64, MyError> {
    let contents = fs::read_to_string(path)?;  // io::Error -> MyError via From
    let number = contents.trim().parse::<i64>()?;  // ParseIntError -> MyError via From
    Ok(number)
}
```

### 3.5 — Collecting Results

```rust
// Convert Vec<Result<T, E>> -> Result<Vec<T>, E>
// (Fails on first error)
let numbers: Result<Vec<i32>, _> = vec!["1", "2", "three", "4"]
    .iter()
    .map(|s| s.parse::<i32>())
    .collect();
// Err(ParseIntError { kind: InvalidDigit })

// Partition into successes and failures:
let (successes, failures): (Vec<_>, Vec<_>) = vec!["1", "2", "three", "4"]
    .iter()
    .map(|s| s.parse::<i32>())
    .partition(Result::is_ok);

let numbers: Vec<i32> = successes.into_iter().map(Result::unwrap).collect();
let errors: Vec<_> = failures.into_iter().map(Result::unwrap_err).collect();
```

### 3.6 — Error Handling in main()

```rust
// Option 1: Return Result from main (prints error on failure)
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let contents = fs::read_to_string("config.toml")?;
    println!("{contents}");
    Ok(())
}

// Option 2: anyhow for better error messages
fn main() -> anyhow::Result<()> {
    let contents = fs::read_to_string("config.toml")
        .context("Failed to read configuration file")?;
    println!("{contents}");
    Ok(())
}

// Option 3: Handle errors explicitly in main
fn main() {
    if let Err(e) = run() {
        eprintln!("Error: {e:#}");  // {:#} shows full error chain with anyhow
        std::process::exit(1);
    }
}

fn run() -> anyhow::Result<()> {
    // ... actual logic here
    Ok(())
}
```

## 💡 4. Worked Examples

### Example 11.4.1 — Config File Parser

```rust
use std::collections::HashMap;
use std::fs;
use thiserror::Error;

#[derive(Error, Debug)]
enum ConfigError {
    #[error("Failed to read config file: {0}")]
    ReadError(#[from] std::io::Error),

    #[error("Invalid config format at line {line}: {message}")]
    ParseError { line: usize, message: String },

    #[error("Missing required key: {0}")]
    MissingKey(String),
}

type Config = HashMap<String, String>;

fn parse_config(path: &str) -> Result<Config, ConfigError> {
    let contents = fs::read_to_string(path)?;

    let mut config = HashMap::new();

    for (i, line) in contents.lines().enumerate() {
        let line = line.trim();
        if line.is_empty() || line.starts_with('#') {
            continue;
        }

        let (key, value) = line.split_once('=').ok_or_else(|| {
            ConfigError::ParseError {
                line: i + 1,
                message: format!("Expected KEY=VALUE, got: {line}"),
            }
        })?;

        config.insert(key.trim().to_string(), value.trim().to_string());
    }

    Ok(config)
}

fn get_required<'a>(config: &'a Config, key: &str) -> Result<&'a str, ConfigError> {
    config.get(key)
        .map(|s| s.as_str())
        .ok_or_else(|| ConfigError::MissingKey(key.to_string()))
}

fn main() -> Result<(), ConfigError> {
    let config = parse_config("app.conf")?;
    let host = get_required(&config, "host")?;
    let port = get_required(&config, "port")?;
    println!("Server: {host}:{port}");
    Ok(())
}
```

### Example 11.4.2 — Retry Logic with Result

```rust
use std::time::Duration;
use std::thread;

fn retry<T, E, F>(mut operation: F, max_attempts: u32, delay: Duration) -> Result<T, E>
where
    F: FnMut() -> Result<T, E>,
    E: std::fmt::Display,
{
    let mut last_error = None;

    for attempt in 1..=max_attempts {
        match operation() {
            Ok(value) => return Ok(value),
            Err(e) => {
                eprintln!("Attempt {attempt}/{max_attempts} failed: {e}");
                last_error = Some(e);
                if attempt < max_attempts {
                    thread::sleep(delay);
                }
            }
        }
    }

    Err(last_error.unwrap())
}
```

### Example 11.4.3 — Builder Pattern with Validation

```rust
use thiserror::Error;

#[derive(Error, Debug)]
enum BuildError {
    #[error("Missing required field: {0}")]
    MissingField(&'static str),

    #[error("Invalid value for {field}: {message}")]
    InvalidValue { field: &'static str, message: String },
}

struct ServerConfig {
    host: String,
    port: u16,
    max_connections: u32,
}

struct ServerConfigBuilder {
    host: Option<String>,
    port: Option<u16>,
    max_connections: Option<u32>,
}

impl ServerConfigBuilder {
    fn new() -> Self {
        Self { host: None, port: None, max_connections: None }
    }

    fn host(mut self, host: impl Into<String>) -> Self {
        self.host = Some(host.into());
        self
    }

    fn port(mut self, port: u16) -> Self {
        self.port = Some(port);
        self
    }

    fn max_connections(mut self, n: u32) -> Self {
        self.max_connections = Some(n);
        self
    }

    fn build(self) -> Result<ServerConfig, BuildError> {
        let host = self.host.ok_or(BuildError::MissingField("host"))?;
        let port = self.port.ok_or(BuildError::MissingField("port"))?;

        if port == 0 {
            return Err(BuildError::InvalidValue {
                field: "port",
                message: "port must be non-zero".into(),
            });
        }

        Ok(ServerConfig {
            host,
            port,
            max_connections: self.max_connections.unwrap_or(100),
        })
    }
}
```

## ⚠️ 5. Gotchas & Common Mistakes

### Gotcha 14.4.1 — Don't unwrap() in Production

```rust
// These will panic on failure:
let file = fs::read_to_string("config.toml").unwrap();       // BAD
let port: u16 = "8080".parse().unwrap();                     // BAD

// Handle the error:
let file = fs::read_to_string("config.toml")?;              // GOOD
let port: u16 = "8080".parse().unwrap_or(8080);             // GOOD

// unwrap() is acceptable in:
// - Tests (test will fail with a clear message)
// - Cases where you've already validated (with expect() explaining why)
let validated_port: u16 = port_string.parse()
    .expect("port was validated by regex on line 42");  // Documents the invariant
```

### Gotcha 14.4.2 — ? Only Works in Functions Returning Result/Option

```rust
// Can't use ? in main() without the right return type:
// fn main() {
//     let contents = fs::read_to_string("file.txt")?;  // ERROR: main returns ()
// }

// Fix: change main's return type
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let contents = fs::read_to_string("file.txt")?;
    Ok(())
}
```

### Gotcha 14.4.3 — Error Type Mismatch with ?

```rust
// Different error types — ? can't convert automatically without From impls:
// fn broken() -> Result<(), std::io::Error> {
//     let s = fs::read_to_string("file.txt")?;  // OK: io::Error
//     let n: i32 = s.parse()?;  // ERROR: ParseIntError != io::Error
//     Ok(())
// }

// Fix 1: Use Box<dyn Error> (quick and dirty)
fn fixed_box() -> Result<(), Box<dyn std::error::Error>> {
    let s = fs::read_to_string("file.txt")?;
    let n: i32 = s.parse()?;
    Ok(())
}

// Fix 2: Use anyhow (better for applications)
fn fixed_anyhow() -> anyhow::Result<()> {
    let s = fs::read_to_string("file.txt")?;
    let n: i32 = s.parse()?;
    Ok(())
}
```

### Example 8.1 — thiserror vs anyhow vs eyre: Complete Comparison

**Problem:** You're building a system with both a library crate (consumed by other Rust code) and a binary crate (user-facing CLI). Demonstrate the correct error handling strategy for each, including error context, downcasting, and display formatting.

<details>
<summary>🔍 Full step-by-step solution</summary>

```rust
// ============================================================
// LIBRARY CRATE: Use `thiserror` for structured, matchable errors
// ============================================================

// === lib.rs (the library) ===
use thiserror::Error;
use std::path::PathBuf;

/// All errors that can occur in the database layer.
/// Consumers can match on specific variants.
#[derive(Error, Debug)]
pub enum DatabaseError {
    #[error("Connection failed to {host}:{port}: {source}")]
    ConnectionFailed {
        host: String,
        port: u16,
        #[source]  // Sets the source() method for error chaining
        source: std::io::Error,
    },
    
    #[error("Query failed: {query}")]
    QueryFailed {
        query: String,
        #[source]
        source: SqlError,
    },
    
    #[error("Migration {version} failed: {reason}")]
    MigrationFailed {
        version: u32,
        reason: String,
    },
    
    #[error("Connection pool exhausted (max: {max_connections})")]
    PoolExhausted { max_connections: u32 },
    
    #[error(transparent)]  // Delegates Display and source() to the inner error
    Io(#[from] std::io::Error),
}

/// SQL-specific errors (nested error type)
#[derive(Error, Debug)]
pub enum SqlError {
    #[error("Syntax error at position {position}: {message}")]
    Syntax { position: usize, message: String },
    
    #[error("Constraint violation: {0}")]
    Constraint(String),
    
    #[error("Timeout after {0:?}")]
    Timeout(std::time::Duration),
}

/// The library's public API returns structured errors
pub fn connect(host: &str, port: u16) -> Result<Connection, DatabaseError> {
    let stream = std::net::TcpStream::connect(format!("{host}:{port}"))
        .map_err(|source| DatabaseError::ConnectionFailed {
            host: host.to_string(),
            port,
            source,
        })?;
    Ok(Connection { stream })
}

pub struct Connection {
    stream: std::net::TcpStream,
}

// ============================================================
// BINARY CRATE: Use `anyhow` for ergonomic error reporting
// ============================================================

// === main.rs (the binary) ===
use anyhow::{Context, Result, bail, ensure};
// Note: anyhow::Result<T> = Result<T, anyhow::Error>

fn main() -> Result<()> {
    let config = load_config()
        .context("Failed to initialize application")?;
    
    run_server(config)
}

fn load_config() -> Result<AppConfig> {
    let path = std::env::var("CONFIG_PATH")
        .context("CONFIG_PATH environment variable not set")?;
    
    let contents = std::fs::read_to_string(&path)
        .with_context(|| format!("Failed to read config file: {path}"))?;
    
    let config: AppConfig = toml::from_str(&contents)
        .with_context(|| format!("Failed to parse config file: {path}"))?;
    
    ensure!(config.port > 0, "Port must be positive, got {}", config.port);
    ensure!(config.port < 65536, "Port must be < 65536, got {}", config.port);
    
    if config.host.is_empty() {
        bail!("Host cannot be empty");
    }
    
    Ok(config)
}

fn run_server(config: AppConfig) -> Result<()> {
    // anyhow automatically converts any Error type via From
    let conn = my_db_lib::connect(&config.host, config.port as u16)
        .context("Database connection failed during startup")?;
    
    // Downcast to inspect specific error types when needed:
    match my_db_lib::connect("bad-host", 0) {
        Err(e) => {
            // Try to downcast the anyhow::Error to our specific type
            if let Some(db_err) = e.downcast_ref::<DatabaseError>() {
                match db_err {
                    DatabaseError::PoolExhausted { max_connections } => {
                        eprintln!("Pool full ({max_connections}), retrying...");
                    }
                    _ => return Err(e.context("Unrecoverable database error")),
                }
            }
        }
        Ok(_) => {}
    }
    
    Ok(())
}

#[derive(serde::Deserialize)]
struct AppConfig {
    host: String,
    port: u32,
}

// ============================================================
// ALTERNATIVE: `eyre` for even richer error reports
// ============================================================

// eyre is a fork of anyhow with customizable error reporters.
// The `color-eyre` reporter adds:
// - Colored terminal output
// - Span traces (like backtraces but for logical operations)
// - Suggestion sections ("help: did you mean...?")

// use color_eyre::eyre::{Result, WrapErr};

// fn main() -> Result<()> {
//     color_eyre::install()?;  // Install the fancy reporter
//

//         .suggestion("Check that CONFIG_PATH is set correctly")?;
//     
//     Ok(())

// ============================================================
// DECISION GUIDE
// ============================================================
//
// Use thiserror when:
//   - You're writing a LIBRARY
//   - Callers need to MATCH on specific error variants
//   - You want structured errors with typed fields
//   - You need From conversions for ? operator
//
// Use anyhow when:
//   - You're writing an APPLICATION (binary)
//   - You just need to display errors to users
//   - You want .context() for adding human-readable messages
//   - You don't need callers to match on error types
//
// Use eyre/color-eyre when:
//   - You want anyhow's ergonomics + prettier output
//   - You want span traces for debugging
//   - You're building a CLI tool with rich error display
```

### Example 8.2 — Result Combinator Chains: Real-World Data Pipeline

**Problem:** Parse a configuration file, validate its contents, connect to a database, and run a migration — all using Result combinators without a single `match` statement. Show the full combinator vocabulary.

<details>
<summary>🔍 Full step-by-step solution</summary>

```rust
use std::collections::HashMap;
use std::fs;
use std::path::Path;

#[derive(Debug)]
struct DbConfig {
    host: String,
    port: u16,
    database: String,
    max_connections: u32,
}

#[derive(Debug, thiserror::Error)]
enum SetupError {
    #[error("Config file not found: {0}")]
    NotFound(String),
    #[error("Parse error: {0}")]
    Parse(String),
    #[error("Validation error: {0}")]
    Validation(String),
    #[error("Connection error: {0}")]
    Connection(String),
}

/// Full pipeline using only combinators (no match, no if-let)
fn setup_database(config_path: &str) -> Result<DbConfig, SetupError> {
    // === STEP 1: Read file (map_err to convert error type) ===
    fs::read_to_string(config_path)
        .map_err(|e| SetupError::NotFound(format!("{config_path}: {e}")))
    
    // === STEP 2: Parse key=value pairs (and_then for fallible transform) ===
        .and_then(|contents| {
            parse_config(&contents)
                .map_err(|e| SetupError::Parse(e))
        })
    
    // === STEP 3: Extract and validate fields (and_then chains) ===
        .and_then(|map| {
            let host = map.get("host")
                .ok_or_else(|| SetupError::Validation("missing 'host'".into()))?;
            
            let port = map.get("port")
                .ok_or_else(|| SetupError::Validation("missing 'port'".into()))
                .and_then(|p| p.parse::<u16>()
                    .map_err(|_| SetupError::Validation(format!("invalid port: {p}"))))?;
            
            let database = map.get("database")
                .ok_or_else(|| SetupError::Validation("missing 'database'".into()))?;
            
            let max_connections = map.get("max_connections")
                .map(|s| s.parse::<u32>())
                .transpose()  // Option<Result<T,E>> → Result<Option<T>, E>
                .map_err(|_| SetupError::Validation("invalid max_connections".into()))?
                .unwrap_or(10);  // Default value
            
            Ok(DbConfig {
                host: host.clone(),
                port,
                database: database.clone(),
                max_connections,
            })
        })
    
    // === STEP 4: Validate the constructed config ===
        .and_then(|config| {
            if config.port == 0 {
                Err(SetupError::Validation("port cannot be 0".into()))
            } else if config.host.is_empty() {
                Err(SetupError::Validation("host cannot be empty".into()))
            } else {
                Ok(config)
            }
        })
}

fn parse_config(contents: &str) -> Result<HashMap<String, String>, String> {
    contents.lines()
        .filter(|line| !line.trim().is_empty() && !line.starts_with('#'))
        .map(|line| {
            line.split_once('=')
                .map(|(k, v)| (k.trim().to_string(), v.trim().to_string()))
                .ok_or_else(|| format!("invalid line: {line}"))
        })
        .collect()  // Collects Result<(K,V), E> into Result<HashMap<K,V>, E>
}

// === COMBINATOR REFERENCE ===
fn combinator_cheatsheet() {
    let ok_val: Result<i32, &str> = Ok(42);
    let err_val: Result<i32, &str> = Err("oops");
    
    // map: transform Ok value (Err passes through unchanged)
    let _: Result<String, &str> = ok_val.map(|n| n.to_string());
    
    // map_err: transform Err value (Ok passes through unchanged)
    let _: Result<i32, String> = err_val.map_err(|e| e.to_uppercase());
    
    // and_then (flatmap): chain fallible operations
    let _: Result<i32, &str> = ok_val.and_then(|n| {
        if n > 0 { Ok(n * 2) } else { Err("must be positive") }
    });
    
    // or_else: recover from error with fallible operation
    let _: Result<i32, &str> = err_val.or_else(|_| Ok(0));
    
    // unwrap_or: default value on error
    let _: i32 = err_val.unwrap_or(0);
    
    // unwrap_or_else: lazy default (only computed on error)
    let _: i32 = err_val.unwrap_or_else(|_| expensive_default());
    
    // ok(): Result<T,E> → Option<T> (discards error)
    let _: Option<i32> = err_val.ok();
    
    // transpose: Option<Result<T,E>> ↔ Result<Option<T>, E>
    let opt_result: Option<Result<i32, &str>> = Some(Ok(42));
    let _: Result<Option<i32>, &str> = opt_result.transpose();
    
    // flatten (nightly, or use and_then(|x| x)):
    let nested: Result<Result<i32, &str>, &str> = Ok(Ok(42));
    let _: Result<i32, &str> = nested.and_then(|inner| inner);
    
    // inspect (Rust 1.76+): peek at Ok value without consuming
    let _ = ok_val.inspect(|n| println!("got: {n}"));
    
    // inspect_err: peek at Err value
    let _ = err_val.inspect_err(|e| eprintln!("error: {e}"));
```

### 9.1 Try Blocks (Nightly): Inline Error Handling Without Functions

The `try` block feature (available on nightly with `#![feature(try_blocks)]`) allows you to use the `?` operator inside a block expression without requiring a separate function. The block evaluates to a `Result` (or `Option`).

**The problem try blocks solve:**

```rust
// Without try blocks, you need a helper function just to use ?:
fn process() -> Result<(), Error> {
    let result = helper()?;  // ? works here (function returns Result)
    Ok(())
}

// But what if you want ? in the MIDDLE of a function that doesn't return Result?
fn main() {
    // Can't use ? here — main returns ()
    // let data = fs::read_to_string("file.txt")?;  // ERROR
    
    // Workaround: wrap in a closure or helper function
    let result: Result<String, std::io::Error> = (|| {
        let data = std::fs::read_to_string("file.txt")?;
        Ok(data)
    })();
}
```

**With try blocks (nightly):**

```rust
#![feature(try_blocks)]

fn main() {
    // try block: ? works inside, result is a Result
    let result: Result<i32, std::num::ParseIntError> = try {
        let x: i32 = "42".parse()?;
        let y: i32 = "17".parse()?;
        x + y
    };
    
    match result {
        Ok(sum) => println!("Sum: {sum}"),
        Err(e) => eprintln!("Parse error: {e}"),
    }
    
    // Useful for optional chains:
    let config: Option<String> = try {
        let path = std::env::var("CONFIG").ok()?;
        let contents = std::fs::read_to_string(&path).ok()?;
        contents
    };
}
```

**Why it's not yet stable:** The Rust team is still deciding on the exact semantics, particularly around type inference. The block's type must be inferable, which sometimes requires explicit type annotations. There are also questions about interaction with `async try` blocks.

**Stable alternative — the IIFE (Immediately Invoked Function Expression) pattern:**

```rust
fn main() {
    // This works on stable Rust:
    let result: Result<String, Box<dyn std::error::Error>> = (|| {
        let port = std::env::var("PORT")?;
        let num: u16 = port.parse()?;
        Ok(format!("Listening on port {num}"))
    })();
    
    println!("{:?}", result);
}
```

### 9.2 std::backtrace — Capturing Error Origins

Rust's `std::backtrace::Backtrace` (stabilized in Rust 1.65) captures the call stack at the point where an error is created. This is invaluable for debugging errors that propagate through many layers.

**How backtraces work in Rust's error model:**

```rust
use std::backtrace::Backtrace;

#[derive(Debug)]
struct MyError {
    message: String,
    backtrace: Backtrace,
}

impl MyError {
    fn new(message: impl Into<String>) -> Self {
        MyError {
            message: message.into(),
            // Captures the stack trace at this point
            backtrace: Backtrace::capture(),
        }
    }
}
```

**Backtrace capture modes:**

Backtraces are controlled by the `RUST_BACKTRACE` environment variable:
- `RUST_BACKTRACE=0` (default): `Backtrace::capture()` returns `Backtrace::disabled()` (no cost)
- `RUST_BACKTRACE=1`: Captures backtrace (moderate overhead: ~1-10μs)
- `RUST_BACKTRACE=full`: Captures with full symbols (slower but more detail)

```rust
fn demonstrate_backtrace() {
    let bt = Backtrace::capture();
    
    match bt.status() {
        std::backtrace::BacktraceStatus::Captured => {
            println!("Backtrace:\n{bt}");
        }
        std::backtrace::BacktraceStatus::Disabled => {
            println!("Set RUST_BACKTRACE=1 to enable");
        }
        _ => println!("Unsupported"),
    }
}
```

**Integration with anyhow:**

`anyhow` automatically captures backtraces when `RUST_BACKTRACE=1`:

```rust
use anyhow::{Context, Result};

fn deep_function() -> Result<()> {
    std::fs::read_to_string("/nonexistent")
        .context("reading critical file")?;
    Ok(())
}

fn middle_function() -> Result<()> {
    deep_function().context("in middle_function")?;
    Ok(())
}

fn main() {
    // With RUST_BACKTRACE=1, the error output includes:
    // Error: in middle_function
    //
    // Caused by:
    //     0: reading critical file
    //     1: No such file or directory (os error 2)
    //
    // Stack backtrace:
    //    0: std::backtrace_rs::backtrace::...
    //    1: deep_function at src/main.rs:4
    //    2: middle_function at src/main.rs:9
    //    3: main at src/main.rs:13
    
    if let Err(e) = middle_function() {
        eprintln!("Error: {e:#}");  // {:#} shows the full chain
    }
}
```

**Performance considerations:**

- Backtrace capture is expensive (~1-10μs) — don't capture in hot loops
- The `Backtrace::capture()` call is a no-op when `RUST_BACKTRACE` is unset
- For production: capture backtraces only for unexpected errors, not for expected failures like "file not found"
- `anyhow` and `eyre` handle this automatically (only capture when the env var is set)

### 9.3 The Error Trait Ecosystem: std::error::Error in Depth

The `std::error::Error` trait is the foundation of Rust's error handling ecosystem:

```rust
pub trait Error: Debug + Display {
    // The lower-level cause of this error, if any.
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        None  // Default: no source
    }
    
    // Nightly: provide typed context (backtraces, span traces, etc.)
    // fn provide<'a>(&'a self, request: &mut Request<'a>) {}
}
```

**The error chain pattern:**

Every error can point to its `source()` — the underlying error that caused it. This creates a chain:

```
AppError: "failed to start server"
  └─ caused by: ConfigError: "invalid port in config.toml"
       └─ caused by: ParseIntError: "invalid digit found in string"
```

**Walking the error chain:**

```rust
fn print_error_chain(error: &dyn std::error::Error) {
    eprintln!("Error: {error}");
    let mut source = error.source();
    let mut depth = 1;
    while let Some(cause) = source {
        eprintln!("  {depth}: {cause}");
        source = cause.source();
        depth += 1;
    }
}
```

**The `?` operator's hidden mechanism:**

When you write `operation()?`, the compiler desugars it to:

```rust
match operation() {
    Ok(val) => val,
    Err(err) => return Err(From::from(err)),
    //                      ^^^^^^^^^^^^^^
    //                      This is the key: automatic conversion via From
}
```

The `From::from(err)` call is what enables `?` to convert between error types. When you implement `From<IoError> for MyError`, the `?` operator can automatically convert `io::Error` into `MyError`.

**The `#[from]` attribute in thiserror generates this From impl:**

```rust
#[derive(thiserror::Error, Debug)]

    #[error("io: {0}")]
    Io(#[from] std::io::Error),

    // impl From<std::io::Error> for MyError {

    //     }

}
```

### 9.4 Error Handling Patterns for Async Code

Async code introduces unique error handling challenges because errors can occur across `.await` points, in spawned tasks, and in concurrent operations.

**Pattern 1: JoinError wrapping**

```rust
use tokio::task::JoinError;

#[derive(thiserror::Error, Debug)]
enum AppError {
    #[error("Task panicked: {0}")]
    TaskPanic(#[from] JoinError),
    
    #[error("Operation failed: {0}")]
    Operation(String),
}

async fn run_tasks() -> Result<(), AppError> {
    let handle = tokio::spawn(async {
        // This task might panic
        risky_operation().await
    });
    
    // JoinError occurs if the task panicked or was cancelled
    let result = handle.await?;  // ? converts JoinError → AppError::TaskPanic
    result.map_err(|e| AppError::Operation(e.to_string()))?;
    Ok(())
}
```

**Pattern 2: Collecting errors from concurrent operations**

```rust
async fn fetch_all(urls: &[&str]) -> (Vec<String>, Vec<anyhow::Error>) {
    let mut successes = Vec::new();
    let mut failures = Vec::new();
    
    let results = futures::future::join_all(
        urls.iter().map(|url| async move {
            reqwest::get(*url).await?.text().await
        })
    ).await;
    
    for result in results {
        match result {
            Ok(body) => successes.push(body),
            Err(e) => failures.push(e.into()),
        }
    }
    
    (successes, failures)
}
```

**Pattern 3: Timeout as an error**

```rust
use tokio::time::{timeout, Duration};

#[derive(thiserror::Error, Debug)]
enum FetchError {
    #[error("Request timed out after {0:?}")]
    Timeout(Duration),
    
    #[error("HTTP error: {0}")]
    Http(#[from] reqwest::Error),
}

async fn fetch_with_timeout(url: &str, dur: Duration) -> Result<String, FetchError> {
    timeout(dur, reqwest::get(url))
        .await
        .map_err(|_| FetchError::Timeout(dur))?  // Elapsed → Timeout
        .map_err(FetchError::Http)?               // reqwest::Error → Http
        .text()
        .await
        .map_err(FetchError::Http)
}
```
