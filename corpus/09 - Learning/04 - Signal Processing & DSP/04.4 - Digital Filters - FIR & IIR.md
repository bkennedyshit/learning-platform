# 04.4 — Digital Filters: FIR & IIR

> *"A filter is a system that allows certain frequencies to pass and attenuates others. The art of filter design is controlling exactly which frequencies, and how much, with the fewest operations."*

Filters are the workhorse of DSP. They remove noise, separate channels, implement equalisers, shape spectra for codecs, and underlie the mel filterbank inside every speech model. There are two fundamental families: **FIR** (Finite Impulse Response) and **IIR** (Infinite Impulse Response). They trade stability, phase linearity, and computational cost against each other.

Prerequisite: [[04.3 - Discrete Fourier Transform & FFT|04.3]] and [[04.2 - Fourier Series & Fourier Transform|04.2]]. Forward links: [[04.5 - Audio Signal Processing & Psychoacoustics|04.5]], [[04.7 - Speech & Voice Processing (ASR-TTS Foundations)|04.7]].

## 📚 1. FIR Filters — Finite Impulse Response

### 1.1 Definition

An **FIR filter** of order N has the difference equation:

```
y[n] = Σ_{k=0}^{N}  h[k] · x[n − k]
     = h[0]·x[n] + h[1]·x[n−1] + … + h[N]·x[n−N]
```

The **impulse response** is exactly the coefficient sequence h[0], h[1], …, h[N]. It has finite length (N+1 terms), hence the name.

**Z-transform (transfer function):**
```
H(z) = Σ_{k=0}^{N}  h[k] · z^{−k}       (all zeros, no poles)
```

### 1.2 Properties of FIR Filters

| Property | FIR | Why |
|----------|-----|-----|
| **Stability** | Always stable | No poles — output cannot grow unboundedly |
| **Phase** | Can be exactly linear phase | Symmetric coefficient sequence: h[k] = h[N−k] |
| **Causality** | Easily made causal | All taps use past/present samples |
| **Computational cost** | High (long filters needed for sharp rolloff) | Requires many multiplications per sample |
| **Memory** | Proportional to filter order | N+1 previous samples |

### 1.3 Linear Phase FIR

A **Type I FIR** filter (N even, symmetric impulse response) has exactly linear phase:

```
∠H(e^{jω}) = −ω · N/2   (constant group delay of N/2 samples)
```

All frequencies are delayed by the same amount — no phase distortion. This is critical for audio (no pre-ringing on transients) and for phase-sensitive applications like speech encoding.

### 1.4 FIR Design: Windowing Method

The ideal lowpass filter in the frequency domain is a rectangular function (brick wall). Its impulse response is a **sinc** function:

```
h_ideal[n] = (2fc/fs) · sinc(2πfc(n − N/2) / fs)     n = 0, 1, …, N
```

But this is infinite in length. **Windowing** truncates it:

```
h[n] = h_ideal[n] · w[n]
```

The window choice determines the trade-off between main-lobe width (transition bandwidth) and sidelobe level (stopband attenuation):

| Window | Minimum stopband attenuation | Transition width |
|--------|------------------------------|-----------------|
| Rectangular | −21 dB | 0.9/N |
| Hann | −44 dB | 3.1/N |
| Hamming | −53 dB | 3.3/N |
| Blackman | −74 dB | 5.5/N |
| Kaiser (β=8.6) | −80 dB | 4.6/N |

**Rule of thumb for filter order:** For stopband attenuation A_s dB and transition bandwidth Δf:

```
N ≈ (A_s − 8) / (2.285 · 2π · Δf/fs)    (Kaiser approximation)
```

### 1.5 Parks-McClellan (Equiripple) Algorithm

The windowing method is not optimal — it wastes some stopband attenuation. The **Parks-McClellan algorithm** (also called Remez exchange) finds the FIR coefficients that **minimise the maximum error** in the passband and stopband (minimax / Chebyshev approximation):

- Passband ripple δ_p (e.g. ±0.1 dB)
- Stopband attenuation δ_s (e.g. −60 dB)
- Transition band f_pass … f_stop

For given specifications, Parks-McClellan produces a shorter filter than windowing (by ~30-50%).

```python
from scipy.signal import remez, freqz
import numpy as np
import matplotlib.pyplot as plt

fs = 44100
nyq = fs / 2

# Design equiripple LPF: pass 0-4kHz, stop 5kHz+, 60dB atten
bands = [0, 4000, 5000, nyq]
desired = [1, 0]      # passband gain, stopband gain
N = 101               # filter order (try 51, 101, 201)

h = remez(N, [f/nyq for f in bands], desired, weight=[1, 10])

# Frequency response
w, H = freqz(h, worN=8192, fs=fs)
plt.figure(figsize=(10, 4))
plt.subplot(1, 2, 1)
plt.plot(w, 20*np.log10(np.abs(H) + 1e-10))
plt.ylim(-80, 5); plt.xlabel("Hz"); plt.ylabel("dB")
plt.title(f"Parks-McClellan LPF (N={N})")

plt.subplot(1, 2, 2)
plt.plot(np.arange(N), h)
plt.xlabel("n"); plt.ylabel("h[n]")
plt.title("Impulse response")
plt.tight_layout(); plt.show()
```

## 📚 2. IIR Filters — Infinite Impulse Response

### 2.1 Definition

An **IIR filter** uses feedback — the output depends on *previous output samples* as well as input samples:

```
y[n] = Σ_{k=0}^{M}  b[k]·x[n−k]  −  Σ_{k=1}^{N}  a[k]·y[n−k]
```

**Transfer function (Z-domain):**
```
H(z) = B(z)/A(z) = (b₀ + b₁z⁻¹ + … + b_M z⁻ᴹ) / (1 + a₁z⁻¹ + … + a_N z⁻ᴺ)
```

Poles of H(z) are the roots of A(z). **Stability requires all poles inside the unit circle** |z| < 1.

### 2.2 IIR vs FIR Trade-offs

| Property | IIR | FIR |
|----------|-----|-----|
| **Order for given sharpness** | Much lower (e.g. 4th-order Butterworth vs 50-tap FIR) | Higher |
| **Phase** | Non-linear (phase distortion) | Can be linear (symmetric) |
| **Stability** | Not guaranteed — design carefully | Always stable |
| **Numerical precision** | Sensitive to coefficient quantisation | More robust |
| **Computational cost** | Low | Higher |

**Rule:** Use IIR when you need efficiency and can tolerate phase distortion (audio effects, EQ, anti-aliasing). Use FIR when linear phase is required (audio coding, geophysics, communication).

### 2.3 Analog Prototype Filters

IIR digital filters are usually designed by:
1. Designing an **analog prototype** (Laplace domain H(s)) with normalised cutoff ω_c = 1 rad/s.
2. Applying the **bilinear transform** s = 2fs · (z−1)/(z+1) to map H(s) → H(z).

**Analog prototype families:**

| Type | Passband | Stopband | Phase | Choice |
|------|----------|----------|-------|--------|
| **Butterworth** | Monotone (maximally flat) | Monotone | Moderate | General purpose, gentle roll-off |
| **Chebyshev I** | Equiripple | Monotone | Worse | Sharper rolloff, accept passband ripple |
| **Chebyshev II** | Monotone | Equiripple | Better | Sharp rolloff, accept stopband ripple |
| **Elliptic (Cauer)** | Equiripple | Equiripple | Worst | Sharpest rolloff for given order |
| **Bessel** | Near-linear group delay | Gradual | Best | Linear phase priority (not steep rolloff) |

### 2.4 The Bilinear Transform

The bilinear transform maps every pole on the left half of the s-plane to inside the unit circle in the z-plane — guaranteeing stability. The mapping:

```
s = 2fs · (z − 1) / (z + 1)
```

**Frequency warping:** the bilinear transform compresses the infinite analog frequency axis (0, ∞) into the finite digital frequency range (0, π). The mapping is:

```
Ω_analog = 2fs · tan(ω_digital / 2)
```

**Pre-warping correction:** to design a filter with exact digital cutoff f_c, apply pre-warping:

```
Ω_c = 2fs · tan(π f_c / fs)
```

Then design the analog prototype at Ω_c, then apply bilinear transform.

### 2.5 Direct Form II (Biquad) Implementation

High-order IIR filters are numerically fragile. The **standard practice** is to factor H(z) into **second-order sections (biquad sections)**:

```
H(z) = H₁(z) · H₂(z) · … · H_K(z)
```

where each Hₖ(z) = (b₀ + b₁z⁻¹ + b₂z⁻²) / (1 + a₁z⁻¹ + a₂z⁻²)

**Direct Form II computation for each biquad:**
```
w[n] = x[n] − a₁·w[n−1] − a₂·w[n−2]    (feedback/recursive part)
y[n] = b₀·w[n] + b₁·w[n−1] + b₂·w[n−2] (feedforward part)
```

This requires only 2 state variables per section, regardless of filter order.

```python
from scipy.signal import butter, sosfilt, sosfreqz
import numpy as np

fs = 44100
fc = 1000  # cutoff frequency in Hz

# Design 4th-order Butterworth LPF using second-order sections
sos = butter(4, fc, btype='low', fs=fs, output='sos')

# Apply to signal
y = sosfilt(sos, x)   # x is your input signal array

# Frequency response
w, H = sosfreqz(sos, worN=8192, fs=fs)
print(f"Filter has {len(sos)} biquad sections")
print(f"At fc={fc} Hz: {20*np.log10(abs(H[np.argmin(abs(w-fc))])):.1f} dB (expect ≈ -3 dB)")
```

**Always use `output='sos'` and `sosfilt` for IIR filters** — never use `ba` (transfer function coefficients) with `lfilter` for order > 3, as it is numerically unstable.

## 📚 3. Filter Design Cookbook

### 3.1 Anti-Aliasing Filter (before downsampling)

```python
from scipy.signal import butter, sosfiltfilt

def anti_alias_lowpass(x, fs, target_fs):
    """Lowpass filter before downsampling x from fs to target_fs."""
    fc = target_fs / 2 * 0.9        # 90% of Nyquist (leave 10% transition band)
    sos = butter(8, fc, btype='low', fs=fs, output='sos')
    return sosfiltfilt(sos, x)      # zero-phase (offline) filtering
```

### 3.2 Notch Filter (60 Hz / 50 Hz hum removal)

```python
from scipy.signal import iirnotch

def notch_60hz(x, fs):
    """Remove 60 Hz power line hum."""
    b, a = iirnotch(60.0, Q=30, fs=fs)   # Q=30: narrow notch
    from scipy.signal import lfilter
    return lfilter(b, a, x)
```

### 3.3 Parametric EQ (Bell Filter — used in audio production)

```python
def parametric_eq(x, fs, fc, gain_dB, Q):
    """Bell (peaking) EQ filter."""
    A = 10**(gain_dB / 40)     # linear amplitude factor
    w0 = 2 * np.pi * fc / fs
    alpha = np.sin(w0) / (2 * Q)
    
    b0 = 1 + alpha * A
    b1 = -2 * np.cos(w0)
    b2 = 1 - alpha * A
    a0 = 1 + alpha / A
    a1 = -2 * np.cos(w0)
    a2 = 1 - alpha / A
    
    b = [b0/a0, b1/a0, b2/a0]
    a = [1.0,   a1/a0, a2/a0]
    from scipy.signal import lfilter
    return lfilter(b, a, x)
```

## 📚 4. Zero-Phase Filtering (Offline Processing)

When processing audio offline (not real-time), **zero-phase filtering** eliminates all phase distortion:

```python
from scipy.signal import sosfiltfilt
# sosfiltfilt applies the filter forward, then backward
# Result: zero phase shift, double the magnitude attenuation rate
y_zp = sosfiltfilt(sos, x)
```

This is equivalent to squaring the magnitude response while zeroing the phase. Useful for analysis, not real-time processing (requires future samples = not causal).

## 📚 5. Filter Design Decision Tree

```
Is phase linearity critical?
├── YES → FIR filter
│         └── Use Parks-McClellan (scipy.signal.remez) for minimum length
│             Use windowing (scipy.signal.firwin) for simplicity
│
└── NO → IIR filter
         ├── Need sharpest possible rolloff? → Elliptic (scipy.signal.ellip)
         ├── Accept passband ripple, want sharp? → Chebyshev I (scipy.signal.cheby1)
         ├── Accept stopband ripple, smooth pass? → Chebyshev II (scipy.signal.cheby2)
         └── Smooth response everywhere? → Butterworth (scipy.signal.butter)
                                           Always use output='sos' + sosfilt!
```

## 📚 6. Common Misconceptions

- **"Higher-order IIR = better filter."** Higher order = more poles = more instability risk and more numerical sensitivity. The standard answer is: factor into biquad SOS and use sosfilt, never a large polynomial.
- **"FIR filters are always slower."** FIR via FFT-based fast convolution (overlap-add) can be very fast for large filter lengths. For small lengths (N < ~32), direct FIR is fast.
- **"Butterworth is always the right choice."** Butterworth has the flattest passband but the slowest rolloff. For audio anti-aliasing where you need 60+ dB attenuation with a tight transition band, elliptic is more appropriate.
- **"sosfiltfilt doubles the filter order."** It doubles the *effective attenuation*, not the order. The filter order stays the same; only zero phase and squared magnitude result.
- **"IIR filters are always causal."** When you use `sosfiltfilt`, they are non-causal (bidirectional). For real-time, use `sosfilt` (forward direction only, causal).
