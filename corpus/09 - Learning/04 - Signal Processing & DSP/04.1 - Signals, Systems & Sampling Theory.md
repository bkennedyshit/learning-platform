# 04.1 — Signals, Systems & Sampling Theory

> *"A signal is just a function of one or more variables that conveys information. Everything else is deciding how to destroy it as little as possible on the way to the destination."*

This chapter is the **absolute foundation** for everything that follows. Before FFTs, before filters, before mel spectrograms — you need to know what a signal *is*, what the ADC/DAC chain *does* to it, and why the Nyquist theorem is not optional. Every mistake in audio AI — aliased features, wrong sample rates, quantization artefacts — traces back to ignoring something in this chapter.

Cross-links this builds toward: [[04.2 - Fourier Series & Fourier Transform|04.2]], [[04.3 - Discrete Fourier Transform & FFT|04.3]], [[04.5 - Audio Signal Processing & Psychoacoustics|04.5]], [[04.7 - Speech & Voice Processing (ASR-TTS Foundations)|04.7]].

## 🎯 Learning Objectives

By the end of this chapter you will be able to:

1. Define a **signal** (continuous-time, discrete-time, analog, digital) and correctly place any example in the taxonomy.
2. State the **Nyquist–Shannon sampling theorem** with its mathematical form and explain why it is a *sufficient* not just necessary condition.
3. Explain **aliasing** — what it sounds like, what it looks like in a spectrum, and how to prevent it.
4. Calculate **quantization noise**, signal-to-quantization-noise ratio (SQNR), and the number of bits needed for a given dynamic range.
5. Trace an audio signal through the full **ADC → DSP → DAC** chain and identify where information can be permanently lost.
6. Describe **LTI (Linear Time-Invariant)** systems and why they are the canonical model for most useful DSP operations.
7. Apply basic system properties: **linearity**, **time-invariance**, **causality**, **stability (BIBO)**.

## 📚 1. What is a Signal?

### Definition 04.1.1 — Signal

A **signal** is a function (usually of time, sometimes of space) that carries information. In DSP we deal with four fundamental types:

| Type | Time axis | Amplitude | Notation | Example |
|------|-----------|-----------|----------|---------|
| **Continuous-time analog** | ℝ (continuous) | ℝ (continuous) | x(t) | Microphone voltage |
| **Discrete-time** | ℤ (n = …−1,0,1,2…) | ℝ (continuous) | x[n] | After ideal sampler |
| **Quantized** | ℝ (continuous) | Finite levels | — | DAC staircase output |
| **Digital (PCM)** | ℤ | Finite levels | x[n] ∈ ℤ | WAV file samples |

> The route from microphone to computer is: *continuous-time → sampled (discrete-time) → quantized → digital*. Each step is a one-way information reduction; no step can be perfectly reversed.

### Definition 04.1.2 — System

A **system** is any device or algorithm that accepts an input signal and produces an output signal. Notation:

```
x(t) → [System H] → y(t) = H{x(t)}
```

---

## 📚 2. Linear Time-Invariant (LTI) Systems

Most useful DSP building blocks are **LTI systems**. An LTI system satisfies two properties:

### 2.1 Linearity (Superposition Principle)

If x₁(t) → y₁(t) and x₂(t) → y₂(t), then:

```
α·x₁(t) + β·x₂(t)  →  α·y₁(t) + β·y₂(t)
```

This means: **scale and add before or after the system — same result**. Sine wave response tells you everything about the system's response to *any* signal (because any signal is a sum of sinusoids — Fourier's key insight).

### 2.2 Time-Invariance

If x(t) → y(t), then x(t − t₀) → y(t − t₀) for any delay t₀.

A *time-varying* filter (e.g. a pitch-shifting algorithm that changes its cutoff frequency each sample) is **not LTI** — standard frequency-domain analysis does not apply directly.

### 2.3 Impulse Response — The Complete Description of an LTI System

The **impulse response h(t)** (or h[n] in discrete time) completely characterises an LTI system:

```
y(t) = x(t) * h(t) = ∫ x(τ)·h(t−τ) dτ   (convolution integral)

y[n] = x[n] * h[n] = Σₖ x[k]·h[n−k]      (discrete convolution sum)
```

**Key insight:** the impulse response of a system is what you get if you feed in a Dirac delta (continuous) or unit impulse δ[n] (discrete). This will be critical in [[04.4 - Digital Filters - FIR & IIR|04.4]] — a FIR filter *is* its impulse response.

### 2.4 Other Important System Properties

| Property | Definition | Why it matters |
|----------|-----------|----------------|
| **Causality** | y[n] depends only on x[k] for k ≤ n (past/present only) | Required for real-time processing; non-causal = offline/lookahead |
| **BIBO Stability** | Bounded input → bounded output | Necessary for IIR filter design; unstable filter explodes |
| **Memory** | Output depends on past inputs | Memoryless = purely instantaneous; most useful filters have memory |
| **Invertibility** | H has a unique inverse H⁻¹ | Equalization / deconvolution require this |

## 📚 3. Sampling Theory — The Nyquist–Shannon Theorem

This is **the most important theorem in all of DSP**. Every audio engineer, firmware developer, and AI researcher who works with audio must have this burned in.

### 3.1 The Theorem (Statement)

> **Nyquist–Shannon Sampling Theorem:** A continuous-time bandlimited signal with maximum frequency component f_max can be *perfectly* reconstructed from its samples if and only if the sampling frequency satisfies:
>
> ```
> fs ≥ 2 · f_max
> ```
>
> The quantity f_N = fs / 2 is called the **Nyquist frequency** (or folding frequency). — paraphrased from [dspguide.com — Chapter 3](https://www.dspguide.com/ch3.htm). Content rephrased for compliance.

### 3.2 Why "2×" — Intuition

Imagine a sine wave at exactly f_max Hz. To unambiguously determine this sine wave's amplitude and phase, you need at least **two samples per cycle** — one near the peak and one near the trough. Fewer than two samples per cycle and you can't distinguish it from a lower-frequency imposter. That imposter is the **alias**.

### 3.3 The Sampling Process — Mathematical Model

Sampling multiplies the continuous signal x(t) by an **ideal impulse train** (Dirac comb):

```
s(t) = Σₙ δ(t − nT)    where T = 1/fs = sample period
x_s(t) = x(t) · s(t) = Σₙ x(nT)·δ(t − nT)
```

In the frequency domain, multiplication by the impulse train becomes **periodic replication** of X(f) with period fs. If fs ≥ 2·f_max, the copies don't overlap and X(f) can be extracted with a lowpass filter. If fs < 2·f_max, the copies **overlap** — that's aliasing.

### 3.4 Aliasing — When Sampling Goes Wrong

**Aliasing** occurs when a frequency component f > fs/2 is sampled at rate fs. The alias appears at:

```
f_alias = |f − round(f / fs) · fs|
```

**Concrete example:** Sample a 12 kHz tone at fs = 16 kHz (Nyquist = 8 kHz). The alias appears at |12 000 − 16 000| = 4 000 Hz — a 4 kHz ghost that was never in the original signal. In audio this sounds like a wrong note; in images it creates moiré patterns.

**Prevention:** Always place an **anti-aliasing lowpass filter** before the ADC with cutoff at fs/2 (or slightly below, to allow filter rolloff). This is part 2 of the ADC chain in the visual anchor above.

### 3.5 Reconstruction (DAC Side)

Perfect reconstruction requires:
1. A **sample-and-hold** circuit (holds each sample level between clock pulses).
2. A **reconstruction lowpass filter** (removes the spectral images at multiples of fs).

In practice, oversampling (running the DAC at 4× or 8× the target rate) dramatically reduces the requirements on the reconstruction filter's sharpness — this is how modern Σ-Δ DACs work.

## 📚 4. Quantization — Turning Real Numbers into Integers

### 4.1 Uniform Quantizer

After sampling, each sample x[n] is rounded to the nearest of 2^N equally-spaced levels. The number of bits N is called the **bit depth**. Parameters:

| Parameter | Formula | CD audio (16-bit) |
|-----------|---------|-------------------|
| Number of levels | 2^N | 65 536 |
| Step size Δ | FullScale / 2^N | ~0.030 mV for ±1V FS |
| Max quantization error | ±Δ/2 | ±0.015 mV |

### 4.2 Quantization Noise

Quantization error e[n] = x_quantized[n] − x[n] behaves approximately as **uniformly distributed white noise** in the range [−Δ/2, +Δ/2]. Its power:

```
σ²_e = Δ²/12
```

### 4.3 Signal-to-Quantization-Noise Ratio (SQNR)

For a full-scale sinusoidal input:

```
SQNR ≈ 6.02·N + 1.76  dB
```

**Rule of thumb: each additional bit adds ~6 dB of dynamic range.**

| Bit depth | SQNR | Application |
|-----------|------|-------------|
| 8-bit | ~50 dB | Vintage games, telephony (G.711) |
| 16-bit | ~98 dB | CD audio, WAV consumer |
| 24-bit | ~146 dB | Studio recording, mastering |
| 32-bit float | ~190 dB effective | DAW internal processing |

### 4.4 Dithering

Adding a tiny amount of noise (dither) *before* quantization has a counter-intuitive benefit: it breaks up the correlated quantization error pattern into uncorrelated white noise, which is less audible. Triangular PDF (TPDF) dither is the standard. This is why professional audio engineers add dither when reducing bit depth from 24-bit to 16-bit.

## 📚 5. The Full ADC → DSP → DAC Chain

```
Microphone       Anti-alias LPF      Sampler         Quantizer       Digital Signal
 x(t)        →   (fc < fs/2)     →   T=1/fs      →   N bits      →   Processor
continuous        removes f>fn        x(nT)           x[n] ∈ ℤ        y[n]
                  [Brick-wall ideal;
                   real = Butterworth/
                   elliptic IIR]
                                                                          ↓
Speaker          Smoothing LPF       Sample-Hold         DAC         DSP Output
 y(t)        ←   removes images  ←   staircase      ←   N-bit R-2R  ←  y[n]
reconstructed     (reconstruction     output          ladder
```

**Critical points where information is lost forever:**
1. **Before sampling:** if anti-alias filter is too wide, aliases contaminate the spectrum permanently.
2. **During quantization:** if bit depth is too low, quantization noise floor is audible.
3. **After DAC:** if reconstruction filter is poor, spectral images create distortion.

### 5.1 Practical Sample Rates

| Rate | Nyquist limit | Use case |
|------|--------------|----------|
| 8 000 Hz | 4 000 Hz | Telephone (G.711), VoIP minimal |
| 16 000 Hz | 8 000 Hz | **Whisper default**, speech recognition, podcast processing |
| 22 050 Hz | 11 025 Hz | Old games, some TTS systems |
| 44 100 Hz | 22 050 Hz | **CD audio**, consumer music, YouTube |
| 48 000 Hz | 24 000 Hz | **Video/broadcast standard**, DAW default, streaming |
| 96 000 Hz | 48 000 Hz | High-res audio, studio capture |
| 192 000 Hz | 96 000 Hz | Mastering, research |

> **For AI audio work:** resample everything to 16 kHz before feeding Whisper. Resample to 22 050 Hz or 24 000 Hz for most TTS vocoders (check the model's expected rate — it matters).

## 📚 6. Worked Example — "Will This Alias?"

**Problem:** You have a microphone that captures up to 20 kHz. You sample at fs = 22 050 Hz. Your anti-alias filter has a −3 dB point at 11 kHz and −60 dB at 11.5 kHz. Is there a problem?

**Solution:**

1. Nyquist frequency = fs/2 = 11 025 Hz.
2. Anti-alias filter cuts to −3 dB at 11 kHz — frequencies above 11 kHz are *attenuated*, not eliminated.
3. A 19 kHz component (inaudible but present in transients) reaches the sampler with about −60 dB attenuation.
4. Its alias appears at: |19 000 − 22 050| = 3 050 Hz — an audible 3 kHz ghost at −60 dB.
5. For a 16-bit system (−96 dB noise floor), −60 dB is **inaudible**. For a sensitive measurement system at 24-bit, you might care.

**Conclusion:** The system is fine for 16-bit audio. The anti-alias filter's transition band is the limiting factor; a steeper filter (elliptic IIR) would push aliases further below the noise floor.

## 🛠️ 7. Python Quickstart — Sampling & Aliasing Demo

```python
import numpy as np
import matplotlib.pyplot as plt
from scipy.io.wavfile import write

fs = 16000          # sample rate (Hz)
duration = 0.5      # seconds
t = np.linspace(0, duration, int(fs * duration), endpoint=False)

# Proper signal: 2 kHz (well below Nyquist = 8 kHz)
sig_ok = np.sin(2 * np.pi * 2000 * t)

# Alias signal: 10 kHz (above Nyquist → aliases to 6 kHz)
sig_alias = np.sin(2 * np.pi * 10000 * t)
# alias frequency = |10000 - 16000| = 6000 Hz

# Check: plot both spectra with numpy FFT
freqs = np.fft.rfftfreq(len(t), d=1/fs)
plt.figure(figsize=(12, 4))
plt.subplot(1, 2, 1)
plt.plot(freqs, np.abs(np.fft.rfft(sig_ok)))
plt.title("2 kHz — No alias")
plt.xlabel("Hz"); plt.xlim(0, 8000)

plt.subplot(1, 2, 2)
plt.plot(freqs, np.abs(np.fft.rfft(sig_alias)))
plt.title("10 kHz sampled at 16 kHz → alias at 6 kHz")
plt.xlabel("Hz"); plt.xlim(0, 8000)
plt.tight_layout()
plt.show()
```

## 📚 8. Common Misconceptions

- **"Nyquist says you need exactly 2 samples per cycle."** No — 2 samples per cycle is the *minimum*; at exactly 2× you can reconstruct a sine wave only if you know its phase. In practice, oversample by at least 10–20% to give the anti-alias filter room.
- **"44.1 kHz captures everything the human ear hears."** True for steady-state hearing (≤20 kHz), but transients contain ultra-high-frequency components. Studio engineers record at 96 kHz/24-bit for headroom, then dither down for distribution.
- **"Digital is exact."** Quantization adds noise. A 16-bit WAV has an inherent noise floor around −96 dB. Only 32-bit float representation approaches "exact" for practical audio processing.
- **"Aliasing only happens at high frequencies."** Aliasing affects any signal component above fs/2, including when you **downsample** (decimate) a signal. Always apply a lowpass filter *before* downsampling, not after.
- **"Causality is always required."** Not in offline/batch processing. Whisper processes 30-second chunks non-causally. Real-time streaming requires causal (lookahead-limited) algorithms.
