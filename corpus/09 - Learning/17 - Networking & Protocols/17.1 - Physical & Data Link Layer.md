# 17.1 — Physical & Data Link Layer

> *"You cannot fix what you cannot see. And you cannot see the wire until you know what the wire carries."*

This chapter is the bedrock. Every protocol in this track — TCP, TLS, HTTP/3, WebRTC — ultimately becomes bits on a physical medium. Understanding what those bits look like, how nodes discover each other on a local network, and how switches forward frames separates developers who *guess* at network problems from those who *read the packets*.

---

## 🎯 Learning Objectives

By the end of this chapter you will be able to:

1. Map all 7 OSI layers to TCP/IP's 4-layer model and name real protocols at each layer.
2. Decode an **Ethernet II frame** — every field, its size, and its purpose.
3. Explain the **ARP request/reply** process including gratuitous ARP and ARP cache poisoning.
4. Decode a 48-bit **MAC address** — OUI, device bits, unicast/multicast bit, locally administered bit.
5. Explain how a **layer-2 switch** builds its MAC address table and floods/forwards/filters frames.
6. Describe **VLANs** (802.1Q tagging) and why they exist.
7. Open Wireshark and identify Ethernet, ARP, and 802.1Q frames in a capture.

## 📚 1. OSI Model vs TCP/IP Model

### 1.1 The OSI 7-Layer Model

The **Open Systems Interconnection** model (ISO 7498) describes network communication as seven abstract layers, each responsible for a different concern:

| Layer | Name | PDU | Key protocols / concepts |
|---|---|---|---|
| 7 | Application | Data | HTTP, DNS, SMTP, FTP, SSH, QUIC |
| 6 | Presentation | Data | TLS/SSL, gzip compression, MIME encoding |
| 5 | Session | Data | TLS session management, RPC channels |
| 4 | Transport | Segment / Datagram | TCP, UDP |
| 3 | Network | Packet | IPv4, IPv6, ICMP, OSPF, BGP |
| 2 | Data Link | Frame | Ethernet, Wi-Fi (802.11), PPP, ARP, 802.1Q |
| 1 | Physical | Bit | NIC, cable, signal encoding, optical fiber |

> The OSI model is a conceptual framework, not a strict implementation mandate. Real stacks are messier — TLS spans layers 5–6, QUIC spans layers 4–7. — paraphrased and summarized from standard networking references.

### 1.2 The TCP/IP Model (4 Layers)

The Internet's actual protocol suite uses a simpler 4-layer model:

| TCP/IP Layer | Corresponds to OSI | Protocols |
|---|---|---|
| Application | 5–7 | HTTP, DNS, TLS, QUIC, gRPC, SSH |
| Transport | 4 | TCP, UDP |
| Internet | 3 | IPv4, IPv6, ICMP, ARP |
| Link | 1–2 | Ethernet, Wi-Fi, PPP |

**Which model to use?** OSI is the *vocabulary* for talking about where in the stack a problem lives ("that's a layer 4 issue"). TCP/IP is the *implementation* that actually runs on your machine. Memorize the OSI number for each concept; think in TCP/IP layers when debugging.

### 1.3 Why the Bottom Layers Matter for Application Developers

A few concrete examples of L1/L2 issues that cause application-layer symptoms:

- **MTU mismatch**: Ethernet's default MTU is 1500 bytes. If a router link has a smaller MTU (e.g., a VPN with 1400-byte MTU), IP fragmentation or TCP PMTUD failure causes mysterious connectivity drops. Your `curl` hangs on large responses.
- **ARP cache poisoning**: A malicious host sends gratuitous ARPs claiming ownership of another host's IP → all traffic to that IP is redirected. This is a real attack vector on unprotected LAN segments.
- **Half-duplex collision**: On old Ethernet hubs (CSMA/CD), two nodes transmitting simultaneously cause a collision that must be detected and retransmitted. Gigabit Ethernet is always full-duplex point-to-point, so this is historical — but the backoff algorithm is still in Wi-Fi (CSMA/CA).

## 📚 2. Physical Layer (Layer 1)

### 2.1 What Layer 1 Does

Layer 1 concerns itself with the transmission of raw bits over a physical medium. It defines:

- **Signal encoding**: NRZ-I, Manchester encoding, 8b/10b, PAM4 (for 25/100GbE)
- **Media types**: copper (Cat5e/Cat6 UTP), coaxial (legacy), optical fiber (single-mode, multi-mode), Wi-Fi radio
- **Bit rates**: 10 Mbit/s (10BASE-T) → 1 Gbit/s (1000BASE-T) → 100 Gbit/s (100GBASE-SR4) → 400 Gbit/s+ (modern datacenter)
- **Connectors and pinouts**: RJ-45 (TIA-568B wiring), SFP+ (small form-factor pluggable transceivers)

### 2.2 Auto-negotiation

Modern NICs perform **auto-negotiation** (802.3u) to agree on speed and duplex. A mismatch (one side forced to 100Mbps half-duplex, other auto-negotiating to 1Gbps full-duplex) causes terrible performance that looks like congestion — a classic sysadmin trap.

```bash
# Check NIC speed and duplex (Linux)
ethtool eth0 | grep -E "Speed|Duplex"
# Speed: 1000Mb/s
# Duplex: Full
```

### 2.3 Fiber and Modern Datacenter

In datacenters, Layer 1 is increasingly **Direct Attach Copper (DAC)** twinax cables for short runs (<7m) and **optical fiber with QSFP28 transceivers** for rack-to-rack. The physical medium matters for latency: 5 ns/m in copper, ~5 ns/m in fiber (speed of light in glass ≈ 2×10⁸ m/s).

## 📚 3. Ethernet — The Dominant Layer-2 Protocol

### 3.1 History and Versions

Ethernet was invented at Xerox PARC (1973, Bob Metcalfe) and standardized as IEEE 802.3. There are two common frame formats:

- **Ethernet II (DIX)**: Used by virtually all modern IP traffic. Ethertype field distinguishes protocol.
- **IEEE 802.3 (classic)**: Length field instead of Ethertype; rare today except in STP/CDP frames.

### 3.2 Ethernet II Frame Structure

```
 ┌──────────┬────┬─────────┬─────────┬───────────┬────────────────────────┬──────┬─────┐
 │ Preamble │SFD │ Dst MAC │ Src MAC │ Ethertype │ Payload (IP Packet...) │ FCS  │ IFG │
 │  7 bytes │1 B │  6 B    │  6 B   │   2 B     │  46–1500 bytes         │ 4 B  │12 B │
 └──────────┴────┴─────────┴─────────┴───────────┴────────────────────────┴──────┴─────┘
```

| Field | Size | Purpose |
|---|---|---|
| **Preamble** | 7 bytes | `10101010…` pattern — clocks the receiver |
| **SFD** (Start Frame Delimiter) | 1 byte | `10101011` — marks end of preamble |
| **Destination MAC** | 6 bytes | Target hardware address; FF:FF:FF:FF:FF:FF = broadcast |
| **Source MAC** | 6 bytes | Sender's hardware address |
| **Ethertype** | 2 bytes | `0x0800`=IPv4, `0x0806`=ARP, `0x86DD`=IPv6, `0x8100`=802.1Q VLAN |
| **Payload** | 46–1500 bytes | The IP packet (or other L3 PDU); minimum 46 B to reach 64-byte frame minimum |
| **FCS** (Frame Check Sequence) | 4 bytes | CRC-32 over header+payload; receiver discards corrupt frames silently |
| **IFG** (Inter-Frame Gap) | 12 bytes | Mandatory idle time between frames for receiver reset |

> **Wireshark note**: Wireshark typically strips the preamble and FCS from captured frames — you see only dst MAC through payload in the frame detail.

### 3.3 Minimum Frame Size

The minimum Ethernet frame is **64 bytes** (excluding preamble/IFG). If a payload is smaller than 46 bytes, padding bytes are added. This matters historically for CSMA/CD collision detection: a frame must be on the wire long enough to detect a collision at the far end of a maximum-length segment (2500m in classic Ethernet).

### 3.4 Jumbo Frames

Standard Ethernet MTU = 1500 bytes. **Jumbo frames** extend this to 9000 bytes (vendor-specific). Used in:
- Storage networking (iSCSI, NFS over Ethernet)
- High-throughput intra-datacenter paths (requires all switches in the path to support jumbo frames)

Misconfigured jumbo frames (one node enabled, others not) cause partial connectivity failures that are maddening to debug.

## 📚 4. MAC Addresses

### 4.1 Structure (EUI-48)

A MAC address is a 48-bit (6-byte) globally unique hardware identifier assigned by the NIC manufacturer:

```
AA : BB : CC : DD : EE : FF
└────────┘   └──────────────┘
   OUI           Device-specific
(Organizationally Unique Identifier)
```

- **Bytes 0–2 (OUI)**: Assigned by IEEE to the manufacturer. `00:1A:2B` = Cisco; `DC:A6:32` = Raspberry Pi Foundation.
- **Bytes 3–5**: Manufacturer assigns uniquely per NIC.
- **Bit 0 of byte 0 (LSB)**: `0` = unicast; `1` = multicast.
- **Bit 1 of byte 0**: `0` = globally unique (OUI enforced); `1` = locally administered (software-assigned, e.g., VMs).

### 4.2 Special MAC Addresses

| Address | Meaning |
|---|---|
| `FF:FF:FF:FF:FF:FF` | Ethernet broadcast — all nodes on the segment |
| `01:00:5E:xx:xx:xx` | IPv4 multicast (IANA; `xx:xx:xx` derived from IP group) |
| `33:33:xx:xx:xx:xx` | IPv6 multicast (bit 0 of byte 0 set) |
| `00:00:00:00:00:00` | Placeholder / invalid |

### 4.3 MAC Address Tables in Switches

A Layer-2 switch maintains a **MAC Address Table** (CAM table — Content-Addressable Memory):

```
MAC Address         Port   VLAN   Age
---------------------------------
AA:BB:CC:DD:EE:FF   Gi0/1  1      120s
11:22:33:44:55:66   Gi0/2  1      45s
```

**Learning**: When a frame arrives, the switch records `{src_MAC → ingress_port}` in the table.
**Forwarding**: 
- If `dst_MAC` is in table → forward only to the known port (**unicast forwarding**)
- If `dst_MAC` is not in table → **flood** to all ports except ingress (**unknown unicast flood**)
- If `dst_MAC` is broadcast → flood to all ports in the VLAN

**Aging**: Entries expire (typically 300s) if no frame from that MAC is seen, preventing stale entries.

## 📚 5. ARP — Address Resolution Protocol

### 5.1 Why ARP Exists

IP packets carry 32-bit logical addresses. Ethernet frames carry 48-bit hardware addresses. When a host wants to send an IP packet to `192.168.1.20` on the same subnet, it needs to know what MAC address to put in the frame's destination field. **ARP resolves this**.

### 5.2 ARP Request / Reply Flow

```
Host A (192.168.1.10)                               Host B (192.168.1.20)
        │                                                   │
        │  ARP Request (broadcast: FF:FF:FF:FF:FF:FF)       │
        │  "Who has 192.168.1.20? Tell 192.168.1.10"        │
        ├──────────────────────────────────────────────────►│
        │                                                   │
        │  ARP Reply (unicast to AA:BB:CC:DD:EE:01)         │
        │  "192.168.1.20 is at AA:BB:CC:DD:EE:02"           │
        │◄──────────────────────────────────────────────────┤
        │                                                   │
        [Host A caches: 192.168.1.20 → AA:BB:CC:DD:EE:02]
        [Normal IP communication begins]
```

### 5.3 ARP Packet Format

ARP (RFC 826) sits directly in the Ethernet payload (Ethertype `0x0806`):

| Field | Size | Value |
|---|---|---|
| Hardware type | 2 B | `0x0001` = Ethernet |
| Protocol type | 2 B | `0x0800` = IPv4 |
| HW addr length | 1 B | 6 (MAC bytes) |
| Proto addr length | 1 B | 4 (IPv4 bytes) |
| Operation | 2 B | `1`=Request, `2`=Reply |
| Sender HW addr | 6 B | Source MAC |
| Sender proto addr | 4 B | Source IP |
| Target HW addr | 6 B | `00:00:00:00:00:00` in Request; target MAC in Reply |
| Target proto addr | 4 B | Target IP |

### 5.4 ARP Cache

The kernel caches ARP entries. Cache TTL is typically 20 minutes on Linux (configurable via `net.ipv4.neigh.default.gc_stale_time`).

```bash
# View ARP cache (Linux)
ip neigh show
# 192.168.1.1  dev eth0  lladdr 74:d4:35:aa:bb:cc  REACHABLE

# Force flush
ip neigh flush all
```

### 5.5 Gratuitous ARP

A **gratuitous ARP** is an ARP reply sent without a preceding request, with `sender_IP == target_IP`. Used for:
- **IP address conflict detection**: Announce your IP at boot; anyone already using it will reply.
- **Cache invalidation after failover**: When a virtual IP moves from primary to standby in HA pairs, the new owner sends a gratuitous ARP to update all neighbors' caches.
- **ARP cache poisoning (attack)**: Malicious gratuitous ARPs redirect traffic through an attacker's machine.

### 5.6 Proxy ARP

A router can answer ARP requests on behalf of hosts in another subnet. Used in some legacy VPN and MPLS configurations but generally avoided as it blurs subnet boundaries.

## 📚 6. VLANs and 802.1Q Tagging

### 6.1 What a VLAN Is

A **VLAN** (Virtual Local Area Network) partitions a physical switch into multiple independent broadcast domains. Hosts in VLAN 10 cannot send frames to hosts in VLAN 20 without routing (a Layer-3 hop).

Benefits: security isolation, broadcast containment, flexible topology (same VLAN can span multiple physical switches).

### 6.2 802.1Q Frame Tagging

When a frame crosses a **trunk port** (a switch-to-switch or switch-to-router link carrying multiple VLANs), a 4-byte 802.1Q tag is inserted between the Source MAC and the Ethertype:

```
 ┌─────────┬─────────┬──────┬──────────────┬──────────────┬───────────┬─────────┐
 │ Dst MAC │ Src MAC │ TPID │  TCI         │  Ethertype   │  Payload  │   FCS   │
 │  6 B    │  6 B    │0x8100│ PCP(3b)+DEI+ │  2 B         │  ...      │   4 B   │
 │         │         │  2 B │  VID(12b) 2B │              │           │         │
 └─────────┴─────────┴──────┴──────────────┴──────────────┴───────────┴─────────┘
```

- **TPID** (Tag Protocol Identifier): `0x8100` — signals this is an 802.1Q-tagged frame
- **PCP** (Priority Code Point): 3 bits — QoS priority (`0`=best-effort, `6`=voice, `7`=network control)
- **DEI** (Drop Eligible Indicator): 1 bit — frame may be dropped under congestion
- **VID** (VLAN Identifier): 12 bits — VLAN number (0–4095; 0 and 4095 reserved; 1 is default)

## 🛠️ 7. Worked Example — Tracing a Frame Across a Switch

**Scenario**: Host A (`192.168.1.10`, MAC `AA:AA:AA:AA:AA:01`) pings Host B (`192.168.1.20`, MAC `BB:BB:BB:BB:BB:02`). Both are connected to a switch. It's the first packet.

**Step 1 — ARP**: Host A has no ARP cache entry for `192.168.1.20`.
- Host A constructs ARP Request: `src_ip=192.168.1.10, dst_ip=192.168.1.20, dst_mac=FF:FF:FF:FF:FF:FF`
- Switch receives on port Gi0/1 → learns `AA:AA:AA:AA:AA:01 → Gi0/1` → floods out all ports (Gi0/2, Gi0/3…)
- Host B receives the broadcast → sends ARP Reply unicast to Host A
- Switch receives Reply on Gi0/2 → learns `BB:BB:BB:BB:BB:02 → Gi0/2` → forwards to Gi0/1

**Step 2 — ICMP Echo**: Host A now knows Host B's MAC.
- Host A constructs Ethernet frame: `dst=BB:BB:BB:BB:BB:02, src=AA:AA:AA:AA:AA:01, etype=0x0800, payload=IP{ICMP Echo}`
- Switch looks up `BB:BB:BB:BB:BB:02` → found in CAM at Gi0/2 → forwards **only** to Gi0/2 (no flood)
- Host B receives, sends ICMP Echo Reply, switch forwards back to Gi0/1

**Total RTT** on a modern gigabit switch: ~1–5 µs store-and-forward latency.

## ⚠️ 8. Common Misconceptions

- **"Switches operate at Layer 3."** Layer-2 switches operate at Layer 2 (frame level). Layer-3 switches have built-in routing hardware — they're both. Classic L2 switches know nothing about IP addresses.
- **"ARP is secure."** ARP has no authentication. Any host can claim ownership of any IP. Defenses: Dynamic ARP Inspection (DAI) on managed switches, ARP monitoring with tools like `arpwatch`.
- **"The MAC address is permanent."** The burned-in address (BIA) is permanent, but software can override it with any locally-administered address. Most OSes do this for privacy (random MAC for Wi-Fi probe requests since iOS 14 / Android 10).
- **"Broadcasts are cheap."** On a small network, yes. At 10,000 hosts in one broadcast domain, ARP storms become a real performance problem. VLANs exist partly to contain broadcast domains.
- **"802.1Q adds overhead."** Yes — 4 bytes per frame. At 100 Gbit/s line rate with 64-byte frames, this is measurable (~5.8%) but accepted in any environment with VLANs.
