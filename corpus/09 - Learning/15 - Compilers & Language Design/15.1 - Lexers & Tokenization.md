# 15.1 — Lexers & Tokenization

> *"The lexer is deceptively simple. It takes a stream of characters and turns it into a stream of tokens. That's all. And yet, every mistake in the lexer propagates through every subsequent phase of the compiler."*

The lexer (also called the *scanner* or *tokenizer*) is the front door of every compiler and interpreter. It solves one question: **given a sequence of raw characters, what are the meaningful units?** The word `while` is three characters — but a human reader (and a well-designed lexer) sees it as a single unit meaning "the while keyword". The characters ` + ` are meaningful as a token. The space characters between them are not.

This chapter builds from first principles. We start with regular expressions — the mathematical backbone of lexers — then trace the theoretical pipeline from regex to NFA to DFA to minimized DFA. We finish by implementing a real hand-written lexer in Python that you can extend for any language.

By the end of this chapter you will be able to:

6. Implement a **hand-written lexer in Python** from scratch.

## 📚 1. What Is a Token?

A **token** is the minimal meaningful unit of a programming language. It has:

- A **type** (also called a *tag* or *category*): `NUMBER`, `IDENT`, `PLUS`, `IF`, etc.
- A **lexeme**: the original text — `"3"`, `"x"`, `"+"`, `"if"`.
- Optionally: a **literal value** — the integer `3` as a Python `int`, not the string `"3"`.
- Optionally: **source location** (line, column) for error messages.

### Token Types in a Typical Language

| Category | Examples | Regex pattern |
|---|---|---|
| **Keywords** | `if`, `while`, `return`, `def` | `if\|while\|return\|def` |
| **Identifiers** | `x`, `my_var`, `CamelCase` | `[a-zA-Z_][a-zA-Z_0-9]*` |
| **Integer literals** | `0`, `42`, `255` | `[0-9]+` |
| **Float literals** | `3.14`, `1e-5` | `[0-9]+\.[0-9]*([eE][+-]?[0-9]+)?` |
| **String literals** | `"hello"`, `'world'` | `"[^"]*"\|'[^']*'` |
| **Operators** | `+`, `-`, `*`, `/`, `==` | `\+\|-\|\*\|\/\|==` |
| **Delimiters** | `(`, `)`, `{`, `}`, `;`, `,` | `[(){};,]` |
| **Whitespace** | spaces, tabs, newlines | `[ \t\n\r]+` → *discard* |
| **Comments** | `// ...`, `# ...` | `\/\/.*\|#.*` → *discard* |

> **Keywords vs identifiers:** a lexer typically matches keywords as identifiers first, then checks if the lexeme is in a reserved-word table. This is simpler than writing a separate DFA branch per keyword.

### Definition 15.1.1 — Token

A **token** is a pair `(type, lexeme)`. In code:

```python
from dataclasses import dataclass
from enum import Enum, auto

class TokenType(Enum):
    # Literals
    NUMBER  = auto()
    STRING  = auto()
    # Identifiers & keywords
    IDENT   = auto()
    IF      = auto()
    WHILE   = auto()
    RETURN  = auto()
    DEF     = auto()
    # Operators
    PLUS    = auto()
    MINUS   = auto()
    STAR    = auto()
    SLASH   = auto()
    ASSIGN  = auto()
    EQ      = auto()   # ==
    # Delimiters
    LPAREN  = auto()
    RPAREN  = auto()
    LBRACE  = auto()
    RBRACE  = auto()
    SEMI    = auto()
    COMMA   = auto()
    # Control
    EOF     = auto()

@dataclass
class Token:
    type:    TokenType
    lexeme:  str
    line:    int
    column:  int
    literal: object = None   # parsed value if applicable
```

## 📚 2. Regular Expressions & Their Formal Theory

Regular expressions are more than a search-and-replace tool — they are the **formal specification language** for what tokens look like.

### Definition 15.1.2 — Regular Expression (formal)

Over an alphabet Σ, a **regular expression** is defined recursively:

- **∅** matches nothing.
- **ε** matches the empty string.
- **a** (for any a ∈ Σ) matches the single character `a`.
- **r₁ | r₂** (alternation) matches anything r₁ or r₂ matches.
- **r₁ r₂** (concatenation) matches an r₁-match followed by an r₂-match.
- **r\*** (Kleene star) matches zero or more repetitions of r.

From these primitives, the shorthands `r+` (one or more, = `r r*`), `r?` (zero or one), and `[a-z]` (character class) are all derived.

### Worked Example: regex for a Python identifier

```
[a-zA-Z_][a-zA-Z_0-9]*
```

- `[a-zA-Z_]` — first character: any letter or underscore
- `[a-zA-Z_0-9]*` — remaining characters: zero or more letters, digits, or underscores

This rejects `9bad` (starts with digit) and accepts `_private`, `CamelCase99`.

## 📚 3. From Regex to NFA — Thompson Construction

An **NFA (Nondeterministic Finite Automaton)** is a theoretical machine that:
- Has a finite set of states Q
- Has a start state q₀ ∈ Q
- Has one or more accepting states F ⊆ Q
- Has a transition function δ: Q × (Σ ∪ {ε}) → 2^Q (can go to *multiple* states, or take free ε-transitions)

### Thompson Construction Rules

For each regex operator, there is a systematic NFA construction:

| Regex | NFA construction |
|---|---|
| **ε** | →(q₀)→→(q₁)  — ε from q₀ to q₁ |
| **a** | →(q₀)—a→(q₁) |
| **r₁ \| r₂** | New start state with ε-transitions to both NFA(r₁) and NFA(r₂); both accept into a new final state |
| **r₁ r₂** | Connect NFA(r₁)'s accept state to NFA(r₂)'s start state with ε |
| **r\*** | New start/final state; ε to NFA(r); NFA(r)'s accept goes back to NFA(r)'s start (loop); ε from NFA(r)'s accept to final |

### Example: NFA for `[a-z]+` (one or more lowercase letters)

```
→(q0) --[a-z]--> (q1) --[a-z]--> (accepting)
                   ^                   |
                   |_____ε_____________|
```
The self-loop on q1 via ε back allows any number of letters. The final state is q1 itself (double-ringed).

> Thompson construction guarantees: **every regex has an equivalent NFA**, and the NFA has at most 2×(number of operators) states.

## 📚 4. From NFA to DFA — Subset Construction

NFAs are great for theoretical proofs but impractical for implementation (exponential branching). We convert to a **DFA (Deterministic Finite Automaton)**:

- Each DFA state corresponds to a **set of NFA states**
- No ε-transitions
- Each input character leads to **exactly one** next state

### The Subset Construction Algorithm

```python
def nfa_to_dfa(nfa, start):
    initial = epsilon_closure({start})  # all states reachable via ε from start
    worklist = [frozenset(initial)]
    dfa_states = {frozenset(initial): "S0"}
    dfa_transitions = {}
    accepting = set()
    
    while worklist:
        current = worklist.pop()
        for symbol in nfa.alphabet:
            # move: all NFA states reachable on 'symbol' from any state in current
            moved = set()
            for nfa_state in current:
                moved |= nfa.transitions.get((nfa_state, symbol), set())
            # close under ε
            closed = epsilon_closure(moved)
            if not closed:
                continue
            fs = frozenset(closed)
            if fs not in dfa_states:
                name = f"S{len(dfa_states)}"
                dfa_states[fs] = name
                worklist.append(fs)
            dfa_transitions[(dfa_states[current], symbol)] = dfa_states[fs]
        
        # accepting if any NFA accept state is in this subset
        if any(s in nfa.accepting for s in current):
            accepting.add(dfa_states[current])
    
    return dfa_transitions, accepting
```

### Why bother converting?

| Property | NFA | DFA |
|---|---|---|
| # states | O(N) | O(2^N) worst case |
| Matching step | Exponential backtracking | O(1) per input char |
| Implementation | Complex | Simple table lookup |
| Used in | Theory | Real lexer tools (flex, re2) |

The DFA can have exponentially more states than the NFA, but in practice tokenizer DFAs are small, and the O(1)-per-character matching is decisive.

## 📚 5. DFA Minimization — Hopcroft's Algorithm

Two states are **equivalent** if they produce identical behavior for all input suffixes. Merging equivalent states gives the **minimal DFA** — the smallest possible automaton for the language.

**Hopcroft's algorithm** (1971):
1. Start with two partitions: accepting states and non-accepting states.
2. Iteratively split partitions when some input symbol distinguishes states within a partition.
3. Terminate when no more splits are possible.
4. Each partition becomes one state in the minimized DFA.

Time complexity: O(n log n) in the number of DFA states.

> Most production lexers (like Flex) operate on the minimized DFA. Python's `re` module uses a different approach (bytecode-based NFA simulation) for flexibility, which is why it supports backreferences that a pure DFA cannot.

## 📚 6. The Maximal Munch Rule

When multiple tokens could start at the current position, the lexer should always take the **longest possible match**. This is the **maximal munch rule** (also called *greedy matching*).

### Examples

| Input | Wrong (short) | Correct (maximal munch) |
|---|---|---|
| `x++` | `x`, `+`, `+` | `x`, `++` (increment operator) |
| `!=` | `!`, `=` | `!=` (not-equal operator) |
| `while` | `w`, `h`, `i`, `l`, `e` (5 idents!) | `while` (keyword) |
| `123.45` | `123`, `.`, `45` | `123.45` (float literal) |
| `<=` | `<`, `=` | `<=` (less-or-equal operator) |

Implementation: the DFA always continues as long as it can make a transition. When it gets stuck, it backtracks to the last accepting state and emits that token.

```python
def next_token(source: str, pos: int) -> tuple[Token, int]:
    """Return the next token and the new position."""
    # Skip whitespace
    while pos < len(source) and source[pos] in ' \t\n\r':
        pos += 1
    if pos >= len(source):
        return Token(TokenType.EOF, '', -1, -1), pos
    
    last_accept_pos = -1
    last_accept_type = None
    state = DFA_START
    i = pos
    
    while i < len(source):
        ch = source[i]
        next_state = dfa_transition(state, ch)
        if next_state == DFA_ERROR:
            break
        state = next_state
        if state in DFA_ACCEPTING:
            last_accept_pos = i + 1
            last_accept_type = DFA_ACCEPTING[state]
        i += 1
    
    if last_accept_pos == -1:
        raise LexError(f"Unexpected character {source[pos]!r} at position {pos}")
    
    lexeme = source[pos:last_accept_pos]
    return Token(last_accept_type, lexeme, -1, -1), last_accept_pos
```

## 📚 7. Hand-Written Lexer in Python

Real production compilers (GCC, Clang, CPython, rustc) use **hand-written lexers**, not generated ones, for:
- Better error messages
- Finer control over edge cases
- No dependency on a lexer generator

Here is a complete hand-written lexer for a small expression language:

```python
from dataclasses import dataclass
from enum import Enum, auto
from typing import Iterator

class TT(Enum):
    NUMBER = auto(); IDENT = auto(); PLUS = auto(); MINUS = auto()
    STAR = auto(); SLASH = auto(); ASSIGN = auto(); EQ = auto()
    LPAREN = auto(); RPAREN = auto(); IF = auto(); ELSE = auto()
    RETURN = auto(); EOF = auto()

KEYWORDS = {'if': TT.IF, 'else': TT.ELSE, 'return': TT.RETURN}

@dataclass
class Token:
    type: TT; lexeme: str; line: int

class Lexer:
    def __init__(self, source: str):
        self.source = source
        self.pos = 0
        self.line = 1

    def _peek(self) -> str:
        return self.source[self.pos] if self.pos < len(self.source) else '\0'

    def _peek2(self) -> str:
        return self.source[self.pos + 1] if self.pos + 1 < len(self.source) else '\0'

    def _advance(self) -> str:
        ch = self.source[self.pos]
        self.pos += 1
        if ch == '\n':
            self.line += 1
        return ch

    def _skip_whitespace_and_comments(self):
        while self.pos < len(self.source):
            ch = self._peek()
            if ch in ' \t\r\n':
                self._advance()
            elif ch == '#':                        # Python-style line comment
                while self._peek() not in ('\n', '\0'):
                    self._advance()
            else:
                break

    def _read_number(self) -> Token:
        start = self.pos
        while self._peek().isdigit():
            self._advance()
        # Optional decimal part
        if self._peek() == '.' and self._peek2().isdigit():
            self._advance()
            while self._peek().isdigit():
                self._advance()
        lexeme = self.source[start:self.pos]
        return Token(TT.NUMBER, lexeme, self.line)

    def _read_ident_or_keyword(self) -> Token:
        start = self.pos
        while self._peek().isalnum() or self._peek() == '_':
            self._advance()
        lexeme = self.source[start:self.pos]
        tt = KEYWORDS.get(lexeme, TT.IDENT)
        return Token(tt, lexeme, self.line)

    def next_token(self) -> Token:
        self._skip_whitespace_and_comments()
        ch = self._peek()
        if ch == '\0':
            return Token(TT.EOF, '', self.line)

        if ch.isdigit():
            return self._read_number()
        if ch.isalpha() or ch == '_':
            return self._read_ident_or_keyword()

        self._advance()
        match ch:
            case '+': return Token(TT.PLUS,   '+', self.line)
            case '-': return Token(TT.MINUS,  '-', self.line)
            case '*': return Token(TT.STAR,   '*', self.line)
            case '/': return Token(TT.SLASH,  '/', self.line)
            case '(':  return Token(TT.LPAREN, '(', self.line)
            case ')':  return Token(TT.RPAREN, ')', self.line)
            case '=':
                if self._peek() == '=':
                    self._advance()
                    return Token(TT.EQ, '==', self.line)
                return Token(TT.ASSIGN, '=', self.line)
            case _:
                raise SyntaxError(f"Unexpected character {ch!r} at line {self.line}")

    def tokenize(self) -> list[Token]:
        tokens = []
        while True:
            tok = self.next_token()
            tokens.append(tok)
            if tok.type == TT.EOF:
                break
        return tokens

# Demo
if __name__ == '__main__':
    src = "x = 3 + y * 2"
    lexer = Lexer(src)
    for tok in lexer.tokenize():
        print(tok)
```

Running this on `x = 3 + y * 2` produces:

```
Token(type=<TT.IDENT: 2>,  lexeme='x',  line=1)
Token(type=<TT.ASSIGN: 8>, lexeme='=',  line=1)
Token(type=<TT.NUMBER: 1>, lexeme='3',  line=1)
Token(type=<TT.PLUS: 3>,   lexeme='+',  line=1)
Token(type=<TT.IDENT: 2>,  lexeme='y',  line=1)
Token(type=<TT.STAR: 5>,   lexeme='*',  line=1)
Token(type=<TT.NUMBER: 1>, lexeme='2',  line=1)
Token(type=<TT.EOF: 14>,   lexeme='',   line=1)
```

Let us trace the lexer step by step.

| Step | pos | ch | State | Action | Emitted token |
|---|---|---|---|---|---|
| 1 | 0 | `x` | start | isalpha → read_ident | — |
| 2 | 0→1 | `x` | ident | consume | — |
| 3 | 1 | ` ` | ident end | ` ` not alnum → stop | `IDENT "x"` |
| 4 | 1 | ` ` | start | skip whitespace | — |
| 5 | 2 | `=` | start | `=` → peek next | — |
| 6 | 2→3 | `=`,` ` | `=` | next is ` ` not `=` → ASSIGN | `ASSIGN "="` |
| 7 | 3 | ` ` | start | skip | — |

## 📚 9. Regex-Based Tokenizer (Python `re` module)

For simpler use cases, Python's `re.match` with named groups provides a concise alternative:

```python
import re
from typing import Iterator

TOKEN_SPEC = [
    ('NUMBER',  r'\d+(\.\d*)?'),
    ('IDENT',   r'[a-zA-Z_]\w*'),
    ('ASSIGN',  r'=='),     # must come BEFORE single '='
    ('EQ',      r'='),
    ('PLUS',    r'\+'),
    ('MINUS',   r'-'),
    ('STAR',    r'\*'),
    ('SLASH',   r'/'),
    ('LPAREN',  r'\('),
    ('RPAREN',  r'\)'),
    ('SKIP',    r'[ \t\n]+'),   # whitespace → discard
    ('MISMATCH', r'.'),          # any other char → error
]

MASTER_RE = re.compile(
    '|'.join(f'(?P<{name}>{pattern})' for name, pattern in TOKEN_SPEC)
)

KEYWORDS = {'if', 'while', 'return', 'def', 'else'}

def tokenize(code: str) -> Iterator[tuple[str, str]]:
    for mo in MASTER_RE.finditer(code):
        kind = mo.lastgroup
        value = mo.group()
        if kind == 'SKIP':
            continue
        elif kind == 'MISMATCH':
            raise SyntaxError(f"Unexpected {value!r}")
        elif kind == 'IDENT' and value in KEYWORDS:
            kind = value.upper()    # 'if' → 'IF'
        yield kind, value

# Demo
for tt, lex in tokenize("x = 3 + y * 2"):
    print(f"{tt:10} {lex!r}")
```

Output:
```
IDENT      'x'
EQ         '='
NUMBER     '3'
PLUS       '+'
IDENT      'y'
STAR       '*'
NUMBER     '2'
```

> **When to use hand-written vs regex-based:** For small DSLs, regex is fine. For production compilers with complex string/comment handling (raw strings, nested comments, unicode escapes), hand-written is safer and gives better errors.

## 📚 10. Using Python's Built-In `tokenize` Module

Python ships a complete tokenizer for its own syntax:

import io

## ⚠️ 12. Common Misconceptions

- **"Regular expressions can parse HTML/XML."** No — HTML requires balanced tags (context-free), which is beyond what regular expressions can express. Don't use `re` to parse HTML. Use `html.parser` or `BeautifulSoup`.
- **"Keywords are separate from identifiers in the DFA."** Typically not. The lexer matches `while` as an identifier, then checks the keyword table. This avoids building a separate DFA branch per keyword.
- **"Python's `re` module implements a pure DFA."** No — Python's `re` uses a bytecode-based NFA simulation that supports backreferences (which a pure DFA cannot). Libraries like `re2` (Google) and `hyperscan` use actual DFAs and are much faster for large inputs.
- **"The lexer resolves ambiguity."** The lexer resolves *lexical* ambiguity with maximal munch. Syntactic ambiguity (like `if-else` pairing) is the parser's problem.
- **"Whitespace is always discarded."** Not in Python! Indentation tokens (`INDENT`, `DEDENT`) are generated by the Python tokenizer and carry syntactic meaning. This is why Python's grammar is context-sensitive at the token level.
