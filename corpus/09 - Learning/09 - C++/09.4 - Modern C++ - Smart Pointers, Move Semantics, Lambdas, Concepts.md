# 09.4 — Modern C++: Smart Pointers, Move Semantics, Lambdas, Concepts

> *"The most important single thing you can do to improve your C++ code is to use smart pointers and move semantics. They eliminate entire categories of bugs."* — Herb Sutter

This chapter covers the features that transformed C++ from "C with classes" into a modern, safe, expressive language. These four features work together: smart pointers use move semantics for ownership transfer, lambdas capture variables by move, and concepts constrain what types your templates accept.

---

## 🎯 Learning Objectives

By the end of this chapter you will be able to:

1. Choose between `unique_ptr`, `shared_ptr`, and `weak_ptr` for any ownership scenario.
2. Implement move constructors/assignment and understand when the compiler moves automatically.
3. Write lambdas with captures (by value, by reference, by move) and use them with STL algorithms.
4. Define and use concepts to constrain templates with clear, readable requirements.
5. Apply perfect forwarding with `std::forward` in generic code.
6. Identify and fix common pitfalls: circular references, moved-from objects, dangling captures.

## 📚 1. Concepts & Definitions

### Definition 09.4.1 — Smart Pointers

Smart pointers are RAII wrappers around raw pointers that automatically manage memory:

| Type | Ownership | Overhead | Use Case |
|------|-----------|----------|----------|
| `std::unique_ptr<T>` | Exclusive (one owner) | Zero (same as raw pointer) | Default choice for heap objects |
| `std::shared_ptr<T>` | Shared (reference counted) | Control block + atomic refcount | Multiple owners, unclear lifetime |
| `std::weak_ptr<T>` | Non-owning observer | Shares control block | Break cycles, optional observation |

```cpp
#include <memory>

// unique_ptr: exclusive ownership, zero overhead
auto player = std::make_unique<Player>("Bill", 100);
// player->name();  // Use like a raw pointer
// auto copy = player;  // COMPILE ERROR: can't copy unique_ptr
auto transferred = std::move(player);  // OK: transfer ownership
// player is now nullptr

// shared_ptr: reference-counted shared ownership
auto texture = std::make_shared<Texture>("wall.png");
auto alias = texture;  // refcount = 2
// texture destroyed when last shared_ptr dies

// weak_ptr: non-owning observer (doesn't prevent destruction)
std::weak_ptr<Texture> cache_entry = texture;
if (auto locked = cache_entry.lock()) {  // Promotes to shared_ptr if alive
    locked->bind();
}
```

### Definition 09.4.2 — Move Semantics

**Moving** transfers resources from one object to another without copying. The source object is left in a "valid but unspecified state" (typically empty/null).

```cpp
std::vector<int> a = {1, 2, 3, 4, 5};  // a owns heap buffer

std::vector<int> b = std::move(a);
// b now owns the buffer (pointer transferred)
// a is empty (size 0, no allocation)
// Total cost: 3 pointer copies (data, size, capacity) — O(1)
// Without move: would copy all elements — O(n)
```

**When moves happen automatically:**
1. Returning a local variable: `return local_vec;`
2. Passing a temporary: `process(std::vector{1,2,3});`
3. `std::move()` explicitly: `process(std::move(my_vec));`

### Definition 09.4.3 — Rvalue References (`T&&`)

An **rvalue reference** binds to temporaries and moved-from objects. It's the mechanism that enables move semantics:

```cpp
void process(std::string&& s) {
    // s is an rvalue reference — we're allowed to "steal" its guts
    internal_buffer_ = std::move(s);  // Transfer ownership
}

std::string greeting = "Hello";
// process(greeting);           // ERROR: can't bind lvalue to &&
process(std::move(greeting));   // OK: explicitly cast to rvalue
process(std::string("temp"));   // OK: temporary is already an rvalue
```

### Definition 09.4.4 — Lambdas

Lambdas are **anonymous function objects** (closures) defined inline:

```cpp
// Basic lambda
auto square = [](int x) { return x * x; };
square(5);  // 25

// With captures
int multiplier = 3;
auto scale = [multiplier](int x) { return x * multiplier; };
scale(5);  // 15

// Capture modes:
[=]  // Capture all by value (copy)
[&]  // Capture all by reference
[x]  // Capture x by value
[&x] // Capture x by reference
[x = std::move(obj)]  // Capture by move (C++14)
[this]  // Capture this pointer
[*this] // Capture this by value (copy the object, C++17)
```

### Definition 09.4.5 — Concepts (C++20)

**Concepts** are named constraints on template parameters. They replace SFINAE with readable, composable requirements:

```cpp
#include <concepts>

// Define a concept
template<typename T>
concept Numeric = std::integral<T> || std::floating_point<T>;

// Use it to constrain a template
template<Numeric T>
T clamp(T value, T min, T max) {
    return value < min ? min : (value > max ? max : value);
}

clamp(5, 0, 10);      // OK: int satisfies Numeric
clamp(3.14, 0.0, 1.0); // OK: double satisfies Numeric
// clamp("hi", "a", "z"); // ERROR: string doesn't satisfy Numeric
```

## 🧩 2. Mental Models

### Model 2.4.1 — "unique_ptr = Python's Default (But Explicit)"

In Python, when you assign `x = SomeObject()`, x is the sole reference. When x goes out of scope, the object is garbage collected. `unique_ptr` is the same concept, but:
- Destruction is **immediate** (not deferred to GC)
- Ownership transfer is **explicit** (`std::move`)
- The compiler **enforces** single ownership (can't accidentally share)

```python
# Python: implicit reference semantics
player = Player("Bill")  # player "owns" the object
other = player           # Now both reference it (shared!)
```

```cpp
// C++: explicit ownership
auto player = std::make_unique<Player>("Bill");  // player owns it
// auto other = player;                          // COMPILE ERROR
auto other = std::move(player);                  // Explicit transfer
```

### Model 2.4.2 — "Move = Stealing the Guts"

A move doesn't copy data — it **steals the internal pointers/handles** from the source:

```
Before move:
  src: [ptr → heap data] [size: 1000] [capacity: 1024]
  dst: [ptr → nullptr]   [size: 0]    [capacity: 0]

After move (3 pointer-sized copies):
  src: [ptr → nullptr]   [size: 0]    [capacity: 0]     ← "empty shell"
  dst: [ptr → heap data] [size: 1000] [capacity: 1024]  ← "stole the guts"
```

### Model 2.4.3 — "Lambdas Are Compiler-Generated Classes"

When you write a lambda, the compiler generates an anonymous class:

```cpp
int x = 10;
auto fn = [x](int y) { return x + y; };

// Compiler generates something like:
struct __lambda_42 {
    int x;  // Captured variable
    int operator()(int y) const { return x + y; }
};
__lambda_42 fn{x};
```

This is why lambdas are zero-cost — they're just structs with `operator()`. The compiler can inline them completely.

## 🔑 3. Mechanics

### 3.1 — `unique_ptr` Patterns

```cpp
#include <memory>

// Creation
auto p = std::make_unique<Player>("Bill", 100);  // Preferred
std::unique_ptr<Player> p2(new Player("Alice", 95));  // OK but less safe

// Custom deleter (for C APIs)
auto file = std::unique_ptr<FILE, decltype(&fclose)>(
    fopen("data.bin", "rb"), &fclose
);

// Array form
auto buffer = std::make_unique<float[]>(1024);
buffer[0] = 3.14f;

// Transfer ownership
void game_world_takes_ownership(std::unique_ptr<Entity> entity);
game_world_takes_ownership(std::move(p));  // Caller gives up ownership

// Factory pattern
std::unique_ptr<Shape> create_shape(std::string_view type) {
    if (type == "circle") return std::make_unique<Circle>(1.0);
    if (type == "rect")   return std::make_unique<Rectangle>(09.0, 3.0);
    return nullptr;
}
```

### 3.2 — `shared_ptr` and `weak_ptr`

```cpp
// shared_ptr: reference-counted ownership
auto texture = std::make_shared<Texture>("brick.png");
// Control block: [strong_count: 1, weak_count: 0, ptr, deleter]

{
    auto alias = texture;  // strong_count: 2
    auto another = texture; // strong_count: 3
}  // strong_count: 1 (aliases destroyed)

// weak_ptr: observe without owning
class TextureCache {
    std::unordered_map<std::string, std::weak_ptr<Texture>> cache_;
public:
    std::shared_ptr<Texture> get(const std::string& path) {
        if (auto it = cache_.find(path); it != cache_.end()) {
            if (auto tex = it->second.lock()) {  // Still alive?
                return tex;  // Return existing
            }
            cache_.erase(it);  // Dead, clean up
        }
        auto tex = std::make_shared<Texture>(path);
        cache_[path] = tex;  // Store weak reference
        return tex;
    }
};
```

### 3.3 — Move Constructor & Assignment

```cpp
class DynamicArray {
    int* data_ = nullptr;
    size_t size_ = 0;

public:
    explicit DynamicArray(size_t n)
        : data_(new int[n]{}), size_(n) {}

    ~DynamicArray() { delete[] data_; }

    // Copy constructor (deep copy)
    DynamicArray(const DynamicArray& other)
        : data_(new int[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + size_, data_);
    }

    // Move constructor (steal resources)
    DynamicArray(DynamicArray&& other) noexcept
        : data_(std::exchange(other.data_, nullptr))
        , size_(std::exchange(other.size_, 0)) {}

    // Copy assignment
    DynamicArray& operator=(const DynamicArray& other) {
        if (this != &other) {
            DynamicArray tmp(other);  // Copy-and-swap idiom
            swap(*this, tmp);
        }
        return *this;
    }

    // Move assignment
    DynamicArray& operator=(DynamicArray&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = std::exchange(other.data_, nullptr);
            size_ = std::exchange(other.size_, 0);
        }
        return *this;
    }

    friend void swap(DynamicArray& a, DynamicArray& b) noexcept {
        std::swap(a.data_, b.data_);
        std::swap(a.size_, b.size_);
    }
};
```

### 3.4 — Perfect Forwarding

```cpp
// Problem: How to write a wrapper that passes arguments perfectly?
template<typename T, typename... Args>
std::unique_ptr<T> make_unique_wrapper(Args&&... args) {
    // std::forward preserves value category:
    // - lvalue args stay lvalues
    // - rvalue args stay rvalues
    return std::make_unique<T>(std::forward<Args>(args)...);
}

// Without forward: everything would be copied (args are lvalues inside the function)
// With forward: moves happen when the caller passed rvalues

std::string name = "Bill";
auto p1 = make_unique_wrapper<Player>(name, 100);       // name copied (lvalue)
auto p2 = make_unique_wrapper<Player>("Alice", 95);     // "Alice" moved (rvalue)
auto p3 = make_unique_wrapper<Player>(std::move(name), 100); // name moved
```

### 3.5 — Lambda Deep Dive

```cpp
// Generic lambda (C++14) — auto parameters
auto print_any = [](const auto& x) { fmt::print("{}\n", x); };

// Mutable lambda (modify captured values)
int counter = 0;
auto increment = [counter]() mutable { return ++counter; };
increment(); // returns 1
increment(); // returns 2
// counter is still 0 (lambda has its own copy)

// Move capture (C++14)
auto buffer = std::make_unique<std::vector<int>>(1000);
auto processor = [buf = std::move(buffer)]() {
    // buf is owned by the lambda now
    process(*buf);
};

// Immediately-invoked lambda (IIFE) for complex initialization
const auto config = [&]() {
    Config c;
    c.width = parse_int(args["width"]);
    c.height = parse_int(args["height"]);
    c.fullscreen = args.contains("fullscreen");
    return c;
}();  // Note the () — invoked immediately

// Lambda as comparator
std::vector<Player> players = /* ... */;
std::ranges::sort(players, [](const Player& a, const Player& b) {
    return a.score() > b.score();  // Sort descending by score
});

// Recursive lambda (C++23 deducing this, or std::function workaround)
// C++23:
auto fibonacci = [](this auto&& self, int n) -> int {
    if (n <= 1) return n;
    return self(n - 1) + self(n - 2);
};
```

### 3.6 — Concepts in Depth (C++20)

```cpp
#include <concepts>
#include <ranges>

// Custom concept: anything that can be serialized to JSON
template<typename T>
concept Serializable = requires(const T& obj) {
    { obj.to_json() } -> std::convertible_to<std::string>;
    { T::from_json(std::string{}) } -> std::same_as<T>;
};

// Compound concept
template<typename T>
concept GameEntity = requires(T& entity, float dt) {
    { entity.update(dt) } -> std::same_as<void>;
    { entity.position() } -> std::convertible_to<Vec3>;
    { entity.is_alive() } -> std::same_as<bool>;
    requires std::movable<T>;
};

// Using concepts in function signatures
void tick(GameEntity auto& entity, float dt) {
    if (entity.is_alive()) {
        entity.update(dt);
    }
}

// Concept with multiple constraints
template<typename Container>
concept SortableContainer =
    std::ranges::random_access_range<Container> &&
    std::sortable<std::ranges::iterator_t<Container>>;

void sort_it(SortableContainer auto& c) {
    std::ranges::sort(c);
}
```

## ✍️ 4. Worked Examples

### Example 09.4.1 — Ownership Transfer in a Scene Graph

<details>
<summary>Design a scene graph where parent nodes own their children</summary>

```cpp
#include <memory>
#include <vector>
#include <string>
#include <fmt/core.h>

class SceneNode {
    std::string name_;
    SceneNode* parent_ = nullptr;  // Non-owning back-pointer
    std::vector<std::unique_ptr<SceneNode>> children_;
    Transform local_transform_;

public:
    explicit SceneNode(std::string name) : name_(std::move(name)) {}

    // Add child — parent takes ownership
    SceneNode& add_child(std::unique_ptr<SceneNode> child) {
        child->parent_ = this;
        children_.push_back(std::move(child));
        return *children_.back();
    }

    // Remove child — returns ownership to caller
    std::unique_ptr<SceneNode> remove_child(const std::string& name) {
        auto it = std::ranges::find_if(children_,
            [&](const auto& c) { return c->name_ == name; });
        if (it == children_.end()) return nullptr;

        auto node = std::move(*it);
        node->parent_ = nullptr;
        children_.erase(it);
        return node;
    }

    // Reparent: move child from one parent to another
    void reparent_to(SceneNode& new_parent) {
        if (!parent_) return;
        auto self = parent_->remove_child(name_);
        if (self) new_parent.add_child(std::move(self));
    }
};

// Usage:
auto root = std::make_unique<SceneNode>("Root");
auto& player = root->add_child(std::make_unique<SceneNode>("Player"));
player.add_child(std::make_unique<SceneNode>("Weapon"));
player.add_child(std::make_unique<SceneNode>("Shield"));

// Transfer weapon to another node:
auto weapon = player.remove_child("Weapon");  // Player no longer owns it
root->add_child(std::move(weapon));           // Root now owns it
```

</details>

### Example 09.4.2 — Move-Only Type (Thread Pool Task)

<details>
<summary>Create a task wrapper that can only be moved, not copied</summary>

```cpp
#include <functional>
#include <future>
#include <memory>

class Task {
    std::function<void()> work_;
    std::string description_;

public:
    // Constructor takes any callable
    template<typename F>
    explicit Task(std::string desc, F&& func)
        : work_(std::forward<F>(func))
        , description_(std::move(desc)) {}

    // Move-only (tasks shouldn't be duplicated)
    Task(Task&&) noexcept = default;
    Task& operator=(Task&&) noexcept = default;
    Task(const Task&) = delete;
    Task& operator=(const Task&) = delete;

    void execute() {
        if (work_) {
            fmt::print("[Task] Executing: {}\n", description_);
            work_();
        }
    }

    std::string_view description() const { return description_; }
};

// Factory with packaged_task for getting results
template<typename F>
auto make_async_task(std::string desc, F&& func)
    -> std::pair<Task, std::future<std::invoke_result_t<F>>> {
    using R = std::invoke_result_t<F>;
    auto promise = std::make_shared<std::promise<R>>();
    auto future = promise->get_future();

    Task task(std::move(desc), [p = std::move(promise), f = std::forward<F>(func)]() {
        try {
            if constexpr (std::is_void_v<R>) {
                f();
                p->set_value();
            } else {
                p->set_value(f());
            }
        } catch (...) {
            p->set_exception(std::current_exception());
        }
    });

    return {std::move(task), std::move(future)};
}
```

</details>

### Example 09.4.3 — Concept-Constrained Generic Algorithm

<details>
<summary>Write a generic "find closest" algorithm constrained by concepts</summary>

```cpp
#include <concepts>
#include <cmath>
#include <ranges>
#include <optional>

// Concept: anything with a position we can measure distance to
template<typename T>
concept Locatable = requires(const T& obj) {
    { obj.x() } -> std::convertible_to<float>;
    { obj.y() } -> std::convertible_to<float>;
};

// Concept: a range of Locatable things
template<typename R>
concept LocatableRange = std::ranges::range<R> &&
    Locatable<std::ranges::range_value_t<R>>;

// Generic "find closest" — works with any Locatable type
template<LocatableRange R>
auto find_closest(const R& entities, float target_x, float target_y)
    -> std::optional<std::reference_wrapper<const std::ranges::range_value_t<R>>>
{
    using Entity = std::ranges::range_value_t<R>;
    const Entity* closest = nullptr;
    float min_dist = std::numeric_limits<float>::max();

    for (const auto& e : entities) {
        float dx = e.x() - target_x;
        float dy = e.y() - target_y;
        float dist = dx * dx + dy * dy;  // Skip sqrt for comparison
        if (dist < min_dist) {
            min_dist = dist;
            closest = &e;
        }
    }

    if (closest) return std::cref(*closest);
    return std::nullopt;
}

// Works with any type that has x() and y():
struct Enemy { float x_, y_; float x() const { return x_; } float y() const { return y_; } };
struct Pickup { float x_, y_; float x() const { return x_; } float y() const { return y_; } };

std::vector<Enemy> enemies = {{1,2}, {5,5}, {3,1}};
auto nearest = find_closest(enemies, 4.0f, 4.0f);  // Returns the {5,5} enemy
```

</details>

## 💻 5. Code Patterns & Idioms

### Pattern 2.4.1 — Factory with `unique_ptr`

```cpp
// Abstract product
class Renderer {
public:
    virtual ~Renderer() = default;
    virtual void draw_frame() = 0;
};

// Concrete products
class VulkanRenderer : public Renderer {
public:
    void draw_frame() override { /* Vulkan calls */ }
};

class OpenGLRenderer : public Renderer {
public:
    void draw_frame() override { /* OpenGL calls */ }
};

// Factory function — returns ownership via unique_ptr
enum class GraphicsAPI { Vulkan, OpenGL };

std::unique_ptr<Renderer> create_renderer(GraphicsAPI api) {
    switch (api) {
        case GraphicsAPI::Vulkan: return std::make_unique<VulkanRenderer>();
        case GraphicsAPI::OpenGL: return std::make_unique<OpenGLRenderer>();
    }
    std::unreachable();  // C++23
}

// Caller owns the renderer:
auto renderer = create_renderer(GraphicsAPI::Vulkan);
renderer->draw_frame();
// Automatically destroyed when renderer goes out of scope
```

### Pattern 2.4.2 — `std::variant` + `std::visit` (Type-Safe Union)

```cpp
#include <variant>
#include <string>

// Closed set of message types (no heap allocation, no virtual)
using GameEvent = std::variant<
    struct PlayerMoved { int id; float x, y; },
    struct PlayerDied { int id; std::string cause; },
    struct ItemPickup { int player_id; int item_id; }
>;

// Process with visitor pattern
struct EventHandler {
    void operator()(const PlayerMoved& e) {
        fmt::print("Player {} moved to ({}, {})\n", e.id, e.x, e.y);
    }
    void operator()(const PlayerDied& e) {
        fmt::print("Player {} died: {}\n", e.id, e.cause);
    }
    void operator()(const ItemPickup& e) {
        fmt::print("Player {} picked up item {}\n", e.player_id, e.item_id);
    }
};

void process_event(const GameEvent& event) {
    std::visit(EventHandler{}, event);
}

// Or with overloaded lambdas:
void process_event_lambda(const GameEvent& event) {
    std::visit(overloaded{
        [](const PlayerMoved& e) { /* ... */ },
        [](const PlayerDied& e) { /* ... */ },
        [](const ItemPickup& e) { /* ... */ },
    }, event);
}
```

## ⚠️ 6. Gotchas & Anti-Patterns

### Gotcha 2.4.1 — Circular `shared_ptr` References (Memory Leak)

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::shared_ptr<Node> prev;  // BUG: circular reference!
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->prev = a;
// Neither a nor b will ever be freed! refcount never reaches 0.

// FIX: Use weak_ptr for back-references
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;  // Doesn't prevent destruction
};
```

### Gotcha 2.4.2 — Using Object After `std::move`

```cpp
std::vector<int> data = {1, 2, 3};
process(std::move(data));

// BUG: data is in "valid but unspecified state"
fmt::print("Size: {}\n", data.size());  // Might print 0, might not
data.push_back(4);  // Technically OK (valid state) but confusing

// BEST PRACTICE: Don't use moved-from objects (except to reassign or destroy)
data = {4, 5, 6};  // OK: reassignment
```

### Gotcha 2.4.3 — Lambda Capturing Dangling References

```cpp
std::function<int()> make_counter() {
    int count = 0;
    return [&count]() { return ++count; };  // BUG: count destroyed at }
    // The lambda captures a reference to a local variable!
}

auto counter = make_counter();
counter();  // UNDEFINED BEHAVIOR: dangling reference

// FIX: Capture by value
std::function<int()> make_counter_fixed() {
    int count = 0;
    return [count]() mutable { return ++count; };  // Own copy
}
```

### Gotcha 2.4.4 — `shared_ptr` from `this`

```cpp
class Widget {
public:
    std::shared_ptr<Widget> get_shared() {
        return std::shared_ptr<Widget>(this);  // BUG: double-free!
        // Creates a NEW control block for an already-managed object
    }
};

// FIX: Inherit from enable_shared_from_this
class Widget : public std::enable_shared_from_this<Widget> {
public:
    std::shared_ptr<Widget> get_shared() {
        return shared_from_this();  // Returns existing shared_ptr
    }
};
```

### Gotcha 2.4.5 — `std::move` Doesn't Move

`std::move` is just a cast — it doesn't move anything. It casts to rvalue reference, which *enables* a move if the receiving function has a move overload:

```cpp
const std::string s = "hello";
std::string t = std::move(s);  // COPIES! Can't move from const.
// std::move(s) returns const std::string&& which binds to const& (copy ctor)
```

### Example 8.1 — Fold Expressions (C++17) — Complete Guide

**Problem:** Implement variadic utility functions using fold expressions: a type-safe `print_all`, a compile-time `sum`, and a `has_any_of` predicate.

<details>
<summary>🔍 Full step-by-step solution</summary>

```cpp
#include <concepts>
#include <string>
#include <type_traits>
#include <fmt/core.h>

// ═══════════════════════════════════════════════════════════════
// Fold expression syntax:
//   (pack op ...)      — unary right fold: (p1 op (p2 op (p3 op p4)))
//   (... op pack)      — unary left fold:  (((p1 op p2) op p3) op p4)
//   (pack op ... op init) — binary right fold
//   (init op ... op pack) — binary left fold
// ═══════════════════════════════════════════════════════════════

// Example 1: Print all arguments with separator
template<typename... Args>
void print_all(Args&&... args) {
    // Binary left fold with comma operator
    // Expands to: (((cout << a1, cout << " "), cout << a2, cout << " "), ...)
    ((fmt::print("{} ", args)), ...);
    fmt::print("\n");
}

// Example 2: Compile-time sum of all arguments
template<typename... Args>
constexpr auto sum(Args... args) {
    return (args + ...);  // Unary right fold: a1 + (a2 + (a3 + a4))
}
static_assert(sum(1, 2, 3, 4, 5) == 15);

// Example 3: All/Any/None predicates
template<typename... Bools>
constexpr bool all_of(Bools... bs) {
    return (bs && ...);  // Unary right fold with &&
}

template<typename... Bools>
constexpr bool any_of(Bools... bs) {
    return (bs || ...);  // Unary right fold with ||
}

template<typename... Bools>
constexpr bool none_of(Bools... bs) {
    return !(bs || ...);
}

static_assert(all_of(true, true, true));
static_assert(any_of(false, true, false));
static_assert(none_of(false, false, false));

// Example 4: Type-safe push_back to container
template<typename Container, typename... Items>
void push_all(Container& c, Items&&... items) {
    (c.push_back(std::forward<Items>(items)), ...);
    // Expands to:
    // c.push_back(item1), c.push_back(item2), c.push_back(item3);
}

std::vector<int> v;
push_all(v, 1, 2, 3, 4, 5);  // v = {1, 2, 3, 4, 5}

// Example 5: Check if a value matches any of several options
template<typename T, typename... Options>
constexpr bool is_one_of(const T& value, const Options&... options) {
    return ((value == options) || ...);
}

bool valid = is_one_of(status, Status::Active, Status::Pending, Status::Review);

// Example 6: Construct a string by concatenating with fold
template<typename... Strings>
std::string concat(Strings&&... parts) {
    return (std::string{} + ... + std::forward<Strings>(parts));
    // Binary left fold: ((("" + s1) + s2) + s3)
}

auto msg = concat("Hello", " ", "World", "!");  // "Hello World!"

// Example 7: Apply a function to each element of a tuple
template<typename Func, typename Tuple, size_t... Is>
void for_each_impl(Func&& f, Tuple&& t, std::index_sequence<Is...>) {
    (f(std::get<Is>(std::forward<Tuple>(t))), ...);
}

template<typename Func, typename Tuple>
void for_each_tuple(Func&& f, Tuple&& t) {
    for_each_impl(std::forward<Func>(f), std::forward<Tuple>(t),
        std::make_index_sequence<std::tuple_size_v<std::decay_t<Tuple>>>{});
}

auto tup = std::make_tuple(42, "hello", 3.14);
for_each_tuple([](const auto& x) { fmt::print("{}\n", x); }, tup);
```

### Example 8.2 — Structured Bindings Deep Dive

**Problem:** Use structured bindings with custom types, understand the underlying mechanism, and handle edge cases (const, reference, move).

<details>
<summary>🔍 Full step-by-step solution</summary>

```cpp
#include <tuple>
#include <map>
#include <array>
#include <string>
#include <fmt/core.h>

// ═══════════════════════════════════════════════════════════════
// Structured bindings work with 3 categories:
// 1. Arrays (including std::array)
// 2. Tuple-like types (std::tuple, std::pair, custom)
// 3. Public non-static data members (aggregates)
// ═══════════════════════════════════════════════════════════════

// Category 1: Arrays
void array_bindings() {
    int arr[3] = {10, 20, 30};
    auto [a, b, c] = arr;  // Copies! a=10, b=20, c=30
    auto& [x, y, z] = arr;  // References! x IS arr[0]
    x = 99;  // Modifies arr[0]

    std::array<float, 2> pos = {3.14f, 2.71f};
    auto [px, py] = pos;
}

// Category 2: Tuple-like types
void tuple_bindings() {
    auto [name, age, score] = std::make_tuple("Bill", 30, 9001);
    // name is const char*, age is int, score is int

    std::map<std::string, int> scores = {{"Alice", 100}, {"Bob", 200}};
    for (const auto& [key, value] : scores) {
        fmt::print("{}: {}\n", key, value);
    }

    // With try_emplace (C++17):
    if (auto [it, inserted] = scores.try_emplace("Charlie", 300); inserted) {
        fmt::print("Added {} with score {}\n", it->first, it->second);
    }
}

// Category 3: Aggregates (public members)
struct GameEntity {
    std::string name;
    float x, y;
    int health;
};

void aggregate_bindings() {
    GameEntity e{"Goblin", 5.0f, 3.0f, 100};
    auto& [name, x, y, hp] = e;  // References to members
    hp -= 25;  // Modifies e.health directly
}

// ═══════════════════════════════════════════════════════════════
// Custom tuple-like type (make YOUR class work with structured bindings)
// ═══════════════════════════════════════════════════════════════
class Color {
    uint8_t r_, g_, b_, a_;
public:
    Color(uint8_t r, uint8_t g, uint8_t b, uint8_t a = 255)
        : r_(r), g_(g), b_(b), a_(a) {}

    // Required: tuple_size, tuple_element, and get<>
    template<size_t I>
    auto get() const {
        if constexpr (I == 0) return r_;
        else if constexpr (I == 1) return g_;
        else if constexpr (I == 2) return b_;
        else if constexpr (I == 3) return a_;
    }
};

// Specialize in namespace std:
namespace std {
    template<> struct tuple_size<Color> : integral_constant<size_t, 4> {};
    template<size_t I> struct tuple_element<I, Color> { using type = uint8_t; };
}

void custom_bindings() {
    Color red(255, 0, 0);
    auto [r, g, b, a] = red;  // Works! r=255, g=0, b=0, a=255
}

// ═══════════════════════════════════════════════════════════════
// Edge cases and gotchas
// ═══════════════════════════════════════════════════════════════

void edge_cases() {
    // Gotcha 1: auto vs auto& vs const auto&
    std::pair<std::string, std::vector<int>> data = {"key", {1,2,3}};

    auto [k1, v1] = data;         // COPIES both string and vector!
    auto& [k2, v2] = data;        // References — no copy
    const auto& [k3, v3] = data;  // Const references

    // Gotcha 2: Can't use structured bindings with constexpr (until C++26)
    // constexpr auto [a, b] = std::pair{1, 2};  // ERROR in C++20

    // Gotcha 3: Can't capture structured bindings in lambdas (C++17)
    // Fixed in C++20:
    auto [name, score] = std::pair{"Bill", 100};
    auto fn = [name, score]() { return score; };  // OK in C++20

    // Gotcha 4: Move semantics
    auto [s, v] = std::pair{std::string("hello"), std::vector{1,2,3}};
    // s and v are moved from the temporary pair — efficient!
}
```

### Example 8.3 — `std::expected` (C++23) — Error Handling Without Exceptions

**Problem:** Implement a file parser that can fail in multiple ways. Use `std::expected` for composable, zero-overhead error handling that's clearer than error codes and faster than exceptions.

<details>
<summary>🔍 Full step-by-step solution</summary>

```cpp
#include <expected>
#include <string>
#include <vector>
#include <fstream>
#include <charconv>
#include <fmt/core.h>

// ═══════════════════════════════════════════════════════════════
// Define error types
// ═══════════════════════════════════════════════════════════════
enum class ParseError {
    FileNotFound,
    PermissionDenied,
    InvalidFormat,
    InvalidNumber,
    UnexpectedEOF,
    TooManyEntries,
};

std::string_view to_string(ParseError e) {
    switch (e) {
        case ParseError::FileNotFound:    return "file not found";
        case ParseError::PermissionDenied: return "permission denied";
        case ParseError::InvalidFormat:   return "invalid format";
        case ParseError::InvalidNumber:   return "invalid number";
        case ParseError::UnexpectedEOF:   return "unexpected end of file";
        case ParseError::TooManyEntries:  return "too many entries";
    }
    return "unknown";
}

// ═══════════════════════════════════════════════════════════════
// Functions return std::expected<T, E> instead of throwing
// ═══════════════════════════════════════════════════════════════

struct Config {
    std::string name;
    int width, height;
    float scale;
};

// Read file contents
std::expected<std::string, ParseError> read_file(const std::string& path) {
    std::ifstream file(path);
    if (!file.is_open()) {
        return std::unexpected(ParseError::FileNotFound);
    }
    std::string content((std::istreambuf_iterator<char>(file)),
                         std::istreambuf_iterator<char>());
    if (content.empty()) {
        return std::unexpected(ParseError::UnexpectedEOF);
    }
    return content;  // Implicit conversion to expected<string, E>
}

// Parse an integer from a string
std::expected<int, ParseError> parse_int(std::string_view sv) {
    int value;
    auto [ptr, ec] = std::from_chars(sv.data(), sv.data() + sv.size(), value);
    if (ec != std::errc{}) {
        return std::unexpected(ParseError::InvalidNumber);
    }
    return value;
}

// Parse config file
std::expected<Config, ParseError> parse_config(const std::string& path) {
    // Monadic chaining with and_then (C++23)
    return read_file(path)
        .and_then([](const std::string& content) -> std::expected<Config, ParseError> {
            // Parse the content...
            Config cfg;
            // (simplified parsing logic)
            cfg.name = "MyGame";
            cfg.width = 1920;
            cfg.height = 1080;
            cfg.scale = 1.0f;
            return cfg;
        });
}

// ═══════════════════════════════════════════════════════════════
// Monadic operations (C++23): and_then, transform, or_else
// ═══════════════════════════════════════════════════════════════

std::expected<int, ParseError> get_width(const std::string& path) {
    return parse_config(path)
        .transform([](const Config& cfg) { return cfg.width; })  // Map value
        .or_else([](ParseError e) -> std::expected<int, ParseError> {
            fmt::print("Warning: {}, using default\n", to_string(e));
            return 1920;  // Fallback value
        });
}

// ═══════════════════════════════════════════════════════════════
// Usage patterns
// ═══════════════════════════════════════════════════════════════
void usage() {
    // Pattern 1: Check and use
    auto result = parse_config("game.cfg");
    if (result) {
        fmt::print("Config: {}x{}\n", result->width, result->height);
    } else {
        fmt::print("Error: {}\n", to_string(result.error()));
    }

    // Pattern 2: value_or (provide default)
    int width = parse_int("1920").value_or(800);

    // Pattern 3: Chain operations
    auto final_result = read_file("data.txt")
        .and_then([](const std::string& s) { return parse_int(s); })
        .transform([](int n) { return n * 2; })
        .value_or(0);
}

// ═══════════════════════════════════════════════════════════════
// Comparison with other error handling approaches
// ═══════════════════════════════════════════════════════════════
// Exceptions:  try { auto cfg = parse_config(path); } catch (...)
//   + Familiar syntax, automatic propagation
//   - Invisible control flow, expensive throw, hard to reason about
//
// Error codes: int err = parse_config(path, &cfg);
//   + Zero overhead, C-compatible
//   - Easy to ignore, can't return value and error simultaneously
//
// std::expected: auto result = parse_config(path);
//   + Zero overhead, composable, self-documenting, can't ignore
//   - Verbose without monadic ops, new (C++23)
```

### Example 8.4 — Spaceship Operator (`<=>`) Gotchas

**Problem:** Implement correct three-way comparison for a complex type with mixed comparison semantics (some members use strong ordering, others use partial ordering).

<details>
<summary>🔍 Full step-by-step solution</summary>

```cpp
#include <compare>
#include <string>
#include <cmath>
#include <fmt/core.h>

// ═══════════════════════════════════════════════════════════════
// The three comparison categories:
// strong_ordering:  exactly one of <, ==, > (integers, strings)
// weak_ordering:    equivalent values may not be equal (case-insensitive)
// partial_ordering: some values are incomparable (NaN in floats)
// ═══════════════════════════════════════════════════════════════

// Simple case: compiler generates everything
struct Point {
    int x, y;
    auto operator<=>(const Point&) const = default;
    // Generates: ==, !=, <, >, <=, >= (all six!)
    // Uses strong_ordering because int has strong_ordering
};

// Gotcha 1: float members give partial_ordering
struct Position {
    float x, y, z;
    auto operator<=>(const Position&) const = default;
    // Returns std::partial_ordering (because float has NaN)
    // NaN != NaN, so Position{NaN,0,0} is not equal to itself!
};

// Fix: If you know your floats are never NaN, force strong ordering:
struct SafePosition {
    float x, y, z;

    std::strong_ordering operator<=>(const SafePosition& other) const {
        // Lexicographic comparison, treating floats as if they were ints
        if (auto cmp = x <=> other.x; cmp != 0)
            return cmp > 0 ? std::strong_ordering::greater
                           : std::strong_ordering::less;
        if (auto cmp = y <=> other.y; cmp != 0)
            return cmp > 0 ? std::strong_ordering::greater
                           : std::strong_ordering::less;
        if (auto cmp = z <=> other.z; cmp != 0)
            return cmp > 0 ? std::strong_ordering::greater
                           : std::strong_ordering::less;
        return std::strong_ordering::equal;
    }
    bool operator==(const SafePosition&) const = default;
};

// Gotcha 2: Mixed ordering categories
struct GameEntity {
    std::string name;    // strong_ordering
    int priority;        // strong_ordering
    float distance;      // partial_ordering (NaN possible)

    // Can't use = default (would give partial_ordering due to float)
    // Must define manually if you want strong_ordering:
    std::strong_ordering operator<=>(const GameEntity& other) const {
        if (auto cmp = priority <=> other.priority; cmp != 0) return cmp;
        if (auto cmp = name <=> other.name; cmp != 0) return cmp;
        // For distance: define a total order (NaN sorts last)
        if (std::isnan(distance) && std::isnan(other.distance))
            return std::strong_ordering::equal;
        if (std::isnan(distance)) return std::strong_ordering::greater;
        if (std::isnan(other.distance)) return std::strong_ordering::less;
        return (distance < other.distance) ? std::strong_ordering::less
             : (distance > other.distance) ? std::strong_ordering::greater
             : std::strong_ordering::equal;
    }
    bool operator==(const GameEntity&) const = default;
};

// Gotcha 3: operator== must be separately defaulted for performance
struct BigStruct {
    std::string name;
    std::vector<int> data;

    // If you only define <=>, then == uses <=> (which is SLOW for strings!)
    // String == can short-circuit on length; <=> cannot.
    auto operator<=>(const BigStruct&) const = default;
    bool operator==(const BigStruct&) const = default;  // IMPORTANT: separate ==
    // The compiler generates an optimized == that checks lengths first
};

// Gotcha 4: Heterogeneous comparison (comparing different types)
struct Meters {
    double value;
    auto operator<=>(const Meters&) const = default;

    // Compare Meters with raw double:
    std::partial_ordering operator<=>(double other) const {
        return value <=> other;
    }
    bool operator==(double other) const { return value == other; }
};

void demo() {
    Meters m{5.0};
    bool b = (m > 3.0);   // Works! Uses heterogeneous <=>
    bool c = (3.0 < m);   // Also works! Compiler rewrites as m > 3.0
}
```

</details>

### 9.1 C++20 Modules Adoption Status (Clang/GCC/MSVC) — 2025 Reality Check

**C++20 modules promise to revolutionize C++ compilation**, but adoption has been painfully slow due to the complexity of implementation. Here's the real-world status as of early 2026:

#### Compiler Support Matrix

| Feature | MSVC 19.38+ | Clang 18+ | GCC 14+ |
|---------|-------------|-----------|---------|
| Named modules (`export module X`) | ✅ Full | ✅ Full | ⚠️ Mostly |
| Module partitions | ✅ | ✅ | ⚠️ Partial |
| Header units (`import <iostream>`) | ✅ | ⚠️ Experimental | ❌ |
| `import std;` (standard library module) | ✅ (VS 2022 17.5+) | ⚠️ (libc++ only) | ❌ |
| Private module fragment | ✅ | ✅ | ⚠️ |

#### Build System Support

| Build System | Module Support | Status |
|-------------|---------------|--------|
| MSBuild (Visual Studio) | ✅ Full | Production-ready |
| CMake 3.28+ | ⚠️ Experimental | `CMAKE_CXX_SCAN_FOR_MODULES` flag |
| Ninja | ⚠️ Dynamic deps | Requires `dyndep` feature |
| Meson | ⚠️ Experimental | Behind a flag |
| Bazel | ❌ | No support yet |

#### The Fundamental Problem: Build Order Dependencies

Traditional C++ compilation is embarrassingly parallel — every .cpp file can compile independently. Modules break this:

```
// math.cppm must compile BEFORE physics.cppm
export module math;
export class Vec3 { ... };

// physics.cppm depends on math module's BMI (Binary Module Interface)
export module physics;
import math;  // Needs math.cppm's compiled BMI file
export class RigidBody { Vec3 position; };
```

The build system must:
1. Scan all source files for `import`/`export` declarations
2. Build a dependency graph
3. Compile modules in topological order
4. Only then compile regular .cpp files that `import` modules

This "module dependency scanning" phase is what makes build system support so difficult.

#### Practical Recommendation (2026)

```cmake
# For new projects targeting MSVC only: modules are viable
# For cross-platform projects: wait for CMake 3.30+ and GCC 15

# Hybrid approach: use modules internally, export traditional headers
# module_interface.cppm
export module engine;
export import :renderer;
export import :physics;
export import :audio;

# Traditional header for external consumers
# include/engine/engine.h (wraps module interface for non-module users)
```

**Bottom line:** Use modules in new MSVC-only projects (game dev targeting Windows). For cross-platform libraries, continue using headers with precompiled headers (PCH) for compilation speed. The ecosystem should be fully ready by 2027.

### 9.2 The Complete Move Semantics Mental Model

**Move semantics is the single most impactful C++11 feature for performance.** Here's the complete mental model:

#### What "Move" Actually Means

A move is a **transfer of ownership of resources** (heap memory, file handles, GPU buffers). After a move, the source object is in a "valid but unspecified state" — it can be destroyed or reassigned, but its value is unknown.

```cpp
std::string a = "Hello, World!";  // a owns heap-allocated char array
std::string b = std::move(a);     // b steals a's internal pointer
// a is now empty (or some valid state) — its buffer was transferred to b
// This was O(1) instead of O(n) copy
```

#### The Five Special Member Functions

```cpp
class Resource {
    int* data_;
    size_t size_;
public:
    // 1. Default constructor
    Resource() : data_(nullptr), size_(0) {}

    // 2. Copy constructor (deep copy)
    Resource(const Resource& other) : data_(new int[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + size_, data_);
    }

    // 3. Copy assignment (copy-and-swap idiom)
    Resource& operator=(Resource other) {  // Note: by value (copies or moves)
        swap(*this, other);
        return *this;
    }

    // 4. Move constructor (steal resources)
    Resource(Resource&& other) noexcept
        : data_(std::exchange(other.data_, nullptr))
        , size_(std::exchange(other.size_, 0)) {}

    // 5. Destructor
    ~Resource() { delete[] data_; }

    friend void swap(Resource& a, Resource& b) noexcept {
        std::swap(a.data_, b.data_);
        std::swap(a.size_, b.size_);
    }
};
```

#### When Moves Happen Automatically

1. **Returning local variables** (NRVO/copy elision, or implicit move)
2. **Passing temporaries** (`func(std::string("temp"))`)
3. **`std::move` cast** (explicit "I'm done with this")
4. **STL operations** (`vector::push_back` with rvalue, `std::sort` swaps)

#### The `noexcept` Contract

Move constructors **must** be `noexcept` for STL containers to use them:

```cpp
// std::vector::push_back logic:
// if (move_ctor is noexcept) → move elements during reallocation
// else → COPY elements (safe fallback, but O(n) slower)

// This is why noexcept on move operations is critical:
Resource(Resource&&) noexcept;  // vector will move
Resource(Resource&&);           // vector will COPY (can't risk exception mid-move)
```

### 9.3 Universal References and Perfect Forwarding — The Complete Picture

**`T&&` doesn't always mean "rvalue reference."** When `T` is a deduced template parameter, `T&&` is a **forwarding reference** (also called universal reference) that can bind to both lvalues and rvalues:

```cpp
template<typename T>
void wrapper(T&& arg) {
    // If called with lvalue: T = int&, T&& = int& && = int& (reference collapsing)
    // If called with rvalue: T = int,  T&& = int&&
    inner(std::forward<T>(arg));  // Preserves value category
}

int x = 42;
wrapper(x);    // T = int&,  arg is lvalue reference
wrapper(42);   // T = int,   arg is rvalue reference
```

**Reference collapsing rules:**
- `T& &` → `T&`
- `T& &&` → `T&`
- `T&& &` → `T&`
- `T&& &&` → `T&&`

**`std::forward` implementation (simplified):**
```cpp
template<typename T>
T&& forward(std::remove_reference_t<T>& arg) noexcept {
    return static_cast<T&&>(arg);
}
// When T = int&:  returns static_cast<int& &&>(arg) = int& (lvalue)
// When T = int:   returns static_cast<int&&>(arg) = int&& (rvalue)
```
