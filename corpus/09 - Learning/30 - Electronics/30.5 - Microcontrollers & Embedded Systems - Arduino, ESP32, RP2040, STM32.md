# 30.5 — Microcontrollers & Embedded Systems: Arduino, ESP32, RP2040, STM32

> *"A microcontroller is a CPU with the universe baked in: clock, RAM, flash, GPIOs, timers, ADC, DAC, UART, I²C, SPI — all on one chip the size of a fingernail."*

The four microcontrollers below are the **2026 default toolkit** for any embedded learner:

| MCU | Core | Best at | Price |
|---|---|---|---|
| Arduino Uno (ATmega328P) | AVR 8-bit @ 16 MHz | Pedagogy, simplicity | ~$25 |
| **ESP32** (S3 / C6 / H2) | Xtensa LX7 / RISC-V dual-core | Wi-Fi/BLE/Thread | ~$5–10 |
| **RP2040 / RP2350 (Pico)** | ARM Cortex-M0+ / Cortex-M33 dual-core + PIO | Cheap, PIO | ~$4 |
| **STM32** (F / G / H / U series) | ARM Cortex-M0/3/4/7/33 | Industry, real-time | varies |

---

## 🎯 Learning Objectives

1. Set up a build environment with **PlatformIO** (Arduino, ESP-IDF, STM32, RP2040 Pico SDK in one tool).
2. Blink an LED on each of the four MCUs above.
3. Read a button via a GPIO interrupt with proper debounce.
4. Use a **timer** to generate PWM and read an ADC at fixed sample rate.
5. Communicate over **UART**, **I²C**, **SPI** (next chapter on protocols).
6. Use an **RTOS** (FreeRTOS on ESP32 / STM32) to run multiple tasks.
7. Use **MicroPython** on ESP32 / RP2040 for fast prototyping.
8. Power-profile and debug an embedded program (printf, RTT, JTAG/SWD).

## 📚 1. The Anatomy of a Microcontroller

```
+--------------------- MCU Chip ---------------------+
| CPU core (Cortex-M / AVR / RISC-V / Xtensa)        |
| Flash (program memory) — kBs to MBs                |
| SRAM (data memory) — kBs to MBs                    |
| Clock tree (PLL, dividers, watchdog)               |
| GPIOs — push-pull / open-drain / pull-up           |
| Timers (PWM, capture/compare, encoder modes)       |
| ADC / DAC (12–16 bit)                              |
| Serial peripherals: UART, I²C, SPI, CAN, USB, etc. |
| DMA controller                                     |
| Wi-Fi / BLE / Thread (ESP32, nRF52, STM32WB...)    |
+----------------------------------------------------+
```

**Memory map** is critical — peripherals are **memory-mapped registers**. Writing to address `0x40020014` toggles a GPIO. Higher-level frameworks (Arduino, HAL, MicroPython) hide this.

## ⚙️ 2. The Toolchain Spectrum

| Layer | Pros | Cons |
|---|---|---|
| **Arduino IDE / framework** | Easiest start | Hides too much |
| **PlatformIO** | Unified across MCUs, dependency mgmt | Slight learning curve |
| **MicroPython / CircuitPython** | Fast prototyping | Slower runtime, limited RAM |
| **ESP-IDF** (ESP32 native) | Full Wi-Fi/BLE control | Verbose |
| **STM32Cube + HAL** | Industry standard | Heavy |
| **Bare-metal / register access** | Maximum performance | Steep learning curve |
| **Rust embedded (`embedded-hal`)** | Memory safety + zero-cost abstractions | Smaller ecosystem |

A pragmatic path: **PlatformIO + Arduino framework** for first projects, then graduate to **ESP-IDF** or **STM32 HAL** when you need fine control.

## 🧠 3. The Four Embedded Programming Patterns

1. **Super-loop**:
   ```c
   while (1) { read_sensors(); update_state(); drive_outputs(); }
   ```
   Simple, often enough.

2. **Interrupt-driven**: hardware events (timer overflow, GPIO edge) call ISRs that flag work for the main loop.

3. **State machine**: explicit FSM in the main loop; clean for protocols.

4. **RTOS (FreeRTOS, Zephyr, NuttX)**: real preemptive scheduler with tasks, queues, semaphores. Required when you have multiple concurrent timing-critical activities.

## 🐍 4. MicroPython Quick Win

```python
from machine import Pin, ADC
import time

led = Pin(2, Pin.OUT)        # ESP32: LED on GPIO2
btn = Pin(0, Pin.IN, Pin.PULL_UP)
adc = ADC(Pin(34))           # photoresistor on GPIO34

while True:
    if btn.value() == 0:     # pressed
        led.on()
    else:
        led.off()
    print(adc.read())        # 0..4095
    time.sleep(0.1)
```

Flash with `mpremote` or `esptool.py`. Excellent for sensors + dashboards; not for hard-real-time motor control.

## 🚦 5. RP2040's Trick: PIO

The RP2040 has **Programmable I/O state machines** — small co-processors you write tiny assembly snippets for, that run timing-critical bit-banged protocols (WS2812, custom serial, video output) without consuming CPU cycles.

This is the killer differentiator vs older MCUs and partly why robotics + maker projects gravitated to the Pico in 2023–2026.

## 🛠️ 6. Worked Example (skeleton) — Sensor → Dashboard

Goal: ESP32 reads a BME280 (temperature/humidity/pressure) over I²C every 10 s, posts to MQTT, dashboard shows live chart.

1. PlatformIO project, Arduino framework, ESP32 board.
2. `Wire.begin()`; instantiate Adafruit_BME280; read in loop.
3. Connect to Wi-Fi via `WiFi.begin(...)`.
4. PubSubClient → connect to broker (Mosquitto, EMQX) → publish JSON.
5. Node-RED or Grafana dashboard subscribes and renders.

## ⚠️ 8. Common Misconceptions

- **"`delay(1000)` is fine."** It blocks; ISRs and other tasks starve. Use `millis()`, timers, or RTOS.
- **"GPIO is GPIO."** Pin modes (input, input-pullup, output, open-drain), drive strength, slew rate, and 5 V-tolerance vary widely.
- **"Watchdogs are optional."** In production embedded, watchdogs are required — they reset a hung MCU before the user notices.
- **"More flash = more capable."** Flash size doesn't equal performance; clock, peripherals, and architecture do. Pick by feature match, not flash.
