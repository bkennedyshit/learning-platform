## 📚 1. Definitions / Concepts

### Definition 08.16.1 — Parallelism Strategies

| Strategy | What's Distributed | Communication | Memory Savings |
|----------|-------------------|---------------|----------------|
| **Data Parallel (DDP)** | Data batches | AllReduce gradients | None (full model copy per GPU) |
| **FSDP / ZeRO** | Parameters + gradients + optimizer states | AllGather + ReduceScatter | Up to N× (N = num GPUs) |
| **Tensor Parallel** | Individual layers (split matrices) | AllReduce activations | Per-layer |
| **Pipeline Parallel** | Model stages (groups of layers) | Point-to-point activations | Per-stage |

### Definition 08.16.2 — NCCL (NVIDIA Collective Communications Library)

NCCL provides optimized implementations of collective operations across GPUs:

- **AllReduce**: Every GPU gets the sum (or average) of all GPUs' data
- **AllGather**: Every GPU gets the concatenation of all GPUs' data
- **ReduceScatter**: Each GPU gets a shard of the reduced result
- **Broadcast**: One GPU sends data to all others

### Definition 08.16.3 — ZeRO Optimization Stages

| Stage | What's Sharded | Memory per GPU | Communication |
|-------|---------------|----------------|---------------|
| ZeRO-1 | Optimizer states | ~4× reduction | Same as DDP |
| ZeRO-2 | + Gradients | ~8× reduction | Slightly more |
| ZeRO-3 (FSDP) | + Parameters | ~N× reduction | AllGather in forward |

### Definition 08.16.4 — Gradient Accumulation

When the desired batch size exceeds GPU memory, accumulate gradients over multiple micro-batches before stepping the optimizer:

```python
accumulation_steps = 4
for i, batch in enumerate(dataloader):
    loss = model(batch) / accumulation_steps
    loss.backward()
    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

## 📐 2. Mental Models / Principles

### Principle 1.16.1 — Communication is the Bottleneck

For DDP with N GPUs:
- Computation scales linearly: N× throughput
- Communication is constant: AllReduce of full gradient (same size regardless of N)
- Efficiency = Computation / (Computation + Communication)

As you add GPUs, communication becomes a larger fraction → diminishing returns. Solutions: gradient compression, overlap communication with computation, reduce communication frequency.

### Principle 1.16.2 — The Memory Budget

For a model with P parameters in mixed precision:
- Parameters: 2P bytes (FP16/BF16)
- Gradients: 2P bytes
- Optimizer states (Adam): 12P bytes (FP32 params + momentum + variance)
- Activations: Depends on batch size and sequence length

**Total for a 7B model:** ~2×7B + 2×7B + 12×7B = 112 GB → doesn't fit on one 80GB A100!
**With FSDP (8 GPUs):** 112/8 = 14 GB per GPU → fits easily.

### Principle 1.16.3 — Fault Tolerance at Scale

At 1000+ GPUs, hardware failures are not exceptional — they're expected. Training must handle:
- GPU memory errors (ECC failures)
- Network partitions
- Node crashes
- Checkpoint corruption

Solution: Periodic checkpointing + elastic training (can resume with fewer nodes).

### 3.4 — Checkpointing for Fault Tolerance

```python
from torch.distributed.checkpoint import save, load
from torch.distributed.fsdp import StateDictType, FullStateDictConfig

def save_checkpoint(model, optimizer, epoch, path):
    """Save distributed checkpoint (each rank saves its shard)."""
    with FSDP.state_dict_type(model, StateDictType.SHARDED_STATE_DICT):
        state = {
            "model": model.state_dict(),
            "optimizer": optimizer.state_dict(),
            "epoch": epoch,
        }
        save(state, checkpoint_id=path)

def load_checkpoint(model, optimizer, path):
    """Load distributed checkpoint."""
    with FSDP.state_dict_type(model, StateDictType.SHARDED_STATE_DICT):
        state = {"model": model.state_dict(), "optimizer": optimizer.state_dict()}
        load(state, checkpoint_id=path)
        model.load_state_dict(state["model"])
        optimizer.load_state_dict(state["optimizer"])
```

## ⚠️ 6. Gotchas & Anti-Patterns

### Gotcha 1.16.1 — Forgetting `set_epoch()` on DistributedSampler

Without `sampler.set_epoch(epoch)`, every epoch uses the same data order → poor convergence.

### Gotcha 1.16.2 — Deadlocks from Uneven Batches

If one rank has fewer batches than others, it exits the loop while others wait for AllReduce → deadlock. Use `drop_last=True` in DataLoader or pad batches.

### Gotcha 1.16.3 — OOM from Activation Memory

Large batch sizes + long sequences = massive activation memory. Solutions:
- Gradient checkpointing (`model.gradient_checkpointing_enable()`)
- Reduce batch size + increase gradient accumulation steps
- Activation offloading to CPU

### Example 9.1 — Minimal DDP Setup with torchrun

**Problem:** Set up PyTorch Distributed Data Parallel (DDP) training from scratch using `torchrun`. Show the complete boilerplate, explain each component, and demonstrate scaling from 1 GPU to 8 GPUs with near-linear speedup.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### Step 1: Understanding DDP Architecture

```python
# DDP (DistributedDataParallel) replicates the model on each GPU.
# Each GPU processes a different mini-batch (data parallelism).
# After backward pass, gradients are synchronized via AllReduce.
#
# Process topology:
# torchrun spawns N processes (one per GPU)
# Each process: own model replica, own data shard, own optimizer
# Synchronization: NCCL AllReduce after each backward pass
#
# Environment variables set by torchrun:
# RANK: global process rank (0 to world_size-1)
# LOCAL_RANK: GPU index on this node (0 to num_gpus_per_node-1)
# WORLD_SIZE: total number of processes
# MASTER_ADDR: address of rank 0 process
# MASTER_PORT: port for rendezvous
```

#### Step 2: Complete DDP Training Script

```python
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data import DataLoader, DistributedSampler
import torch.optim as optim


def setup():
    """Initialize the distributed process group."""
    # torchrun sets these environment variables automatically
    dist.init_process_group(backend="nccl")  # NCCL for GPU, gloo for CPU
    torch.cuda.set_device(int(os.environ["LOCAL_RANK"]))


def cleanup():
    """Destroy the process group."""
    dist.destroy_process_group()


def get_rank() -> int:
    return int(os.environ.get("RANK", 0))


def get_local_rank() -> int:
    return int(os.environ.get("LOCAL_RANK", 0))


def get_world_size() -> int:
    return int(os.environ.get("WORLD_SIZE", 1))


def is_main_process() -> bool:
    return get_rank() == 0


class SimpleModel(nn.Module):
    def __init__(self, input_dim: int = 784, hidden_dim: int = 256, output_dim: int = 10):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, output_dim),
        )

    def forward(self, x):
        return self.net(x.flatten(1))


def train():
    """Main training function — runs in each process."""
    setup()
    rank = get_rank()
    local_rank = get_local_rank()
    world_size = get_world_size()
    device = torch.device(f"cuda:{local_rank}")

    if is_main_process():
        print(f"Training with {world_size} GPUs")

    # Model — wrap with DDP
    model = SimpleModel().to(device)
    model = DDP(model, device_ids=[local_rank])

    # Optimizer — each process has its own optimizer (same initial state)
    optimizer = optim.Adam(model.parameters(), lr=1e-3)

    # Dataset with DistributedSampler
    # DistributedSampler shards data across processes (no overlap)
    from torchvision import datasets, transforms
    dataset = datasets.MNIST(
        "./data", train=True, download=is_main_process(),
        transform=transforms.ToTensor()
    )
    # Wait for rank 0 to download
    dist.barrier()

    sampler = DistributedSampler(
        dataset,
        num_replicas=world_size,
        rank=rank,
        shuffle=True,
    )
    dataloader = DataLoader(
        dataset,
        batch_size=64,  # Per-GPU batch size (effective = 64 * world_size)
        sampler=sampler,
        num_workers=4,
        pin_memory=True,
    )

    # Training loop
    criterion = nn.CrossEntropyLoss()

    for epoch in range(5):
        sampler.set_epoch(epoch)  # CRITICAL: ensures different shuffling per epoch
        model.train()
        total_loss = 0.0

        for batch_idx, (data, target) in enumerate(dataloader):
            data = data.to(device, non_blocking=True)
            target = target.to(device, non_blocking=True)

            optimizer.zero_grad()
            output = model(data)
            loss = criterion(output, target)
            loss.backward()  # DDP automatically AllReduces gradients here
            optimizer.step()

            total_loss += loss.item()

        # Only log from main process
        if is_main_process():
            avg_loss = total_loss / len(dataloader)
            print(f"Epoch {epoch+1}: avg_loss = {avg_loss:.4f}")

    # Save model (only from rank 0)
    if is_main_process():
        torch.save(model.module.state_dict(), "model.pt")
        print("Model saved")

    cleanup()


if __name__ == "__main__":
    train()
```

### Example 9.2 — FSDP Shard Configuration: Training Models Larger Than GPU Memory

**Problem:** Your model has 7B parameters (14 GB in fp16) but each GPU only has 24 GB VRAM. With optimizer states and activations, a single GPU can't fit it. Use Fully Sharded Data Parallel (FSDP) to shard the model across GPUs.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### Step 1: Why DDP Isn't Enough

```python
# DDP replicates the ENTIRE model on each GPU:
# Model (7B, fp16): 14 GB
# Optimizer states (Adam): 2× model = 28 GB (fp32 momentum + variance)
# Gradients: 14 GB
# Activations: 5-20 GB (depends on batch size)
# Total per GPU: ~60+ GB — doesn't fit in 24 GB!
#
# FSDP solution: SHARD model parameters, gradients, and optimizer states
# across all GPUs. Each GPU holds only 1/N of each.
# 8 GPUs: each holds ~14/8 = 08.75 GB of parameters
# Trade-off: more communication (gather params before forward/backward)
```

#### Step 2: FSDP Sharding Strategies

```python
from torch.distributed.fsdp import (
    FullyShardedDataParallel as FSDP,
    ShardingStrategy,
    MixedPrecision,
    CPUOffload,
)
from torch.distributed.fsdp.wrap import (
    size_based_auto_wrap_policy,
    transformer_auto_wrap_policy,
)
import functools

# Three sharding strategies:
# 1. FULL_SHARD: Shard params + gradients + optimizer states (most memory efficient)
#    Memory per GPU: model/N + optimizer/N + activations
#    Communication: AllGather before forward, ReduceScatter after backward
#
# 2. SHARD_GRAD_OP: Shard gradients + optimizer states only (params replicated)
#    Memory per GPU: model + optimizer/N + activations
#    Communication: ReduceScatter after backward only
#    Faster than FULL_SHARD but uses more memory
#
# 3. NO_SHARD: Equivalent to DDP (no sharding)
#    Memory per GPU: model + optimizer + activations
```

#### Step 3: Complete FSDP Training Script

```python
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp import ShardingStrategy, MixedPrecision
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy
import functools
import os


def create_large_model():
    """Create a transformer model (simplified 7B-scale)."""
    from torch.nn import TransformerEncoderLayer, TransformerEncoder

    encoder_layer = TransformerEncoderLayer(
        d_model=4096,
        nhead=32,
        dim_feedforward=11008,
        batch_first=True,
        norm_first=True,
    )
    model = TransformerEncoder(encoder_layer, num_layers=32)
    return model


def train_fsdp():
    """Train with FSDP — model sharded across GPUs."""
    dist.init_process_group("nccl")
    local_rank = int(os.environ["LOCAL_RANK"])
    torch.cuda.set_device(local_rank)

    # Mixed precision policy
    mp_policy = MixedPrecision(
        param_dtype=torch.bfloat16,      # Parameters in bf16
        reduce_dtype=torch.bfloat16,     # Gradient reduction in bf16
        buffer_dtype=torch.bfloat16,     # Buffers in bf16
    )

    # Auto-wrap policy: wrap each TransformerEncoderLayer as a separate FSDP unit
    # This controls granularity of sharding (per-layer is typical)
    from torch.nn import TransformerEncoderLayer
    auto_wrap_policy = functools.partial(
        transformer_auto_wrap_policy,
        transformer_layer_cls={TransformerEncoderLayer},
    )

    # Create model (on CPU first to avoid OOM)
    model = create_large_model()

    # Wrap with FSDP
    model = FSDP(
        model,
        sharding_strategy=ShardingStrategy.FULL_SHARD,
        mixed_precision=mp_policy,
        auto_wrap_policy=auto_wrap_policy,
        device_id=local_rank,
        # cpu_offload=CPUOffload(offload_params=True),  # For extreme memory savings
    )

    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

    # Training loop
    for step in range(100):
        # Dummy data (replace with real DataLoader)
        x = torch.randn(2, 512, 4096, device=f"cuda:{local_rank}")

        output = model(x)
        loss = output.sum()
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()

        if local_rank == 0 and step % 10 == 0:
            print(f"Step {step}: loss = {loss.item():.4f}")
            mem = torch.cuda.memory_allocated() / 1e9
            print(f"  GPU memory: {mem:.2f} GB")

    # Save with FSDP (must use special API)
    from torch.distributed.fsdp import FullStateDictConfig, StateDictType
    save_policy = FullStateDictConfig(offload_to_cpu=True, rank0_only=True)
    with FSDP.state_dict_type(model, StateDictType.FULL_STATE_DICT, save_policy):
        state_dict = model.state_dict()
        if local_rank == 0:
            torch.save(state_dict, "model_fsdp.pt")

    dist.destroy_process_group()


if __name__ == "__main__":
    train_fsdp()
```

#### Step 4: Memory Comparison

```python
# 7B parameter model, 8× A100 80GB GPUs:
#
# | Strategy      | Params/GPU | Optim/GPU | Total/GPU | Fits? |
# |---------------|-----------|-----------|-----------|-------|
# | DDP           | 14 GB     | 28 GB     | ~60 GB    | ❌    |
# | SHARD_GRAD_OP | 14 GB     | 3.5 GB    | ~25 GB    | ⚠️    |
# | FULL_SHARD    | 08.75 GB   | 3.5 GB    | ~12 GB    | ✅    |
# | FULL + offload| ~0 GB     | ~0 GB     | ~5 GB     | ✅✅  |
```

**Final Answer:**

```python
# FSDP decision tree:
# Model fits in 1 GPU with DDP? → Use DDP (simpler, faster)
# Model fits with SHARD_GRAD_OP? → Use it (less communication than FULL_SHARD)
# Model doesn't fit at all? → Use FULL_SHARD
# Still doesn't fit? → Add CPU offload or activation checkpointing
# Still doesn't fit? → Use pipeline parallelism (split model across GPUs)
```

### Example 9.3 — DeepSpeed ZeRO Stages: Memory Optimization Hierarchy

**Problem:** Explain DeepSpeed's ZeRO (Zero Redundancy Optimizer) stages 1-3, show configuration for each, and demonstrate when to use DeepSpeed vs PyTorch FSDP.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### Step 1: ZeRO Stage Breakdown

```python
# ZeRO partitions model state across data-parallel processes:
#
# Baseline (DDP): Each GPU holds full copy of:
#   - Parameters (P): model_size
#   - Gradients (G): model_size
#   - Optimizer states (OS): 2× model_size (Adam momentum + variance, fp32)
#   Total per GPU: 4× model_size (in mixed precision)
#
# ZeRO Stage 1: Partition Optimizer States
#   Each GPU: P + G + OS/N
#   Savings: ~4× model → ~2.5× model per GPU (for N=8)
#
# ZeRO Stage 2: Partition Optimizer States + Gradients
#   Each GPU: P + G/N + OS/N
#   Savings: ~2× model per GPU
#   Communication: ReduceScatter gradients (same as DDP)
#
# ZeRO Stage 3: Partition Everything (≈ FSDP FULL_SHARD)
#   Each GPU: P/N + G/N + OS/N
#   Savings: ~4×model/N per GPU
#   Communication: AllGather params before forward/backward
```

#### Step 2: DeepSpeed Configuration


## 📘 10. Appendix: Extended Derivations & Special Cases

### 10.1 Collective Operation Semantics — AllReduce, AllGather, Scatter, Gather, Broadcast

Distributed training relies on collective communication operations. Understanding their semantics explains the communication patterns in DDP, FSDP, and ZeRO.

**The Five Core Collectives:**

```python
import torch
import torch.distributed as dist

# Assume 4 processes (ranks 0-3), each with a tensor

# 1. BROADCAST: One rank sends its data to all others
# Before: rank0=[A], rank1=[?], rank2=[?], rank3=[?]
# After:  rank0=[A], rank1=[A], rank2=[A], rank3=[A]
# Use case: distribute model weights from rank 0 to all ranks
dist.broadcast(tensor, src=0)

# 2. REDUCE: All ranks contribute, result goes to ONE rank
# Before: rank0=[1], rank1=[2], rank2=[3], rank3=[4]
# After:  rank0=[10], rank1=[2], rank2=[3], rank3=[4]  (sum at rank 0)
# Use case: aggregate loss values for logging
dist.reduce(tensor, dst=0, op=dist.ReduceOp.SUM)

# 3. ALL_REDUCE: All ranks contribute, ALL get the result
# Before: rank0=[1], rank1=[2], rank2=[3], rank3=[4]
# After:  rank0=[10], rank1=[10], rank2=[10], rank3=[10]
# Use case: DDP gradient synchronization (average gradients across ranks)
dist.all_reduce(tensor, op=dist.ReduceOp.SUM)
# Then divide by world_size for average

# 4. GATHER: Collect tensors from all ranks to one rank
# Before: rank0=[A], rank1=[B], rank2=[C], rank3=[D]
# After:  rank0=[A,B,C,D], rank1=[B], rank2=[C], rank3=[D]
# Use case: collect predictions from all ranks for evaluation
gather_list = [torch.empty_like(tensor) for _ in range(world_size)]
dist.gather(tensor, gather_list, dst=0)

# 5. ALL_GATHER: Collect tensors from all ranks, ALL get the full collection
# Before: rank0=[A], rank1=[B], rank2=[C], rank3=[D]
# After:  rank0=[A,B,C,D], rank1=[A,B,C,D], rank2=[A,B,C,D], rank3=[A,B,C,D]
# Use case: FSDP gathers sharded parameters before forward pass
dist.all_gather(gather_list, tensor)

# 6. SCATTER: Distribute chunks from one rank to all ranks
# Before: rank0=[A,B,C,D], rank1=[?], rank2=[?], rank3=[?]
# After:  rank0=[A], rank1=[B], rank2=[C], rank3=[D]
# Use case: distribute data shards
scatter_list = [chunk_A, chunk_B, chunk_C, chunk_D]  # Only on src rank
dist.scatter(tensor, scatter_list, src=0)

# 7. REDUCE_SCATTER: Reduce + Scatter in one operation
# Before: rank0=[1,2,3,4], rank1=[5,6,7,8], rank2=[9,10,11,12], rank3=[13,14,15,16]
# After:  rank0=[28], rank1=[32], rank2=[36], rank3=[40]
# (Each rank gets the sum of its corresponding chunk across all ranks)
# Use case: FSDP/ZeRO gradient synchronization (each rank gets its shard's gradient)
dist.reduce_scatter(output, input_list, op=dist.ReduceOp.SUM)
```

**Communication Complexity:**

For $N$ processes each with data of size $D$:

$$
\text{AllReduce: } 2(N-1) \cdot \frac{D}{N} \text{ data transferred per process (ring algorithm)}
$$

$$
\text{AllGather: } (N-1) \cdot \frac{D}{N} \text{ data transferred per process}
$$

$$
\text{ReduceScatter: } (N-1) \cdot \frac{D}{N} \text{ data transferred per process}
$$

Key insight: AllReduce = ReduceScatter + AllGather. FSDP uses these two primitives separately to overlap communication with computation.

**Ring AllReduce (How NCCL Implements It):**

```python
# Ring AllReduce splits data into N chunks and passes them around a ring:
#
# Phase 1 (ReduceScatter): N-1 steps
#   Each step: send one chunk to next rank, receive and accumulate from previous
#   After N-1 steps: each rank has the fully-reduced version of one chunk
#
# Phase 2 (AllGather): N-1 steps
#   Each step: send reduced chunk to next rank, receive from previous
#   After N-1 steps: all ranks have all reduced chunks
#
# Total data per rank: 2 × (N-1)/N × D ≈ 2D for large N
# This is OPTIMAL — independent of N (scales perfectly!)
# Bandwidth-bound, not latency-bound (good for large tensors)
```

### 10.2 Gradient Accumulation — Simulating Large Batch Sizes

When GPU memory limits the per-device batch size, gradient accumulation simulates larger effective batches by accumulating gradients over multiple forward/backward passes before updating weights.

**The Math:**

Standard SGD update with batch size $B$:

$$
\theta_{t+1} = \theta_t - \eta \cdot \frac{1}{B} \sum_{i=1}^{B} \nabla L(x_i, \theta_t)
$$

With gradient accumulation over $K$ micro-batches of size $b$ (effective batch = $K \cdot b$):

$$
\theta_{t+1} = \theta_t - \eta \cdot \frac{1}{K} \sum_{k=1}^{K} \left( \frac{1}{b} \sum_{i=1}^{b} \nabla L(x_i^{(k)}, \theta_t) \right)
$$

These are mathematically equivalent when $B = K \cdot b$.

**Implementation:**

```python
def train_with_gradient_accumulation(
    model, dataloader, optimizer, accumulation_steps: int = 4
):
    """
    Accumulate gradients over multiple micro-batches.
    Effective batch size = micro_batch_size × accumulation_steps × world_size
    """
    model.train()
    optimizer.zero_grad()

    for step, (data, target) in enumerate(dataloader):
        data = data.cuda(non_blocking=True)
        target = target.cuda(non_blocking=True)

        # Forward + backward (gradients accumulate in .grad)
        output = model(data)
        loss = output.sum() / accumulation_steps  # Scale loss by K
        loss.backward()  # Gradients ADD to existing .grad (not replace)

        # Only update weights every K steps
        if (step + 1) % accumulation_steps == 0:
            # Optional: gradient clipping
            torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=08.0)
            optimizer.step()
            optimizer.zero_grad()

    # Handle remaining steps (if dataset size not divisible by K)
    if (step + 1) % accumulation_steps != 0:
        optimizer.step()
        optimizer.zero_grad()
```

**Interaction with DDP:**

```python
# DDP synchronizes gradients on EVERY backward() call.
# With gradient accumulation, we only need sync on the LAST micro-batch.
# Use no_sync() context manager to skip AllReduce on intermediate steps:

from torch.nn.parallel import DistributedDataParallel as DDP

def train_ddp_with_accumulation(model: DDP, dataloader, optimizer, accum_steps: int):
    optimizer.zero_grad()

    for step, (data, target) in enumerate(dataloader):
        # Skip gradient sync for intermediate micro-batches
        context = model.no_sync() if (step + 1) % accum_steps != 0 else nullcontext()

        with context:
            output = model(data.cuda())
            loss = output.sum() / accum_steps
            loss.backward()

        if (step + 1) % accum_steps == 0:
            optimizer.step()  # Gradients were synced on last backward()
            optimizer.zero_grad()
```

This optimization reduces communication by $K\times$ — only one AllReduce per effective batch instead of one per micro-batch.
