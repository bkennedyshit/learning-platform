## 📚 1. Definitions / Concepts

### Definition 08.14.1 — Structured Concurrency

**Structured concurrency** ensures that concurrent tasks have well-defined lifetimes tied to lexical scopes. When a scope exits, all tasks within it are guaranteed to have completed (or been cancelled). No orphaned tasks.

```python
async with asyncio.TaskGroup() as tg:
    tg.create_task(fetch_a())
    tg.create_task(fetch_b())
# GUARANTEE: Both tasks done here. If one raises, the other is cancelled.
```

### Definition 08.14.2 — Backpressure

**Backpressure** is the mechanism by which a slow consumer signals a fast producer to slow down. Without it, unbounded queues grow until OOM. With it, the system self-regulates.

```python
# Bounded queue = automatic backpressure
queue = asyncio.Queue(maxsize=100)
await queue.put(item)  # Blocks when full → producer slows down
```

### Definition 08.14.3 — Fan-Out / Fan-In

- **Fan-out**: One producer distributes work to N workers
- **Fan-in**: N workers send results to one collector

This is the fundamental pattern for parallel data processing and distributed training.

## 📐 2. Mental Models / Principles

### Principle 1.14.1 — Choose Your Isolation Level

| Model | Isolation | Communication | Failure Mode |
|-------|-----------|---------------|-------------|
| Threads + locks | None (shared memory) | Direct access | Deadlock, race condition |
| Message passing | Process-level | Queues/pipes | Message loss, ordering |
| Actors | Actor-level | Mailboxes | Supervision trees |
| Structured concurrency | Scope-level | Return values | Cancellation propagation |

### Principle 1.14.2 — The Pipeline Pattern for ML

```
Data Loading → Preprocessing → GPU Transfer → Forward Pass → Backward Pass → Gradient Sync
     ↑              ↑              ↑              ↑              ↑              ↑
  (I/O bound)  (CPU bound)   (PCIe bound)   (GPU bound)   (GPU bound)   (Network bound)
```

Each stage runs concurrently. The pipeline is only as fast as its slowest stage (Amdahl's Law applied to pipelines).

## 🔑 3. Mechanics

### 3.1 — Production Pipeline with Graceful Shutdown

```python
import asyncio
from typing import AsyncIterator

SENTINEL = object()

async def data_loader(queue: asyncio.Queue, paths: list[str]) -> None:
    """Stage 1: Load data from disk (I/O bound)."""
    for path in paths:
        data = await asyncio.to_thread(load_file, path)
        await queue.put(data)
    await queue.put(SENTINEL)

async def preprocessor(in_q: asyncio.Queue, out_q: asyncio.Queue) -> None:
    """Stage 2: Transform data (CPU bound)."""
    while True:
        item = await in_q.get()
        if item is SENTINEL:
            await out_q.put(SENTINEL)
            break
        result = await asyncio.to_thread(transform, item)
        await out_q.put(result)

async def pipeline(paths: list[str]) -> AsyncIterator:
    """Compose stages with bounded queues (backpressure)."""
    q1: asyncio.Queue = asyncio.Queue(maxsize=10)
    q2: asyncio.Queue = asyncio.Queue(maxsize=10)

    async with asyncio.TaskGroup() as tg:
        tg.create_task(data_loader(q1, paths))
        tg.create_task(preprocessor(q1, q2))

        while True:
            item = await q2.get()
            if item is SENTINEL:
                break
            yield item
```

### 3.2 — Actor Pattern with Ray

```python
import ray

@ray.remote
class GradientAggregator:
    """Actor that collects gradients from multiple workers."""
    def __init__(self, num_workers: int):
        self.gradients = []
        self.num_workers = num_workers

    def submit_gradient(self, grad):
        self.gradients.append(grad)
        if len(self.gradients) == self.num_workers:
            avg = sum(self.gradients) / self.num_workers
            self.gradients.clear()
            return avg
        return None

# Usage:
ray.init()
aggregator = GradientAggregator.remote(num_workers=4)
result = ray.get(aggregator.submit_gradient.remote(my_gradient))
```

### 3.3 — Worker Pool with ProcessPoolExecutor

```python
from concurrent.futures import ProcessPoolExecutor, as_completed
import multiprocessing as mp

def cpu_intensive_task(chunk: list[int]) -> float:
    return sum(x**0.5 for x in chunk)

def parallel_compute(data: list[int], num_workers: int = None) -> float:
    num_workers = num_workers or mp.cpu_count()
    chunk_size = len(data) // num_workers
    chunks = [data[i:i+chunk_size] for i in range(0, len(data), chunk_size)]

    total = 0.0
    with ProcessPoolExecutor(max_workers=num_workers) as executor:
        futures = {executor.submit(cpu_intensive_task, chunk): i for i, chunk in enumerate(chunks)}
        for future in as_completed(futures):
            total += future.result()
    return total
```

### Example 08.14.1 — Rate-Limited API Crawler with Semaphore

```python
import asyncio
import httpx
from dataclasses import dataclass, field
from time import monotonic

@dataclass
class RateLimiter:
    """Token bucket rate limiter."""
    rate: float  # tokens per second
    _tokens: float = field(init=False)
    _last: float = field(init=False)
    _lock: asyncio.Lock = field(default_factory=asyncio.Lock, init=False)

    def __post_init__(self):
        self._tokens = self.rate
        self._last = monotonic()

    async def acquire(self):
        async with self._lock:
            now = monotonic()
            self._tokens = min(self.rate, self._tokens + (now - self._last) * self.rate)
            self._last = now
            if self._tokens < 1:
                await asyncio.sleep((1 - self._tokens) / self.rate)
                self._tokens = 0
            else:
                self._tokens -= 1

limiter = RateLimiter(rate=10)  # 10 requests/second

async def fetch(client: httpx.AsyncClient, url: str) -> str:
    await limiter.acquire()
    resp = await client.get(url)
    return resp.text
```

## ⚠️ 6. Gotchas & Anti-Patterns

### Gotcha 1.14.1 — Fire-and-Forget Tasks

```python
# BAD: Task can be garbage collected before completion
asyncio.create_task(background_work())  # No reference held!

# GOOD: Keep reference or use TaskGroup
task = asyncio.create_task(background_work())
# ... later ...
await task
```

### Gotcha 1.14.2 — Deadlock from Nested Locks

Never acquire multiple locks in different orders across threads. Use a consistent lock ordering or use `asyncio` (cooperative, no deadlocks from lock ordering).

### Example 9.1 — Actor Model: Building a Homemade Actor System with asyncio

**Problem:** Implement a minimal actor system in Python using asyncio. Each actor has a mailbox (queue), processes messages sequentially, and can spawn child actors. Demonstrate with a word-count pipeline: Reader → Splitter → Counter → Aggregator.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### Step 1: The Actor Base Class

```python
import asyncio
from typing import Any, Optional
from dataclasses import dataclass, field
from abc import ABC, abstractmethod


@dataclass
class Message:
    """Base message type."""
    sender: Optional["Actor"] = None


@dataclass
class PoisonPill(Message):
    """Tells an actor to shut down gracefully."""
    pass


class Actor(ABC):
    """
    Minimal actor implementation.
    
    Properties of the Actor Model:
    1. Each actor has a MAILBOX (async queue) — messages are buffered
    2. Each actor processes ONE message at a time (sequential, no locks needed)
    3. Actors communicate ONLY via messages (no shared state)
    4. Actors can CREATE child actors
    5. Actors can CHANGE behavior for the next message
    """

    def __init__(self, name: str, mailbox_size: int = 1000):
        self.name = name
        self._mailbox: asyncio.Queue[Message] = asyncio.Queue(maxsize=mailbox_size)
        self._task: Optional[asyncio.Task] = None
        self._running = False
        self._children: list["Actor"] = []

    async def start(self) -> "Actor":
        """Start the actor's message processing loop."""
        self._running = True
        self._task = asyncio.create_task(self._run(), name=f"actor-{self.name}")
        return self

    async def _run(self):
        """Main loop: dequeue and process messages one at a time."""
        try:
            while self._running:
                message = await self._mailbox.get()
                if isinstance(message, PoisonPill):
                    await self.on_shutdown()
                    self._running = False
                    break
                await self.receive(message)
        except asyncio.CancelledError:
            await self.on_shutdown()
        except Exception as e:
            print(f"Actor {self.name} crashed: {e}")
            await self.on_shutdown()

    async def send(self, message: Message) -> None:
        """Send a message to this actor's mailbox."""
        await self._mailbox.put(message)

    def send_nowait(self, message: Message) -> None:
        """Non-blocking send (raises if mailbox full)."""
        self._mailbox.put_nowait(message)

    @abstractmethod
    async def receive(self, message: Message) -> None:
        """Handle a received message. Override in subclasses."""
        ...

    async def on_shutdown(self) -> None:
        """Cleanup hook. Override for resource cleanup."""
        for child in self._children:
            await child.send(PoisonPill())

    async def spawn(self, actor: "Actor") -> "Actor":
        """Create and start a child actor."""
        self._children.append(actor)
        await actor.start()
        return actor

    async def stop(self):
        """Request graceful shutdown."""
        await self.send(PoisonPill())
        if self._task:
            await self._task
```

#### Step 2: Word-Count Pipeline Actors

```python
@dataclass
class TextChunk(Message):
    """A chunk of text to process."""
    text: str
    chunk_id: int = 0


@dataclass
class WordBatch(Message):
    """A batch of words extracted from text."""
    words: list[str] = field(default_factory=list)


@dataclass
class WordCount(Message):
    """Count for a single word."""
    word: str = ""
    count: int = 0


@dataclass
class GetResults(Message):
    """Request final results."""
    reply_to: Optional[asyncio.Queue] = None


class ReaderActor(Actor):
    """Reads text and sends chunks to splitter."""

    def __init__(self, splitter: Actor):
        super().__init__("reader")
        self.splitter = splitter

    async def receive(self, message: Message):
        if isinstance(message, TextChunk):
            # Forward to splitter
            await self.splitter.send(message)


class SplitterActor(Actor):
    """Splits text into words and sends batches to counter."""

    def __init__(self, counter: Actor, batch_size: int = 100):
        super().__init__("splitter")
        self.counter = counter
        self.batch_size = batch_size

    async def receive(self, message: Message):
        if isinstance(message, TextChunk):
            words = message.text.lower().split()
            # Send in batches to avoid overwhelming the counter
            for i in range(0, len(words), self.batch_size):
                batch = words[i:i + self.batch_size]
                await self.counter.send(WordBatch(words=batch))


class CounterActor(Actor):
    """Counts word frequencies. Maintains local state (safe — single-threaded)."""

    def __init__(self):
        super().__init__("counter")
        self.counts: dict[str, int] = {}

    async def receive(self, message: Message):
        if isinstance(message, WordBatch):
            for word in message.words:
                self.counts[word] = self.counts.get(word, 0) + 1
        elif isinstance(message, GetResults):
            # Send results back via the reply queue
            if message.reply_to:
                await message.reply_to.put(dict(self.counts))
```

#### Step 3: Running the Pipeline

```python
async def word_count_pipeline():
    """Demonstrate the actor pipeline."""
    # Create actors (bottom-up: counter first, then splitter, then reader)
    counter = CounterActor()
    splitter = SplitterActor(counter)
    reader = ReaderActor(splitter)

    # Start all actors
    await counter.start()
    await splitter.start()
    await reader.start()

    # Feed text chunks
    texts = [
        "the quick brown fox jumps over the lazy dog",
        "the dog barked at the fox and the fox ran away",
        "quick quick quick the fox is very quick",
    ]

    for i, text in enumerate(texts):
        await reader.send(TextChunk(text=text, chunk_id=i))

    # Allow processing to complete
    await asyncio.sleep(0.1)

    # Request results
    reply_queue: asyncio.Queue = asyncio.Queue()
    await counter.send(GetResults(reply_to=reply_queue))
    results = await reply_queue.get()

    # Print top words
    sorted_words = sorted(results.items(), key=lambda x: -x[1])
    print("Top 10 words:")
    for word, count in sorted_words[:10]:
        print(f"  {word}: {count}")

    # Shutdown pipeline
    await reader.stop()
    await splitter.stop()
    await counter.stop()

# asyncio.run(word_count_pipeline())
```

**Final Answer:**

```python
# Actor model properties:
# 1. No shared state → no locks, no race conditions
# 2. Sequential message processing → easy to reason about
# 3. Location transparency → actors can be on different machines
# 4. Fault isolation → one actor crashing doesn't kill others
#
# When to use actors in Python:
# - Complex stateful concurrent systems (chat servers, game engines)
# - Pipeline processing with backpressure (mailbox size limits)
# - When you want Erlang/Akka-style supervision trees
#
# Libraries: pykka, thespian, or just asyncio.Queue (as shown above)
```

### Example 9.2 — CSP with Trio Channels: Structured Concurrency Done Right

**Problem:** Implement a producer-consumer pipeline using Trio's memory channels (CSP-style communication). Show how Trio's structured concurrency prevents resource leaks that plague asyncio code.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### Step 1: CSP (Communicating Sequential Processes) Concept

```python
# CSP: processes communicate by SENDING and RECEIVING on channels.
# Key difference from Actor model:
# - Actors: async mailbox (sender never blocks)
# - CSP: synchronous channels (sender blocks until receiver is ready)
#
# Trio's memory channels are buffered CSP channels:
# - send_channel.send(value) blocks if buffer is full (backpressure!)
# - receive_channel.receive() blocks if buffer is empty
# - Closing a channel signals "no more data" (like Go's close(ch))
```

#### Step 2: Producer-Consumer with Trio

```python
import trio

async def producer(send_channel: trio.MemorySendChannel, items: list[str]):
    """
    Produce items into the channel.
    Blocks if channel buffer is full (natural backpressure).
    """
    async with send_channel:  # Closes channel when done
        for item in items:
            await send_channel.send(item)
            print(f"  Produced: {item}")
            await trio.sleep(0.1)  # Simulate work
    print("  Producer: done, channel closed")


async def transformer(
    receive_channel: trio.MemoryReceiveChannel,
    send_channel: trio.MemorySendChannel,
):
    """
    Transform items: receive from input, process, send to output.
    """
    async with receive_channel, send_channel:
        async for item in receive_channel:
            # Transform
            result = item.upper()
            await send_channel.send(result)
            print(f"  Transformed: {item} → {result}")


async def consumer(receive_channel: trio.MemoryReceiveChannel):
    """
    Consume items from the channel.
    Loop ends automatically when channel is closed by producer.
    """
    results = []
    async with receive_channel:
        async for item in receive_channel:
            results.append(item)
            print(f"  Consumed: {item}")
    print(f"  Consumer: received {len(results)} items total")
    return results


async def pipeline():
    """
    Three-stage pipeline: producer → transformer → consumer.
    Trio's structured concurrency guarantees:
    - All tasks complete before pipeline() returns
    - If any task crashes, all others are cancelled
    - No orphaned tasks, no resource leaks
    """
    # Create channels (buffered with capacity 5)
    send1, recv1 = trio.open_memory_channel[str](5)
    send2, recv2 = trio.open_memory_channel[str](5)

    items = ["hello", "world", "trio", "is", "great"]

    async with trio.open_nursery() as nursery:
        # Nursery = structured concurrency scope
        # ALL tasks must complete before nursery exits
        nursery.start_soon(producer, send1, items)
        nursery.start_soon(transformer, recv1, send2)
        nursery.start_soon(consumer, recv2)

    print("Pipeline complete — all tasks finished cleanly")

# trio.run(pipeline)
```

#### Step 3: Fan-Out / Fan-In Pattern

```python
async def fan_out_fan_in():
    """
    One producer, multiple workers, one collector.
    Demonstrates channel cloning for multiple consumers.
    """
    work_send, work_recv = trio.open_memory_channel[int](100)
    result_send, result_recv = trio.open_memory_channel[int](100)

    async def producer(send_ch):
        async with send_ch:
            for i in range(20):
                await send_ch.send(i)

    async def worker(worker_id, recv_ch, send_ch):
        async with recv_ch, send_ch:
            async for item in recv_ch:
                # Simulate CPU work
                await trio.sleep(0.05)
                result = item * item
                await send_ch.send(result)
                print(f"  Worker {worker_id}: {item}² = {result}")

    async def collector(recv_ch):
        results = []
        async with recv_ch:
            async for item in recv_ch:
                results.append(item)
        print(f"  Collected {len(results)} results: sum = {sum(results)}")

    async with trio.open_nursery() as nursery:
        nursery.start_soon(producer, work_send)

        # Clone channels for multiple workers
        # Each worker gets its own receive end (load balancing)
        nursery.start_soon(worker, 1, work_recv.clone(), result_send.clone())
        nursery.start_soon(worker, 2, work_recv.clone(), result_send.clone())
        nursery.start_soon(worker, 3, work_recv, result_send)
        # Note: last worker takes the original (not cloned)
        # Channel closes when ALL clones are closed

        nursery.start_soon(collector, result_recv)

# trio.run(fan_out_fan_in)
```

**Final Answer:**

```python
# CSP vs Actor Model:
# | Property        | CSP (Trio channels)      | Actor (mailbox)         |
# |-----------------|--------------------------|-------------------------|
# | Communication   | Synchronous (blocking)   | Asynchronous (buffered) |
# | Backpressure    | Built-in (channel full)  | Manual (mailbox limit)  |
# | Completion      | Channel close signals end | PoisonPill message      |
# | Error handling  | Nursery cancels siblings | Supervisor restarts     |
# | Best for        | Pipelines, fan-out/in    | Stateful services       |
#
# Trio vs asyncio:
# - Trio: structured concurrency (nurseries), no orphaned tasks, safer
# - asyncio: more ecosystem support, TaskGroup (3.11+) adds structure
# - For new projects: consider Trio for correctness guarantees
```

### Example 9.3 — Fork-Join with ProcessPoolExecutor: CPU-Bound Parallelism

**Problem:** Implement a parallel merge sort using the fork-join pattern with `concurrent.futures.ProcessPoolExecutor`. Demonstrate the overhead crossover point where parallelism becomes beneficial.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### Step 1: The Fork-Join Pattern

```python
from concurrent.futures import ProcessPoolExecutor, Future
import multiprocessing as mp
from typing import List
import time

# Fork-Join:
# 1. FORK: Split work into independent subtasks
# 2. Execute subtasks in parallel (on separate cores)
# 3. JOIN: Wait for all subtasks, combine results
#
# Key insight: only beneficial when subtask work >> fork/join overhead
# Python process creation: ~50ms
# So subtasks must take >> 50ms to benefit from parallelism


def merge(left: List[int], right: List[int]) -> List[int]:
    """Merge two sorted lists into one sorted list. O(n+m)."""
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result


def sequential_merge_sort(arr: List[int]) -> List[int]:
    """Standard merge sort. O(n log n)."""
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = sequential_merge_sort(arr[:mid])
    right = sequential_merge_sort(arr[mid:])
    return merge(left, right)
```

#### Step 2: Parallel Merge Sort

```python
def parallel_merge_sort(
    arr: List[int],
    executor: ProcessPoolExecutor,
    threshold: int = 100_000,
) -> List[int]:
    """
    Parallel merge sort using fork-join.
    
    - Arrays smaller than threshold: sort sequentially (avoid overhead)
    - Arrays larger than threshold: fork into two parallel subtasks
    
    The threshold is critical: too small = overhead dominates,
    too large = not enough parallelism.
    """
    if len(arr) <= threshold:
        return sequential_merge_sort(arr)

    mid = len(arr) // 2

    # FORK: submit both halves as parallel tasks
    future_left = executor.submit(sequential_merge_sort, arr[:mid])
    future_right = executor.submit(sequential_merge_sort, arr[mid:])

    # JOIN: wait for both to complete
    left = future_left.result()
    right = future_right.result()

    # COMBINE: merge the sorted halves
    return merge(left, right)


def benchmark_parallel_sort():
    """Find the crossover point where parallelism helps."""
    import random

    sizes = [10_000, 100_000, 500_000, 1_000_000, 5_000_000]
    num_workers = mp.cpu_count()

    print(f"CPU cores: {num_workers}")
    print(f"{'Size':>12} {'Sequential':>12} {'Parallel':>12} {'Speedup':>10}")
    print("-" * 50)

    for size in sizes:
        arr = [random.randint(0, 10**9) for _ in range(size)]

        # Sequential
        start = time.perf_counter()
        sequential_merge_sort(arr.copy())
        seq_time = time.perf_counter() - start

        # Parallel
        with ProcessPoolExecutor(max_workers=num_workers) as executor:
            start = time.perf_counter()
            parallel_merge_sort(arr.copy(), executor, threshold=size // num_workers)
            par_time = time.perf_counter() - start

        speedup = seq_time / par_time
        print(f"{size:>12,} {seq_time:>10.3f}s {par_time:>10.3f}s {speedup:>8.2f}x")

    # Typical results (8-core machine):
    # Size 10,000: speedup 0.3x (overhead dominates!)
    # Size 100,000: speedup 1.2x (barely worth it)
    # Size 1,000,000: speedup 3.5x (good)
    # Size 5,000,000: speedup 5.8x (approaching core count)

# benchmark_parallel_sort()
```

**Final Answer:**

```python
# Fork-Join rules of thumb:
# 1. Subtask work must be >> 50ms (process creation overhead)
# 2. Use a threshold to fall back to sequential for small inputs
# 3. Optimal threshold ≈ total_work / num_workers
# 4. Maximum speedup ≈ num_cores (Amdahl's law limits further)
# 5. For Python: prefer ProcessPoolExecutor over manual Process management
# 6. Data must be picklable (serialization overhead for large arrays)
#
# Better alternatives for numeric work:
# - NumPy (C-level parallelism, no pickle overhead)
# - multiprocessing.shared_memory (avoid copying large arrays)
# - Dask (automatic task graph parallelization)
```

### 10.1 The Reactor Pattern — Foundation of All Event-Driven Servers

The Reactor pattern is the architectural foundation of asyncio, Node.js, nginx, and every high-performance event-driven server. Understanding it explains why these systems handle thousands of connections on a single thread.

**The Pattern:**

```python
# Components:
# 1. Event Demultiplexer: OS mechanism that blocks until I/O is ready
#    (select, poll, epoll, kqueue, io_uring)
# 2. Event Loop: Calls demultiplexer, dispatches ready events to handlers
# 3. Event Handlers: Callbacks that process ready I/O (non-blocking)
# 4. Resources: File descriptors (sockets, files, pipes)

# Pseudocode:
# while running:
#     ready_events = demultiplexer.wait(registered_fds, timeout)
#     for event in ready_events:
#         handler = handler_map[event.fd]
#         handler(event)  # Must be NON-BLOCKING (no sleep, no blocking I/O)

# This is EXACTLY what asyncio.run() does internally:
# 1. Register coroutines as handlers for I/O events
# 2. Loop: wait for I/O → resume the coroutine that was waiting
# 3. Coroutine runs until next await (yields back to event loop)
```

**Why Single-Threaded Reactor Scales:**

The key insight: most server time is spent WAITING for I/O (network, disk). A single thread can manage 10,000 connections because:
- It only processes connections that are READY (have data to read/write)
- While one connection waits for a database response, the thread handles other connections
- No thread context switching overhead (threads cost ~8KB stack + scheduling)
- No lock contention (single thread = no races)

**Limitations:**

1. **CPU-bound work blocks the entire reactor.** One slow computation starves all connections. Solution: offload to thread pool (`asyncio.to_thread()`) or process pool.

2. **Single core utilization.** One reactor uses one CPU core. Solution: run multiple reactor processes (one per core), with load balancing (nginx does this).

3. **Callback complexity (pre-async/await).** Raw reactor code is "callback hell." Solution: async/await syntax (coroutines that LOOK sequential but execute as callbacks).

### 10.2 Software Transactional Memory (STM) in Python

Software Transactional Memory (STM) is a concurrency control mechanism that treats shared memory access like database transactions: reads and writes are grouped into atomic transactions that either commit entirely or roll back.

**The Concept:**

```python
# Traditional locking:
# lock.acquire()
# balance_a -= 100
# balance_b += 100
# lock.release()
# Problem: deadlocks, priority inversion, composability issues

# STM approach:
# with atomic():
#     balance_a -= 100
#     balance_b += 100
# If another transaction conflicts: automatically RETRY (no deadlocks!)
```

**Minimal STM Implementation:**

```python
import threading
from typing import TypeVar, Generic, Any
from copy import deepcopy

T = TypeVar("T")


class TVar(Generic[T]):
    """Transactional variable — the unit of shared state in STM."""

    def __init__(self, value: T):
        self._value = value
        self._lock = threading.Lock()
        self._version = 0

    @property
    def value(self) -> T:
        return self._value

    @value.setter
    def value(self, new_value: T):
        self._value = new_value
        self._version += 1


class Transaction:
    """
    Represents an atomic transaction.
    Tracks reads and writes, commits atomically or retries.
    """

    def __init__(self):
        self.read_set: dict[int, tuple[TVar, int]] = {}  # id(tvar) → (tvar, version_read)
        self.write_set: dict[int, tuple[TVar, Any]] = {}  # id(tvar) → (tvar, new_value)

    def read(self, tvar: TVar[T]) -> T:
        """Read a TVar within this transaction."""
        tid = id(tvar)
        if tid in self.write_set:
            return self.write_set[tid][1]  # Return our pending write
        self.read_set[tid] = (tvar, tvar._version)
        return tvar.value

    def write(self, tvar: TVar[T], value: T):
        """Write to a TVar within this transaction."""
        tid = id(tvar)
        if tid not in self.read_set:
            self.read_set[tid] = (tvar, tvar._version)
        self.write_set[tid] = (tvar, value)

    def validate(self) -> bool:
        """Check that no read values have been modified by other transactions."""
        for tid, (tvar, version_read) in self.read_set.items():
            if tvar._version != version_read:
                return False  # Conflict! Another transaction modified this TVar
        return True

    def commit(self) -> bool:
        """Attempt to commit. Returns False if validation fails."""
        # Acquire all locks (in consistent order to prevent deadlocks)
        tvars = sorted(self.write_set.values(), key=lambda x: id(x[0]))
        locks_held = []

        try:
            for tvar, _ in tvars:
                tvar._lock.acquire()
                locks_held.append(tvar._lock)

            # Validate read set (optimistic concurrency control)
            if not self.validate():
                return False

            # Commit writes
            for tvar, new_value in self.write_set.values():
                tvar.value = new_value

            return True
        finally:
            for lock in locks_held:
                lock.release()


def atomic(func, max_retries: int = 100):
    """
    Execute func as an atomic transaction.
    Automatically retries on conflict.
    """
    for attempt in range(max_retries):
        txn = Transaction()
        try:
            result = func(txn)
            if txn.commit():
                return result
            # Commit failed (conflict) — retry
        except Exception:
            raise  # Don't retry on application errors

    raise RuntimeError(f"Transaction failed after {max_retries} retries")


# Usage:
balance_a = TVar(1000)
balance_b = TVar(500)

def transfer(txn: Transaction):
    """Transfer 100 from A to B — atomic, no explicit locks."""
    a = txn.read(balance_a)
    b = txn.read(balance_b)
    txn.write(balance_a, a - 100)
    txn.write(balance_b, b + 100)

atomic(transfer)
print(f"A: {balance_a.value}, B: {balance_b.value}")  # A: 900, B: 600
```

**STM vs Locks:**

| Property | Locks | STM |
|----------|-------|-----|
| Deadlocks | Possible | Impossible (retry, not block) |
| Composability | Hard (lock ordering) | Easy (nest transactions) |
| Performance (low contention) | Faster (no validation) | Slightly slower (overhead) |
| Performance (high contention) | Degrades (lock convoy) | Degrades (many retries) |
| Complexity | Manual lock management | Automatic retry |

**In Practice:** STM is rarely used in Python because the GIL already serializes access. It's more relevant in languages with true shared-memory parallelism (Haskell's STM, Clojure's refs, Java's Multiverse). With Python's free-threaded future (PEP 703), STM may become more relevant.
