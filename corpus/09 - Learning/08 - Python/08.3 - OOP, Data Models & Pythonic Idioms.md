# 08.3 — OOP, Data Models & Pythonic Idioms

> *"There is only one class in Python: `type`. Everything else is an instance of it."* — Guido van Rossum

Python's OOP is not Java's OOP. There are no access modifiers, no interfaces (in the Java sense), no abstract base class requirement. Instead, Python offers a **protocol-based** object model where behavior is defined by which dunder methods you implement. This chapter teaches you to think in protocols, not inheritance hierarchies.

---

## 🎯 Learning Objectives

By the end of this chapter you will be able to:

1. Design classes using the descriptor protocol, `__slots__`, and `__init_subclass__`.
2. Implement all major protocols: iterable, comparable, hashable, context manager, callable.
3. Use `dataclasses` and `attrs` for data-bearing classes with minimal boilerplate.

5. Build metaclasses and class decorators for framework-level metaprogramming.
6. Apply SOLID principles in a Pythonic way (composition over inheritance, protocols over ABCs).

## 📚 1. Definitions / Concepts

### Definition 08.3.1 — The Data Model (Dunder Methods)

Python's **data model** is the set of special methods (double-underscore, "dunder") that the interpreter calls to perform operations on objects. When you write `a + b`, Python calls `a.__add__(b)`. When you write `len(x)`, Python calls `x.__len__()`.

The data model is Python's **operator overloading** system — but it's far more comprehensive than C++ operator overloading because it covers attribute access, iteration, context management, and object lifecycle.

### Definition 08.3.2 — Descriptor Protocol

A **descriptor** is any object that defines `__get__`, `__set__`, or `__delete__`. Descriptors are the mechanism behind `@property`, `@classmethod`, `@staticmethod`, and even plain method binding.

```python
class Validator:
    """A data descriptor that validates on assignment."""
    def __set_name__(self, owner, name):
        self.storage_name = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.storage_name, None)

    def __set__(self, obj, value):
        self.validate(value)
        setattr(obj, self.storage_name, value)

    def validate(self, value):
        raise NotImplementedError
```

### Definition 08.3.3 — Method Resolution Order (MRO)

The **MRO** is the order in which Python searches base classes when looking up a method. It uses the **C3 linearization** algorithm, which guarantees:
1. Children come before parents
2. The order of bases in the class definition is preserved
3. A consistent ordering exists (or Python raises `TypeError`)

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print(D.__mro__)
# (D, B, C, A, object)
```

### Definition 08.3.4 — `__slots__`

By default, Python stores instance attributes in a per-instance `__dict__` (a hash table). `__slots__` replaces this with a fixed-size struct, saving ~40-60% memory per instance and providing faster attribute access.

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

# p.__dict__  # AttributeError — no dict!
# p.z = 3    # AttributeError — can't add attributes
```

### Definition 08.3.5 — Dataclasses

`@dataclass` auto-generates `__init__`, `__repr__`, `__eq__`, and optionally `__hash__`, `__lt__`, etc. from class-level type annotations:

```python
from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True)
class Vector3:
    x: float
    y: float
    z: float

    @property
    def magnitude(self) -> float:
        return (self.x**2 + self.y**2 + self.z**2) ** 0.5
```

`frozen=True` makes instances immutable (hashable). `slots=True` (3.10+) adds `__slots__` automatically.

## 📐 2. Mental Models / Principles

### Principle 1.3.1 — Composition Over Inheritance

Python supports multiple inheritance, but that doesn't mean you should use deep hierarchies. Prefer:

```python
# GOOD: Composition
class GameEngine:
    def __init__(self):
        self.physics = PhysicsSystem()
        self.renderer = RenderSystem()
        self.audio = AudioSystem()

# BAD: Deep inheritance
class GameEngine(PhysicsSystem, RenderSystem, AudioSystem):
    pass  # Diamond problem, fragile base class, tight coupling
```

### Principle 1.3.2 — Protocols > ABCs > Inheritance

For type checking, prefer `Protocol` (structural subtyping) over `ABC` (nominal subtyping):

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Drawable(Protocol):
    def draw(self, surface: "Surface") -> None: ...
    def get_bounds(self) -> tuple[int, int, int, int]: ...

# Any class with draw() and get_bounds() satisfies Drawable
# No inheritance required!
class Sprite:
    def draw(self, surface): ...
    def get_bounds(self): return (0, 0, 64, 64)

def render(obj: Drawable) -> None:  # Type-safe without inheritance
    obj.draw(screen)
```

### Principle 1.3.3 — The Descriptor Lookup Chain

When you access `obj.attr`, Python follows this resolution order:
1. **Data descriptor** on the class (has `__get__` AND `__set__`)
2. **Instance `__dict__`** (the object's own attributes)
3. **Non-data descriptor** on the class (has only `__get__`)
4. **Class `__dict__`** (class variables)
5. `__getattr__` (fallback, only if nothing found)

This is why `@property` (a data descriptor) overrides instance attributes.

## 🔑 3. Mechanics

### 3.1 — Complete Dunder Method Catalog (Most Important)

```python
class FullyLoaded:
    # --- Lifecycle ---
    def __init__(self, value):       # Initialize (NOT create)
        self.value = value
    def __new__(cls, *args):         # Create (rarely override)
        return super().__new__(cls)
    def __del__(self):               # Destructor (unreliable, avoid)
        pass

    # --- Representation ---
    def __repr__(self):              # Developer-facing (unambiguous)
        return f"FullyLoaded({self.value!r})"
    def __str__(self):               # User-facing (readable)
        return str(self.value)
    def __format__(self, spec):      # f-string / format()
        return format(self.value, spec)

    # --- Comparison ---
    def __eq__(self, other):         # ==
        return self.value == other.value
    def __lt__(self, other):         # < (enables sorting with @total_ordering)
        return self.value < other.value
    def __hash__(self):              # Required if __eq__ defined and you want set/dict membership
        return hash(self.value)

    # --- Arithmetic ---
    def __add__(self, other):        # self + other
        return FullyLoaded(self.value + other.value)
    def __radd__(self, other):       # other + self (when other doesn't know how)
        return self.__add__(other)
    def __iadd__(self, other):       # self += other (in-place)
        self.value += other.value
        return self

    # --- Container ---
    def __len__(self):               # len(self)
        return len(self.value)
    def __getitem__(self, key):      # self[key]
        return self.value[key]
    def __contains__(self, item):    # item in self
        return item in self.value
    def __iter__(self):              # for x in self
        return iter(self.value)

    # --- Context Manager ---
    def __enter__(self):             # with self as x:
        return self
    def __exit__(self, exc_type, exc_val, exc_tb):
        return False                 # Don't suppress exceptions

    # --- Callable ---
    def __call__(self, *args):       # self(args)
        return self.value(*args) if callable(self.value) else self.value

    # --- Attribute Access ---
    def __getattr__(self, name):     # Fallback for missing attributes
        raise AttributeError(f"No {name}")
    def __setattr__(self, name, value):  # ALL attribute assignment
        super().__setattr__(name, value)
```

### 3.2 — Dataclass Patterns for Production

```python
from dataclasses import dataclass, field, asdict, replace
from typing import Self

@dataclass(frozen=True, slots=True, order=True)
class Trade:
    """Immutable trade record."""
    symbol: str = field(compare=False)  # Excluded from ordering
    price: float
    quantity: int
    timestamp: float = field(default_factory=time.time, compare=False)

    @property
    def notional(self) -> float:
        return self.price * self.quantity

    def with_price(self, new_price: float) -> Self:
        """Immutable update pattern."""
        return replace(self, price=new_price)

# Usage:
t = Trade("AAPL", 150.0, 100)
t2 = t.with_price(155.0)  # New object, original unchanged
trades = sorted([t, t2])   # Sorts by price (order=True)
```

### 3.3 — Metaclasses (When You Need Them)

```python
class SingletonMeta(type):
    """Metaclass that ensures only one instance exists."""
    _instances: dict[type, object] = {}

    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class Database(metaclass=SingletonMeta):
    def __init__(self, url: str):
        self.url = url
        self.connect()

# Database("postgres://...") always returns the same instance
```

**When to use metaclasses:** Almost never. Prefer `__init_subclass__` (3.6+) or class decorators. Metaclasses are for framework authors (ORMs, serialization libraries, plugin systems).

**Problem:** Create a type-checked, range-validated descriptor for game entity attributes.

```python
class RangeChecked:
    """Descriptor that enforces type and range constraints."""
    def __init__(self, min_val: float = float('-inf'), max_val: float = float('inf')):
        self.min_val = min_val
        self.max_val = max_val

    def __set_name__(self, owner, name):
        self.public_name = name
        self.private_name = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.private_name, None)

    def __set__(self, obj, value):
        if not isinstance(value, (int, float)):
            raise TypeError(f"{self.public_name} must be numeric, got {type(value).__name__}")
        if not (self.min_val <= value <= self.max_val):
            raise ValueError(f"{self.public_name} must be in [{self.min_val}, {self.max_val}], got {value}")
        setattr(obj, self.private_name, value)

class GameEntity:
    health = RangeChecked(0, 100)
    speed = RangeChecked(0, 50)
    x = RangeChecked(-1000, 1000)
    y = RangeChecked(-1000, 1000)

    def __init__(self, health: float, speed: float, x: float, y: float):
        self.health = health
        self.speed = speed
        self.x = x
        self.y = y

entity = GameEntity(100, 25, 0, 0)
# entity.health = 150  # ValueError!
# entity.speed = "fast"  # TypeError!
```

### Example 08.3.2 — Implementing `__init_subclass__` for Plugin Registration

<details>
<summary>🔍 View Step-by-Step Solution</summary>

```python
class Plugin:
    """Base class that auto-registers subclasses."""
    _registry: dict[str, type["Plugin"]] = {}

    def __init_subclass__(cls, *, plugin_name: str | None = None, **kwargs):
        super().__init_subclass__(**kwargs)
        name = plugin_name or cls.__name__.lower()
        cls._registry[name] = cls

    @classmethod
    def get(cls, name: str) -> "Plugin":
        return cls._registry[name]()

class JSONExporter(Plugin, plugin_name="json"):
    def export(self, data): return json.dumps(data)

class CSVExporter(Plugin, plugin_name="csv"):
    def export(self, data): return "\n".join(",".join(row) for row in data)

# Usage:
exporter = Plugin.get("json")  # Returns JSONExporter instance
```

### Example 08.3.3 — Custom Container with Full Protocol Support

<details>
<summary>🔍 View Step-by-Step Solution</summary>

```python
from typing import Iterator, overload

class Matrix:
    """2D matrix with full container protocol."""
    __slots__ = ("_data", "_rows", "_cols")

    def __init__(self, rows: int, cols: int, data: list[float] | None = None):
        self._rows = rows
        self._cols = cols
        self._data = data if data else [0.0] * (rows * cols)

    def __repr__(self) -> str:
        return f"Matrix({self._rows}, {self._cols})"

    def __len__(self) -> int:
        return self._rows * self._cols

    @overload
    def __getitem__(self, key: tuple[int, int]) -> float: ...
    @overload
    def __getitem__(self, key: int) -> list[float]: ...

    def __getitem__(self, key):
        if isinstance(key, tuple):
            r, c = key
            return self._data[r * self._cols + c]
        return self._data[key * self._cols:(key + 1) * self._cols]

    def __setitem__(self, key: tuple[int, int], value: float) -> None:
        r, c = key
        self._data[r * self._cols + c] = value

    def __iter__(self) -> Iterator[list[float]]:
        for r in range(self._rows):
            yield self[r]

    def __contains__(self, value: float) -> bool:
        return value in self._data

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Matrix):
            return NotImplemented
        return self._data == other._data

    def __add__(self, other: "Matrix") -> "Matrix":
        if (self._rows, self._cols) != (other._rows, other._cols):
            raise ValueError("Dimension mismatch")
        return Matrix(self._rows, self._cols,
                      [a + b for a, b in zip(self._data, other._data)])

m = Matrix(3, 3)
m[1, 2] = 5.0
for row in m:
    print(row)
```

## 💻 5. Code Patterns & Idioms

### Pattern 1.3.1 — The `__repr__` / `__str__` Contract

```python
# __repr__: unambiguous, ideally eval()-able
# __str__: human-readable

class Money:
    def __init__(self, amount: float, currency: str = "USD"):
        self.amount = amount
        self.currency = currency

    def __repr__(self) -> str:
        return f"Money({self.amount!r}, {self.currency!r})"

    def __str__(self) -> str:
        return f"${self.amount:,.2f} {self.currency}"

m = Money(1234.5)
repr(m)  # "Money(1234.5, 'USD')"
str(m)   # "$1,234.50 USD"
```

### Pattern 1.3.2 — Abstract Base Classes (When Protocols Aren't Enough)

```python
from abc import ABC, abstractmethod

class Serializer(ABC):
    """Use ABC when you need enforced implementation + shared logic."""

    @abstractmethod
    def serialize(self, data: dict) -> bytes:
        """Subclasses MUST implement this."""
        ...

    def serialize_to_file(self, data: dict, path: Path) -> None:
        """Shared logic that uses the abstract method."""
        path.write_bytes(self.serialize(data))
```

### Pattern 1.3.3 — `__class_getitem__` for Generic Types

```python
class Response[T]:  # Python 3.12+ syntax
    def __init__(self, data: T, status: int = 200):
        self.data = data
        self.status = status

# Pre-3.12 equivalent:
from typing import Generic, TypeVar
T = TypeVar("T")
class Response(Generic[T]):
    ...
```

## ⚠️ 6. Gotchas & Anti-Patterns

### Gotcha 1.3.1 — Mutable Class Variables

```python
class Bad:
    items = []  # Shared across ALL instances!

    def add(self, item):
        self.items.append(item)  # Mutates the CLASS variable

a, b = Bad(), Bad()
a.add(1)
print(b.items)  # [1] — oops, shared state!

# Fix: Initialize in __init__
class Good:
    def __init__(self):
        self.items = []  # Per-instance
```

### Gotcha 1.3.2 — `__eq__` Without `__hash__`

If you define `__eq__`, Python sets `__hash__ = None` (making instances unhashable). If you need set/dict membership, explicitly define `__hash__`:

```python
@dataclass(frozen=True)  # Auto-generates both __eq__ and __hash__
class Point:
    x: float
    y: float
```

### Gotcha 1.3.3 — `super()` in Multiple Inheritance

```python
class A:
    def method(self):
        print("A")

class B(A):
    def method(self):
        print("B")
        super().method()  # Calls NEXT in MRO, not necessarily A!

class C(A):
    def method(self):
        print("C")
        super().method()

class D(B, C):
    def method(self):
        print("D")
        super().method()

D().method()  # D → B → C → A (follows MRO, not parent)
```

### Example 9.1 — The Descriptor Protocol: Building a Type-Checked Attribute System

**Problem:** Implement a reusable descriptor that enforces type checking, range validation, and immutability — demonstrating the full descriptor protocol (`__get__`, `__set__`, `__delete__`, `__set_name__`). Then show how Python's own `property`, `classmethod`, and `staticmethod` are implemented as descriptors.

<details>
<summary>🔍 Full step-by-step solution</summary>

#### Step 1: Understanding the Descriptor Protocol

A descriptor is any object that defines at least one of `__get__`, `__set__`, or `__delete__`. When placed as a class variable, Python's attribute lookup machinery invokes these methods instead of returning the descriptor object itself.

**Data descriptor** (defines `__set__` or `__delete__`): Takes priority over instance `__dict__`.
**Non-data descriptor** (defines only `__get__`): Instance `__dict__` takes priority.

The lookup order for `obj.attr`:
1. **Data descriptors** on `type(obj)` (and its MRO)
2. Instance `__dict__` (`obj.__dict__['attr']`)
3. **Non-data descriptors** on `type(obj)` (and its MRO)

#### Step 2: Building a Validated Descriptor

```python
from typing import Any, TypeVar, Generic, Callable, Optional

T = TypeVar("T")


class Validated(Generic[T]):
    """
    A data descriptor that enforces type and custom validation.
    
    Usage:
        class Circle:
            radius = Validated(float, lambda x: x > 0, "must be positive")
    """

    def __init__(
        self,
        expected_type: type[T],
        validator: Optional[Callable[[T], bool]] = None,
        error_msg: str = "validation failed",
    ):
        self.expected_type = expected_type
        self.validator = validator
        self.error_msg = error_msg
        self.attr_name: str = ""  # Set by __set_name__

    def __set_name__(self, owner: type, name: str) -> None:
        """
        Called automatically when the descriptor is assigned to a class variable.
        PEP 487 (Python 3.6+). `owner` is the class, `name` is the attribute name.
        """
        self.attr_name = name
        self.storage_name = f"_validated_{name}"  # Private storage key

    def __get__(self, obj: Any, objtype: Optional[type] = None) -> T:
        """
        Called on attribute access: obj.attr or Class.attr.
        If obj is None, we're accessing from the class itself.
        """
        if obj is None:
            return self  # type: ignore — accessing descriptor from class
        return getattr(obj, self.storage_name)  # type: ignore

    def __set__(self, obj: Any, value: T) -> None:
        """
        Called on attribute assignment: obj.attr = value.
        This is what makes it a DATA descriptor (overrides instance __dict__).
        """
        # Type check
        if not isinstance(value, self.expected_type):
            raise TypeError(
                f"{self.attr_name}: expected {self.expected_type.__name__}, "
                f"got {type(value).__name__}"
            )
        # Custom validation
        if self.validator is not None and not self.validator(value):
            raise ValueError(f"{self.attr_name}: {self.error_msg}")
        # Store in instance's __dict__ under a mangled name
        setattr(obj, self.storage_name, value)

    def __delete__(self, obj: Any) -> None:
        """Called on: del obj.attr"""
        try:
            delattr(obj, self.storage_name)
        except AttributeError:
            raise AttributeError(
                f"'{type(obj).__name__}' object has no attribute '{self.attr_name}'"
            )
```

#### Step 3: Using the Descriptor

```python
class Circle:
    radius = Validated(float, lambda r: r > 0, "must be positive")
    color = Validated(str)

    def __init__(self, radius: float, color: str = "red"):
        self.radius = radius  # Triggers Validated.__set__
        self.color = color

    @property
    def area(self) -> float:
        import math
        return math.pi * self.radius ** 2


# Usage:
c = Circle(5.0, "blue")
print(c.radius)  # 5.0 — triggers Validated.__get__
print(c.area)    # 78.54...

c.radius = 10.0  # OK
# c.radius = -08.0  # ValueError: radius: must be positive
# c.radius = "big"  # TypeError: radius: expected float, got str

# Inspect storage:
print(c.__dict__)  # {'_validated_radius': 10.0, '_validated_color': 'blue'}
```

#### Step 4: How property() Is a Descriptor

```python
# property is implemented (conceptually) as:
class property_reimplemented:
    """Simplified reimplementation showing descriptor mechanics."""

    def __init__(self, fget=None, fset=None, fdel=None, doc=None):
        self.fget = fget
        self.fset = fset
        self.fdel = fdel
        self.__doc__ = doc or (fget.__doc__ if fget else None)

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        if self.fget is None:
            raise AttributeError("unreadable attribute")
        return self.fget(obj)

    def __set__(self, obj, value):
        if self.fset is None:
            raise AttributeError("can't set attribute")
        self.fset(obj, value)

    def __delete__(self, obj):
        if self.fdel is None:
            raise AttributeError("can't delete attribute")
        self.fdel(obj)

    def setter(self, fset):
        return type(self)(self.fget, fset, self.fdel, self.__doc__)

    def deleter(self, fdel):
        return type(self)(self.fget, self.fset, fdel, self.__doc__)
```

#### Step 5: classmethod and staticmethod as Non-Data Descriptors

```python
class staticmethod_reimplemented:
    """staticmethod is a non-data descriptor that ignores the instance."""

    def __init__(self, func):
        self.func = func

    def __get__(self, obj, objtype=None):
        return self.func  # Return the raw function, no binding


class classmethod_reimplemented:
    """classmethod binds the function to the class, not the instance."""

    def __init__(self, func):
        self.func = func

    def __get__(self, obj, objtype=None):
        if objtype is None:
            objtype = type(obj)
        # Return a bound method where first arg is the class
        def class_bound(*args, **kwargs):
            return self.func(objtype, *args, **kwargs)
        return class_bound
```

**Final Answer:**

```python
# The descriptor protocol is Python's mechanism for customizing attribute access.
# Key insight: property, classmethod, staticmethod, __slots__, and even
# regular method binding ALL use the descriptor protocol internally.
# 
# Data descriptors (__set__/__delete__) override instance __dict__.
# Non-data descriptors (only __get__) yield to instance __dict__.
# This priority system is what makes Python's attribute lookup so flexible.
```

### Example 9.2 — Metaclass Tutorial: Building an Auto-Registering Plugin System

**Problem:** Design a plugin system where any class that inherits from `Plugin` is automatically registered in a global registry — without decorators, without manual registration calls. Use metaclasses to intercept class creation.

<details>

#### Step 1: The Goal

#### Step 2: The Metaclass

```python
class PluginMeta(type):
    """
    Metaclass that auto-registers subclasses into a registry.
    
    How metaclasses work:
    - `type` is the default metaclass for all classes
    - When Python executes `class Foo(Base):`, it calls:
      metaclass.__new__(mcs, name, bases, namespace)
      metaclass.__init__(cls, name, bases, namespace)
    - By overriding these, we intercept class creation
    """

    def __new__(mcs, name: str, bases: tuple, namespace: dict):
        """
        Called BEFORE the class object is created.
        `mcs` is the metaclass itself (PluginMeta).
        `name` is the class name being created.
        `bases` is the tuple of base classes.
        `namespace` is the class body's local namespace (methods, attributes).
        """
        cls = super().__new__(mcs, name, bases, namespace)

        # Don't register the base Plugin class itself
        if bases:  # Only register subclasses (bases is non-empty)
            # Validate that subclass defines required interface
            if not hasattr(cls, "format"):
                raise TypeError(
                    f"Plugin subclass '{name}' must define a 'format' class attribute"
                )
            if not callable(getattr(cls, "process", None)):
                raise TypeError(
                    f"Plugin subclass '{name}' must define a 'process' method"
                )

            # Register in the base class's registry
            registry = cls._get_registry()
            fmt = cls.format
            if fmt in registry:
                raise ValueError(
                    f"Duplicate plugin format '{fmt}': "
                    f"{registry[fmt].__name__} and {name}"
                )
            registry[fmt] = cls

        return cls

    def _get_registry(cls) -> dict:
        """Walk MRO to find the registry on the base Plugin class."""
        for base in cls.__mro__:
            if "_registry" in base.__dict__:
                return base._registry
        return {}


class Plugin(metaclass=PluginMeta):
    """
    Base class for all plugins. Subclasses are auto-registered.
    """
    _registry: dict[str, type] = {}
    format: str  # Must be defined by subclasses

    def process(self, data):
        raise NotImplementedError

    @classmethod
    def get_plugin(cls, format_name: str) -> "Plugin":
        """Retrieve a registered plugin by format."""
        plugin_cls = cls._registry.get(format_name)
        if plugin_cls is None:
            available = ", ".join(cls._registry.keys())
            raise KeyError(
                f"No plugin for '{format_name}'. Available: {available}"
            )
        return plugin_cls()

    @classmethod
    def list_plugins(cls) -> list[str]:
        return list(cls._registry.keys())
```

#### Step 5: Modern Alternative — `__init_subclass__` (Python 3.6+)

For simpler cases, `__init_subclass__` (PEP 487) avoids the need for an explicit metaclass:

```python
class PluginSimple:
    """Same behavior without explicit metaclass."""
    _registry: dict[str, type] = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        if hasattr(cls, "format"):
            PluginSimple._registry[cls.format] = cls

class JSONPlugin(PluginSimple):
    format = "json"
    def process(self, data): ...

print(PluginSimple._registry)  # {'json': JSONPlugin}
```

**When to use metaclass vs `__init_subclass__`:**
- `__init_subclass__`: Simple registration, validation, attribute injection
- Metaclass: Control over `__new__` (modify class before creation), custom `__call__` (control instantiation), `__instancecheck__`/`__subclasscheck__` (custom isinstance behavior)

**Final Answer:**

```python
# Metaclasses intercept class CREATION (not instantiation).
# They're the "class of a class" — type(MyClass) returns the metaclass.
# Use cases: ORMs (Django models), plugin systems, API frameworks, ABCs.
# Prefer __init_subclass__ for simple cases (90% of use cases).
# Reserve metaclasses for when you need to modify the class BEFORE it exists.
```

**Problem:** Design a set of mixins for a web framework's view system: `JSONMixin` (serialization), `AuthMixin` (authentication), `CacheMixin` (response caching), and `LogMixin` (request logging). Show how to compose them safely, handle method resolution order (MRO), and avoid the fragile base class problem.

#### Step 1: Mixin Design Rules

```python
# Rule 1: Mixins should NOT have __init__ (or call super().__init__() cooperatively)
# Rule 2: Mixins should be narrow — one responsibility per mixin
# Rule 3: Mixins should use super() for cooperative multiple inheritance
# Rule 4: Mixins should not hold state (or use minimal, namespaced state)
# Rule 5: Mixins go LEFT of the base class in inheritance list
```

#### Step 2: The Base View Class

```python
from typing import Any
import json
import time
import hashlib
import functools


class Request:
    """Simplified request object."""
    def __init__(self, path: str, method: str = "GET",
                 headers: dict[str, str] | None = None,
                 user: str | None = None):
        self.path = path
        self.method = method
        self.headers = headers or {}
        self.user = user


class Response:
    """Simplified response object."""
    def __init__(self, body: Any = "", status: int = 200,
                 headers: dict[str, str] | None = None):
        self.body = body
        self.status = status
        self.headers = headers or {"Content-Type": "text/html"}


class View:
    """Base view class — the foundation all mixins build upon."""

    def dispatch(self, request: Request) -> Response:
        """Route request to appropriate handler method."""
        handler = getattr(self, request.method.lower(), self.method_not_allowed)
        return handler(request)

    def method_not_allowed(self, request: Request) -> Response:
        return Response(body="Method Not Allowed", status=405)
```

#### Step 3: The Mixins

```python
class JSONMixin:
    """Adds JSON serialization to responses."""

    def dispatch(self, request: Request) -> Response:
        response = super().dispatch(request)  # Cooperative call
        if isinstance(response.body, (dict, list)):
            response.body = json.dumps(response.body, default=str)
            response.headers["Content-Type"] = "application/json"
        return response


class AuthMixin:
    """Requires authentication before processing."""
    required_role: str = "user"  # Override in subclass for role-based access

    def dispatch(self, request: Request) -> Response:
        if not request.user:
            return Response(body="Unauthorized", status=401)
        # In real app: check role against required_role
        return super().dispatch(request)


class CacheMixin:
    """Caches GET responses based on path."""
    _cache: dict[str, tuple[Response, float]] = {}
    cache_ttl: int = 60  # seconds

    def dispatch(self, request: Request) -> Response:
        if request.method != "GET":
            return super().dispatch(request)

        cache_key = self._make_cache_key(request)
        cached = self._cache.get(cache_key)

        if cached and (time.time() - cached[1]) < self.cache_ttl:
            response = cached[0]
            response.headers["X-Cache"] = "HIT"
            return response

        response = super().dispatch(request)
        self._cache[cache_key] = (response, time.time())
        response.headers["X-Cache"] = "MISS"
        return response

    def _make_cache_key(self, request: Request) -> str:
        return hashlib.md5(request.path.encode()).hexdigest()


class LogMixin:
    """Logs request/response details."""

    def dispatch(self, request: Request) -> Response:
        start = time.perf_counter()
        print(f"→ {request.method} {request.path} (user={request.user})")

        response = super().dispatch(request)

        elapsed = (time.perf_counter() - start) * 1000
        print(f"← {response.status} ({elapsed:.1f}ms)")
        return response
```

#### Step 4: Composing Mixins

```python
class UserAPIView(LogMixin, AuthMixin, CacheMixin, JSONMixin, View):
    """
    MRO: LogMixin → AuthMixin → CacheMixin → JSONMixin → View → object
    
    Request flow:
    1. LogMixin.dispatch — logs entry, calls super()
    2. AuthMixin.dispatch — checks auth, calls super()
    3. CacheMixin.dispatch — checks cache, calls super() on miss
    4. JSONMixin.dispatch — calls super(), serializes response
    5. View.dispatch — routes to get/post/etc handler
    """
    cache_ttl = 30  # Override cache duration

    def get(self, request: Request) -> Response:
        users = [
            {"id": 1, "name": "Alice"},
            {"id": 2, "name": "Bob"},
        ]
        return Response(body=users)


# Verify MRO:
print(UserAPIView.__mro__)
# (UserAPIView, LogMixin, AuthMixin, CacheMixin, JSONMixin, View, object)

# Test:
view = UserAPIView()
req = Request("/api/users", "GET", user="admin")
resp = view.dispatch(req)
# → GET /api/users (user=admin)
# ← 200 (0.1ms)
print(resp.body)  # '[{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]'
print(resp.headers["X-Cache"])  # MISS (first request)
```

#### Step 5: Why Order Matters

```python
# WRONG order — Auth after Cache means unauthenticated responses get cached:
# class BadView(CacheMixin, AuthMixin, JSONMixin, View): ...
# A cached response from an authenticated user would be served to anonymous users!

# CORRECT order — Auth BEFORE Cache:
# class GoodView(AuthMixin, CacheMixin, JSONMixin, View): ...
# Unauthenticated requests are rejected before hitting the cache.
```

**Final Answer:**

```python
# Mixin composition rules:
# 1. Mixins go LEFT of base class (processed first in MRO)
# 2. Order = execution order (leftmost runs first)
# 3. Security mixins (Auth) should run BEFORE caching mixins
# 4. Logging mixins should be OUTERMOST (first and last to execute)
# 5. Always use super().method() for cooperative chaining
# 6. Test MRO with ClassName.__mro__ to verify order
```

### 10.1 How super() Actually Works — MRO and C3 Linearization

`super()` is one of Python's most misunderstood features. It does NOT simply call "the parent class." It calls the **next class in the Method Resolution Order (MRO)**, which is computed using the C3 linearization algorithm.

**The Problem super() Solves:**

In single inheritance, "call the parent" is unambiguous. In multiple inheritance (diamond problem), it's not:

```python
class A:
    def method(self):
        print("A")

class B(A):
    def method(self):
        print("B")
        super().method()  # Calls next in MRO, not necessarily A

class C(A):
    def method(self):
        print("C")
        super().method()

class D(B, C):
    def method(self):
        print("D")
        super().method()

D().method()
# Output: D, B, C, A
# MRO: D → B → C → A → object
```

Without C3 linearization, `B.method()` calling `super().method()` would skip `C` entirely, calling `A` directly. C3 ensures every class in the hierarchy is called exactly once, in a consistent order.

**The C3 Linearization Algorithm:**

Given a class `C` with bases `B1, B2, ..., Bn`, the MRO is computed as:

$$
L[C] = C + \text{merge}(L[B_1], L[B_2], \ldots, L[B_n], [B_1, B_2, \ldots, B_n])
$$

The `merge` operation:
1. Take the head (first element) of the first non-empty list
2. If that head does not appear in the tail of any other list, add it to the result and remove it from all lists
3. Otherwise, skip to the next list and try its head
4. Repeat until all lists are empty (success) or no valid head exists (TypeError: inconsistent MRO)

**Worked Example:**

```python
# For class D(B, C) where B(A) and C(A):
# L[A] = [A, object]
# L[B] = [B] + merge(L[A], [A]) = [B] + merge([A, object], [A])
#       = [B, A, object]
# L[C] = [C, A, object]
# L[D] = [D] + merge(L[B], L[C], [B, C])
#       = [D] + merge([B, A, object], [C, A, object], [B, C])
#
# Step 1: head of first list = B. B not in tail of any list? 
#          Tails: [A, object], [A, object], [C]. B not in any. Take B.
#          Remove B: [A, object], [C, A, object], [C]
#
# Step 2: head = A. A in tail of [C, A, object]? YES. Skip.
#          Try next list head = C. C not in tail of any. Take C.
#          Remove C: [A, object], [A, object], []
#
# Step 3: head = A. A not in any tail now. Take A.
#          Remove A: [object], [object], []
#
# Step 4: head = object. Take object.
#
# Result: L[D] = [D, B, C, A, object]
```

**When C3 Fails (Inconsistent MRO):**

```python
# This raises TypeError:
# class X(A, B): ...
# class Y(B, A): ...
# class Z(X, Y): ...  # TypeError: Cannot create a consistent MRO
#
# Because X says A before B, but Y says B before A — contradiction.
```

**Practical Implications:**

1. `super()` with no arguments (Python 3) uses compiler magic: it's equivalent to `super(__class__, self)` where `__class__` is a cell variable injected by the compiler.

2. `super()` returns a **proxy object** that delegates method calls to the next class in the MRO of the *original* object's type — not the class where `super()` is written.

3. For cooperative multiple inheritance to work, ALL classes in the hierarchy must use `super()` (including the root). This is why mixins must always call `super()`.

### 10.2 `__slots__` vs Dict-Backed Instances — Memory and Performance Analysis

By default, Python instances store attributes in a per-instance `__dict__` (a hash table). `__slots__` replaces this with a fixed-size struct, trading flexibility for memory savings and speed.

**Default (dict-backed):**

```python
class PointDict:
    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

p = PointDict(08.0, 2.0)
print(p.__dict__)  # {'x': 08.0, 'y': 2.0}
p.z = 3.0  # Dynamic attribute — works fine
```

Memory per instance: 16 (object header) + 8 (`__dict__` pointer) + 8 (`__weakref__` pointer) + 64 (empty dict) + 2×(key pointer + value pointer) ≈ **168 bytes**

**With `__slots__`:**

```python
class PointSlots:
    __slots__ = ("x", "y")

    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

p = PointSlots(08.0, 2.0)
# p.__dict__  # AttributeError: no __dict__
# p.z = 3.0  # AttributeError: no dynamic attributes
```

Memory per instance: 16 (object header) + 8 (x slot) + 8 (y slot) = **40 bytes** (76% reduction!)

**Benchmark (1 million instances):**

```python
import sys
from pympler import asizeof

points_dict = [PointDict(float(i), float(i)) for i in range(1_000_000)]
points_slots = [PointSlots(float(i), float(i)) for i in range(1_000_000)]

print(f"Dict-backed:  {asizeof.asizeof(points_dict) / 1e6:.1f} MB")   # ~200 MB
print(f"Slots-backed: {asizeof.asizeof(points_slots) / 1e6:.1f} MB")  # ~72 MB
```

**Attribute access speed:**

`__slots__` attributes are accessed via a fixed offset (like a C struct member), while `__dict__` attributes require a hash table lookup. Slots are ~20-30% faster for attribute access in tight loops.

**When NOT to use `__slots__`:**

| Scenario | Use `__slots__`? |
|----------|-----------------|
| Millions of instances (data points, graph nodes) | ✅ Yes |
| Classes with dynamic attributes (ORMs, mocks) | ❌ No |
| Classes using `__dict__` introspection | ❌ No |
| Inheritance hierarchies (each class needs own slots) | ⚠️ Careful |
| Dataclasses with `slots=True` (Python 3.10+) | ✅ Yes |

**The inheritance trap:**

```python
class Base:
    __slots__ = ("x",)

class Child(Base):
    __slots__ = ("y",)  # Must declare OWN slots only
    # If you forget __slots__ here, Child gets a __dict__ anyway!

class BadChild(Base):
    pass  # Has __dict__ because no __slots__ declared
    # BadChild instances have BOTH x slot AND __dict__ — worst of both worlds
```

**Modern best practice (Python 3.10+):**

```python
from dataclasses import dataclass

@dataclass(slots=True, frozen=True)
class Point:
    x: float
    y: float
    # Automatically generates __slots__ = ('x', 'y')
    # frozen=True makes it immutable (hashable, usable as dict key)
```
