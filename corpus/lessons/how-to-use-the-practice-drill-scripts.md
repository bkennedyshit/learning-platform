# How to Use the Practice Drill Scripts

> Quick refresher: every chapter in this curriculum has a Python drill generator that produces fresh, randomized practice problems with full step-by-step solutions. You run a script, it writes a markdown file, you open that file in Obsidian, and you do the problems on paper. This doc explains the whole workflow.

---

## The TL;DR command

For any chapter you want to practice, find its drill script and run it:

```bash
python "<path>/_practice/scripts/<chapter>_<topic>.py" --count 10 --seed 42
```

It will print a single line:

```
Wrote 10 problems (seed=42) -> <path>/_practice/<chapter>_drills.md
```

Open that `.md` file in Obsidian. Done.

---

In Obsidian's **Reading view**, every problem renders as cleanly-typeset LaTeX with a collapsed **"Show solution"** spoiler beneath it. The intended workflow:

1. Click the script command, it writes the `.md` file.
2. Open the file in Obsidian.
3. Read **Problem 1**, do it on paper or in a scratch note.
4. Click **Show solution** → check your work step by step.
5. Repeat for Problem 2, 3, … N.

If you're using the [Obsidian Spaced Repetition plugin](https://www.stephenmwangi.com/obsidian-spaced-repetition/), some scripts (mostly outside Math/Physics — the AI/ML, Biomech, Neuro tracks) also include a `?` delimiter that makes each problem a flashcard the plugin can surface in your daily review queue. Look for the `review/<topic>` tag in frontmatter — that signals SR-plugin compatibility.

## Where the drill files land

By default, **every** drill script writes to:

```
<subject-folder>/_practice/<chapter>_drills.md
```

Examples:

| Script you run | Output file |
|---|---|
| `2.6_eigenvalues.py` | `02 - Linear Algebra & Matrix Theory/_practice/2.6_drills.md` |
| `4.4_central_forces.py` | `04 - Classical Mechanics & Dynamical Systems/_practice/4.4_drills.md` |
| `10.5_attention.py` | `23 - AI & Machine Learning Systems/_practice/10.5_drills.md` |

The output **overwrites** the same file every run. If you want to keep an old set, use `--out` to redirect:

```bash
python 2.6_eigenvalues.py --count 12 --seed 42 --out "C:/scratch/eigen_set_A.md"
```

---

## The three flags

| Flag | What it does | Default |
|---|---|---|
| `--count N` | How many problems to generate | 24 (varies per script) |
| `--seed N` | Reproducibility — same seed → same problems | random each run |
| `--out PATH` | Custom output path | `_practice/<chapter>_drills.md` |

**Pro tip — reproducibility:** If you find a particularly good problem set, jot down the seed. `python 2.6_eigenvalues.py --count 12 --seed 1729` always gives you the same 12 problems.

## Where the scripts live

Every subject folder has the same internal layout:

```
<subject-folder>/
├── Subject_Plan.md          ← syllabus + curriculum mindmap
├── README.md                ← per-subject refresher (lists drill commands)
├── 1.1 - Chapter Title.md   ← chapter notes
├── 1.2 - Chapter Title.md
├── ...
└── _practice/
    ├── 1.1_drills.md        ← appears AFTER you run a drill
    ├── 1.2_drills.md
    └── scripts/
        ├── 1.1_topic.py     ← drill generators (the things you run)
        ├── 1.2_topic.py
        └── ...
```

For Math & Physics there's an extra layer (each numbered subject is its own folder under `07 - Math and Physics/`); for the other Learning tracks (08–13), the chapters and `_practice/` sit directly inside the track folder.

## What about the calculators?

The chapter notes reference local C++/Qt calculators (`MatrixCommander`, `CalculusVisualizer`, `ProbabilityStudio`) for hands-on numerical experimentation. **The drill scripts and the calculators are independent.** Drill scripts use SymPy in pure Python; calculators are separate native apps you launch from `00 - Learning_Tools` or `00 - Dev_Tools`.

If you want to **bundle** them into a single Vite-based GUI app — see the **Practice GUI App vision doc** at `[PRACTICE_GUI_APP_VISION](PRACTICE_GUI_APP_VISION)`.

## Common workflows

### "Give me ten determinant problems right now"

```bash
python "07 - Math and Physics/02 - Linear Algebra & Matrix Theory/_practice/scripts/2.5_determinants.py" --count 10
```

→ Open `02 - Linear Algebra & Matrix Theory/_practice/2.5_drills.md` in Obsidian.

### "Random refresher across a whole subject"

Run several scripts in sequence, then open all the resulting `_drills.md` files in Obsidian's tab pane:

```bash
python "07 - Math and Physics/02 - Linear Algebra & Matrix Theory/_practice/scripts/2.1_vectors.py" --count 4
python "07 - Math and Physics/02 - Linear Algebra & Matrix Theory/_practice/scripts/2.5_determinants.py" --count 4
python "07 - Math and Physics/02 - Linear Algebra & Matrix Theory/_practice/scripts/2.6_eigenvalues.py" --count 4
```

### "Reproducible weekly drill set"

Pin a seed for the week, run several chapters with that seed, you can re-run if files get clobbered:

```bash
python "<script>" --count 8 --seed $(date +%V)
```

## Troubleshooting

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError: No module named 'sympy'` | `pip install sympy numpy scipy` |
| Script runs but writes nothing | The script is missing its `main()` entry point. (Only `2.5_determinants.py` had this bug originally — fixed.) Re-pull the latest version. |
| LaTeX doesn't render in Obsidian | Make sure you're in **Reading view**, not Source view. Also make sure your Obsidian theme isn't overriding MathJax. |
| `<details>` blocks won't expand | Make sure you're in Reading view. In Source view, `<details>` is just plain HTML. |
| File created but Obsidian doesn't show it | Refresh the file tree (right-click in the file pane → Refresh) or restart Obsidian. |
