# 28.3 — Graphics Rendering Pipeline

> *"The speed of light sucks."* — John Carmack

The graphics rendering pipeline is the assembly line that converts 3D geometry into 2D pixels at 60–144 frames per second. Understanding each stage — from vertex assembly through rasterization to fragment shading — is essential for writing performant shaders, debugging visual artifacts, and optimizing VR applications where every millisecond counts. This chapter dissects the modern GPU pipeline stage by stage, derives the mathematics of clipping and rasterization, and explains how hardware parallelism makes real-time rendering possible.

## 📚 1. Definitions

### Definition 28.3.1 — The Rendering Pipeline

The **rendering pipeline** is the sequence of computational stages that transforms 3D scene data (vertices, textures, lights) into a 2D raster image (framebuffer). Stages are either **programmable** (shaders written by the developer) or **fixed-function** (hardware-implemented, configurable but not programmable).

### Definition 28.3.2 — Vertex Buffer Object (VBO) and Index Buffer Object (IBO)

A **VBO** stores per-vertex attributes (position, normal, UV, color, tangent) in GPU memory. An **IBO** stores indices that define how vertices connect into primitives (triangles, lines, points), enabling vertex reuse.

### Definition 28.3.3 — Clip Space and the Homogeneous Divide

After the vertex shader outputs a 4D position $\mathbf{v}_{\text{clip}} = (x, y, z, w)$, a vertex is **inside the view frustum** if and only if:

$$
-w \leq x \leq w, \quad -w \leq y \leq w, \quad -w \leq z \leq w
$$

(OpenGL convention; DirectX uses $0 \leq z \leq w$.) The **perspective divide** maps to NDC: $(x/w, y/w, z/w)$.

### Definition 28.3.4 — Barycentric Coordinates

Given a triangle with vertices $\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2$, any point $\mathbf{p}$ in the plane can be expressed as:

$$
\mathbf{p} = \lambda_0 \mathbf{v}_0 + \lambda_1 \mathbf{v}_1 + \lambda_2 \mathbf{v}_2, \quad \lambda_0 + \lambda_1 + \lambda_2 = 1
$$

The point is **inside** the triangle iff $\lambda_0, \lambda_1, \lambda_2 \geq 0$. Barycentric coordinates are used to interpolate vertex attributes (color, UV, normals) across the triangle face.

### Definition 28.3.5 — Edge Function

For 2D triangle rasterization, the **edge function** for edge from $\mathbf{v}_a$ to $\mathbf{v}_b$ evaluated at point $\mathbf{p}$:

$$
E_{ab}(\mathbf{p}) = (p_x - a_x)(b_y - a_y) - (p_y - a_y)(b_x - a_x)
$$

A point is inside the triangle if all three edge functions have the same sign (positive for counter-clockwise winding).

### Definition 28.3.6 — Fragment

A **fragment** is a candidate pixel generated by rasterization. It carries interpolated attributes (position, normal, UV, depth) and may or may not survive the depth/stencil test to become a final pixel in the framebuffer.

### Definition 28.3.7 — Depth Buffer (Z-Buffer)

The **depth buffer** stores the closest depth value $z_{\text{ndc}}$ at each pixel. During the output merger, a fragment's depth is compared against the stored value. If closer (less than, by default), the fragment overwrites the pixel; otherwise it is discarded.

### Definition 28.3.8 — Draw Call

A **draw call** is a single command from the CPU to the GPU instructing it to render a batch of primitives with a specific shader, texture set, and render state. Minimizing draw calls is critical for performance because each call incurs CPU-GPU synchronization overhead.

### Definition 28.3.9 — Perspective-Correct Interpolation

After the perspective divide, linearly interpolating attributes in screen space produces incorrect results (straight lines on surfaces appear curved). **Perspective-correct interpolation** divides each attribute by $w$ before interpolation and multiplies back afterward:

$$
A(\mathbf{p}) = \frac{\lambda_0 A_0/w_0 + \lambda_1 A_1/w_1 + \lambda_2 A_2/w_2}{\lambda_0/w_0 + \lambda_1/w_1 + \lambda_2/w_2}
$$

### Definition 28.3.10 — Forward vs. Deferred Rendering

**Forward rendering:** Each object is shaded with all affecting lights in a single pass. Cost: $O(\text{objects} \times \text{lights})$.

**Deferred rendering:** Geometry pass writes position, normal, albedo to a G-buffer. A screen-space lighting pass then evaluates lights per-pixel. Cost: $O(\text{pixels} \times \text{lights})$, decoupled from geometry complexity. Drawback: high memory bandwidth, difficulty with transparency and MSAA.

## 📐 2. Axioms / Postulates

### Axiom 28.3.A1 — The Painter's Algorithm Is Insufficient

Sorting triangles back-to-front and drawing in order (painter's algorithm) fails for intersecting or cyclically overlapping geometry. The z-buffer provides a per-pixel solution that handles all cases correctly.

### Axiom 28.3.A2 — GPU Parallelism Model

The GPU executes vertex shaders in parallel across all vertices and fragment shaders in parallel across all fragments. Stages are pipelined: while one triangle is being rasterized, the next is being vertex-shaded. This massive parallelism (thousands of shader cores) is what enables real-time rendering.

### Axiom 28.3.A3 — Winding Order Determines Front/Back Face

A triangle with vertices ordered counter-clockwise (CCW) when viewed from the front is considered **front-facing**. The GPU can cull back-facing triangles (those with CW winding from the camera's perspective) before rasterization, halving the fragment workload for closed meshes.

## 🛡️ 3. Lemmas

### Lemma 28.3.1 — Barycentric Coordinates from Edge Functions

Given edge functions $E_{01}$, $E_{12}$, $E_{20}$ for a triangle, the barycentric coordinates at point $\mathbf{p}$ are:

$$
\lambda_0 = \frac{E_{12}(\mathbf{p})}{E_{12}(\mathbf{v}_0)}, \quad \lambda_1 = \frac{E_{20}(\mathbf{p})}{E_{20}(\mathbf{v}_1)}, \quad \lambda_2 = \frac{E_{01}(\mathbf{p})}{E_{01}(\mathbf{v}_2)}
$$

**Proof.** The edge function $E_{12}(\mathbf{p})$ computes twice the signed area of triangle $(\mathbf{v}_1, \mathbf{v}_2, \mathbf{p})$. The full triangle has signed area $E_{12}(\mathbf{v}_0)/2$. The ratio gives the fractional area opposite vertex 0, which is exactly $\lambda_0$ by the geometric definition of barycentric coordinates.

Formally: $\lambda_0 = \text{Area}(\mathbf{v}_1, \mathbf{v}_2, \mathbf{p}) / \text{Area}(\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2)$.

The edge function $E_{ab}(\mathbf{p}) = (\mathbf{p} - \mathbf{a}) \times (\mathbf{b} - \mathbf{a})$ (2D cross product) equals twice the signed area of triangle $(\mathbf{a}, \mathbf{b}, \mathbf{p})$.

Therefore $\lambda_0 = E_{12}(\mathbf{p}) / E_{12}(\mathbf{v}_0)$, and similarly for $\lambda_1, \lambda_2$. $\blacksquare$

### Lemma 28.3.2 — Clipping Preserves Convexity

The Sutherland-Hodgman algorithm clips a convex polygon against a half-plane and produces a convex polygon. Since a triangle is convex and each clip plane defines a half-space, the result of clipping against all 6 frustum planes is a convex polygon (with at most $n + 6$ vertices for an $n$-gon input).

**Proof.** A convex polygon intersected with a half-plane (convex set) is convex (intersection of convex sets is convex). By induction over the 6 clip planes, the result remains convex at each step. $\blacksquare$

### Lemma 28.3.3 — Depth Buffer Precision Distribution

The perspective projection maps view-space depth $z_v \in [-n, -f]$ to NDC depth:

$$
z_{\text{ndc}} = \frac{f + n}{f - n} + \frac{2fn}{(f - n) z_v}
$$

The derivative with respect to $z_v$:

$$
\frac{dz_{\text{ndc}}}{dz_v} = \frac{-2fn}{(f-n)z_v^2}
$$

This is large near $z_v = -n$ (high precision near the camera) and small near $z_v = -f$ (low precision far away). The ratio of precision at near vs. far is approximately $f/n$. For $n = 0.1$, $f = 1000$: the far half of the depth range gets only $0.01\%$ of the available precision.

**Mitigation:** Reversed-Z (map near to 1, far to 0) combined with a floating-point depth buffer concentrates precision where $1/z$ varies most. $\blacksquare$

### Lemma 28.3.4 — Perspective-Correct Interpolation Derivation

**Claim:** In screen space, attribute $A$ must be interpolated as $A/w$ (not $A$ directly) to account for perspective foreshortening.

**Proof.** In clip space, a point on the triangle is:

$$
\mathbf{P}_{\text{clip}} = \lambda_0 \mathbf{V}_0 + \lambda_1 \mathbf{V}_1 + \lambda_2 \mathbf{V}_2
$$

where $\lambda_i$ are the true (3D) barycentric coordinates. After perspective divide, screen position is:

$$
\mathbf{p}_{\text{screen}} = \frac{\mathbf{P}_{\text{clip}}.xy}{w(\lambda_0, \lambda_1, \lambda_2)}
$$

The screen-space barycentric coordinates $\mu_i$ differ from the 3D $\lambda_i$. The relationship is:

$$
\lambda_i = \frac{\mu_i / w_i}{\mu_0/w_0 + \mu_1/w_1 + \mu_2/w_2}
$$

Therefore, to interpolate attribute $A$:

$$
A = \lambda_0 A_0 + \lambda_1 A_1 + \lambda_2 A_2 = \frac{\mu_0 A_0/w_0 + \mu_1 A_1/w_1 + \mu_2 A_2/w_2}{\mu_0/w_0 + \mu_1/w_1 + \mu_2/w_2}
$$

This is the formula the GPU hardware implements for all `varying`/`out` interpolations. $\blacksquare$

## 👑 4. Theorems

### Theorem 28.3.1 — Sutherland-Hodgman Clipping Algorithm

A polygon can be clipped against a convex region (the view frustum) by sequentially clipping against each bounding half-plane. For each edge of the polygon and each clip boundary, there are four cases:

1. **Both vertices inside:** Keep the second vertex.
2. **First inside, second outside:** Output the intersection point.
3. **Both outside:** Output nothing.
4. **First outside, second inside:** Output the intersection point and the second vertex.

The algorithm processes all edges against one clip plane before moving to the next.

### Theorem 28.3.2 — The Z-Buffer Algorithm Correctness

The z-buffer algorithm correctly resolves visibility for any configuration of opaque triangles (including intersecting and cyclically overlapping ones) by making per-fragment depth comparisons.

**Correctness condition:** For each pixel, the fragment with the smallest depth value (closest to camera) determines the final color. Since depth comparison is transitive and total-ordered on $\mathbb{R}$, the minimum always exists and is unique (ties broken by draw order).

### Theorem 28.3.3 — Rasterization via Edge Functions Is $O(1)$ Per Pixel

The edge function $E_{ab}(\mathbf{p})$ is a linear function of $\mathbf{p}$. Therefore:
- Moving one pixel right: $E_{ab}(p_x + 1, p_y) = E_{ab}(p_x, p_y) + (b_y - a_y)$
- Moving one pixel down: $E_{ab}(p_x, p_y + 1) = E_{ab}(p_x, p_y) - (b_x - a_x)$

After computing the edge function at one point, subsequent pixels require only one addition per edge — $O(1)$ per pixel regardless of triangle size.

### Theorem 28.3.4 — Early-Z Rejection

If the depth test is performed **before** the fragment shader (early-Z), fragments that would fail the depth test are discarded without executing the expensive fragment shader. This optimization is valid when:
- The fragment shader does not write to `gl_FragDepth` (no custom depth).
- Alpha testing / `discard` is not used (which could prevent the fragment from writing depth).

Modern GPUs implement hierarchical-Z (Hi-Z) that rejects entire tiles of fragments using a coarse depth buffer.

## ✍️ 5. Proofs / Derivations

### 5.1 Derivation of the Edge Function

**Goal:** Show that the edge function computes twice the signed area and determines point-in-triangle.

**Setup:** Triangle vertices $\mathbf{v}_0 = (x_0, y_0)$, $\mathbf{v}_1 = (x_1, y_1)$, $\mathbf{v}_2 = (x_2, y_2)$ in screen space (2D after projection).

**Step 1:** The signed area of a triangle with vertices $A, B, C$ is:

$$
\text{Area}(A, B, C) = \frac{1}{2} \det \begin{pmatrix} B_x - A_x & C_x - A_x \\ B_y - A_y & C_y - A_y \end{pmatrix}
$$

$$
= \frac{1}{2}[(B_x - A_x)(C_y - A_y) - (B_y - A_y)(C_x - A_x)]
$$

**Step 2:** Define the edge function for edge $(\mathbf{v}_1, \mathbf{v}_2)$ evaluated at point $\mathbf{p}$:

$$
E_{12}(\mathbf{p}) = (p_x - v_{1x})(v_{2y} - v_{1y}) - (p_y - v_{1y})(v_{2x} - v_{1x})
$$

This equals $2 \cdot \text{Area}(\mathbf{v}_1, \mathbf{v}_2, \mathbf{p})$.

**Step 3:** For a CCW-wound triangle, $E_{12}(\mathbf{v}_0) > 0$ (the third vertex is on the positive side of edge 1→2). A point $\mathbf{p}$ is inside the triangle iff it is on the positive side of all three edges:

$$
E_{12}(\mathbf{p}) \geq 0, \quad E_{20}(\mathbf{p}) \geq 0, \quad E_{01}(\mathbf{p}) \geq 0
$$

**Step 4:** The incremental property. Since $E_{12}$ is linear in $(p_x, p_y)$:

$$
E_{12}(p_x + 1, p_y) = E_{12}(p_x, p_y) + (v_{2y} - v_{1y})
$$

$$
E_{12}(p_x, p_y + 1) = E_{12}(p_x, p_y) - (v_{2x} - v_{1x})
$$

These increments are constants for a given triangle, precomputed once. $\blacksquare$

### 5.2 Derivation of Clip-Space Line-Plane Intersection

**Goal:** Find the intersection of a line segment with a clip plane in homogeneous coordinates.

**Setup:** Two vertices $\mathbf{A} = (x_A, y_A, z_A, w_A)$ and $\mathbf{B} = (x_B, y_B, z_B, w_B)$ in clip space. Consider the clip plane $x = w$ (right frustum boundary).

**Step 1:** A point is inside if $x \leq w$, i.e., $x - w \leq 0$. Define:

$$
d_A = x_A - w_A, \quad d_B = x_B - w_B
$$

If $d_A$ and $d_B$ have opposite signs, the edge crosses the clip plane.

**Step 2:** Parameterize the edge: $\mathbf{P}(t) = (1-t)\mathbf{A} + t\mathbf{B}$ for $t \in [0, 1]$.

At the intersection, $x(t) = w(t)$:

$$
(1-t)x_A + t \cdot x_B = (1-t)w_A + t \cdot w_B
$$

$$
(1-t)(x_A - w_A) + t(x_B - w_B) = 0
$$

$$
(1-t)d_A + t \cdot d_B = 0
$$

$$
d_A - t \cdot d_A + t \cdot d_B = 0
$$

$$
t(d_B - d_A) = -d_A
$$

$$
t = \frac{-d_A}{d_B - d_A} = \frac{d_A}{d_A - d_B}
$$

**Step 3:** The intersection point is:

$$
\mathbf{I} = (1 - t)\mathbf{A} + t\mathbf{B} = \mathbf{A} + t(\mathbf{B} - \mathbf{A})
$$

All vertex attributes (position, normal, UV, color) are interpolated with the same $t$ value. This is performed in clip space (before the perspective divide) to ensure correctness. $\blacksquare$

### 5.3 Why Naive Screen-Space Interpolation Fails

**Goal:** Demonstrate the error in linear screen-space interpolation.

**Setup:** Consider two vertices at view-space depths $z_0 = -1$ and $z_1 = -10$, with attribute values $A_0 = 0$ and $A_1 = 1$. The midpoint in 3D has $A = 0.5$ at $z = -5.5$.

**Step 1:** After perspective projection with near $= 1$, the screen-space positions are:

$$
s_0 = \frac{x_0}{-z_0} = \frac{x_0}{1}, \quad s_1 = \frac{x_1}{-z_1} = \frac{x_1}{10}
$$

The screen-space midpoint $s = (s_0 + s_1)/2$ does NOT correspond to the 3D midpoint because perspective compresses distant geometry.

**Step 2:** The 3D midpoint projects to screen position:

$$
s_{\text{mid}} = \frac{x_{\text{mid}}}{5.5}
$$

which is NOT $(s_0 + s_1)/2$ in general.

**Step 3:** Perspective-correct interpolation fixes this by interpolating $A/w$ and $1/w$ linearly in screen space, then dividing:

$$
A_{\text{correct}} = \frac{\text{lerp}(A_0/w_0, A_1/w_1, t_{\text{screen}})}{\text{lerp}(1/w_0, 1/w_1, t_{\text{screen}})}
$$

Since $1/z$ (and thus $1/w$) varies linearly in screen space (a property of perspective projection), this recovers the correct 3D interpolation. $\blacksquare$

## 💻 6. Code Examples

### 6.1 Python: Software Rasterizer (Edge Function Method)

```python
import numpy as np

def edge_function(v0, v1, p):
    """Compute edge function: 2x signed area of triangle (v0, v1, p)."""
    return (p[0] - v0[0]) * (v1[1] - v0[1]) - (p[1] - v0[1]) * (v1[0] - v0[0])

def rasterize_triangle(v0, v1, v2, width, height, framebuffer, depthbuffer, colors):
    """Rasterize a single triangle using edge functions."""
    # Bounding box (clamped to screen)
    min_x = max(0, int(min(v0[0], v1[0], v2[0])))
    max_x = min(width - 1, int(max(v0[0], v1[0], v2[0])))
    min_y = max(0, int(min(v0[1], v1[1], v2[1])))
    max_y = min(height - 1, int(max(v0[1], v1[1], v2[1])))

    # Total area (for normalization)
    area = edge_function(v0, v1, v2)
    if area <= 0:
        return  # Back-facing or degenerate

    for y in range(min_y, max_y + 1):
        for x in range(min_x, max_x + 1):
            p = np.array([x + 0.5, y + 0.5])  # pixel center

            # Barycentric via edge functions
            w0 = edge_function(v1, v2, p)
            w1 = edge_function(v2, v0, p)
            w2 = edge_function(v0, v1, p)

            if w0 >= 0 and w1 >= 0 and w2 >= 0:
                # Normalize
                w0 /= area
                w1 /= area
                w2 /= area

                # Perspective-correct interpolation
                inv_w = w0/v0[3] + w1/v1[3] + w2/v2[3]
                depth = 1.0 / inv_w  # not exactly, simplified

                # Depth test
                z = w0*v0[2] + w1*v1[2] + w2*v2[2]
                if z < depthbuffer[y, x]:
                    depthbuffer[y, x] = z
                    # Interpolate color
                    color = w0*colors[0] + w1*colors[1] + w2*colors[2]
                    framebuffer[y, x] = color
```

### 6.2 GLSL: Minimal Vertex + Fragment Shader Pair

```glsl
// === Vertex Shader ===
#version 450 core

layout(location = 0) in vec3 aPos;
layout(location = 1) in vec3 aNormal;
layout(location = 2) in vec2 aTexCoord;

uniform mat4 u_MVP;
uniform mat4 u_Model;
uniform mat3 u_NormalMatrix;

out vec3 fragWorldPos;
out vec3 fragNormal;
out vec2 fragUV;

void main() {
    fragWorldPos = vec3(u_Model * vec4(aPos, 1.0));
    fragNormal = normalize(u_NormalMatrix * aNormal);
    fragUV = aTexCoord;
    gl_Position = u_MVP * vec4(aPos, 1.0);
}
```

```glsl
// === Fragment Shader ===
#version 450 core

in vec3 fragWorldPos;
in vec3 fragNormal;
in vec2 fragUV;

uniform vec3 u_LightPos;
uniform vec3 u_ViewPos;
uniform sampler2D u_Albedo;

out vec4 FragColor;

void main() {
    vec3 albedo = texture(u_Albedo, fragUV).rgb;
    vec3 N = normalize(fragNormal);
    vec3 L = normalize(u_LightPos - fragWorldPos);
    vec3 V = normalize(u_ViewPos - fragWorldPos);
    vec3 H = normalize(L + V);

    // Blinn-Phong
    float diff = max(dot(N, L), 0.0);
    float spec = pow(max(dot(N, H), 0.0), 64.0);
    vec3 ambient = 0.03 * albedo;

    FragColor = vec4(ambient + diff * albedo + spec * vec3(1.0), 1.0);
}
```

### Example 28.3.1 — Edge Function Point-in-Triangle Test

**Problem:** Triangle vertices (screen space): $\mathbf{v}_0 = (100, 50)$, $\mathbf{v}_1 = (300, 50)$, $\mathbf{v}_2 = (200, 250)$. Is point $\mathbf{p} = (180, 120)$ inside?

<details>
<summary>🔍 View Step-by-Step Solution</summary>

**Step 1:** Compute edge functions.

$E_{01}(\mathbf{p}) = (180 - 100)(50 - 50) - (120 - 50)(300 - 100) = 80 \cdot 0 - 70 \cdot 200 = -14000$

$E_{12}(\mathbf{p}) = (180 - 300)(250 - 50) - (120 - 50)(200 - 300) = (-120)(200) - (70)(-100) = -24000 + 7000 = -17000$

$E_{20}(\mathbf{p}) = (180 - 200)(50 - 250) - (120 - 250)(100 - 200) = (-20)(-200) - (-130)(-100) = 4000 - 13000 = -9000$

**Step 2:** Check signs. All three are negative. For a CW-wound triangle, all negative means inside. Let us verify the winding:

$E_{01}(\mathbf{v}_2) = (200-100)(50-50) - (250-50)(300-100) = 0 - 200 \cdot 200 = -40000 \lt  0$

The triangle is CW-wound (negative area). Since all edge functions at $\mathbf{p}$ are negative (same sign as the area), $\mathbf{p}$ is **inside**. ✓

**Step 3:** Compute barycentric coordinates:

$$
\lambda_0 = E_{12}(\mathbf{p}) / E_{12}(\mathbf{v}_0) = -17000 / E_{12}(100, 50)
$$

$E_{12}(\mathbf{v}_0) = (100-300)(250-50) - (50-50)(200-300) = (-200)(200) - 0 = -40000$

$\lambda_0 = -17000 / -40000 = 0.425$

$\lambda_1 = E_{20}(\mathbf{p}) / E_{20}(\mathbf{v}_1)$

$E_{20}(\mathbf{v}_1) = (300-200)(50-250) - (50-250)(100-200) = (100)(-200) - (-200)(-100) = -20000 - 20000 = -40000$

$\lambda_1 = -9000 / -40000 = 0.225$

$\lambda_2 = 1 - 0.425 - 0.225 = 0.35$

Verify: $\lambda_0 + \lambda_1 + \lambda_2 = 1.0$ ✓, all $\geq 0$ ✓.

</details>

### Example 28.3.2 — Clip-Space Line Clipping

**Problem:** Vertex $A = (5, 2, -3, 4)$ and vertex $B = (-1, 1, -2, 2)$ in clip space. Clip against the right plane ($x \leq w$).

<details>
<summary>🔍 View Step-by-Step Solution</summary>

**Step 1:** Compute distances to clip plane $x = w$ (inside when $x - w \leq 0$):

$d_A = x_A - w_A = 5 - 4 = 1 \gt  0$ → A is **outside**

$d_B = x_B - w_B = -1 - 2 = -3 \lt  0$ → B is **inside**

**Step 2:** This is case 4 (first outside, second inside). Compute intersection parameter:

$$
t = \frac{d_A}{d_A - d_B} = \frac{1}{1 - (-3)} = \frac{1}{4} = 0.25
$$

**Step 3:** Compute intersection point:

$$
\mathbf{I} = A + 0.25(B - A) = (5, 2, -3, 4) + 0.25(-6, -1, 1, -2)
$$

$$
= (5 - 1.5, 2 - 0.25, -3 + 0.25, 4 - 0.5) = (3.5, 1.75, -2.75, 3.5)
$$

**Step 4:** Verify: $x_I = 3.5 = w_I = 3.5$. ✓ (exactly on the clip plane)

**Output:** The clipped edge goes from $\mathbf{I} = (3.5, 1.75, -2.75, 3.5)$ to $B = (-1, 1, -2, 2)$.

</details>

### Example 28.3.3 — Perspective-Correct UV Interpolation

**Problem:** Two vertices with depths $w_0 = 2$, $w_1 = 8$ and UV coordinates $u_0 = 0$, $u_1 = 1$. At screen-space midpoint ($t = 0.5$), compute the perspective-correct $u$ value.

<details>
<summary>🔍 View Step-by-Step Solution</summary>

**Step 1:** Naive linear interpolation would give $u = 0.5$. This is incorrect.

**Step 2:** Perspective-correct interpolation:

Interpolate $u/w$: $(1-t) \cdot u_0/w_0 + t \cdot u_1/w_1 = 0.5 \cdot 0/2 + 0.5 \cdot 1/8 = 0 + 0.0625 = 0.0625$

Interpolate $1/w$: $(1-t) \cdot 1/w_0 + t \cdot 1/w_1 = 0.5 \cdot 1/2 + 0.5 \cdot 1/8 = 0.25 + 0.0625 = 0.3125$

**Step 3:** Divide:

$$
u_{\text{correct}} = \frac{0.0625}{0.3125} = 0.2
$$

**Interpretation:** The screen midpoint corresponds to a 3D point much closer to vertex 0 (which is nearer to the camera at $w = 2$). The correct UV is $0.2$, not $0.5$. The perspective projection compresses the far vertex's contribution.

</details>
